# 法术位（环位数量）展示需求

## 1. 背景与目标

用户反馈：法师等可以施法的职业，玩家**无法知道当前等级每个法术环位有几个法术位**。例如 5 级法师应知道"4 个 1 环、3 个 2 环、2 个 3 环"，但界面只显示"最高 3 环"，看不到具体数量。

根因已核验：项目现有施法数据与界面只关心"可选法术的最高环级"（`maxSpellLevelByClassLevel`），**从未登记与展示法术位数量表（spell slots table）**。`docs/rules.md`"跑团查看模式优先展示……可用资源"的约定与 `docs/需求文档/角色卡法术展示需求.md` R3"法术位与资源展示（后续批次）"均指向该缺口，本需求将其落地。

目标产物：

- 数据层：为 2014 全部 8 个施法职业登记 1—20 级法术位表（全施法者表、半施法者表、邪术师契约法术位表三张共享表），来源为已核验的 2014 Basic Rules / SRD 5.1 开放规则。
- 规则层：提供纯函数按职业等级返回法术位明细，保持"派生值由规则重算、不持久化"的既有约定。
- 界面层：施法配置步骤（`SpellcastingStep`）与角色卡"法术"页签（`CharacterSheetStep`）展示法术位概览，邪术师契约法术位（数量 + 环级 + 短休恢复）单独呈现。

## 3. 需求项

### R1 数据层：登记三张法术位表并挂接 `SpellcastingConfig`（必须）

1. 新增 `app/src/rules/data/spell-slots-2014.ts`，导出三个共享常量（只读，来源 `basic-rules-2014`）：
   - `FULL_CASTER_SPELL_SLOTS`：`readonly (readonly number[])[]`，20 项，下标为职业等级 − 1；每项为数组，元素下标为环级 − 1（0 = 1 环），值为该环法术位数量，数组长度即该级拥有的环位数。
   - `HALF_CASTER_SPELL_SLOTS`：同上结构，但 1 级为空数组（2 级起有 1 环位）。
   - `PACT_SPELL_SLOTS`：`readonly (readonly [count, level])[]`，20 项，每项 `[法术位数量, 契约法术位环级]`。
2. `SpellcastingConfig`（`app/src/types/rules.ts`）新增可选字段：
   - `slotsByClassLevel?: readonly (readonly number[])[]`——标准表（full / half caster 共用）。
   - `pactSlotsByClassLevel?: readonly (readonly [number, number])[]`——仅 `mode: 'pact'` 使用。
3. 8 个施法职业的 `spellcasting` 配置分别挂接对应表：
   - 全施法者 5 职业（含法师）：`slotsByClassLevel: FULL_CASTER_SPELL_SLOTS`；
   - 圣武士、游侠：`slotsByClassLevel: HALF_CASTER_SPELL_SLOTS`；
   - 邪术师：`pactSlotsByClassLevel: PACT_SPELL_SLOTS`。
4. 顺带收敛重复：`fullCasterMaximumSpellLevels` / `halfCasterMaximumSpellLevels` / `pactMaximumSpellLevels` 三个常量已分别在 2—3 个文件中重复定义，可一并上提到 `spell-slots-2014.ts` 导出，三个施法者数据文件统一引用（纯重构，不改数值；若为最小改动也可保留原处，仅新增表，二选一即可，但不得产生第四份重复定义）。
5. `maxSpellLevelByClassLevel` 字段保留不动（现有测试与逻辑依赖它；法术位表为新增数据，不替换旧字段）。

### R2 规则层：新增 `getSpellSlots` 纯函数（必须）

`app/src/rules/spellcasting.ts` 新增：

```ts
/** 单个环位的法术位信息。pact 模式下 count 为契约法术位数量、level 为契约环级。 */
export interface SpellSlotInfo {
  readonly level: number      // 环级（1—9；pact 模式即契约环级）
  readonly count: number      // 该环法术位数量
  readonly pact?: boolean     // 是否契约法术位（短休恢复）
}

export function getSpellSlots(config: SpellcastingConfig, classLevel: number): readonly SpellSlotInfo[]
```

- 非 pact 模式：取 `config.slotsByClassLevel[classLevel - 1]`，将数组映射为 `{ level: index + 1, count }[]`，过滤 `count > 0`；未挂表或等级 < 施法起始等级时返回空数组。
- pact 模式：取 `config.pactSlotsByClassLevel[classLevel - 1]`，返回 `[{ level, count, pact: true }]`；`classLevel < 1` 返回空数组。
- 纯函数，不读取草稿以外的状态；**不放入 `DerivedCharacter`**（`derive.ts -> repository` 与 `spellcasting.ts -> derive` 存在既有依赖方向，若 `derive` 反向依赖 `spellcasting` 会形成循环；界面层已可直接调用 `rules/spellcasting`，符合权限矩阵"页面组件可直接使用 rules"）。

### R3 施法配置步骤展示法术位（必须）

`SpellcastingStep.vue`：

1. 在 header 区"最高 X 环"旁（或其下）增加法术位概览，调用 `getSpellSlots(config, draft.targetLevel)`：
   - 非 pact：按环级列出，如 `1环×4 · 2环×3 · 3环×2`；无任何环位时（如圣武士 1 级）不显示。
   - pact：显示 `2 个 3 环契约法术位（短休恢复）`，并沿用现有 `UiNotice` 说明文案补充"契约法术位按短休恢复"。
2. 展示为只读信息，不进入选择交互；组件不硬编码任何职业或表数据。
3. 等级调整（升级/降级）后概览随 `targetLevel` 即时重算，无需玩家重新确认。

### R4 角色卡"法术"页签展示法术位（必须）

`CharacterSheetStep.vue`：

1. "法术"页签顶部新增法术位概览区块（跑团查看模式优先展示可用资源，对应 `docs/rules.md` 约定）：`1环×4 · 2环×3 · 3环×2`；pact 模式显示"契约法术位：3 个 5 环（短休恢复）"。
2. 数值调用同一 `getSpellSlots` 纯函数，与施法步骤展示一致，禁止组件内复制公式。
3. 非施法职业或无环位时不渲染该区块；空状态沿用现有"当前没有需要展示的法术"提示。
4. 角色卡摘要（`DerivedCharacterSummary`）不做展示变更（本需求不扩展摘要抽屉）。

## 4. 非目标与边界

- 不实现法术位"消耗/剩余"追踪（战斗资源管理）：角色卡展示的是当前等级完整法术位数量，不跟踪长休/短休后的已消耗数量。
- 不实现职业资源交互：法师"奥术恢复"、德鲁伊"自然恢复"、术士"术法点转换法术位"、邪术师"秘法奥秘"额外法术位等均属后续批次。
- 不修改 `SpellcastingConfig` 既有字段（`maxSpellLevelByClassLevel` 等）与 `CharacterDraft` 结构；法术位为纯派生展示数据，不新增草稿持久化字段，保持 JSON 导入导出兼容。
- 不涉及 2024 规则与多职业（施法等级 = 职业等级，单职业范围内无需施法等级换算）。
- 不修改 `DerivedCharacter` / `DerivedCharacterSummary`（循环依赖风险见 R2 说明；界面层直接调用 `rules/spellcasting` 即可）。
- 不改变 `SpellcastingStep` 的写入、计数与校验逻辑。

## 5. 涉及模块与依赖方向

```text
新增：app/src/rules/data/spell-slots-2014.ts（无依赖，纯数据常量）
  <- app/src/rules/data/{full-casters,arcane-casters,half-casters}-2014.ts（横向引用，单向无环）
      <- app/src/types/rules.ts（SpellcastingConfig 新增可选字段）

app/src/rules/spellcasting.ts（新增 getSpellSlots / SpellSlotInfo）
  -> 仅依赖既有 types（无新依赖，不反向依赖 derive）

views/character-builder/components/{SpellcastingStep,CharacterSheetStep}.vue
  -> rules/spellcasting（getSpellSlots）
  -> components/ui（沿用现有卡片/通知组件与 scoped SCSS）

app/test/rules/spellcasting-2014.test.ts（新增用例）
```

依赖方向不变：`views -> rules -> types`，rules 保持框架无关；`rules/data` 间横向依赖保持单向无环（`spell-slots-2014` 为最底层，不被任何职业文件反向依赖）。新增模块需同步 `docs/frontend-architecture.md` 8.7 拓扑。

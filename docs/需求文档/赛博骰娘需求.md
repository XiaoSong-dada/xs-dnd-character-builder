# 赛博骰娘需求

## 1. 文档状态

- 需求版本：`v1.1`
- 当前状态：v1.1 已实现
- 对应页面：`/dice`
- 当前页面名称：赛博骰娘
- 本文需求对象：赛博骰娘的基础掷骰能力

## 2. 背景与目标

当前 `/dice` 页面仅展示“骰子工具功能正在开发中”的占位内容，尚未实现掷骰、动画或结果计算。

本阶段的目标是把该页面建设为具有真实骰子观感的 D&D 掷骰工具。玩家可以选择 D&D 常用的全部标准骰型及 `d100`，一次投掷一颗或多颗骰子，并清楚看到每颗骰子的结果与本次投掷总和。

目标体验：

- 骰子具有接近真实投掷的滚动、碰撞和停稳过程，而不是只播放数字跳动。
- 支持 `d4、d6、d8、d10、d12、d20、d100`。
- 支持同类型多颗骰子，也支持多种类型组成一个骰池后一起投掷。
- 投掷结束后展示每颗骰子的独立结果，并自动计算全部结果的数值总和。
- 页面以手机端触控为优先，同时保证结果清晰、操作简单。
- 骰子较多时，物理骰盘应随物理骰体数量扩大，降低骰子堆叠、卡墙和歪骰导致整组动画降级的概率。
- 手机端应能在骰子停稳后缩放、移动并复位 3D 骰盘视图，方便查看密集骰池。
- 从点击投掷开始最多等待 `20` 秒；到达上限仍未完成时应立即公布文字结果，不能让玩家无限等待。

## 3. 已确认需求

1. 赛博骰娘需要模仿真实骰子的感觉。
2. 支持 D&D 常用全部骰型：`d4、d6、d8、d10、d12、d20`。
3. 额外支持百分骰 `d100`。
4. 支持一次投掷多颗骰子。
5. 支持自动计算本次全部骰子结果的总和。

## 4. 名词与规则定义

### 4.1 逻辑骰子

玩家在骰池中添加的一项骰子称为一颗“逻辑骰子”。普通骰型由一颗实体外观骰子表示；一颗 `d100` 由两颗十面骰共同表示，但在数量统计和总和计算中仍视为一颗逻辑骰子。

### 4.2 百分骰 `d100`

`d100` 使用标准百分骰表达：

- 一颗十面骰表示十位：`00、10、20……90`；
- 另一颗十面骰表示个位：`0—9`；
- 两颗骰组合为 `1—100`；
- `00 + 0` 解释为 `100`，不是 `0`。

结果区应同时显示两颗骰的原始读数和换算后的 `d100` 结果，避免玩家无法理解结果来源。

### 4.3 骰池

一次准备投掷的全部逻辑骰子称为“骰池”。骰池可以包含：

- 同一骰型的多颗骰子，例如 `3d6`；
- 多种骰型的组合，例如 `1d20 + 2d6 + 1d4`；
- 一颗或多颗 `d100`。

### 4.4 总和

本次总和等于骰池内每颗逻辑骰子的最终点数之和：

```text
总和 = 所有普通骰结果之和 + 所有 d100 换算结果之和
```

`d100` 的十位骰和个位骰不得作为两颗普通 `d10` 重复计入总和。

## 5. 用户流程

1. 玩家进入“赛博骰娘”页面。
2. 玩家选择一种骰型并添加到骰池。
3. 玩家可以继续增加相同骰型的数量，或添加其他骰型。
4. 页面持续展示当前骰池表达式，例如 `1d20 + 2d6`。
5. 玩家点击“投掷”后，骰子进入滚动、碰撞和停稳动画。
6. 所有骰子停稳后，页面公布每颗骰子的结果。
7. 页面自动显示本次结果总和。
8. 玩家可以保留当前骰池再次投掷，也可以清空后重新配置。

## 6. 功能需求

### R1 骰型选择

- 页面必须提供 `d4、d6、d8、d10、d12、d20、d100` 七种骰型。
- 每种骰型同时显示外形或图形标识与文字名称，不能只依赖颜色区分。
- 点击骰型可将一颗对应逻辑骰子加入骰池。
- 骰池内每种骰型应能增加数量、减少数量或移除。
- 骰子数量不得出现负数；数量减到 `0` 时从骰池移除该项。
- 空骰池状态下“投掷”不可执行，并给出易懂提示。

### R2 多骰与混合骰池

- 同一骰型可一次投掷多颗，例如 `4d6`。
- 不同骰型可在同一次投掷中混合，例如 `1d20 + 2d8 + 1d4`。
- 投掷前必须展示规范化骰池表达式，并与实际进入投掷区域的逻辑骰子一致。
- 一次操作触发骰池内全部骰子共同投掷，不要求玩家逐颗点击。
- 投掷进行中不得重复触发另一轮投掷，避免结果和动画状态交叉。

### R3 真实骰子观感

- 每种普通骰型应使用与真实多面骰相符的几何外观，不能统一用六面骰或纯数字卡片代替。
- 点击“投掷”后，骰子应表现出抛出、旋转、下落、碰撞和逐渐停稳的连续过程。
- 多颗骰子一起投掷时，应在同一投掷区域内独立运动，并呈现骰子之间或骰子与边界之间的碰撞感。
- 骰子停稳后的朝上面或可读结果必须与结果区公布的点数一致。
- 结果只能在骰子停稳后正式公布；动画过程中不得提前泄露最终结果。
- 每次重新投掷都应产生新的运动过程，不能始终重复完全相同的动画轨迹。
- 动画不能影响随机结果的合法范围与均匀性。

### R4 随机结果

- 每颗逻辑骰子独立产生结果。
- 普通 `dN` 的结果必须为 `1—N` 的整数，范围上下界都包含在内。
- `d100` 的换算结果必须为 `1—100` 的整数。
- 任何骰型都不得产生 `0`、负数、小数或超过最大面的结果。
- 重新投掷沿用当前骰池配置，但必须重新生成全部骰子结果。

### R5 结果展示与总和

- 投掷完成后必须同时展示：
  - 本次骰池表达式；
  - 每颗逻辑骰子的骰型与独立结果；
  - 本次全部逻辑骰子的数值总和。
- 同类型多骰结果应清楚展开，例如 `3d6：[2, 5, 6]`，不能只显示总和 `13`。
- 混合骰池应按骰型分组或按实际骰子逐颗展示，且玩家能够判断每个结果属于哪种骰型。
- `d100` 结果应展示百分骰原始读数及换算值，例如 `00 + 0 = 100`、`40 + 7 = 47`。
- 总和应由本次独立结果实时派生，不作为另一份可单独修改的数据保存。
- 新一轮投掷完成后，结果区替换为新结果；本批不要求保存历史记录。

### R6 基础操作

- 提供明确的“投掷”主操作。
- 提供“再次投掷”操作，保留当前骰池并重新投掷。
- 提供“清空骰池”操作，清除当前选择与当前结果。
- 修改骰池后，旧结果必须明确失效或被清除，不能让旧总和看起来属于新骰池。

### R7 移动端与可访问性

- 以手机宽度为主要设计目标，骰型选择、数量调整和投掷按钮的主要触控目标至少为 `44px`。
- 骰子较多时，投掷区域与结果区域不能横向撑破页面。
- 动画结束后，文字结果必须独立可读，不能要求玩家仅凭 3D 骰子朝向判断点数。
- 所有操作按钮需具备可访问名称、键盘焦点状态和禁用状态。
- 对启用“减少动态效果”的用户，应提供缩短或简化动画的表现，但仍需正确生成并展示结果。
- 动画、颜色和光效不能成为传达骰型或最终结果的唯一方式。

### R8 异常与性能边界

- 骰池为空时不得开始投掷。
- 动画或视觉渲染发生异常时，页面仍应能够公布合法的文字结果与总和，不能丢失整次投掷。
- 快速连续点击“投掷”只能产生一轮有效结果。
- 页面离开或组件卸载时应停止本页动画与事件监听，避免在其他页面继续占用资源。
- 单次最多投掷 `20` 个物理骰体；普通骰占一个额度，`d100` 由两颗 d10 构成并占两个额度，达到上限时应提示原因。

### R9 动态物理骰盘

- 骰盘的物理面积必须根据本轮“物理骰体数量”动态计算；普通骰占一个物理骰体，`d100` 占两个物理骰体。
- `1—6` 个物理骰体沿用基础骰盘尺寸；超过 `6` 个后，骰盘长宽按以下比例同步扩大：

```text
骰盘线性缩放比例 = clamp(sqrt(物理骰体数量 / 6), 1, 1.85)
```

- 骰盘面积扩大时，地面、四周碰撞边界、骰子初始投放区域和摄像机可视范围必须使用同一份骰盘尺寸配置，不能只放大画面或只向外移动墙体。
- 骰子初始位置应随骰盘尺寸重新排布，在二维投放区域内保持合理间距；不得继续把 `20` 个骰子集中生成在只适合少量骰子的固定区域。
- 初始速度与旋转仍应保持每颗骰子独立，并避免所有骰子集中朝同一面墙运动。
- 骰盘扩大不得改变骰型尺寸、随机结果、结果总和或单次最多 `20` 个物理骰体的限制。
- 摄像机应在每次投掷开始时自动适配完整骰盘，保证默认视图能看到全部运动区域。
- 动态扩大用于降低高骰量下的碰撞密度与歪骰概率，但不替代原有物理失败降级；无法稳定落骰时仍必须提供文字结果。

### R10 手机端视图缩放与移动

- 视图缩放和移动只改变摄像机，不得改变物理世界尺寸、骰子位置、碰撞结果或最终点数。
- 投掷准备和动画播放期间使用自动全景视图，暂不响应手动缩放和移动，避免玩家把运动中的骰子移出视野。
- 骰子停稳并公布结果后启用视图操作：
  - 双指捏合用于放大或缩小；
  - 双指拖动用于平移视图，避免与页面单指上下滚动冲突；
  - 提供可见的“放大”“缩小”“复位视图”按钮，作为触控手势和键盘操作的等价入口。
- “复位视图”应恢复为能够完整显示当前骰盘的自动全景状态。
- 最小缩放级别不得小于完整骰盘全景；最大放大倍率为全景状态的 `3` 倍。
- 平移范围必须限制在骰盘边界附近，不能把视图永久移动到完全看不到骰子的空白区域。
- 修改骰池或开始新一轮投掷时，应自动复位视图，避免沿用上一轮局部放大状态。
- 手机端视图控制按钮的触控目标不得小于 `44px`，必须具有可访问名称、焦点状态和禁用状态。
- 桌面端应提供等价能力：滚轮或触控板缩放、拖动平移，以及相同的按钮控制；不得依赖悬停才能使用。

### R11 20 秒投掷超时降级

- 一次投掷的端到端等待上限固定为 `20` 秒，从玩家成功触发“投掷”或“再次投掷”的时刻开始计时。
- `20` 秒上限包含 Worker 初始化、物理轨迹预演、重试、主线程接收轨迹和动画播放的全部时间，而不是只限制其中某一个阶段。
- 公平随机结果必须在启动物理流程前生成并暂存；超时降级只能公布这一批既有结果，不得因超时再次随机。
- 若任一阶段在 `20` 秒内明确失败，应立即降级，不必等待计时结束。
- 到达 `20` 秒时仍未完成结果公布，系统必须：
  1. 停止本轮动画并取消或隔离仍在运行的物理请求；
  2. 清除本轮未完成的 3D 展示状态；
  3. 立即在结果区展示逐颗文字结果与总和；
  4. 显示非阻断提示：“本次投掷超过 20 秒，已直接展示公平文字结果。”；
  5. 解锁“再次投掷”和骰池操作。
- 超时后的迟到 Worker 响应或动画完成事件必须被忽略，不能覆盖已经展示的结果、重复公布结果或改变页面状态。
- 超时降级不计为随机失败；结果范围、`d100` 换算和总和规则必须与正常动画完成时完全一致。
- 开启系统“减少动态效果”时仍可直接展示停稳画面和结果，不应为了满足 `20` 秒计时而人为等待。

## 8. 非目标与后续需求

以下能力不包含在本次基础需求中，后续如需要应另行确认：

- 固定修正值和完整骰子表达式输入，例如 `1d20 + 5`、`2d6 - 1`。
- 优势、劣势、取高、取低、爆骰、重掷等高级规则。
- 投掷历史、收藏骰池、快捷预设与结果分享。
- 与角色卡属性、攻击、伤害或法术自动联动。
- 联机房间、多人同步掷骰和防作弊验证。
- 骰子皮肤、材质、颜色、背景场景与个性化特效。
- 骰娘人格、语音播报、台词或角色形象。
- 自定义任意面数骰子。

## 9. 已确认实现决策

1. 页面、底部导航与浏览器标题统一使用“赛博骰娘”，路由仍为 `/dice`。
2. 单次最多 `20` 个物理骰体，`d100` 占两个额度。
3. 首版不加入声音、震动、固定修正值、优势/劣势或投掷历史。
4. 使用可靠随机源预先生成公平结果，再通过 Three.js 与 cannon-es 播放真实碰撞轨迹；物理或 WebGL 不可用时降级为文字结果。
5. “赛博”只属于功能名称，视觉继续使用项目现有羊皮纸暖色、酒红与金色主题，不采用赛博朋克风格。
6. v1.1 按物理骰体数量动态扩大物理骰盘，并同步调整投放区域与摄像机，不通过缩小骰子规避碰撞。
7. 手机端采用双指缩放与双指平移，并提供按钮等价操作；投掷期间保持自动全景，结果公布后开放手动查看。
8. 单次投掷使用 `20` 秒端到端硬上限；超时直接公布投掷开始时已经生成的公平结果。

## 11. 验收标准

### 11.1 自动化验证

1. 七种骰型的结果范围测试全部通过。
2. 普通骰上下界均可作为合法结果：`d4` 为 `1—4`，依此类推。
3. `d100` 换算覆盖 `00 + 0 = 100`、`00 + 1 = 1`、`90 + 9 = 99`。
4. 同类型多骰和混合骰池的总和计算正确。
5. `d100` 只以换算后的逻辑结果计入一次总和。
6. 空骰池、数量边界和投掷中重复点击均受到正确限制。
7. 修改骰池后旧结果不会继续作为当前结果展示。
8. 动态骰盘缩放比例在 `1、6、7、12、20` 个物理骰体边界计算正确，并保持单调不减且不超过 `1.85`。
9. 不同骰量下的出生点都位于对应骰盘边界内，固定种子下不出现初始穿模或明显重叠。
10. 视图缩放和平移只改变摄像机状态，不改变物理轨迹、随机结果或总和。
11. 使用可控时钟验证 `19.999` 秒时不提前降级、`20` 秒时立即降级，且迟到 Worker 响应和动画完成事件不会覆盖结果。
12. 验证物理预演提前失败时立即降级，不等待 `20` 秒；超时降级复用原始预生成结果，不发生二次随机。
13. TypeScript 类型检查、相关测试和生产构建通过。

### 11.2 人工验证

1. 在 `375px` 与 `430px` 手机宽度完成骰型选择、数量调整、投掷、再次投掷和清空流程。
2. 分别验证 `1d20`、`3d6`、`1d20 + 2d6 + 1d4`、`1d100`。
3. 多颗骰子能同时滚动、碰撞并停稳，停稳画面与文字结果一致。
4. 玩家能看到每颗骰子的结果以及正确总和。

# 添加物品筛选与物品库补全需求

> 实施更新（2026-08-26）：字段迁移、共用弹窗筛选和 DMG 2014 的 247 条候选索引已完成；ERftLW 23 条与 EGtW 48 条扩展元数据已作为 `index-only` 首批导入。当前运行时为 677 条物品（普通 222、魔法 455）；历史 432/210/101 数量保留为立项基线。其余扩展来源逐书补全状态见《添加物品筛选与物品库补全-更新计划》。
>
> 补充修订（2026-08-26）：追加弹窗布局固定（R16）、按钮式筛选（R17—R18）与物品目录延迟加载及缓存（R19—R22）三组需求，并同步修订 R6.6、R7.4、实施批次、验收标准与依赖拓扑章节。本轮仅完成需求与加载链路核对，尚未修改代码；前端依赖拓扑已复核，无需更新。

## 1. 背景与目标

角色卡与跑团助手已经能够通过“添加物品”弹窗向角色草稿写入普通装备、魔法物品或自定义物品，但当前能力存在两个明确缺口：

1. 弹窗只有中文名称搜索、单选类别和单选来源，无法按稀有度、魔法物品类别、同调状态和多个来源组合筛选。
2. 运行时物品库虽有 432 条物品，但其中普通装备 222 条、魔法物品约 210 条；DMG 2014 仅登记 101 条，项目文档中的 DMG 2014 候选目录有 247 条，运行时覆盖明显不足且部分中文译名需要重新审校。

本需求的目标产物为：

- 将添加物品弹窗升级为适合移动端的多条件索引。
- 补充可表达稀有度、细分类别、同调条件和英文名的规则字段。
- 以 `5e-2014` 为唯一运行时规则集，分批补全官方物品元数据与原创中文摘要。
- 建立中文名、英文名、稳定 ID、来源和实现状态之间的可审计关系。
- 保持现有草稿中的 `itemId` 稳定，不因译名修正破坏存档。

## 2. 已确认范围

### 2.1 规则集

- 当前可编辑物品仅允许 `5e-2014`。
- 5e 不全书同时包含旧版 2014 与 2024 内容；截图中的筛选交互可以参考，但 `DMG24`、2024 重印条目和 2024 专属来源不得进入当前运行时仓库。
- 资料获取优先使用网站中的旧版《城主指南2014》与项目已经登记的 2014 官方扩展来源。
- 第三方、合作内容和无法确认规则版本的条目不进入本批候选池。

### 2.2 页面入口

本需求覆盖共用组件 `app/src/components/AddItemModal.vue`，其调用方包括：

- 角色卡物品页签。
- 跑团助手物品面板。

两个入口必须共用同一套搜索、筛选和物品数据，不允许出现两份行为不同的目录实现。

### 2.3 数据内容

- 普通装备继续保留现有护甲、盾牌、武器、工具和杂物分类。
- 魔法物品补充护甲、药水、戒指、权杖、卷轴、法杖、魔杖、武器、奇物九类索引。
- 商业资料仅保存必要元数据、稳定名称、来源索引与原创摘要，不复制规则书或网站的完整效果正文。
- 未完成机械字段核验的条目可以作为 `index-only` 候选供查看和加入物品栏，但不得参与自动派生。

### 3.2 当前筛选能力

`AddItemModal.vue` 当前支持：

- 中文 `name` 和 `id` 搜索。
- 全部、护甲、盾牌、武器、药水、魔法、工具、杂物单选分类。
- 全部来源或单个来源筛选。
- 根据角色启用来源排除不可用条目。

当前缺少：

- 英文名搜索。
- 稀有度筛选。
- 魔法物品九类细分。
- 同调“否/是/特殊”筛选与条件展示。
- 同一筛选组内的多选。
- 每组全选/取消全选。
- 筛选区显示/隐藏。
- 当前结果数量与清空筛选反馈。

#### 3.2.1 当前交互基线（2026-08-26 复核）

筛选能力上线后的弹窗交互基线：

- 弹窗复用 `UiScrollModal`：标题与底部数量/添加按钮已经固定，仅弹窗内容区滚动。
- 搜索框位于内容区顶部，与筛选面板、物品列表同属滚动区域；浏览长列表时搜索与筛选会滚出可视区域。
- 稀有度、类别、同调、来源四组条件以“显示筛选/隐藏筛选”单开关一次性铺开；每次打开弹窗重置为全选。
- 与 2026-08-26 补充计划的差异点：目标改为按钮展开式筛选，且搜索、筛选与底部固定，仅结果列表滚动（见 R16—R18）。

## 4. 筛选需求

### R1 搜索

1. 搜索必须实时匹配中文名、英文名和稳定 ID，忽略英文大小写与首尾空格。
2. 输入为空时不施加关键词条件。
3. 中文展示名修正后，稳定 ID 仍可命中旧草稿引用。
4. 没有匹配结果时显示中文空状态，并保留自定义物品入口。

### R2 稀有度筛选

魔法物品提供以下选项：

- 普通 `common`
- 非普通 `uncommon`
- 稀有 `rare`
- 极珍稀 `very-rare`
- 传说 `legendary`
- 神器 `artifact`
- 多种稀有度 `varies`

普通装备没有魔法稀有度。界面必须提供明确策略：默认全量浏览时普通装备正常显示；玩家主动限制魔法稀有度后，只筛选魔法物品，不把“普通装备”错误理解为 `common` 魔法物品。

### R3 类别筛选

魔法物品细分类别为：

- 护甲 `armor`
- 药水 `potion`
- 戒指 `ring`
- 权杖 `rod`
- 卷轴 `scroll`
- 法杖 `staff`
- 魔杖 `wand`
- 武器 `weapon`
- 奇物 `wondrous`

普通装备仍需保留盾牌、工具与杂物入口。魔法盾牌在魔法物品索引中归入“护甲”，在装备派生中仍保留盾牌机械字段。

### R4 同调筛选

同调状态不得继续只用布尔值表达，应区分：

- 否 `none`
- 是 `required`
- 特殊 `conditional`

特殊同调必须保存并展示 `attunementCondition`，例如“需要特定职业”“需要特定种族”或“需要施法能力”。条件文字只用于说明；自动校验只有在条件已经结构化且经过测试时才能启用。

### R5 来源筛选

1. 来源选项从 `rulesRepository.sources` 与角色 `enabledSourceIds` 动态生成，不在组件中硬编码书名。
2. Basic Rules 与 PHB 始终启用；其他来源只在角色启用后出现。
3. 同一物品存在多个合法重印来源时，只展示一个稳定条目；任一启用来源命中即可进入候选池。
4. 2024 来源不得出现在当前可编辑角色的筛选列表。

### R6 多条件组合语义

1. 同一筛选组内部采用“或”：选中“戒指”和“魔杖”时显示任一类别。
2. 不同筛选组之间采用“且”：必须同时满足关键词、类别、稀有度、同调和来源。
3. 每组提供“全选/取消全选”。
4. 初始状态等价于全部选中，不减少现有候选池。
5. 某组取消全部选项时结果为空，并显示“此筛选组未选择任何条件”，避免把空集合误解释为全部。
6. 筛选改为按钮展开式（见 R17）：搜索框下方固定显示“来源、同调、类别、稀有度”四个按钮，同一时间只展开一组条件；切换面板与折叠不清除已选条件。

### R7 移动端与无障碍

1. 筛选控件优先采用可换行的复选标签或复选框组，点击目标至少 44px。
2. 每组使用 `fieldset`/`legend` 或等价的可访问标签。
3. 选中状态不能只依赖颜色，必须同时有勾选、文本或图标反馈。
4. 弹窗采用固定头部（标题、搜索框、筛选按钮与展开面板）与固定底部（数量、添加按钮）、仅物品结果列表滚动的布局（见 R16）。

## 5. 数据模型需求

### R8 英文名与规则集

`EquipmentRule` 至少补充：

```ts
readonly englishName?: string
readonly ruleset: '5e-2014'
```

普通装备和既有魔法物品应分批补齐 `englishName`。搜索逻辑不得从中文展示名猜测英文身份。

### R9 魔法物品分类

保留现有 `category` 作为装备机械大类，新增独立字段表达目录分类，避免把戒指等伪装成新的武器或护甲机械类型：

```ts
readonly magicItemCategory?:
  | 'armor'
  | 'potion'
  | 'ring'
  | 'rod'
  | 'scroll'
  | 'staff'
  | 'wand'
  | 'weapon'
  | 'wondrous'
```

### R10 稀有度与多型号

1. 具体可加入物品栏的型号优先拆成独立条目，例如 `+1/+2/+3` 各自具有明确稀有度与稳定 ID。
2. 仅用于浏览的汇总条目可以使用 `varies`，但在加入物品栏前必须选择具体型号。
3. 不得把稀有度不同、机械加值不同的型号合并为一个含糊的可装备条目。

### R11 同调结构

建议字段：

```ts
readonly attunement?: 'none' | 'required' | 'conditional'
readonly attunementCondition?: string
```

兼容迁移规则：既有 `requiresAttunement: true` 映射为 `required`；缺省映射为 `none`。完成迁移前可以保留旧字段作为只读兼容层，但不得长期维护两个相互独立的事实源。

### R12 内容状态

每个补充条目应明确状态：

- `index-only`：中英文名、分类、稀有度、同调与来源已核验；可浏览，必要时可加入物品栏，但不参与机械派生。
- `selectable`：用于选择、保存与导出的必要字段完整；复杂效果由桌面裁定。
- `implemented`：结构化机械字段已接入派生并有测试。
- `dm-only`：神器、诅咒或明确需要 DM 许可的内容；仍可浏览，但应有提示。

## 6. 物品补全与翻译工作流

### R13 身份与去重

1. 英文原名和规则版本用于确认物品身份。
2. 稳定 ID 不使用中文名，不因译名调整而改变。
3. 重印条目只保留一个实体，通过多个 `sourceIds` 记录合法来源。
4. 同名但规则版本不同的 2014/2024 条目必须隔离。
5. 汇总型号拆分时建立旧 ID 到新具体型号的兼容策略，禁止静默改变旧草稿含义。

### R14 中文译名审校

译名优先级：

1. 已确认的 2014 官方简体中文术语。
2. 5e 不全书旧版 2014 译名与社区通行译名交叉核验。
3. 无统一译名时记录候选、依据与最终取舍。

自动比对只用于产生审校候选，不能自动认定网站译名一定正确。译名变更只修改展示字段并同步前置清单，不修改稳定 ID。

### R15 原创摘要与版权边界

1. 网站和商业规则书用于核验名称、分类、稀有度、同调、来源与机械事实。
2. `description` 使用项目原创短摘要，不复制完整段落。
3. 无法可靠核验的效果不得猜测；条目降级为 `index-only` 并明确来源入口。

## 7. 弹窗布局与筛选交互补充

本组需求由 2026-08-26 补充计划引入，针对“添加物品”弹窗的滚动布局与筛选交互。核心目标：浏览长列表时搜索与筛选控件始终可见；四组条件改为按钮展开式，不再一次性铺开。

### R16 弹窗布局固定

1. 弹窗标题固定不动。
2. 搜索框固定不动。
3. 筛选按钮行与展开的条件面板固定不动。
4. 底部数量与添加按钮固定不动。
5. 只有物品结果列表区域滚动。

### R17 按钮式筛选

1. 搜索框下方按固定顺序显示四个按钮：`来源` → `同调` → `类别` → `稀有度`。
2. 点击某个按钮，在其下方展开该组条件；同一时间只展开一个条件面板。
3. 再次点击当前展开的按钮可收起面板。
4. 切换面板不清除已经选择的条件。
5. 每组支持“全选/取消全选”与确认。
6. 按钮应能显示该组是否已限制，或显示已选数量。
7. 所有筛选仍保持“组内或、组间且”语义（R6.1—R6.5 不变）。
8. 来源选项仍受角色 `enabledSourceIds` 限制，选项生成逻辑复用现有实现。

### R18 筛选状态生命周期

1. 每次重新打开弹窗，四组条件恢复默认全选。
2. 弹窗打开期间，切换面板、搜索、滚动列表与“显示更多”均不清除任何一组的已选条件。

## 8. 物品目录延迟加载与缓存补充

本组需求针对物品 Markdown 目录的加载链路。现状核实：`magic-items-dmg-catalog-2014.ts` 以 `?raw` 静态导入 15 份 DMG A–Z/神器目录，`magic-items-expansions-2014.ts` 以 `?raw` 静态导入 ERftLW、EGtW 2 份扩展目录，二者经 `rules/repository.ts` 装配，进入默认车卡主界面即参与加载。开发环境表现为多个 `.md?raw` 请求；生产构建虽将内容打入 JS 分块、不再逐个请求 Markdown，但仍增加主界面分块体积与初始化解析时间。

### R19 构建期目录生成

1. Markdown 只作为开发维护、核对与审计文档，不再作为浏览器运行时数据源。
2. 构建前由脚本读取 `docs/equipment/5e-2014/` 下 17 份目录 Markdown，生成经过类型校验的 TypeScript（或 JSON）物品目录分块。
3. 生成产物纳入类型检查与数据完整性测试；生成脚本沿用 `sync-dmg-catalog-status.mjs`、`sync-expansion-item-indexes.mjs` 的维护方式。

### R20 延迟加载与缓存

1. 主界面首次进入不加载完整物品浏览目录。
2. 用户第一次点击“添加物品”时，才动态加载目录分块。
3. 同一次页面会话使用内存 Promise 缓存，不重复加载或解析。
4. 刷新或再次访问时使用浏览器 HTTP 缓存；当前 Nginx 已对带哈希的 `/assets/` 配置一年 `immutable` 缓存，适合这种动态分块。
5. 新版本文件名变化时自动获取新目录，不会误用旧数据（由构建产物内容哈希天然保证）。
6. 不把完整物品库存入 `localStorage`：体积限制、序列化成本与版本失效管理均不合适。

### R21 加载状态与失败重试

1. 弹窗内显示明确的加载状态（加载中占位）。
2. 加载失败时显示失败原因与“重试”入口，重试复用同一加载器。
3. 加载失败不得阻塞搜索框、筛选按钮与自定义物品入口。

### R22 最小运行时索引保留

1. 保留现有角色物品显示、校验和属性派生所需的最小运行时索引（`equipment-2014`、`magic-items-2014`、`magic-items-xgte-tcoe-2014` 静态装配不变）。
2. 完整候选目录与详情才延迟到“添加物品”时加载，避免为了优化弹窗破坏现有角色卡。
3. 现有草稿 `itemId`、装备派生、来源限制与自定义物品行为不得回归。

- 四按钮展开式筛选改造：复用现有筛选纯函数与多选状态，仅改交互层，不改变筛选语义。
- 补充组件测试：按钮展开/收起、同屏只展开一组、切换面板保留选择、重新打开弹窗重置全选。

### 批次 6：物品目录延迟加载与缓存

- 新增构建期目录生成脚本，产出经过类型校验的分块并纳入测试。
- 抽离目录加载服务（内存 Promise 缓存 + 动态 import）。
- `AddItemModal` 接入加载状态与失败重试。
- 验收：主界面无目录请求、弹窗首次打开才加载、重复开关无重复请求、构建与全量测试通过。

## 10. 非目标

- 不导入 DMG 2024 或其他 2024 内容。
- 不导入第三方和合作内容。
- 不实现完整魔法物品价格、交易、负重或充能追踪。
- 不复制 5e 不全书或商业规则书正文。
- 不在本需求阶段修改角色现有物品持久化结构或删除自定义物品入口。
- 不将完整物品库存入 `localStorage`。

## 11. 验收标准

1. 搜索支持中文名、英文名与稳定 ID。
2. 稀有度、类别、同调和来源均支持多选、全选与组合筛选。
3. 组内“或”、组间“且”、空组结果为空的行为均有纯函数测试。
4. 普通装备与 `common` 魔法物品不会混淆。
5. 魔法物品九类均至少有一条测试数据可命中。
6. 特殊同调条件可展示，不会被错误当作普通“需要同调”。
7. 关闭来源后条目从候选池移除但已有草稿引用不被删除。
8. 所有运行时条目显式属于 `5e-2014`；2024 条目不进入仓库。
9. 中文名、英文名、稳定 ID和来源可以通过清单追溯。
10. 类型检查、相关自动化测试、全量测试和生产构建通过。
11. 主界面首次进入不再请求或解析物品 Markdown 目录：开发环境不再出现 `docs/equipment/**` 的 `.md?raw` 请求，生产构建主界面分块不包含目录解析逻辑。
12. 第一次点击“添加物品”后才加载完整目录；加载中显示明确状态，失败时可重试。
13. 关闭并再次打开弹窗不产生重复目录请求（同一次页面会话命中内存 Promise 缓存）。
14. 刷新或再次访问时浏览器可命中带内容哈希 `assets` 路径的 `immutable` 静态缓存；新版本发布后自动获取新目录分块，不使用旧数据。
15. 搜索框、四个筛选按钮与展开的条件面板始终可见，只有物品结果列表区域滚动。
16. 四组按钮式筛选满足：同屏只展开一组、再次点击收起、切换面板保留已选条件、重新打开弹窗恢复默认全选、按钮可反映组内限制状态。
17. 现有物品添加、装备、自定义物品与来源限制行为不回归。

## 12. 涉及模块与依赖拓扑

```text
components/AddItemModal.vue
  -> rules/item-catalog-loader（内存 Promise 缓存 + 动态 import 分块）
  -> rules/物品筛选纯函数
  -> rules/repository（最小运行时索引，静态装配不变）
  -> types/rules

rules/repository
  -> rules/data/equipment-2014
  -> rules/data/magic-items-2014
  -> rules/data/magic-items-xgte-tcoe-2014
  -> rules/data/generated/magic-items-catalog-index-2014（目录轻量索引）

构建期生成（不进入浏览器运行时依赖图）：
scripts/build-item-catalog.mjs（批次 6 新增）
  -> docs/equipment/5e-2014/magic-items/*.md（15 份）
  -> docs/equipment/5e-2014/expansions/*.md（2 份）
  -> src/rules/data/dmg-attunement-table.json（同调审计表，与运行时共享）
  -> 输出类型校验的目录分块（rules/data/generated/：完整目录 + 轻量索引）

完整目录分块（动态加载）
  -> rules/data/generated/magic-items-catalog-2014
```

运行时依赖方向仍为组件读取规则仓库、纯规则函数与目录加载器；`src/rules` 不依赖 Vue、Pinia、DOM 或存储，延迟加载仅使用语言级动态 `import()`，不改变目录权限矩阵，也不新增运行时目录层级。加载器落在 `src/rules` 而非 `services`：services 静态依赖 rules 属于既有越权点（见 frontend-architecture.md §8.9），按需获取本地规则分块是规则数据层的自然职责。当前需求为计划与需求补充，已复核前端依赖拓扑，无需更新。

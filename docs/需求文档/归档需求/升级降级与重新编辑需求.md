# 升级降级与重新编辑需求

## 1. 背景与目标

当前车卡流程中，目标等级只在 `setup` 步骤（第 1 步"先确定冒险规模"）设置，创建过程中可以通过 `updateSetup` 修改；但**角色创建完成后（`sheet` 角色卡页）没有升级/降级入口**，也无法直接重新编辑角色——玩家只能返回草稿首页再重新打开草稿，且打开后停在上次离开的步骤，没有针对"等级变化后待办事项"的引导。

用户需求：创建完一个人物角色后，可以：

1. **升级**：提高角色等级，派生数值（最终属性、熟练加值、HP、AC、攻击、法术位等）随之重算，等级新增的检查点（属性提升/专长、子职特性、法术选择等）需要玩家补全。
2. **降级**：降低角色等级，超出新等级范围的检查点选择按现有"保留并标记失效"机制作废，减少的资源（专长、法术、特性数量等）需要玩家复查。
3. **重新编辑**：把已完成角色一步拉回车卡编辑流程，可以修改属性数值等任意原始选择（即"重新编辑一遍"），修改后派生值立即重算。

目标产物：

- 角色卡页与草稿首页提供"升级/降级"与"重新编辑"入口。
- 升级/降级复用现有依赖影响确认机制（`pendingChange`），报告受影响、需复查、保留的选择。
- 升级后引导玩家补全新检查点；降级后给出针对性复查清单。
- 不新增 `CharacterDraft` 字段、不做存储迁移，schema v3 与 JSON 导入导出保持兼容。

### 已确认结论（2026-08-06）

以下三项方案已与用户确认，作为实现基线，不再作为待确认项：

1. **升级/降级支持任意跳级**：直接设置目标等级 1—20 一次到位，不做逐级确认或每级结算动画。
2. **"重新编辑"智能定位步骤**：存在失效选择或未完成检查点时进入 `timeline`（或对应需处理步骤），否则进入 `abilities`（属性步骤，满足"修改属性数值"的核心诉求）。
3. **入口收束到角色卡页（2026-08-06 修订）**：升级/降级与重新编辑入口统一放在角色卡页（`CharacterSheetStep`）；草稿首页角色条仅保留打开与删除操作，避免条目拥挤。

## 2. 现状调查（已核验）

### 2.1 规则层（已就绪）

| 模块 | 现状 |
|---|---|
| `app/src/rules/dependency.ts` | 已支持 `DraftChange.kind === 'target-level'`：按新等级重建时间线（`buildTimeline`），把新时间线中不存在的检查点选择列入 `invalidated`；`review` 返回通用文案（生命值、熟练加值、等级相关资源）；`preserved` 为职业、起源、基础属性 |
| `app/src/rules/derive.ts` | HP、熟练加值、AC、先攻、攻击、技能、豁免、法术攻击/DC 全部由草稿原始选择纯函数重算，并返回来源链——等级变化后数值自动正确，无需持久化派生值 |
| `app/src/rules/timeline.ts` | `buildTimeline(classId, targetLevel, { subraceId, subclassId })` 按目标等级生成检查点，等级相关检查点 id 含等级信息，可区分升降级 |
| `app/src/rules/validate.ts` | 检查点未完成报 `error`；`completion` 会因未完成检查点下降 |
| `CharacterDraft` | `targetLevel: number` 为可变字段（schema v3），无需迁移 |

### 2.2 界面层（缺口）

| 界面 | 现状 | 缺口 |
|---|---|---|
| `views/character-builder/components/CharacterSheetStep.vue` | 角色卡顶部可"返回草稿首页"（`returnToStart`）；等级仅展示，无调整入口 | **无升级/降级入口**；无"重新编辑"一步直达入口 |
| `features/quick-build/components/StartPanel.vue` | 角色条目支持打开、删除、导出、导入 | 条目无"等级调整"操作 |
| `useCharacterBuilderPage.updateSetup` | 已支持修改 `targetLevel` + `abilityMethod`，带 `pendingChange` 受影响确认弹窗 | 该能力只挂在 `setup` 步骤，完成角色后无暴露入口；确认后不引导跳转待办步骤 |
| `pendingChange` 确认弹窗 | `getDependencyImpact` 返回 invalidated/review/preserved，弹窗只展示"受影响选择"清单 | 不区分"升级新增待补检查点"与"降级失效选择"；review 为通用文案，无针对减少的专长/法术/特性的复查引导 |

### 2.3 结论

- **规则与存储已支持等级调整**：`dependency`、`derive`、`timeline`、`validate`、`updateSetup` 五处机制齐备，且符合 `docs/rules.md`"修改等级时先报告受影响选择，旧选择保留并标记失效，不静默删除"的约定。
- **缺的是入口与引导**：完成态角色没有升级/降级/重编入口；升级后新增检查点无显式跳转引导（玩家只能靠校验错误自己找）；降级后复查清单不具体。
- **无需数据结构改动**：`targetLevel` 已可变，选择失效机制已存在，schema 兼容。

## 3. 需求项

### R1 升级（提高等级）

1. **入口**：角色卡页"调整等级"按钮触发，选择新目标等级（1—20，任意跳级，不做逐级确认）（已确认）。
2. **受影响确认**：复用 `pendingChange` 弹窗，标题如"升级至 X 级"；清单分三类展示：
   - **待补全（新增检查点）**：新等级时间线中出现、当前未完成的检查点（属性提升/专长、子职特性、战技、法术位等），按等级列出；
   - **需复查**：`review` 项（生命值、熟练加值、等级相关资源、法术位）；
   - **保留**：职业、起源、基础属性。
3. **确认后**：`targetLevel` 更新 → 派生重算 → 若存在待补全检查点，自动跳转 `timeline` 步骤并展示引导条（如"等级提升至 X 级，请完成新增检查点：6 级属性提升或专长、11 级子职特性…"）；检查点未完成时校验报 `error`、完成度下降（现有机制，无需新增校验）。
4. **数值来源**：HP、熟练加值、攻击、法术位等按新等级展示来源链（`DerivedValue.sources`），玩家可核对变化原因。

### R2 降级（降低等级）

1. **入口**：同 R1，选择新目标等级（1—20）。
2. **受影响确认**：复用 `pendingChange`，清单分三类：
   - **将失效**：超出新等级范围的检查点选择（`dependency.ts` 已计算），明确列出将被标记失效的具体选择（如"8 级属性提升 +2 力量"）；
   - **需复查（针对性）**：除通用项外，按新等级列出**数量减少的资源**（专长/属性提升次数、已知法术上限、子职特性、战技数量、HP/熟练变化），提示玩家核对是否符合新等级；
   - **保留**：职业、起源、基础属性。
3. **确认后**：`invalidateSelections` 标记失效（保留原记录并写入 `invalidatedReason`，如"目标等级调整为 X 级"），不静默删除；跳转相关步骤供复查（失效检查点需重新选择或确认放弃）。
4. **完成状态**：存在未处理失效选择时，角色卡显示"待补全/资料不完整"状态，校验报 `error` 或 `warning`（沿用 `validate` 语义）。

### R3 重新编辑

1. **入口**：角色卡页"重新编辑"按钮；草稿首页角色条目"编辑"操作。
2. **交互**：一步激活该草稿并进入车卡流程（无需先返回首页再打开），保留全部原始选择；**智能定位步骤（已确认）**：
   - 存在失效选择或未完成检查点 → 进入 `timeline`（或对应需处理步骤）；
   - 否则进入 `abilities`（属性步骤）——满足"修改属性数值"的核心诉求；
   - 玩家可在任意步骤修改（等级、职业、种族、背景、属性数值、时间线、装备、法术、身份），修改均走现有 `requestChange` 依赖确认。
3. **保存与返回**：沿用现有流程——修改即时写入草稿，返回角色卡即生效；无额外"完成"确认。

### R4 通用约束

- 升级/降级/重编全部复用 `pendingChange` 依赖确认弹窗；旧选择保留并标记失效，不静默删除（遵守 `docs/rules.md`"修改职业、等级、种族、子种族或背景时…"约定）。
- 属性数值修改继续受规则约束：最终值不超过 20；按 `abilityMethod` 校验（标准数组/27 点购点/自定义 3—20 且提示 DM 确认）。
- 不新增 `CharacterDraft` 字段、不改变 schema、不迁移存储；JSON 导入导出兼容。
- 等级调整仅限 `5e-2014` 单职业 1—20 级，不触碰 2024 草稿隔离与多职业边界。

## 4. 非目标与边界

- 不做"逐级升级引导"（1 级 1 级确认、每级结算动画等），直接设置目标等级一次到位。
- 不实现多职业、2024 规则、DM 房规编辑器。
- 不改变现有车卡步骤结构、`validate` 规则与 `derive` 计算。
- 不登记职业基础特性（与 `子职特性展示与升级需求.md` 的 R4 相同，属后续批次）。
- 商业资料 `index-only` 内容在等级调整中不参与自动计算（沿用现有完整性警告）。

## 5. 页面设计

### 5.1 角色卡页（`CharacterSheetStep`）

- **等级调整控件**：角色摘要区（职业/等级处）新增"调整等级"入口（`UiButton` 次级样式）。
  - 点击弹出 `UiModal`：1—20 级选择（当前等级高亮，步进器或数字网格），下方实时预览影响摘要："将新增 X 项检查点待补全 / Y 项选择将失效 / Z 项需复查"。
  - 确认后进入 `pendingChange` 确认弹窗（清单见 R1/R2），确认应用。
- **升级引导条**：应用后角色卡顶部（或跳转 `timeline` 后）展示 `UiNotice` 引导条："等级提升至 X 级，请完成新增检查点：…"，点击直达对应步骤。
- **降级引导条**：展示失效清单摘要："等级降至 X 级，以下选择已失效，请复查：8 级属性提升、11 级子职特性…"。
- **"重新编辑"按钮**：操作区新增，点击一步进入编辑流程（智能定位步骤，见 R3）；与现有"返回草稿首页"并列，语义区分：返回首页 = 回到草稿列表；重新编辑 = 直接改当前角色。
- **完整性状态**：存在未完成检查点或未处理失效选择时，角色卡标题区显示"待补全"徽标（`UiBadge` warning 风格）。

### 5.2 草稿首页（`StartPanel`）

- 角色条目仅保留打开与删除操作，**不再提供编辑/等级调整/导出入口**（2026-08-06 修订：避免角色条拥挤，相关功能统一由角色卡页提供）。
- 条目副信息展示"当前 X 级"；存在失效/未完成时带警告徽标。

### 5.3 交互流程示例

```text
角色卡（5 级战士）
  → 点击"调整等级" → 选 6 级 → 摘要：新增 1 项待补全（6 级属性提升或专长）
  → 确认 → 跳转时间线 → 完成属性提升选择 → 返回角色卡（6 级，数值更新）

角色卡（10 级圣武士）
  → 点击"调整等级" → 选 7 级 → 摘要：2 项选择将失效、法术位需复查
  → 确认 → 失效选择标记并保留记录 → 复查法术配置 → 角色卡显示"待补全"直至处理完成

角色卡（任意）→ 点击"重新编辑" → 直达属性步骤 → 修改力量数值 → 派生立即重算 → 返回角色卡生效
```

## 6. 涉及模块与依赖方向

```text

views/character-builder/components/StartPanel.vue           —— 仅打开/删除（编辑、等级调整与导出均收束到角色卡）

rules/dependency.ts        —— target-level 分支增强：升级时返回"新增待补检查点"清单；降级时给出针对性复查项
rules/derive.ts / timeline.ts / validate.ts —— 无需改动（已支持）
stores/character-drafts.ts —— 无需新增动作（updateDraft / invalidateSelections 已够用）
```

## 3. 设计

### 3.1 数据模型与 ID

- 新文件 `app/src/rules/data/artificer-2024.ts`，导出：
  - `artificerFeatures2024: readonly ClassFeature[]`；
  - `artificerRule2024: ClassRule`；
  - `artificerSubclassFeatures2024: readonly SubclassFeature[]`；
  - `artificerSubclasses2024: readonly SubclassRule[]`；
  - `artificerOptions2024: readonly RuleOption[]`（仿制方案与子职选项）。
- ID：职业 `class-2024-ua-artificer`；子职 `subclass-2024-ua-artificer-<slug>`；特性 `artificer-2024-<slug>`；方案 `artificer-2024-plan-<slug>`（沿用 `infusion` 检查点语义）。
- 来源：所有条目 `sourceIds: ['source-2024-ua-eberron']`，`status: 'selectable'`。
- 复用与隔离：**不复用** `artificer-2014.ts` 的任何数据；仿制方案是独立数据表。绑定关系复用 `CharacterDraft.infusionAssignments`（结构中立：`{ infusionId, inventoryEntryId }`），通过职业 ID 分支校验与派生，避免 schema v9 迁移；实施时在字段注释与文档中标注「2014 灌注／2024 仿制绑定」。

### 3.3 施法与资源

- `SpellcastingConfig`：`mode: 'prepared'`、`ability: 'int'`、`startsAtLevel: 1`、`preparedCountByLevel` 与 `cantripsKnownByLevel` 按 §2 表；施法位按半施法者向上取整（`slotsByClassLevel` 取 1—20 全表）；`maxSpellLevelByClassLevel`：1—4 级 1 环、5—8 级 2 环、9—12 级 3 环、13—16 级 4 环、17—20 级 5 环。
- 资源：
  - 仿制方案已知数（4／5／6／7／8，等级表）→ 检查点规格，不重复登记为资源；
  - 同时存在的仿制物品数（2／3／4／5／6）→ `ClassFeature.resource`，`recovery: 'long-rest'`（按 CHM 复核充能／转变时机）；
  - `魔法物品工艺师`（6 级）的充能／汲取／转变使用次数 → 资源或 `note`（按 CHM 文本确定上限与恢复）；
  - `储法物品`（11 级）登记为资源（上限、恢复）或提示级，按 CHM 文本确定；
  - `奇械之魂`（20 级）登记为 `note`＋资源恢复说明，结算归 B10 模型。

### 3.5 仿制魔法物品

- 方案选项：`RuleOption`＋`replicateItemId`（沿用 `ArtificerInfusionRule` 的字段设计，但在 2024 文件中独立定义）；四档用 `minimumLevel: 2／6／10／14` 与检查点候选池筛选。
- 物品解析：`replicateItemId` 必须命中当前 2024 仓库的 `EquipmentRule.id`；`+1 武器／护甲／盾牌` 等聚合条目需要子选择（基底与加值），实施时给出选项或明确提示；UA 新增 9 件物品由 E07-04 提供数据。
- 绑定与校验：玩家选择方案后，把「创造的物品」加入物品栏并写入 `infusionAssignments`；校验同时存在的绑定数 ≤ 等级表上限、方案必须已知、物品必须存在且来源启用；关闭来源保留绑定但停止生效（沿用现有非破坏语义）。
- 派生：物品本身提供魔法加值（E07-04 数据），不再叠加额外灌注加值；`魔法物品工艺师` 的汲取／转变在 UI 中只做绑定变更，不自动改金币。

### 3.6 UI 与导出

- 职业页、成长速览、时间线、装备步骤、法术步骤、角色卡能力页签均按现有 2024 职业链路接入；职业详情显示来源与游玩测试标记。
- 跑团助手：仿制绑定、资源上限与恢复进入现有资源结算模型（B10）。
- 导出：`buildCharacterExportModel` 输出职业特性、子职、仿制绑定物品、法术与资源，不新增导出格式。

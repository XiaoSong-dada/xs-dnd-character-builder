# 子职业覆盖需求文档

## 1. 背景与目标

本需求基于对现有资料与代码的核对，明确"docs 已准备的职业/子职资料"与"`app/src/rules` 实际实现覆盖"之间的差距，并列出需要补充覆盖的子职业。

- 规则集基线：`5e-2014`，1—20 级单职业。
- 资料基线：`docs/dnd-classes.md` 索引 + `docs/classes/subclasses/<职业ID>/` 目录。
- 代码基线：`app/src/rules/data/subclasses-2014.ts`（统一子职索引，共 114 项）及 `martials-2014.ts`、`half-casters-2014.ts`、`arcane-casters-2014.ts`、`fighter.ts`、`classes-2014.ts`。
- 子职状态定义：`implemented`（可参与车卡选择与派生计算）、`index-only`（仅登记名称/来源/原创摘要，具体效果不参与自动计算）、`dm-only`（仅 DM 批准可用，不进普通车卡）。

## 4. 需求项二：实现 110 个 index-only 子职（代码）

### 4.1 总体要求

每个子职从 `index-only` 提升为 `implemented` 时，至少满足：

1. 子职特性按等级结构化登记（参照 `docs/dnd-classes.md` 3.3 与第 6 节单项特性模板），明确：获得等级、玩家选择（无/单选/多选/数值分配）、资源与恢复、前置/互斥、派生值影响、动作类型。
2. 涉及派生数值（AC、HP、攻击、法术 DC、熟练、伤害等）的影响通过 `app/src/rules/derive.ts` 纯函数表达，不允许在组件或 store 中硬编码。
3. 未获准的商业规则效果保持 `index-only` 或标注"待核验"，不得虚构数值参与自动计算；符合 `AGENTS.md` 内容与版权约定。
4. 每项实现配套单元测试（选择校验、边界值、互斥选择、派生值来源）与回归测试。
5. 更新对应 `docs/classes/subclasses/<职业ID>/` 资料文件的核验状态，并同步 `docs/dnd-classes.md` 与 `docs/quick-build-implementation.md` 的实施状态。

## 5. 建议实施批次

批次顺序建议与现有纵向切片节奏一致，每批完成后均可独立验收；涉及 bard/cleric/druid/sorcerer 的子职须先完成其职业基础时间线（当前 `checkpoints` 为空）。

1. **批次 0（资料补齐，纯文档）**：`barbarian-totem-warrior` 资料文件 + `dnd-classes.md` 索引登记。完成后 114 项子职资料全覆盖。
2. **批次 1（PHB 2014 核心子职，优先无施法子职）**：战士 eldritch-knight、野蛮人 berserker/totem-warrior、武僧 open-hand/shadow、游荡者 thief/assassin/arcane-trickster、游侠 hunter/beast-master、圣武士 devotion/ancients/vengeance、邪术师 archfey/fiend/great-old-one、法师 8 个核心学派。此类职业已有完整时间线，可直接接入子职检查点。
3. **批次 2（bard/cleric/druid/sorcerer 职业基础 + 其 PHB 2014 核心子职）**：先补职业 1—20 级 checkpoints 与施法配置，再实现 lore/valor、life/war/light、land/moon、draconic-bloodline/wild-magic。
4. **批次 3（扩展书子职）**：XGtE、TCoE、SCAG、EGtW、VRGtR、FTD、DSotDQ、Bigby 来源子职，按来源分批。
5. **批次 4（收口）**：复查 `index-only` 清零（DM 专用除外）、更新 `docs/quick-build-implementation.md` 与 `docs/dnd-classes.md` 状态矩阵。

## 6. 验收标准

每批次完成时同时满足：

1. `pnpm typecheck` 类型检查通过（`vue-tsc -b`）。
2. `pnpm test:run` 全部测试通过，含新增子职校验/派生回归测试。
3. `pnpm build` 生产构建通过。
4. 375/390/430 px 手机宽度浏览器验收：子职可正常选择、无资料完整性警告（对应已实现子职）、派生值来源可解释。
5. 新增/变更模块同步更新 `docs/frontend-architecture.md` 当前拓扑（如涉及）与 `docs/dnd-classes.md` 核验状态。
6. 交付说明写明"已复核前端依赖拓扑，已更新/无需更新"。

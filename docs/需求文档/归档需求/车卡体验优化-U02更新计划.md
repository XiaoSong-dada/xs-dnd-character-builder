## 3. 设计

### 3.1 数据字段（U02-01）

```ts
export interface ClassRule {
  // ...
  /** 职业介绍（原创中文转述，1—3 句：定位、常见玩法与核心机制）；两版文本独立。 */
  readonly introduction?: string
}
```

**字段可选的取舍（对计划的细化说明）**：计划原文写「字段设为必填」，实施时改为可选，理由如下：

- 2014 的职业介绍统一放在 `classPreviews2014`（Q-4a），而 2014 的完整职业规则分散在 `martials-2014.ts`、`fighter.ts`、`half-casters-2014.ts`、`arcane-casters-2014.ts`、`full-casters-2014.ts`、`artificer-2014.ts` 且均以 `ClassRule` 字面量声明；字段若必填，同一段文案必须在预览与完整规则两处各写一遍，产生漂移风险。
- 通过「预览投影 + 完整规则覆盖」的合并方式（§3.2）可以获得单一数据源；类型层强制改由数据测试承担：新增 `test/rules/class-introductions.test.ts` 断言 25 个职业（2014 13 + 2024 12）的 `introduction` 非空、非占位、两版文本不重复。
- 未引入新的类型别名（如 `ClassRuleSeed`），避免为单次需求增加难以理解的类型概念。

### 3.2 合并顺序（U02-02）

`rules/repository.ts` 的 2014 装配由 `{ ...classRule, features }` 改为 `{ ...item, ...classRule, features }`：预览提供 `introduction`，完整规则提供检查点等其余字段；无完整规则的职业仍走 `?? { ...item, checkpoints: [] }` 分支。2024 侧 `classes-2024.ts` 直接装配各职业规则，无需改动。

### 3.3 派生（U02-04 前置）

在既有 `rules/recommend.ts` 新增（不新增模块）：

```ts
export interface ClassDetailSummary {
  readonly abilities: readonly string[]     // 主要属性中文标签
  readonly savingThrows: readonly string[]  // 豁免熟练中文标签
  readonly hitDie: string                   // 如 "d10"
}
export function getClassDetailSummary(classRule: ClassRule): ClassDetailSummary
```

`primaryAbilities` 与 `savingThrowAbilities` 都是 `string[]`／`AbilityKey[]`，标签统一取自叶子模块 `rules/data/ability-labels`（顺带把 `recommend.ts` 从 `data/feats-2014` 的再导出改为直接引用叶子模块）。

# PDF 模板替换为国内 5E 术语版角色卡需求

> 状态：实施中（PDF v5 AcroForm 适配已落地；自动化与构建待执行，视觉验收由用户完成；发布前仍须确认模板分发授权）  
> 目标模板：`docs/export-templates/DND_5E_2014_国内5E术语版角色卡_最终版.pdf`  
> 适用规则集：D&D 5e 2014  
> 本文只定义 PDF 模板替换，不改 XLSX、JSON 导出。

## 1. 背景与目标

当前 PDF 导出使用 `app/public/templates/character-sheet-zh.pdf`，由 `src/services/export-pdf.ts` 通过三页坐标映射绘制中文内容。现需评估并规划将模板替换为国内 5E 常用术语版角色卡。

目标：

1. PDF 卡面替换为目标模板的中文术语和版式；
2. 继续复用 `buildCharacterExportModel(draft, derived)` 作为唯一导出数据源；
3. 导出数值与角色卡页面、XLSX 导出保持一致；
4. 保持浏览器端本地生成，不引入后端；
5. 中文在常见 PDF 阅读器和打印场景中稳定显示。

## 2. 已核验现状

### 2.1 当前实现

- 当前运行时模板为 3 页 A4 PDF（约 `595.28 × 841.89 pt`）。
- 当前实现使用 `pdf-lib + @pdf-lib/fontkit`，嵌入 Noto Sans SC 字体，并按 `PDF_REGION_MAP_V4` 坐标绘制。
- 当前导出模型已覆盖身份、六项属性、豁免、技能、战斗数据、攻击、物品、钱币、特性、人物备注、法术位和法术列表。
- 当前测试已覆盖三页输出、区域边界和长文本截断诊断。

### 2.2 目标模板

- 目标模板为 PDF 1.7、3 页 Letter 尺寸（`612 × 792 pt`），不能复用当前 A4 坐标。
- 模板包含 AcroForm 表单字段，不需要重新用坐标定位全部文本框。
- 已确认第一页存在稳定字段名，例如：
  - 身份：`CharacterName`、`ClassLevel`、`Background`、`PlayerName`、`Race `、`Alignment`、`XP`；
  - 核心数据：`STR`～`CHA`、`STRmod`～`CHamod`、`ProfBonus`、`AC`、`Initiative`、`Speed`；
  - 豁免与技能：`ST Strength` 等六项豁免、18 项技能字段及对应复选框；
  - 战斗：`HPMax`、`HPCurrent`、`HPTemp`、`HDTotal`、`HD`、三组武器字段、`AttacksSpellcasting`；
  - 其他：`Passive`、`CP`～`PP`、`ProficienciesLang`、`Equipment`、`Features and Traits`。
- 模板内含大量文本框和复选框，第二、三页仍需在实施前生成完整字段清单并建立语义映射。
- 模板已包含中文字体资源，但不能假设其字体子集覆盖项目导出的全部中文字符；实现仍应使用项目现有 Noto Sans SC 字体更新字段外观。

## 3. 成本结论

### 3.1 结论

**技术成本可控，建议实施。**

主要原因：

- 角色导出数据模型、诊断机制、下载入口和依赖均可复用；
- 新模板有 AcroForm 字段，字段填充比重新测量三页坐标更稳定；
- 改动可收束在 PDF 适配器、运行时模板资产和 PDF 测试，不需要改变规则派生逻辑。

预计可复用现有 PDF 导出链路的约 70%～80%；主要重做部分是模板字段清单、字段映射、中文字段外观和视觉验收。

### 3.2 预计工作量

| 工作项 | 预计成本 |
|---|---:|
| 模板结构核验、导出完整字段清单 | 0.5 人日 |
| 三页字段语义映射与容量定义 | 1～1.5 人日 |
| AcroForm 填充、复选框、中文外观与扁平化适配 | 1～1.5 人日 |
| 长文本、攻击和法术容量处理及诊断 | 0.5～1 人日 |
| 单元测试、黄金样例、三页视觉与打印验收 | 1～1.5 人日 |
| 文档与运行时资产整理 | 0.5 人日 |
| **合计** | **4～6 人日** |

以下情况会增加成本：

- 要求导出后继续编辑表单且兼容 Acrobat、Edge、Chrome、WPS 等不同阅读器：增加约 1～2 人日；
- 要求填满当前草稿模型没有的数据，如玩家名、外貌、个性、理想、羁绊、缺点、盟友组织、宝藏：需要新增角色数据、输入界面和持久化，增加约 3～6 人日，且不再属于单纯模板替换；
- 模板字段名存在重复、损坏或 pdf-lib 无法稳定更新外观时，需局部回退坐标绘制，增加约 1～2 人日。

### 3.3 非技术阻断项

目标模板是社区汉化/改版角色卡，版面与模板分发授权目前未在项目文档中得到确认。即使项目免费，随 Web 应用公开携带并下载模板仍属于再分发。

因此实施前必须满足以下任一条件：

1. 用户能够确认模板允许项目使用、修改和再分发，并记录来源与授权说明；或
2. 不把模板打包到公开应用，由用户在本地自行选择模板文件；或
3. 取得明确授权后再作为 `public/templates` 运行时资产发布。

**授权未确认时，可以完成本地技术验证，但不得将模板作为公开运行时资产发布。**

## 4. 范围

### 4.1 本期范围

- 替换 PDF 运行时模板及 PDF 专用适配器；
- 填充三页中现有 `CharacterExportModel` 能可靠提供的字段；
- 使用 AcroForm 字段名映射，复选框通过表单 API 设置；
- 对缺少数据来源的字段保持空白，不猜测数据；
- 保留现有阻断错误、容量警告、下载状态和防重复点击行为；
- 导出结果默认扁平化，保持当前“生成后用于查看和打印”的行为。

### 4.2 非目标

- 不修改 D&D 规则计算；
- 不新增玩家名、灵感、当前 HP、临时 HP、死亡豁免、外貌和性格等可编辑业务字段；
- 不修改 XLSX、JSON 导出；
- 不支持多职业或 2024 规则；
- 不承诺导出后继续编辑表单；
- 不为填满模板而生成虚构内容。

## 5. 功能需求

### R1 模板资产与版本

1. 授权确认后，将目标模板复制为稳定的 ASCII 运行时文件名，原始文件保留在 `docs/export-templates/` 作为来源底稿；
2. PDF 映射版本从 v4 升级，禁止把新模板字段继续标记为 v4 坐标映射；
3. 构建时必须能读取模板，模板缺失或页数不是 3 页时阻断导出并显示中文错误；
4. 不覆盖或改写原始归档文件。

### R2 完整字段清单

实施前生成目标模板的字段清单，至少记录：

- 字段全名、类型、所在页、矩形坐标；
- 文本字段是否多行、是否只读、最大长度；
- 复选框的开启值；
- 重名、尾随空格和无语义名称字段；
- 对应 `CharacterExportModel` 路径、格式化规则和无数据时行为。

字段映射应成为 PDF 模板的唯一契约，禁止仅按字段出现顺序填充。

### R3 第一页映射

1. 身份字段填充角色名、职业与等级、种族、背景、阵营；
2. 玩家名保持空白，经验值填 `0`；
3. 填充六项属性值、调整值、豁免值和豁免熟练标记；
4. 填充熟练加值、AC、先攻、速度、最大/当前 HP、生命骰和被动感知；
5. 临时 HP 填 `0`；当前模型没有死亡豁免状态，相关字段保持空白；
6. 填充 18 项技能值，熟练与专精必须有可区分标记；如果模板只提供单个复选框，复选框表示“至少熟练”，专精通过数值体现，不伪造第二种勾选状态；
7. 优先填充前三个攻击栏，额外攻击写入“攻击与施法”多行区；
8. 填充钱币、物品、语言/熟练和特性；
9. 个性、理想、羁绊、缺点等当前无独立数据来源的字段保持空白。

### R4 第二页映射

1. 重复填写角色名；
2. `profile.backstory` 写入模板的背景故事区域；
3. 第一页容纳不下的特性写入额外特性区域；
4. 外貌、年龄、身高、体重、眼睛、肤色、头发、盟友组织、徽记、宝藏等无数据来源字段保持空白；
5. 超出模板容量时截断并返回 `content-truncated` 警告，禁止静默丢失。

### R5 第三页法术映射

1. 施法角色填写施法职业、施法关键属性、法术豁免 DC 和法术攻击加值；
2. 按 0～9 环写入法术名称；
3. 写入各环法术位总数；当前模型没有“已消耗法术位”状态，对应格保持空白；
4. 已准备法术勾选对应复选框；已知制或契约魔法不得把全部法术错误标为“已准备”；
5. 非施法角色第三页保持模板空白；
6. 每环法术超过模板容量时保留可见部分并返回分环级警告。

### R6 中文字体与外观

1. 所有文本字段使用项目现有 Noto Sans SC 字体更新 appearance stream；
2. 不依赖模板内置字体子集覆盖项目规则数据；
3. 根据字段宽度自动选择字号；多行字段允许换行；
4. 生成外观后默认扁平化表单，确保浏览器预览和打印一致；
5. 不允许出现乱码、方框字、文字不可见或打开后才显示的问题。

### R7 诊断与失败处理

1. 缺少必需字段、字段类型不符或模板损坏时返回 error 并禁止下载；
2. 可选字段缺失、攻击/法术/长文本超容量时返回 warning，允许下载；
3. 诊断信息使用现有 `ExportDiagnostic` 结构，并明确字段和处理结果；
4. 不得因为单个无来源的可选字段为空而阻断导出。

## 6. 实现约束

建议调用链保持：

```text
角色卡页面 hook
  -> buildCharacterExportModel(draft, derived)
  -> services/export-pdf
  -> pdf-lib / fontkit
  -> 模板与字体静态资产
```

- 不新增规则层依赖；
- `CharacterExportModel` 仍是 PDF/XLSX 的统一事实源；
- PDF 表单字段映射属于 `services/export-pdf` 的模板适配职责；
- 如需保存新的角色资料字段，必须另立需求，先扩展 `CharacterDraft`、JSON 兼容和输入界面，不得在 PDF 服务中读取页面状态。

## 7. 测试与验收

### 7.1 自动化验收

1. 真实目标模板可以被 pdf-lib 加载，页数为 3；
2. 字段清单中全部必需字段存在、类型正确，复选框开启值可识别；
3. 战士黄金样例正确填充第一页，非施法角色第三页不写入错误数据；
4. 法师黄金样例正确填充法术页、法术位和准备标记；
5. 中文角色名、职业、种族、物品、特性和法术生成后无字体编码异常；
6. 长文本、超过三个攻击和法术容量溢出均产生诊断；
7. 输出仍为 3 页，且可被 pdf-lib 重新加载；
8. 现有导出模型、XLSX、JSON 和角色卡导出入口测试不回归；
9. 类型检查、测试和生产构建通过。

### 7.2 视觉与打印验收

至少使用以下样例逐页核对：

- 4 级战士：属性、熟练、三类文本区、多个物品和攻击；
- 3 级法师：戏法、一环/二环法术、准备状态和法术位；
- 长中文角色名、长背景故事和大量特性的容量边界样例。

至少在 Chrome/Edge 内置 PDF 阅读器和一个独立 PDF 阅读器中检查：

- 三页卡面与字段无错位；
- 中文无乱码、截字和重叠；
- 复选框正确；
- Letter 纸打印预览不裁切；
- 扁平化后内容仍完整可见。

## 8. 发布门槛

只有同时满足以下条件才可替换线上模板：

1. 模板分发授权已确认并归档；
2. 三页字段映射完成；
3. 自动化测试、类型检查和生产构建通过；
4. 战士与法师黄金样例由用户完成三页视觉核对；
5. 导出诊断没有阻断错误；
6. `docs/rules.md` 中 PDF 模板描述、导出需求实施状态和必要的模板来源说明已同步更新。

## 9. 待确认项

1. 模板是否允许随本项目公开再分发和修改？
2. 是否接受导出 PDF 默认扁平化、不可继续编辑？本需求按“接受”起草；
3. 是否只替换视觉模板并允许无数据字段留空？本需求按“允许”起草；
4. Letter 纸尺寸是否符合主要打印场景？若必须输出 A4，需额外定义缩放和打印验收。

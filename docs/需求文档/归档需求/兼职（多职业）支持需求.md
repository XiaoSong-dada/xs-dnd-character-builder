## 1. 背景与目标

### 1.1 现状

- 项目当前明确声明「支持 1—20 级**单职业**；多职业暂不开放」（`.agents/AGENTS.md`「当前范围」、`docs/rules.md` 第 59 行、`docs/dnd-classes.md` 第 15 行）。
- 数据模型把「职业」压成三个标量字段：`CharacterDraft.classId`、`CharacterDraft.subclassId`、`CharacterDraft.targetLevel`（`app/src/types/character.ts:187-240`），并在约 90 处规则/界面代码中按「`targetLevel` 就是职业等级」使用（见 §6）。
- 法术位、准备/已知法术、戏法、法术书都是**单一职业口径**的扁平数组（`SpellSelections`，`app/src/types/character.ts:92-103`），`getSpellcastingConfig(draft)` 只解析一个职业或一个子职的施法配置（`app/src/rules/spellcasting.ts:412-419`）。
- 时间线只由单个 `classId` 生成（`app/src/rules/timeline.ts:306-389`）。

### 1.2 目标

让玩家能够创建、编辑、跑团使用与导出**兼职（多职业）角色**，并满足：

1. 兼职规则（先决条件、熟练项、生命骰、熟练加值、职业特性、兼职施法者法术位）按 5e 不全书正文正确计算；
2. 兼职角色仍然可以被「升级 / 降级 / 重新编辑」完整管理，旧选择不静默删除；
3. 2014 与 2024 草稿各自的兼职口径独立、不混用；
4. 旧草稿（schema v9 及更早）零数据损失地迁移，导入导出与 PDF／XLSX／JSON／ZIP 全链路可用；
5. 新玩家能看懂「为什么不能兼这个职业」「这个数值从哪个职业来」。

### 1.3 成功标准

- 一个 `战士3 / 游荡者2` 的 2014 角色：熟练加值 +3、HP 按各职业升级生命值累加、无甲防御只算一次、额外攻击不叠加、法术位为 0（两者均非施法职业）。
- 一个 `游侠4 / 术士3` 的 2014 角色：法术位 = 5 级施法者（4/3/2），但仍不能准备任何 3 环法术，也不能准备 2 环游侠法术；游侠与术士各自的已知/准备列表独立校验。
- 一个 `圣武士6 / 魔契师 (邪术师) 1` 的 2014 角色：同时拥有普通法术位池与契约法术位池，两池可互相施放对方职业的法术。
- 角色卡、跑团助手、PDF、XLSX、JSON 导出的职业行显示为「战士3 / 游荡者2（5 级角色）」。

### 2.1 通用语义

- 兼职是**可选规则**，由 DM 决定是否启用；本项目应在职业步骤给出显式开关或说明，默认不阻断（与「专长」可选规则的既有处理一致）。
- 升级时可以选择获得一个新职业的 1 级，而不是提升当前职业（2014：`玩家手册_自定义选项_兼职.md:6`；2024：`玩家手册2024_创建角色_兼职.md:5`）。
- **角色等级 = 所有职业等级之和**；等级写法为「职业A n / 职业B m」。因此熟练加值、戏法威力成长、经验值门槛一律按**角色总等级**，不按单个职业等级。
- 兼职支持三种及以上职业（2014 举例为「战士4/游荡者1/法师1」）。

### 2.2 先决条件

- 获得一个新职业前，必须**同时**满足**现有职业**与**新职业**的属性要求（2014 原文：「你必须同时满足现有职业和新职业的属性值要求」；2024 原文：「你的新职业及当前职业对应的主要属性至少要有13」）。
- 依官方裁定，**只有基础属性值可以满足兼职先决条件，临时属性提升不算数**（`贤者谏言2025_兼职.md:3-4`）。本项目应使用 `draft.baseAbilities` 判定。
- 兼职先决条件表（2014，`玩家手册_自定义选项_兼职.md:20-72`）：

| 职业 | 最低属性值 |
| --- | --- |
| 野蛮人 | 力量 13 |
| 吟游诗人 | 魅力 13 |
| 牧师 | 感知 13 |
| 德鲁伊 | 感知 13 |
| 战士 | 力量 13 **或** 敏捷 13 |
| 武僧 | 敏捷 13 **及** 感知 13 |
| 圣武士 | 力量 13 **及** 魅力 13 |
| 游侠 | 敏捷 13 **及** 感知 13 |
| 游荡者 | 敏捷 13 |
| 术士 | 魅力 13 |
| 魔契师（邪术师） | 魅力 13 |
| 法师 | 智力 13 |

- 2024 的先决口径与 2014 相同（「主要属性」取各职业核心特质表的「主要属性 Primary Ability」），因此 2024 侧需要按各职业 `primaryAbilities` 建立**结构化属性要求**（当前 `ClassRule.primaryAbilities` 是自由字符串数组，`app/src/types/rules.ts:373`，无法直接表达「或 / 及」）。

### 2.3 经验值

升级所需经验以**角色总等级**计算。例如牧师6/战士1 必须获得足够升到 8 级的 XP 才能再升一级（`玩家手册_自定义选项_兼职.md:76`；2024 同）。

本项目不管理 XP，但**必须在界面上按总等级展示目标等级**，且 `targetLevel` 的语义统一为「角色总等级」。

### 2.4 生命值与生命骰

- 「1 级生命值（生命骰最大值 + 体质调整值）」**只在角色 1 级时获得一次**，即**起始职业**的 1 级；此后每次升级（无论本职业还是兼职）只获得**所升职业的后续升级生命值**。
  - 2014 原文明确：「你只有在作为1级角色时才能获得相应职业的'第一级的生命值'。随后每次升级，你都只获得所升职业（本职或兼职）的'后续升级生命值'。」
  - 2024 原文：「你从新职业获得的生命值和1级之后的等级相同。你只有在作为1级角色时才能获得相应职业的'1级生命值'。」
- 生命骰池由**所有职业的生命骰汇集**而成；同骰面可相加（圣武士5/战士5 = 10d10），不同骰面分开计（圣武士5/牧师5 = 5d10 + 5d8）。
- 因此兼职角色的生命骰池**必须按骰面分组**，当前的单一 `hitDice.total`（`app/src/types/session-state.ts:40-43`）不足以表达。

### 2.5 熟练加值

按**角色总等级**计算（2014 与 2024 同）。

**豁免熟练**：官方裁定明确——「你只能获得该职业前言中'作为兼职角色'一栏的特质，而这其中**没有任何豁免熟练**」（`贤者谏言2025_兼职.md:10-12`）。**角色只拥有起始职业的豁免熟练**；但通过职业**特性**（如牧师圣职·保护者的重甲受训、游侠幽域追猎者的钢铁意志感知豁免）获得的熟练与受训仍然照常获得。

**起始装备**：只能获得**首次选择职业时的起始装备**；兼职获得的等级**不带来**新职业的起始装备（2014:`:18`、`:156`；2024 同）。

### 2.7 职业特性与兼职专属规则

获得某职业某等级的特性，但四个特性有兼职专属规则（2014:`:154-186`；2024:`:30-41`）：

- **额外攻击 Extra Attack**：不叠加。多个职业提供额外攻击也只能攻击两次，除非特性自身写明可以更多（如战士 11 级「额外攻击（二）」→ 3 次、20 级 → 4 次）。魔契师祈唤「饥渴魔刃」不会在有额外攻击时再增加次数。
- **护甲等级计算方式（无甲防御等）**：同一时间只能使用一种 AC 计算方式。例如武僧/术士同时有「无甲防御」与「龙族体魄」，必须择一。
- **引导神力 Channel Divinity**：若已有引导神力，提升另一个同样在该等级给予引导神力的职业时，**只获得该等级的使用方式，不获得额外次数**；次数只在达到「给予额外使用次数」的等级时增加。例：牧师6/圣武士4 之间可使用 2 次（因牧师等级已达标），每次可从两种职业的效应中择一。
- **施法 Spellcasting**：见 §2.8。
- 其他判断（官方裁定补充）：野蛮人/战士（战斗大师）兼职可在狂暴时使用战技；游荡者/武僧不能以徒手打击发动偷袭（徒手打击不是武器），但可用满足条件的武僧武器发动；法术与职业关联，只有作为某职业特性被准备的法术才触发该职业的触发式能力（如狂野魔法浪涌）。

### 2.8 兼职施法

**2014 口径**（`玩家手册_自定义选项_兼职.md:177-186`）：

- **已知/已准备法术**：必须为**每个兼职职业分别**制定已知法术列表与准备法术列表，如同该职业的专职角色。每个法术只与**一个职业**关联，只能用**该职业的施法属性**施展，法器也只能用于对应职业的法术。
- **法术位**：累加各施法职业等级得到「施法等级」：
  - 全施法者（吟游诗人、牧师、德鲁伊、术士、法师）等级**全额**相加；
  - 半施法者（圣武士、游侠）等级**除以 2 向下取整**相加；
  - 奥法骑士（战士子职）与诡术师（游荡者子职）按**战士/游荡者等级除以 3 向下取整**相加；
  - 之后查「兼职施法者」表得到法术位。
- 可能得到高于自身已知/准备法术环阶的法术位：这些法术位只能用于施展低环法术，但**升环施法的强化效应照常生效**。

**2024 口径**（`玩家手册2024_创建角色_兼职.md:465-480`）：

- 同样按职业分别准备法术；每个法术与一个职业关联，只用该职业施法属性施展。
- 戏法威力成长按**角色总等级**。
- 累加规则与 2014 相同结构的三种系数。

### 2.9 子职选择

- 子职按**各自职业的等级**解锁：2014 为牧师/术士/邪术师 1 级、德鲁伊/法师 2 级、其余 3 级；2024 统一 3 级（`docs/rules.md:230-239`、`docs/dnd-classes.md:142`）。
- 兼职角色的每个职业**各自**选择子职，`战士3（奥法骑士）/ 法师5` 与 `法师5 / 战士3` 都是合法组合。
- 1/3 施法子职（奥法骑士、诡术师）只在其职业等级达到子职解锁等级后才把 1/3 等级计入施法等级。

## 3. 需求项

### R1 多职业等级结构

1. 草稿必须能表达「职业 → 该职业等级」的有序集合；**不限制职业数量**（决策 D9）：唯一约束是「每个职业 ≥ 1 级」与「Σ 等级 ≤ 20」，因此同一草稿最多 20 个职业、最少 1 个。同职业不可重复添加。
2. 必须记录**起始职业**（获得 1 级生命值、起始装备、豁免熟练的那个职业）。
3. `targetLevel` 的语义固定为**角色总等级**，等于各职业等级之和；1—20 级校验以总和为准，任何单职业不得超过 20。
4. 每个职业各自持有可选的 `subclassId`。
5. 必须能记录**升级顺序**（第几级选了哪个职业），因为 HP、熟练项、检查点的合法性都依赖「某等级时选了哪个职业」。
6. **总等级是派生值**：数据层不接受与 `Σ 职业等级` 不一致的 `targetLevel`；任何写入路径都必须先改职业分配再重算总等级（校验与写入规格见 §5.1.2、R11）。
7. 草稿需记录兼职开关的开启状态（`multiclass.enabled`），默认关闭；开关与职业分配是两个独立动作。

### R2 兼职先决条件与合法性校验

1. 新增职业或提升已有职业等级时，校验**基础属性**是否同时满足所有既有职业与新职业的要求（含「或 / 及」语义）。
2. 不满足时返回**可执行的中文原因**，例如：「兼职德鲁伊需要同时满足野蛮人（力量13）与德鲁伊（感知13）的要求；当前感知为 11，请在第 5 步提高感知，或改选其他职业。」
3. 兼职为可选规则：提供来源步骤或职业步骤的显式说明/开关；未启用时不出现任何兼职入口与错误。
4. 起始职业固定为第一个职业；改变起始职业等同于重建，走现有「换职业」依赖确认流程。

### R3 熟练项合并

1. 豁免熟练只来自起始职业。
2. 技能熟练 = 起始职业技能（完整）+ 各兼职职业的兼职技能项（如 2014 游侠/游荡者各一项、2024 吟游诗人一项等）+ 背景 + 种族/物种 + 专长；同类不重复叠加，背景与职业重复时沿用现有 `proficiencyReplacements` 替换记录。
3. 护甲/武器/工具受训按各职业的兼职条目合并；2014 使用「兼职熟练项」表，2024 使用各职业「作为兼职角色」条目。
4. 熟练项来源必须标注具体职业（沿用 `ValueSource.detail` 的既有来源链机制）。
5. 德鲁伊兼职条目附带的「不使用铁质护甲或盾牌」沿用项目既有展示级处理（不阻断数值计算）。

### R4 生命值与生命骰

1. HP = 起始职业生命骰最大值 + 体质调整值 + Σ（每个后续等级：所升职业生命骰的固定值或掷骰结果 + 体质调整值）+ 既有子职/专长/物种生命加成。
2. 生命骰池按骰面分组存储与展示（如 `{d10: 5, d8: 5}`），跑团助手的短休消耗按**具体骰面**扣减。
3. 生命骰总数 = 各职业等级之和。（2024 结算沿用现有短休/长休管道。）

### R5 职业特性与互斥去重

1. 特性按「职业 + 该职业等级」累积，且只累积到该职业的等级上限。
2. 互斥/去重规则必须结构化实现（不得散落在模板或临时判断中）：
   - 额外攻击族：取最大值而非累加；仅战士的「额外攻击（二）/（三）」提升次数上限。
   - AC 计算方式：多来源并存时由玩家显式择一（含子职提供的公式，如龙族体魄、炫目舞步），未选择时给中文提示；`derive` 现有硬编码分支必须改为按「已生效 AC 公式集合」判定。
   - 引导神力：共享使用次数池，使用方式取并集。
   - 其他同名特性（如无甲防御）不重复授予。
3. 特性资源（`ClassResource`、`DicePoolRule`）按角色汇总；同名资源的已用量在跑团状态中**合并为一个计数池**。

### R6 兼职施法

1. **每个职业一份法术选择**：戏法、已知法术、准备法术、法术书都必须带职业归属；数据结构见 R6.4。
2. **每职业独立校验**：数量（按该职业等级表/公式）、候选池（该职业法术列表 + 既有扩表来源）、最高可准备环级（按该职业等级）。
3. **通用法术位池**：按 §2.8 累加施法等级，查兼职施法者表得到 1—9 环法术位；与现有 `manualEdits.spellSlotAdjustments` 人工差值兼容。
4. **契约魔法**：魔契师同时存在契约法术位池（按魔契师等级）；两池可互相施放对方来源的法术；跑团助手需分别展示与结算。
5. **升环施法**：允许用高于法术环阶的法术位施展低环法术（现有 `getAvailableSlotLevels` 已支持，但要覆盖兼职池）。
6. **法术归属性**：法术的施法属性、法器、以及与职业绑定的触发式能力（如狂野魔法浪涌）都按该法术的归属职业解析。
7. **施法攻击与 DC**：法术攻击/DC 按**每个施法职业**分别给出（可多个），角色卡并列展示；沿用现有 `getSpeciesSpellcastingProfiles` 的多来源展示范式。
8. **戏法威力**：戏法按等级成长的数值以**角色总等级**为准。本项目**必须建模**（决策 D4）：新增 `CantripScalingRule` 并逐条登记，不得解析展示文本、不得从规则表反推；未登记的条目只展示、不显示成长行。详见 §4.5。
9. **1/3 施法子职**：奥法骑士/诡术师在其职业等级达到子职解锁等级后，把该职业等级 ÷3（向下取整）计入施法等级与可用法术池。

### R7 时间线、升级与降级

1. 时间线按**等级 1 → 总等级**展开，每个检查点标注它属于哪个职业（或起源/物种/背景/专长）。
2. 检查点 id 必须带职业限定（如 `class-2014-fighter-skills`），避免多职业撞 id。
3. 升级必须支持两种选择：提升某既有职业，或新增一个职业的 1 级；两种操作都先给出「受影响 / 需复查 / 保留」三分类确认。
4. 降级支持降低某职业等级（并可在降为 0 时移除该职业）；被移除职业的检查点选择、法术、特性标记失效并保留记录（沿用 `inactiveSpellSelections` 的停用历史语义）。
5. `getDependencyImpact` 的 `DraftChange` 必须扩展为「职业分配变更」（新增 `{ kind: 'class-allocation'; classes; levelOrder; enabled }`），实现为「旧分配 vs 新分配」两条时间线求差（复用现有 `target-level` 分支的 invalidated/added 算法），并保留 `target-level` 兼容分支。
6. 兼职检查点未完成时校验报 error，完成度下降（沿用现有机制）。
7. 关闭兼职开关触发的「合并到起始职业」也走同一变更类型（总等级不变、职业集合变化），以便失效清单与复查清单自动生成。

### R8 展示与导出

1. 职业展示统一为「战士3 / 游荡者2（5 级角色）」格式，覆盖：草稿列表条目、车卡吸底摘要、角色卡头部、跑团助手标题、PDF、XLSX、JSON。
2. 角色卡需分区展示：每个职业的等级、子职、职业特性、资源、法术列表与施法属性；生命骰按骰面分组；法术位显示通用池与契约池。
3. 数值来源链（`DerivedValue.sources`）必须能说明「该加值来自哪个职业的哪一级」。
4. 装备步骤只提供起始职业的起始装备，并明确提示「兼职不获得新职业的起始装备」。

### R9 数据迁移与兼容

1. 新 schema 版本（v10）承载多职业结构；v2—v9 草稿迁移为「单职业 + 起始职业」形态，**数据不失真、不重排、不改写既有选择**。
2. 导入旧 JSON／ZIP 必须成功；导入新 JSON 到旧版本应用的行为不在本期保证（沿用现有「版本不受支持」错误提示）。
3. 跑团助手局内状态按草稿 id 隔离的机制不变；职业结构变化后按新上限协调（沿用 `reconcileSessionLimits`）。
4. 旧 2024 只读隔离草稿的原样导出能力不受影响。

### R10 规则集隔离

1. 2014 与 2024 的兼职熟练项、先决属性、施法系数、检查点 id 完全独立登记，禁止隐式共享。
2. 同一草稿内不得混用两版职业（沿用「同一草稿不混用、不提供原地切换」的既有约定）。
3. UA/第三方职业（如 UA 奇械师、灵能使）**同样可以兼职**（决策 D3）；先决与兼职熟练项按各自资料登记，未登记先决的职业**不得**推断，界面标注「先决条件待核验」并给出提示级问题、不阻断。

### R11 兼职开关与等级分配控件（决策 D2）

详细交互规格见 §5.1。需求项：

1. 第 1 步（`SetupStep`）、第 3 步（`ClassStep`）、角色卡等级调整弹窗（`LevelAdjustModal`）三处渲染**同一个**等级分配控件，读写 `multiclass` 同一份数据；不得各自维护等级状态。
2. 控件提供兼职开关（默认关闭，标注「可选规则需 DM 同意」）、只读总等级行、职业等级分配列表、「添加职业」入口（受开关控制）与起始职业标记。
3. **总等级只读**，恒等于 Σ 各职业等级；不提供独立的总等级输入。
4. 单职业模式下保留现有 1—20 数字网格；兼职模式下用逐职业 `− / +` 步进；**第 1 步与第 3 步均可完成分配**，分配完成后第 3 步可直接继续（决策 D6，见 §5.1.3）。
5. 约束：总等级 1—20；单职业 1—19；**职业数不设上限**（受总等级约束，最多 20）；同职业不可重复添加；每个职业最低 1 级（降到 0 = 移除该职业，需二次确认）；起始职业不可直接移除。
6. 关闭开关时若存在多个职业，必须让玩家显式选择「合并到起始职业」或「取消」，并在合并前展示依赖影响摘要；合并与移除**不可撤销且不保留等级分配历史**（决策 D7），因此必须提供常驻说明、二次确认、明细预览且不提供快捷关闭入口。
7. 分配变更确认后统一走 `pendingChange` 三分类弹窗与既有升级/降级引导；先决条件不满足在分配阶段为 warning，在校验期为 error。
8. 兼职模式下点击「确认」前必须展示变更摘要：总等级前后、各职业等级前后、将失效选择数、待补全检查点数。
9. 戏法威力等按**角色总等级**成长的数值必须进入派生计算（决策 D4，见 §4.5），并在来源说明中写明「按角色总等级」。

### 4.5 戏法成长建模（决策 D4）

**现状**：法术库**没有**任何结构化的戏法成长数据 —— 2014 条目的 `SpellRule.description` 为空（`rules/data/spells-2014.ts` 头注释明确「仅保存选择所需：名称、环级、职业归属、来源索引，不复制效果正文」）；2024 条目把成长写进展示文本，如 `spells-2024.ts:33` 火焰箭「命中1d10火焰；5/11/17级各+1d10」、`:31` 魔能爆「5级2道、11级3道、17级4道光束」。两者都无法参与计算。

**本决策要求**：按**角色总等级**结构化建模戏法成长（兼职角色戏法威力跟随总等级，见 §2.8），而不解析展示文本。

```ts
/** 戏法成长：随角色总等级提升的伤害骰、伤害骰数量或射线数量。 */
export interface CantripScalingRule {
  /** 成长节点与对应表达式（按节点升序）；如 [{ level: 5, dice: '2d10' }, { level: 11, dice: '3d10' }, { level: 17, dice: '4d10' }]。 */
  readonly steps: readonly {
    readonly level: number
    readonly dice?: string
    /** 骰数成长（如魔能爆射线数、亡者丧钟的 d8→d12 分支）。 */
    readonly count?: number
    readonly note?: string
  }[]
}
```

- `SpellRule` 新增 `cantripScaling?: CantripScalingRule`（仅 0 环条目可能填写）。
- 新增纯函数 `getCantripScalingAtLevel(spellId, ruleset, characterLevel)`，返回当前生效的骰式/数量与来源说明；派生值必须把「按角色总等级」写进 `ValueSource.detail`。
- 数据登记范围（必须有明确边界，避免把整本法术库重录一遍）：
  - **本期登记**：职业法术选择的戏法池中被选中的 0 环法术，且其成长影响实际数值的条目（伤害骰成长、射线/光束数量成长、射程成长如维生术）。依据 2014 与 2024 不全书正文。
  - **支持法术位升环成长的条目不在本字段范围**（升环由法术位环级决定，与总等级无关，现有机制已处理）。
  - 特殊分支（亡者丧钟按目标是否缺失生命值取 d8/d12、橡棍术骰型升级、克敌先击额外光耀）用 `note` 记录分支，本期**只做展示**，不进入自动伤害结算。

### 5.1 兼职开关与等级分配交互设计（决策 D2）

> 本节回答「第 1 步与角色卡调整等级弹窗内新增兼职开关、上方总等级、下方职业等级分配」的设计是否成立，并给出可直接实现的规格。

#### 5.1.1 设计结论

方向成立，但有三个前提必须满足，否则会出现数据漂移或流程死角：

1. **总等级必须是派生的和，不能是与分配并列的独立输入。** 上方总等级 = Σ 各职业等级，只读展示；调节方式统一为「给某个职业加减级」。单职业时该职业等级自然等于总等级，玩家观感与现在完全一致（1—20 大网格仍然可用，见 5.1.3）。
2. **开关与「添加职业」是两个动作。** 开关只控制「是否允许添加更多职业」；真正的兼职发生在玩家点击「添加职业」并看到确认摘要之后。仅打开开关不产生任何数据变化，也不产生依赖影响。
3. **入口不能只在第 1 步。** 第 1 步、第 3 步「职业与等级分配」、角色卡「调整等级」弹窗三处必须渲染**同一个控件、读写同一份数据**，否则玩家分配完职业后无法回到第 1 步修改，角色卡也只能改总等级。

#### 5.1.2 控件语义与状态模型

| 项 | 说明 |
| --- | --- |
| 兼职开关 | 存于草稿（建议 `multiclass.enabled`，见 §4.1）。**默认关闭**，以保持绝大多数新玩家的现有流程不变。文案为「**启用兼职**」（决策 D10），旁附辅助说明「可选规则，需 DM 同意」（决策 D3）。开启不改变任何等级数据；关闭时的处理见 5.1.5 |
| 上方总等级 | **只读**展示，文案为「总等级 5（战士 3 + 游荡者 2）」。总等级只由分配派生，不提供独立输入框，从数据层杜绝不一致 |
| 下方职业等级 | 每个职业一行：职业名 · 该职业等级步进器 · 该职业子职（达到解锁等级后出现）· 先决条件状态 · 移除按钮（起始职业除外） |
| 添加职业 | 开关开启后出现在列表下方；候选列表复用第 3 步职业候选与来源过滤，**已选职业不可重复添加**（同职业不能取两次） |
| 起始职业标记 | 第一行标注「起始职业」，说明其承载 1 级生命值、起始装备与豁免熟练 |
| 上限 | **职业数不设上限**（决策 D9，受总等级约束，最多 20 个）；单职业等级 1—19；Σ 职业等级 = 总等级 ∈ [1, 20] |

#### 5.1.3 两种排布与第 3 步的衔接（决策 D6）

- **单职业模式**（开关关闭）：保留现有 1—20 大网格，点击格子即直接把唯一职业调到该等级；下方显示当前职业卡片与灰色提示「开启兼职后可分配多个职业的等级」。大网格之所以仍可用，是因为单职业下「总等级 = 该职业等级」成立。
- **兼职模式**（开关开启）：上方只读总等级行；下方职业行列表用 `− / +` 步进；`+` 在总等级 20 时禁用并提示「总等级已达 20，请先降低其他职业等级」，某职业到 19 级时禁用该行 `+`。**职业数不设上限（决策 D9）**，因此列表必须支持纵向滚动，并在职业较多时按「起始职业 → 其余按加入顺序」折叠或分组，避免把移动端弹窗撑满。
- **第 1 步与第 3 步都能完成分配（D6）**：两处渲染同一控件，因此第 1 步分配好职业等级后，第 3 步打开时直接呈现已完成的分配结果；玩家确认无需改动即可**直接点击下一步**继续。
- **第 3 步的完成判定**：`canContinue` 的条件从现有 `Boolean(draft.classId)` 改为「至少一个职业且其等级 ≥ 1，且 Σ 等级 = 总等级，且总等级 ∈ [1, 20]」。分配已完成时按钮即为可继续态，不再要求玩家重做一次选择。
- **第 1 步的完成判定**：等级分配不再是自由参数，`targetLevel ∈ [1, 20]` 的既有校验改为对分配结果求和后判定；分配未完成（如新增职业后等级为 0）时给出行内提示。
- 第 1 步与第 3 步之间的数据一致性由「同一份数据源」保证：不存在「第 1 步的总等级」与「第 3 步的职业等级」两份状态，因此来回切换步骤不会覆盖或重算任何内容。

#### 5.1.4 分配规则

1. 达到 20 级总等级时禁用一切 `+`，已到 19 级的职业禁用该行 `+`。
2. 每个职业最低 1 级；降低到 0 视为**移除该职业**（需二次确认）。
3. 起始职业不能直接移除；若要把起始职业改为其他职业，走现有「换职业」整体替换确认（`useCharacterBuilderPage.ts:435-466`、`dependency.ts:109-115`），不做静默切换。
4. 子职保留：降低该职业等级到其子职解锁等级以下时，给出两个明确选项——「提高该职业等级」或「更换／清除该子职」；被清除的子职及其特性选择标记失效并保留记录，不静默删除。
5. 先决条件：每次分配后即时检查**基础属性**是否满足全部职业的要求（§2.2），不满足时在该行内以 warning 显示，并提供「去第 5 步调整属性」的跳转；**不加顶部横幅**（决策 D13），也**不在分配阶段硬阻断**（此时属性步骤本就尚未完成）。
6. 生命骰、HP、熟练加值、法术位、检查点变化全部由分配派生重算，不写入任何派生字段。

#### 5.1.5 关闭开关与降级（决策 D7：不留历史 + 防误触）

- **关闭兼职开关且存在 2 个以上职业**：弹出选择「把其他职业的等级合并到起始职业（总等级不变）」或「取消，先手动处理其他职业」；合并前展示依赖影响摘要（哪些检查点会失效、哪些需要复查），确认后执行。
- **不留历史（D7）**：合并与移除职业是**不可撤销**的破坏性动作——被合并/移除职业的**等级分配本身不保留**（不写入任何历史结构、不提供一键还原）；其检查点选择与法术仍按既有约定标记失效并保留记录（那属于「选择历史」，与「等级分配历史」是两件事）。
- **防误触（D7）**：因为不可撤销，关闭开关必须做到：
  1. 开关旁常驻说明文字，例如「关闭兼职会合并其他职业的等级，且无法撤销」；
  2. 点击关闭时先弹二次确认，确认弹窗的破坏性按钮使用警示样式，并把「取消」置于主操作位置；
  3. 确认弹窗内必须列出将被合并的「职业 + 等级」明细，以及预计失效的选择数量；
  4. 不提供「一键关闭」的快捷入口（不在列表页、吸底栏等位置放关闭开关），只在等级分配控件内出现。
- 关闭开关本身**不清空** `multiclass` 的职业列表数据（保留当前分配，仅关闭「添加职业」入口）；清空只发生在玩家明确确认合并之后。重新打开开关时，若尚未合并则显示原分配。
- 该行为与现有「旧选择保留并标记失效、不静默删除」的既有语义一致（`docs/rules.md:89`、`:93`）；与 D7 的差异仅在于**等级分配数字本身不保留**，这是用户明确确认过的取舍。

#### 5.1.6 确认与引导（复用既有机制）

- 分配变更确认后统一走 `LevelAdjustModal` 的既有链路：确认 → `pendingChange` 三分类弹窗（待补全 / 需复查 / 保留）→ 应用。现有 `adjustLevel` 已使用 `alwaysConfirm: true`（`useCharacterBuilderPage.ts:366-406`），分配变更沿用同一入口，仅把变更类型从 `target-level` 换成职业分配变更（§R7.5）。
- **升级**：新增检查点转入「待补全」，确认后沿用现有引导跳到时间线（`useCharacterBuilderPage.ts:395-401`），并在检查点标题上标注归属职业（「战士 3 级 · 选择武术范型」）。
- **降级或移除职业**：受影响选择列入「将失效」，法术按归属职业归档到 `inactiveSpellSelections`（现有 `reconcileSpellSelections` 已按职业写入 `sourceKey`），跑团局内状态按新上限协调（`reconcileSessionLimits`）。

#### 5.1.7 不建议的做法（明确排除）

- ❌ 上方总等级做成可输入的独立字段 + 下方分配：两处会不一致，且总等级变化时无法判断该改哪个职业的等级。
- ❌ 只加开关不加「添加职业」按钮，靠开关自动生成第二个职业：玩家无法选择第二个职业是什么。
- ❌ 关闭开关即清空多职业数据：违反「不静默删除」约定。
- ❌ 保留被合并职业的等级分配历史并给出一键还原：已由 D7 明确排除；相应地必须用「常驻说明 + 二次确认 + 明细预览 + 不提供快捷入口」来防误触。
- ❌ 分配阶段用模态硬阻断先决条件、挡住后续步骤：先决条件依赖第 5 步属性，此时尚未完成，硬阻断会让玩家卡死；正确做法是 warning + 校验期报 error。

这些不是「兼职新增的改动」，而是**当前实现里就存在的兼职阻塞点**，若不在本次一并处理，兼职必然出错：

1. **`ChoiceCheckpoint` 没有 `classId` 字段**（`types/rules.ts:250-291`）。职业自带检查点靠 id 前缀（如 `class-2024-fighter-skills-1`）区分，但类型层无法据此分组，时间线上「职业归属」不可见。需新增 `classId?`/`classLevel?` 字段。
2. **子职特性检查点 id 不带职业前缀**（`timeline.ts:136` `subclass-feature-${feature.id}`），且 `validate.ts:707`、`CharacterSheetStep.vue:312`、`dependency.ts:119` 都按 `subclass-feature-` 字面前缀匹配。兼职后无法按职业过滤/拆分，需改为职业限定 id（并保留旧 id 的兼容读取）。
3. **`uniqueGroup` 跨全部检查点去重**（`TimelineStep.vue:98-105`、`validate.ts:593-600`），而 `timeline.ts:74` 把 `kind === 'expertise'` 推断为全局组 `'expertise'`——两个职业都有专精检查点时会**互相锁死候选**。需改为「同职业内唯一」或按职业限定组名。
4. **用户可见文案已写死「多职业不在本轮」**：`CharacterSheetStep.vue:661`、`constants/update-notices.ts:166`。兼职上线时必须同步改写。
5. **起始装备只生成一份 `sourceKind: 'class'` 记录**（`starting-equipment.ts:107-146`），`StartingEquipmentSelection` 无职业字段；起始职业口径需要用 `sourceId` 显式绑定，不能靠 groupId 前缀推断。
| `views/.../hooks/useCharacterBuilderPage.ts:119-155` | 步骤门禁 `Boolean(draft.classId)` | 需按职业分配完成度 |
| `useCharacterBuilderPage.ts:368-437` | 等级调整与换职业 | 需支持按职业升降 |
| `SessionPanel.vue:177-186`、`218-219`、`353` | 单职业名与特性 | 需多职业 |
| `CharacterSheetStep.vue:120-127`、`306-307`、`460-478`、`592-598`、`633-634` | 单职业头部、能力、时间线、子职 | 需多职业分区 |
| `EquipmentStep.vue:38`、`224` | 单职业起始装备与灌注 | 需起始职业口径 |
| `SpellcastingStep.vue:57-64`、`245` | 单职业施法配置与法术位 | 需每职业一组 |
| `StartPanel.vue:62`、`102` | 单职业名 | 需多职业标签 |
| `features/character-export/build-export-data.ts:172-173`、`258`、`399-405` | 导出单职业 | 需多职业字段映射 |

## 8. 测试与验收

### 8.1 单元测试（`app/test/rules`）

- 兼职施法者法术位表：1—20 级全表逐一比对；`游侠4/术士3 → 4/3/2`；`圣武士6/魔契师1`；`战士3（奥法骑士）/法师5`；施法等级 0 的纯非施法兼职。
- 先决条件：满足、单项不满足、多项不满足、「或」条件（战士 力量13 或 敏捷13）、临时加值不计入（使用 `baseAbilities`）。
- HP：起始职业 1 级最大值只算一次；后续按所升职业骰面固定值；混合骰面（圣武士5/牧师5）；降级后重算。
- 生命骰池：同骰面合并、不同骰面分组、短休按骰面消耗。
- 熟练项：豁免只来自起始职业；兼职技能项与背景重复时的替换记录；2024 武僧/术士/法师只获得生命骰。
- 特性互斥：两个额外攻击来源不叠加、战士 11 级提升到 3 次；无甲防御与龙族体魄择一；引导神力共享次数池。
- 法术：每职业独立数量与候选池校验；归属职业的施法属性；升环施法使用兼职池。
- 戏法成长（决策 D4/D11/D12）：`火焰箭` 在角色总等级 1/4/5/10/11/16/17 的骰式为 1d10/1d10/2d10/2d10/3d10/3d10/4d10；`游侠4/术士3` 的术士戏法按**总等级 7** 而非术士等级 3 取值；未登记 `cantripScaling` 的戏法不产出成长值（返回空而非 0 或猜测值）。
- 等级分配（决策 D9）：不设职业数上限——`20 个职业各 1 级` 合法且总等级 20；`21 个职业` 不合法；总等级超过 20 时拒绝写入；每个职业最低 1 级；降到 0 走移除路径。
- 时间线与检查点：id 唯一性（多职业不撞 id）；子职按各职业等级解锁；降级后失效选择保留。

## 1. 背景与用户设计

### 1.1 用户反馈原文（4 条，2026-10-14）

1. 「调整等级是及时的，『调整职业与等级分配』的弹窗层级不稳定，我在调整等级后应该将这个弹窗在最上层，当用户点击确认调整后关闭后，直接调整等级。」
2. 「纯职业线：目前的这种滚轮设计还是不合理，我希望这里有一个需要点击展开的等级列，也就是直接的那种单元格形式的等级表格，可以直接选择调整到对应的等级。首先要的效果是，点击展开会展开这个表格，点击对应表格的单元格可调整至对应的等级，再弹出『调整职业与等级分配』，最后让用户直接点击确认分配。这是第一条线。第二条线就是通过『+』『-』的方式提升或者减少一级，提升或者减少一级后再弹出那个确认调整，如果点击后就调整至对应等级。」
3. 「兼职线：点击开启兼职后，上面纯职业线中的功能依旧保留，但是在下面职业列表中，我希望能加入一个展开功能，这个展开就是展开这个职业的等级列表，可以调整至对应的等级，我认为这样是极其合理的。」
4. 「取消兼职后对应的兼职并没有删除，这里的逻辑是总等级不变，将兼职的其他职业删除，将起始职业等级调整为当前的总等级。」

### 1.2 设计拆解（本需求的目标形态）

| 线 | 目标交互 |
| --- | --- |
| 层级与提交 | 任何等级／分配变更都先进入「调整职业与等级分配」确认弹窗，该弹窗**必须在最上层**；点「确认调整」后关闭弹窗并应用（= 用户反馈 1） |
| 纯职业线 | 等级处提供**点击展开的等级表格**（单元格形式，1—20），点单元格即选该等级 → 弹确认 → 确认即生效；同时保留 `＋/－` 每次 ±1 → 同样弹确认（= 用户反馈 2） |
| 兼职线 | 上半部分与纯职业线一致（总等级表格 + ±1）；下半部分每个职业行可**展开该职业的等级表格**，点单元格把该职业调整到对应等级（= 用户反馈 3） |
| 关闭兼职 | 关闭「启用兼职」时，**总等级不变**：删除其他职业，把起始职业等级调整为当前总等级（= 用户反馈 4） |

### 1.3 现状取证（代码阅读 + 一次性探针实测，探针已删除）

| 编号 | 现象 | 取证 | 结论 |
| --- | --- | --- | --- |

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 等级表格 | 点击展开后出现的单元格网格（纯职业线为 1—20；兼职的每个职业为其可选范围），点单元格即选该等级 |

| 确认弹窗 | 页面级 `pendingChange` 依赖影响弹窗，标题「调整职业与等级分配」（复用，不新建） |

| 合并到起始职业 | 关闭兼职时的收敛：删除其他职业，起始职业等级 = 当前总等级 |

## 3. 需求一：确认流程与弹窗层级（D37）

### 3.1 R1 统一「选值 → 确认 → 应用」

- 单元格选级、`＋/－` 步进、（第 1／3 步的）滑杆产生的等级变更**都**先形成待定变更，弹出确认弹窗，点「确认调整」后才写入草稿。
- 取消确认：不写入任何数据、不残留未生效的显示。

### 3.1.1 R1a 确认弹窗内可直接继续 `＋/－`（D43，Q6 结论）

- 连续调整不应反复开关弹窗：确认弹窗内提供**继续 `＋/－`** 的入口（至少 ±1，并显示当前目标等级）。
- 在弹窗内继续调整只更新**同一个待定变更**与摘要，不重新打开弹窗、不产生第二次确认；点一次「确认调整」即按最终值生效，点「取消」则整批不生效。
- 弹窗内的 `＋/－` 边界与主控件一致（1—20；兼职下限 = 职业数量）。
- 该入口只对「等级／职业分配」类变更出现，其它依赖影响确认（改职业、改种族、扩展书等）保持既有形态。

### 3.2 R2 确认弹窗必须在最上层且可交互

- 不论「调整等级」弹窗、还是控件内的二级弹窗（添加职业／选择起始职业／关闭兼职）是否仍然打开，确认弹窗都要盖在最上面并可点击。
- 实现方向（细节由《更新任务》定）：**推荐**给 `UiModal` 引入层级机制（内部自增 z-index 的弹窗栈，或显式 `layer` 入参），从根本上消除「后挂载者压住先挂载者」；备选是确认弹窗出现时自动关闭下层弹窗（会打断连续调整，不作为首选）。

### 3.3 R3 确认后的收束

- 确认弹窗关闭、等级按所选值生效；派生值、检查点引导（D28—D33）沿用既有规则。
- 「调整等级」弹窗本身**保留**（Q2 结论）：确认后弹窗仍在，内部显示新的等级，便于连续调整；用户可随时用弹窗自带入口关闭。

### 3.4 R4 不重复确认

- 重复点选当前值不产生变更、不弹确认。
- 单次操作只弹一次确认；不得出现「一次操作弹两次确认」或「确认后仍停留在待定态」。

## 4. 需求二：纯职业线——点击展开的等级表格（D38）

### 4.1 R5 入口与形态

- 等级卡默认**收起**，只显示当前等级与展开控件（如「展开等级列表 ▾」）；点击展开后才显示等级表格，再次点击收起。
- 表格为单元格网格（1—20），当前等级高亮且不可重复提交；单元格点击目标不小于 2.5rem，触屏可点。

### 4.2 R6 点选即进入确认流程

- 点单元格 → 选中该等级 → 进入 R1 的确认流程；确认后等级变为所选值。
- 未选职业（第 1 步）时表格表达的是**目标等级**（1—20）；单职业时是该职业等级（1—20）。
- 超出当前可选范围的单元格禁用（兼职时总等级下限 = 职业数量，见 §6；单职业 1—20，依赖 §8 的规则修正）。

### 4.3 R7 与滑杆的关系（Q1 结论：滑杆只在第 1／3 步保留）

- 角色卡「调整等级」弹窗内：**移除滑杆**，等级操作 = 「点击展开的等级表格 + `＋/－`」。
- 第 1／3 步内联：**保留滑杆**（大跨度勾选更快、且内联不存在弹窗层级问题），滑杆与 ±1 在那里同样走「确认后生效」的流程（D39 修订 D35）。
- 同一控件因此有两种形态，差异仅「是否渲染滑杆」，其余（展开表格、±1、边界、提交通道）完全共用，不得出现两套等级写入实现。

### 4.4 R8 可选增强（本批不做）

- 单元格可标注该等级是否带来需要补全的检查点（属性提升／专长、子职特性、战技等），帮助用户判断该选哪一级；本批不做，避免把时间线规则耦合进选级控件，后续可单独评估。

## 5. 需求三：`＋/－` 步进纳入确认流程（D39，并修订 D35）

- R9 保留 `＋/－`（LV 批次新增，纯职业／无职业／兼职都显示），但行为改为：**点按 → 弹出确认 → 确认后生效**。
- R10 边界不变：1 级不能再降、20 级不能再升、兼职下限 = 职业数量；到界按钮禁用且不产生事件。
- R11 兼职时 `＋/－` 仍作用于**总等级**（加级给列表最后一个职业、减级从末尾往前扣，不会移除职业），与表格选级同一口径。
- R12 **修订既有决策 D35**（「步进与滑杆同一条提交通道、单纯升级不弹确认」）：提交通道仍共用，但确认策略由「仅失效才确认」改为「始终确认」；第 1／3 步保留的滑杆同步改为始终确认，避免同一控件内出现两套策略。
- R13 确认次数由 R1a 消化（Q6 结论）：点 `＋/－` 会打开确认弹窗，但可以在弹窗内继续 `＋/－`，最后一次确认生效，不必反复开关弹窗。

## 6. 需求四：兼职线——逐职业展开等级表格（D40）

### 6.1 R14 上部保持纯职业线能力

- 开启兼职后，上部**保留**等级表格与 `＋/－`（此处作用于总等级），语义与 §4／§5 相同。

### 6.2 R15 职业行可展开该职业的等级表格

- 职业列表每一行增加展开控件；展开后显示该职业的可选等级单元格网格，当前等级高亮。
- 点单元格 → 选中该职业等级 → 进入 R1 的确认流程；确认后该职业等级变为所选值，总等级随之变化。
- 等级变更沿用既有 `class-allocation` 影响计算：失效选择标记、法术归档、新增检查点引导（D28—D33）全部保持。

### 6.3 R16 范围与既有入口并存

- 职业等级可选范围：兼职时为 1—19（`MAX_CLASS_LEVEL`）；**不含 0**（Q3 结论）——移除职业仍走 `－` 降到 0（破坏性操作，既有文案与二次确认不变），避免在表格里误点删除。
- 行内既有的 `－/＋`、「设为起始职业」、降到 0 移除的文案与确认策略（D7 防误触）保持。
- **单行展开**（Q5 结论）：同一时刻只展开一个职业的等级表格，点另一行时自动收起上一行。

## 7. 需求五：关闭兼职 = 合并到起始职业（D41）

### 7.1 R17 关闭兼职的语义

- 关闭「启用兼职」→ 一律走「合并到起始职业」确认：**总等级不变**；**删除其他职业**；**起始职业等级 = 当前总等级**。
- 确认弹窗需列出将被删除的职业与各自等级（现状弹窗已具备该明细，可复用并置顶）。

### 7.2 R18 确认是唯一写入点

- 不再「先写入 `enabled=false` 再询问」：取消时开关保持打开、数据完全不变（现状会在「保留兼职」路径上产生一次无谓写入与一次多余的依赖确认，见 P3）。
- 合并确认弹窗必须满足 R2（最上层），并且**不能因为下层「调整等级」弹窗关闭而消失**（现状 P3 的根因）。

### 7.3 R19 与 D20 的关系

- 「兼职关闭但草稿仍保留多个职业」的中间态（D20）**不再由关闭动作产生**；历史上已处于该状态的草稿仍保留只读提示与「重新启用」入口。
- 是否为历史保留态提供「一键合并」入口：本需求默认不新增（历史草稿仍可读、可重新启用），如后续需要再单独评估。

## 8. 需求六：规则层上限修正（D42，已确认纳入本轮）

为兑现 R17 的「总等级不变」与 R6 的单职业 1—20，需要按「是否兼职」区分职业等级上限：

- R20 `MAX_CLASS_LEVEL`（19）的适用条件收窄为**兼职（职业数 > 1）时的职业等级上限**；职业数 = 1 时，职业等级上限 = `MAX_CHARACTER_LEVEL`（20）。
- R21 合并到起始职业的等级上限用 20（当前 `Math.min(MAX_CLASS_LEVEL, total)` 会让总等级 20 掉到 19，见 P4）。
- R22 `validateMulticlassAllocation` 的「职业等级 1—19」错误按同一口径收窄：单职业 20 级不再报错（P5 探针 C）。
- R23 不改变：总等级上限 20、兼职下限 = 职业数量、单次写入的其它校验与错误码语义。

## 10. 验收标准

1. 从角色卡「调整等级」中做任何等级变更（单元格选级／±1）都会先弹出「调整职业与等级分配」确认弹窗，且该弹窗**位于最上层、可点击**（含「调整等级」弹窗仍打开的情况）。
2. 确认弹窗内可直接继续 `＋/－`：连续调整只更新同一个待定变更与摘要，不重新弹窗；点一次「确认调整」按最终值生效，点「取消」整批不生效。
3. 点「确认调整」后弹窗关闭、等级按所选值生效、**「调整等级」弹窗保留并显示新等级**；取消后数据不变、无残留显示；不会出现重复确认或一次操作两次弹窗。
4. 纯职业线：等级卡有展开控件；展开后出现 1—20 的单元格表格；点单元格可选中该等级并进入确认流程；当前等级高亮、重复点选当前值不弹确认。
5. 纯职业线：`＋/－` 每次 ±1，点按后弹确认，确认即生效；1 级／20 级到界禁用且不发事件。
6. 未选职业时表格与 ±1 作用于目标等级（1—20）；**角色卡弹窗内不再出现滑杆**，第 1／3 步内联仍保留滑杆且同样「确认后生效」。
7. 兼职线：上部总等级表格与 ±1 保留且口径与纯职业线一致（加级给最后一个职业、减级从末尾扣）。
8. 兼职线：每个职业行可展开该职业的等级表格（**单行展开**、**不含 0**），点单元格可把该职业调整到对应等级；总等级随之变化，失效选择／法术归档／新增检查点引导行为与既有 `class-allocation` 一致。
9. 关闭兼职：确认后其他职业被删除、起始职业等级 = 当前总等级（含总等级 20 的情况不再掉级）；取消后开关保持打开、数据不变；合并确认弹窗在最上层且不会因下层弹窗关闭而消失。
10. 规则层：单职业可通过控件把等级设为 20；带兼职状态的单职业 20 级不再被校验判为错误；兼职职业等级上限仍为 19。
11. `npx vue-tsc -b`、`npx vitest run`、`npm run build` 全部通过；受影响的既有用例按新语义改写并在《更新任务》中说明理由；版本号保持 1.13.0；未新增第三方依赖。

# PDF 导出字体统一需求

> 状态：已实施  
> 目标字体：Noto Sans SC Regular（无衬线中文字体，字重 Regular / 400）  
> 目标资产：`app/public/templates/fonts/noto-sans-sc-subset.ttf`  
> 适用范围：D&D 5e 2014 PDF 角色卡导出  
> 本文只统一程序动态写入 PDF 的字体，不修改 PDF 模板静态文字、字段布局、字号策略或导出内容。

## 1. 背景

用户希望 PDF 正文比原 Thin 字体更厚，以提高小字号屏幕阅读和打印清晰度，最终确认使用 Noto Sans SC Regular 作为项目 PDF 动态文字的统一字体规范。

经现状核验：

- 圈选文字属于程序写入 AcroForm 字段的动态内容，不是模板页面中的静态文字；
- 字体资产文件名保持 `noto-sans-sc-subset.ttf`，最终字体内部元数据为 `Noto Sans SC Regular`、`Regular` style、400 字重；
- `fillPdfTemplate()` 当前会嵌入该字体，并通过 `form.updateFieldAppearances(font)` 重建全部表单字段外观；
- 当前实现已经基本达到视觉目标，但测试尚未锁定字体家族和字重，后续资产替换可能造成无意回归。

## 2. 目标

1. 将 Noto Sans SC Regular 确立为 PDF 中所有程序动态写入文字的统一字体；
2. 中文、英文、数字和标点使用同一嵌入字体，避免阅读器字体回退造成外观不一致；
3. 保持无衬线字体的紧凑风格，并以 Regular 字重增强小字号长文本可读性；
4. 字体必须嵌入导出成品，使 PDF 在 Chrome、Edge 和独立阅读器中显示一致；
5. 通过自动化检查锁定字体身份，防止未来误换成宋体、常规黑体、系统字体或其他字重。

## 3. 范围

### 3.1 本期范围

- PDF 中所有由 `fillPdfTemplate()` 写入的文本字段，包括：
  - 角色身份、职业等级、种族、背景、阵营和经验；
  - 属性、调整值、豁免、技能、AC、先攻、速度、生命值和生命骰；
  - 攻击、装备、钱币、熟练项与语言；
  - 特性与专长、人物背景和宝物；
  - 施法属性、法术攻击、法术豁免 DC、法术名称和法术位相关文字。
- 动态写入内容中的中文、拉丁字母、数字、常用标点及项目规则数据实际使用字符；
- 字体资产元数据、字符覆盖和导出成品嵌入状态的回归验证。

### 3.2 非目标

- 不修改模板页面已有的标题、标签、边框、Logo 或装饰文字字体；
- 不要求特性名称、职业名称或其他字段局部加粗；
- 不增加 Bold、Light 等第二套动态字体；
- 不统一所有字段字号；现有 7pt、8pt、10pt、12pt、13pt 等字号及换行、截断策略保持不变；
- 不修改字段坐标、尺寸、多行属性、页序、映射版本或导出数据；
- 不修改 XLSX、JSON 导出以及网页 UI 字体。

## 4. 功能需求

### R1 字体身份

1. 运行时字体必须为 Noto Sans SC Regular，PostScript 名称应为 `NotoSansSC-Regular`；
2. 字体视觉分类为无衬线中文字体，OS/2 字重必须为 400，不得以文件名相同但内部字体不同的资产替换；
3. 字体文件继续使用项目内静态资产，不依赖用户操作系统安装字体或在线字体服务；
4. 字体授权信息和现有子集来源必须保留，任何替换资产需重新核验授权。

### R2 应用规则

1. `fillPdfTemplate()` 必须只嵌入一次统一动态字体，并用该字体更新所有文本字段的 appearance stream；
2. 所有动态字段在扁平化前必须完成字体外观更新，成品不得依赖 `/NeedAppearances` 或阅读器自行生成外观；
3. 导出成品扁平化后，动态文字必须保持可见，不得出现乱码、方框、空白或意外字体回退；
4. 现有字段字号、实际字宽换行、禁则标点、容量计算和省略提示继续基于该字体度量；
5. 字体字符子集必须覆盖全部可导出规则数据、玩家常用身份资料字符及现有导出标点；缺字应在发布前被自动化检查发现，不在运行时静默回退。

### R3 视觉一致性

1. “特性与专长”等长文本区域应使用比原 Thin 更厚、更清晰的 Regular 正文效果；
2. 相同字号下，中英文混排的字宽、行距和换行结果不得因字体规范固化而变化；
3. 单行数字字段与多行正文均使用同一字体家族和字重；
4. 本期不通过伪粗体、描边或重复绘制增强特性名称。

### R4 兼容性与体积

1. PDF 仍为三页，字段映射版本保持 `CHARACTER_SHEET_PDF_MAPPING_VERSION = 6`；
2. 战士、法师和黄金样例的字段内容、复选框、页序、换行、诊断与扁平化行为不得回归；
3. 运行时字体与成品 PDF 体积不得因规范固化显著增加；成品继续满足现有 ≤ 5MiB 门槛；
4. 字体规范不得影响已完成瘦身的运行时模板。

## 5. 实施要求

1. 保留现有 `PDF_FONT_URL` 和字体资产路径；若当前实现已满足 R2，不为形式统一重写导出逻辑；
2. 增加字体元数据检查，至少验证字体家族、PostScript 名称和 Thin 字重；
3. 增加字符覆盖检查，字符集合应从 PDF 导出固定文案、规则数据和测试样例汇总，不维护与真实输出脱节的手工小清单；
4. 增加成品字体检查，确认典型导出 PDF 中动态文字使用嵌入字体且没有系统字体依赖；
5. 如测试发现当前字体子集缺少实际可导出字符，应更新字体子集资产并重新执行 PDF 体积、排版与渲染验收；
6. 若只增加测试和文档而生产导出逻辑无需修改，字段映射版本和业务版本无需因字体规范本身升级。

## 6. 测试与验收

### 6.1 自动化验收

1. 解析 `noto-sans-sc-subset.ttf`，确认：
   - family：`Noto Sans SC`；
   - full name：`Noto Sans SC Regular`；
   - PostScript name：`NotoSansSC-Regular`；
   - OS/2 weight：400；
2. 汇总典型中英文、数字、标点和导出数据字符，确认字体 cmap 全部覆盖；
3. 分别生成战士、法师和黄金样例 PDF，确认无新增 error/warning；
4. 重新加载成品，确认三页、无剩余 AcroForm 字段、无 Widget，且成品 ≤ 5MiB；
5. 对长特性、长背景、装备和法术样例执行既有换行与容量回归测试；
6. 执行 `pnpm test:run`、类型检查和 `pnpm build`。

### 6.2 人工验收

1. 在 Chrome/Edge 内置阅读器及一个独立 PDF 阅读器中打开战士和法师成品；
2. 检查长文本正文是否达到用户确认的 Regular 加厚效果；
3. 检查中文、英文、数字、冒号、括号、乘号和省略号无缺字或字体跳变；
4. 检查打印预览中文字粗细、换行和清晰度正常；
5. 与本需求确认时的参考截图进行视觉对比，不要求特性名称加粗。

## 7. 发布门槛

1. R1—R4 全部满足；
2. 自动化验收全部通过；
3. 用户完成人工视觉验收；
4. 未改变 PDF 模板字段结构、映射版本和现有瘦身体积门槛；
5. 已复核前端依赖拓扑；只有新增、删除、移动模块或改变依赖关系时才更新架构拓扑。

## 8. 已确认结论

1. 统一字体采用用户最终确认的 Noto Sans SC Regular；
2. 适用于所有程序动态写入 PDF 的文字，而不仅是“特性与专长”区域；
3. 模板静态文字保持原样；
4. 本期不对特性名称或其他局部文字加粗；
5. 现有字号、布局、换行、字段映射和导出内容保持不变。

## 9. 实施结果

1. 字体家族、完整名称、PostScript 名称和子族元数据已由自动化测试锁定；
2. 字体子集生成脚本通过 fonttools 固定使用 `wght=400`，同步更新名称表与 OS/2 字重，并从当前规则、PDF 固定文案、测试样例和常用身份资料自动汇总字符；
3. 实施前发现 80 个当前规则字符缺失，扩充后覆盖语料共 2,040 个字符且无缺字；
4. 重新生成的字体为 Noto Sans SC Regular，体积由 2,030,864 字节降至 1,167,808 字节；
5. 战士、法师和黄金样例成品均验证字体已嵌入、无 `/NeedAppearances`、无 Widget 且不超过 5MiB；
6. `export-pdf.ts`、字体 URL、字段映射版本、字号、布局和模板静态字体均未修改。

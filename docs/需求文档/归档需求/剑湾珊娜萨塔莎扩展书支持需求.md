# 剑湾、珊娜萨与塔莎扩展书支持需求

## 1. 背景与目标

当前项目以 D&D 5e 2014 为唯一运行时规则集，已经零散登记《剑湾冒险者指南》（SCAG）、《珊娜萨的万事指南》（XGtE）与《塔莎的万事坩埚》（TCoE）的部分来源、子职、背景、法术和魔法物品，但“已经登记来源”不等于“整本扩展书已经可用于完整车卡”。

本需求作为一次大版本功能更新，目标是在不引入 2024 规则、不开放多职业的前提下，把三本扩展书中与玩家创建和维护角色直接相关的内容整理为完整、可解释、可保存和可导出的 2014 玩家选项。

本期目标结果：

1. 以规则书来源为维度完成现状盘点、去重和版本核验。
2. 补齐三本书中本期纳入的种族/种族变体、背景、职业、子职、专长、法术、职业选项与角色可持有物品。
3. 让纳入范围内的内容能够在车卡流程中正确出现、选择、校验、失效、恢复和导出。
4. 明确区分“仅来源索引”“可以选择但规则尚未完整接入”“已完整进入当前车卡模型”三种完成度。
5. 保持旧草稿、JSON 导入导出及已有稳定 ID 的兼容性。

本需求只记录需求与实施边界，不在本轮文档编写阶段修改业务代码。

## 2. 已确认决策

| 决策点 | 本期结论 |
|---|---|
| 规则集 | 仅 `5e-2014`，不得混入 2024 规则 |
| 角色结构 | 继续支持 1—20 级单职业，不开放多职业 |
| 更新级别 | 作为独立分支承载的大版本功能更新 |
| 内容范围 | 只纳入与玩家车卡直接相关的规则选项；不收录整书正文与世界观章节 |
| TCoE 自定义起源 | **本期不支持**，记录为后续 TODO |
| TCoE 可选职业特性 | **本期不支持全部可选职业特性**，记录为后续 TODO |
| Artificer | 本需求按本期纳入处理，包括基础职业、4 个子职、施法与灌注；若后续产品决策调整，应单独修改本需求范围 |
| 商业内容 | 只保存必要机械数据、稳定元数据、原创中文摘要与来源索引，不复制商业正文 |
| 扩展书开关 | 第 2 步改为角色级来源选择；新草稿默认全选当前已登记的 2014 玩家来源，核心规则始终启用 |
| 重印内容 | 同一规则内容只保留一个稳定实体；采用项目选定的有效版本，并记录首发来源与采用版本来源，不生成重复可选项 |

## 3. 当前实现基线

### 3.1 通用基线

- `app/src/rules/repository.ts` 已注册 `scag-2015-index`、`xgte-2017-index`、`tcoe-2020-index`。
- `sourceIds` 已存在于职业、子职、特性、种族、背景、专长、法术和装备等主要规则类型中。
- 当前 UI 主要把来源作为条目说明展示，尚未形成完整的“按书盘点与完成度”能力。
- 当前 12 个基础职业不包含 Artificer。
- 当前专长目录以 2014《玩家手册》42 项为主，扩展书专长尚未形成完整可选目录。
- 当前子职顶层可以标记为 `implemented`，但其下大量 `SubclassFeature` 仍为 `index-only`；因此顶层状态不能直接证明该子职已经完整接入选择、资源、派生和导出。

### 3.2 分书现状

| 来源 | 已有内容 | 主要缺口 |
|---|---|---|
| SCAG | 来源登记；7 个玩家子职；12 个背景；对应子职等级特性摘要 | 种族/血统变体盘点与接入；部分职业附加选项；背景自选技能/工具机制；子职特性选择、前置与派生完整性；重印版本归属 |
| XGtE | 来源登记；30 个玩家子职；95 个来源法术；常见魔法物品；子职特性摘要 | 种族专长；子职内部选择与资源；法术职业列表和勘误复核；魔法物品完整性；扩展内容的完成状态收口 |
| TCoE | 来源登记；26 个玩家子职；当前数据中直接标记 TCoE 来源的法术；2 个超魔选项；部分魔法刺青 | Artificer 与 4 子职；灌注；专长；法术/物品盘点；子职选择与派生；重印规则处理；自定义起源和可选职业特性留作 TODO |

上述数量只描述当前代码登记情况，不作为最终官方内容数量。正式实施前必须根据采用版本和勘误重新生成逐条清单。

## 4. 范围定义

### 4.1 本期纳入

纳入以下与角色创建、升级、角色卡查看或物品管理直接相关的内容：

1. **种族与变体**：SCAG 中具有独立机械效果的 2014 种族、亚种、血统或正式变体；纯叙事地域差异只作为说明或 heritage，不伪造成机械子种族。
2. **背景**：SCAG 12 个背景的现有数据复核，以及自选技能、工具、语言、变体说明和初始装备的可操作化。
3. **职业**：TCoE Artificer 基础职业、1—20 级单职业成长、施法、职业资源、灌注与 4 个子职。
4. **子职**：SCAG、XGtE、TCoE 纳入范围内的全部玩家子职，以及每个子职的等级特性、必选项、互斥项、资源和恢复方式。
5. **专长**：XGtE 与 TCoE 的玩家专长；必须登记前置条件、属性提升、重复选择规则和当前项目可处理的派生影响。
6. **法术**：三本书中新发布或有效重印的玩家法术；补齐中英文名、环级、职业归属、来源、原创摘要和成长信息。
7. **职业内部选项**：不属于“整套可选职业特性”的扩展子职选择、灌注选择及 Artificer 自身必需的职业选择。
8. **角色物品**：与玩家角色持有、装备和导出直接相关的 XGtE/TCoE 魔法物品；本期不实现 DM 发放概率、宝藏表或制作系统。
9. **来源体验**：列表与详情中能够识别来源；同名或重印内容能解释采用哪个版本。

### 4.2 明确不纳入

1. TCoE “自定义起源”（Customizing Your Origin）的属性、语言、熟练替换规则。
2. TCoE 为既有 12 职业提供的整套 Optional Class Features，包括对基础职业时间线的系统性替换或增强。
3. 2024 规则、2024 职业/子职/专长/法术版本及任何 2014→2024 自动转换。
4. 多职业与多职业前置条件。
5. SCAG 世界观、地域、宗教和阵营正文。
6. XGtE/TCoE 的 DM 工具、陷阱、停工期活动、随机遭遇、解谜、团队赞助者、伙伴职业等非标准玩家车卡内容。
7. 商业规则书全文、长段原文、完整表格复刻或未经核验的自动计算。
8. 战役级房规、DM 授权与扩展书授权管理（角色级内容可用开关属于本期）。

## 5. 功能需求

### R1 来源清单与重印规则

1. 为 SCAG、XGtE、TCoE 分别建立逐条玩家内容清单，至少包含：内容域、稳定 ID、中英文名、首发来源、采用版本来源、当前状态、目标状态和核验依据。
2. 同一内容被后续书重印时不得在选择列表中生成两个角色选项。
3. 若重印版本改变机械效果，必须明确项目采用的版本；已有草稿 ID 尽量保持不变，通过版本元数据解释变化。
4. 勘误会影响选择、数值或资源时，采用已确认的 2014 最新勘误，并增加回归测试。
5. 任何无法确认的商业效果保持 `index-only`，不得因“扩展书已支持”而自动升级为 `implemented`。

### R2 完成状态语义

扩展内容至少按以下三层评估：

| 层级 | 定义 | UI 与校验要求 |
|---|---|---|
| 来源索引 | 只有稳定 ID、名称、来源和原创摘要 | 可以浏览，不得声称可完整车卡；不能影响派生 |
| 可选择 | 选择入口、数量、前置与互斥已实现，但仍有当前模型无法自动化的叙事效果 | 可以保存；必须明确未自动计算的效果及 DM 提示 |
| 完整接入 | 所有车卡必选项、资源、法术池和当前模型支持的派生效果均已接入 | 可通过完整性校验，可展示来源，可进入 JSON/PDF/XLSX 导出 |

顶层条目标记为 `implemented` 前，必须检查其子特性和关联选项；不得只因子职能出现在下拉列表中就判定完成。

### R3 SCAG 玩家选项

1. 复核并补齐 7 个玩家子职的等级特性、选择项、职业前置、资源与派生效果。
2. 复核 SCAG 12 个背景，补齐当前仅写在 `description` 中但玩家无法实际选择的技能、工具和语言选项。
3. 盘点 SCAG 种族章节中的机械变体，并与当前 `origins-2014.ts` 已有种族和其他书重印条目去重。
4. 补齐 SCAG 对既有职业/子职提供的附加选择，例如会影响图腾、战斗风格或其他既有检查点候选池的选项。
5. SCAG 首发、后由 XGtE/TCoE 重印的子职或法术，按 R1 记录来源与采用版本，不创建重复项。

### R4 XGtE 玩家选项

1. 复核 30 个玩家子职，使所有必选子特性都能在正确等级进入时间线。
2. 补齐种族专长目录及其种族、亚种、体型或能力值前置条件。
3. 复核现有 95 个来源法术的职业归属、环级、勘误、成长摘要和准备/已知/法术书模式兼容。
4. 补齐子职内部候选池，例如奥术射击、风暴光环、图腾或其他单选/多选能力；跨等级不可重复的选项必须校验。
5. 复核 XGtE 常见魔法物品的名称、稀有度、同调、装备类别与可自动计算字段。

### R5 TCoE 既有职业与子职内容

1. 复核 26 个玩家子职及其等级特性、子职法术、额外已知法术、资源和内部选择。
2. 补齐 TCoE 专长目录，并接入现有“属性提升或专长”检查点。
3. 复核 TCoE 法术与 SCAG 重印法术，确保候选池只出现一个有效版本。
4. 复核魔法刺青及其他本期纳入物品；不能确认的效果只展示，不参与自动派生。
5. 已存在的 TCoE 超魔条目可以保留，但本期不以此为入口扩展整套 Optional Class Features；其选择、消耗与前置仍必须符合现有术士超魔模型。

### R6 Artificer

Artificer 是本期唯一新增的基础职业，必须按独立纵向切片实现：

1. 新增稳定职业 ID、生命骰、豁免、熟练、初始装备和 1—20 级时间线；职业页不再使用推荐标签或评分。
2. 实现 Artificer 施法模式、施法属性、戏法、准备法术、法术位和职业法术列表；不得把其法术位规则硬编码到组件。
3. 实现 Magical Tinkering、Infuse Item 等会产生玩家选择或角色资源的基础职业特性；只读叙事特性仍需出现在能力列表。
4. 建立灌注目录、等级前置、已知数量、同时生效数量、重复选择和物品适用条件；无法自动处理的物品目标规则应给出中文提示。
5. 实现 Alchemist、Armorer、Artillerist、Battle Smith 四个子职及各自必选项、额外法术和资源。
6. Artificer 加入职业列表、成长速览、时间线、派生计算、角色卡、搜索、来源展示和全部导出模型；职业偏好推荐系统在本版移除。
7. 本期只处理单职业 Artificer，不提前实现多职业法术位与多职业前置。

### R7 专长、前置与派生

1. 扩展专长沿用稳定版本化 ID，不使用中文名作为关联键。
2. 前置条件必须结构化；只写在摘要中不能视为已经完成校验。
3. 半专长的属性 `+1` 必须作为原始选择保存，参与最终属性上限校验，并在来源链和导出中显示。
4. 可重复专长、只能选择一次的专长和互斥选项必须分别建模。
5. 当前派生模型无法表达的战斗情境效果允许只读展示，但不得伪造常驻数值。

### R8 法术与法术池

1. 每个扩展法术必须有稳定 ID、中英文名、环级、职业归属、来源和原创中文摘要。
2. 法术候选池必须同时适配已知施法、准备施法、法术书、契约施法、子职施法和 Artificer。
3. 子职额外法术必须区分“加入职业列表”“始终准备”“额外已知”“不计入已知上限”等不同语义。
4. 调整职业、子职或等级时，旧法术选择应保留并标记失效，不静默删除。
5. SCAG 法术采用后续重印版本时，保留首发来源信息，但只展示一个候选项。

### R9 UI、来源与可解释性

1. 职业、子职、种族、背景、专长、法术和物品详情应显示来源简称和完整书名。
2. 条目存在重印时，详情应能说明“首发于 / 当前采用”。
3. `index-only`、需要 DM 确认和已完整接入必须有不同的中文提示，且不能只依赖颜色。
4. 新增大量选项后，现有搜索和列表性能不能明显退化；长列表的页面级来源筛选只影响当前视图，第 2 步来源开关决定内容可用性。
5. 所有新增选择在手机宽度下保持可读、可触控，并沿用现有展开卡片和时间线交互。

### R10 草稿、迁移与导出

1. 不修改已有稳定 ID；确需修正 ID 时提供导入迁移映射。
2. 旧草稿缺少新字段时必须安全加载，不能因扩展书升级导致已有角色不可编辑。
3. 修改职业、子职、种族或等级后，受影响的扩展选项沿用“保留并标记失效”的项目规则。
4. JSON 导入导出必须保留新增原始选择，不保存可重新计算的派生结果。
5. PDF/XLSX/页面角色卡必须共用 `buildCharacterExportModel` 的结果；Artificer 灌注、扩展专长、子职选择和扩展法术需要进入适当导出区块。
6. 导出容量不足时沿用诊断机制，不允许无提示截断关键必选信息。

### R11 文档与版权

1. 规则行为变化必须同步更新 `docs/rules.md`。
2. 职业/子职变化同步更新 `docs/dnd-classes.md` 和目标职业资料；Artificer 需新增职业与 4 个子职资料。
3. 种族、背景、专长、法术和装备变化分别同步对应专项索引与资料文件。
4. 新增、移动模块或改变依赖方向时同步更新 `docs/frontend-architecture.md`。
5. 商业内容使用原创中文转述，只记录实现所需机械数据和来源索引。

## 7. 验收标准

### 7.1 数据完整性

1. 三本书的本期玩家内容均存在逐条清单，清单与代码注册表数量一致。
2. 每条规则均显式标记 `ruleset: '5e-2014'` 与有效来源。
3. 无重复稳定 ID、无重复重印候选、无悬空 `sourceIds`、无悬空选项或法术引用。
4. `implemented` 条目的全部必选子项都存在并可验证；未完成条目保持明确的非完整状态。

### 7.2 规则行为

1. 每个新增职业/子职可在正确等级选择，必选项数量、互斥、跨等级去重和前置条件正确。
2. Artificer 1—20 级施法、灌注数量、子职时间线和角色资源正确。
3. 扩展专长的前置、属性提升和重复选择规则正确。
4. 扩展法术在正确职业、环级和施法模式下出现，重印法术不重复。
5. 修改上游选择后，失效项被保留并给出中文修正原因。
6. 所有进入自动计算的效果都返回可展示的来源说明。

### 7.3 兼容与导出

1. 既有 2014 草稿无需迁移即可继续读取和编辑。
2. 新草稿 JSON 可导出、重新导入并保持全部原始选择。
3. 页面、PDF 与 XLSX 的职业、能力、专长、物品和法术结果一致。
4. 旧 2024 草稿继续只读隔离，不受本需求影响。

### 7.4 工程验证

1. TypeScript 类型检查通过。
2. 全部自动化测试通过，并包含新增规则的数据完整性、合法输入、边界、缺少必选项、互斥和回归测试。
3. 生产构建通过。
4. 组件测试覆盖移动端宽度下的来源提示、长列表搜索、展开详情和时间线选择行为。
5. 发布收口时已复核前端依赖拓扑，并按实际变化更新或明确无需更新。

## 8. 风险与控制

| 风险 | 控制措施 |
|---|---|
| 商业内容体量大，容易把索引误当完整实现 | 使用逐条内容矩阵和三层完成状态；未核验效果不自动计算 |
| 重印版本产生重复或规则冲突 | 单稳定实体 + 首发来源/采用来源；勘误回归测试 |
| Artificer 引入新的职业资源和物品关系 | 独立纵向切片；先建模型和测试，再接 UI/导出 |
| 扩展专长改变属性与前置校验 | 结构化前置与半专长选择；不把效果藏在摘要中 |
| 选项数量增长导致移动端列表难用 | 复用搜索、按需增加来源筛选、组件级移动宽度测试 |
| 旧草稿因新增字段或规则修正失效 | 保持稳定 ID、字段默认值和显式迁移；旧选择不静默删除 |
| 本期边界向 TCoE 可选规则失控扩张 | 自定义起源与全部可选职业特性明确列为 TODO，不在本期顺手实现 |

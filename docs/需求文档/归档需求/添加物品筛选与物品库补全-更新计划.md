## 批次 5：弹窗布局与按钮式筛选（待实施）

### 5.1 目标与范围

覆盖 R16—R18：

- 弹窗标题、搜索框、筛选按钮行与展开的条件面板、底部数量与添加按钮全部固定，只有物品结果列表区域滚动。
- 筛选改为按钮展开式：固定顺序 `来源 → 同调 → 类别 → 稀有度`，同屏只展开一组，再次点击收起，切换面板保留已选条件。
- 每组支持“全选/取消全选”与确认；按钮显示该组限制状态或已选数量。
- 每次重新打开弹窗四组恢复默认全选；打开期间任何操作不清除已选条件。

### 5.2 已核验现状

- `UiScrollModal` 已实现“header/footer 固定、body 滚动”；当前 `AddItemModal` 的 body 内由 `ListShell`（`searchable`）同时容纳搜索框、筛选面板与物品列表，三者在同一滚动区域。
- 筛选状态为 `filtersExpanded` 单开关 + 四组 `selected*` ref；打开弹窗时 watch 重置为全选。
- `filterEquipmentCatalog` 纯函数与四组多选语义（组内或、组间且、空组为空）已完成并有测试，**交互改造不得改变其语义**。
- `ListShell` 是通用组件（其他页面共用），不得改变其通用行为；布局固定通过弹窗内部结构调整实现。

### 5.3 关键实施细节

1. **布局固定**：将搜索框与筛选区移出滚动容器——弹窗结构调整为“固定头部（标题/搜索/筛选按钮行/展开面板）+ 固定底部（数量/添加）+ 独立滚动的结果列表”。优先复用 `ListShell` 现有插槽；若插槽不足以表达固定布局，允许在弹窗内自组织列表滚动容器，不修改 `ListShell` 通用实现。
2. **按钮展开状态**：`filtersExpanded: boolean` 改为 `activeFilterPanel: 'source' | 'attunement' | 'category' | 'rarity' | null`；点击当前展开按钮置回 `null`，点击其他按钮切换，切走不重置对应 `selected*`。
3. **按钮限制状态**：某组已选数量小于全量选项数即为“已限制”，按钮显示已选数量（如“来源 3/4”）或限制标记；全选状态下按钮无标记。
4. **来源选项**：继续按 `props.enabledSourceIds` 过滤（core 来源始终启用），生成时机与现有一致。
5. **重置语义**：沿用打开弹窗时重置为全选；面板展开状态在每次打开时可恢复为默认收起（具体默认状态以交互验收为准）。
6. **无障碍**：按钮行使用语义化按钮与 `aria-expanded`/`aria-controls`；展开面板继续使用 `fieldset`/`legend`；点击目标 ≥ 44px。

## 批次 6：物品目录延迟加载与缓存（待实施 · 方案 A）

### 6.1 目标与范围

覆盖 R19—R22。核心目标：主界面首次进入不再请求或解析物品 Markdown 目录；第一次点击“添加物品”才动态加载目录分块，并配合内存 Promise 缓存、浏览器 HTTP 缓存与失败重试；现有角色物品显示、校验、属性派生、导出与来源限制行为不回归。

### 6.2 已核验现状（数据与链路）

- 加载链路：`magic-items-dmg-catalog-2014.ts` 以 `?raw` 静态导入 15 份 DMG 目录；`magic-items-expansions-2014.ts` 以 `?raw` 静态导入 2 份扩展目录；二者经 `rules/repository.ts` 的 `mergeDmgCatalog` + `mergeOfficialExpansionItems` 装配进 `rulesRepository.equipment`，进入默认车卡主界面即参与加载与运行时解析。
- 数据形态：DMG 目录表列为 `| 中文名 | 英文名 | 稀有度 | 类型 | 效果摘要（原创转述） | 状态 |`；扩展目录表列为 `| 中文名 | 英文名 | 元数据 | 来源 |`。解析逻辑（`parseDocument`/`parse`、`stableId`、`rarity`、`magicCategory`、同调映射）将随脚本迁移到构建期，运行时不再解析 Markdown。
- 同步消费方（必须保持可用）：`derive.ts`、`validate.ts`、`starting-equipment.ts`、`build-export-data.ts`、`CharacterSheetStep.vue`（只消费 `name`/`damageDice`/`damageType`/`equippable` 等轻量字段，不使用 description）、`AddItemModal.vue`。
- 草稿兼容：目录条目（`dmg-2014-index`、ERftLW/EGtW 来源）允许加入物品栏，草稿中已保存的 `itemId` 可能来自目录部分，懒加载后角色卡、校验、导出仍必须能解析这些 ID。
- 缓存前提：`app/nginx.conf` 已对带哈希 `/assets/` 配置 `public, max-age=31536000, immutable`；动态 import 分块天然带内容哈希，新版本自动换新 URL。
- 构建链：`npm run build` = `vue-tsc -b && vite-ssg build`；SSG 预渲染在 Node 端执行 repository 初始化，当前也会承担目录解析成本。

### 6.3 关键实施细节

1. **构建期生成脚本 `app/scripts/build-item-catalog.mjs`（新增）**：
   - 输入：`docs/equipment/5e-2014/magic-items/*.md`（15 份）+ `docs/equipment/5e-2014/expansions/*.md`（2 份）。
   - 输出两份类型化 TS（纳入 `vue-tsc` 校验）：
     - `src/rules/data/generated/magic-items-index-2014.ts`：**最小静态索引**——全部条目（静态三份 + 目录部分）的轻量投影：`id`、`name`、`englishName`、`ruleset`、`category`、`equippable`、`rarity`、`magicItemCategory`、`attunement`、`attunementCondition`、`sourceIds`、`status` 及派生必需字段（`damageDice` 等，以消费方实际使用为准，实施时核对 `build-export-data.ts` 字段）。**不含 description**（角色卡与派生均不消费，已核验）。
     - `src/rules/data/generated/magic-items-catalog-2014.ts`：**完整目录分块**——目录部分完整 `EquipmentRule`（含 description），仅供弹窗浏览。
   - 生成产物提交进仓库（保证类型检查与测试可用）；md 仍为审计与维护源。
2. **仓库装配改造（`rules/repository.ts`）**：
   - `rulesRepository.equipment` = 静态三份（`equipment-2014`、`magic-items-2014`、`magic-items-xgte-tcoe-2014`）+ 目录轻量投影合并装配，**保持同步 API 与既有签名不变**，消费方零改动。
   - `getEquipment` 查合并后的最小索引；`dmgAttunementByEnglishName` 等解析表随解析逻辑移入生成脚本，运行时不再保留 Markdown 解析代码。
3. **目录加载器 `src/rules/item-catalog-loader.ts`（新增）**：
   - 模块级 `Promise` 缓存：同一页面会话内只 `import()` 一次，失败时清缓存供重试。
   - 导出 `loadItemCatalog()`：成功返回完整目录条目；失败抛错由调用方展示重试。
   - 位置落在 `src/rules` 而非 `services`：services 静态依赖 rules 属于既有越权点（见 frontend-architecture.md §8.9），按需获取本地规则分块是规则数据层的自然职责，不违反 rules 的框架无关约束。
4. **弹窗接入（`AddItemModal.vue`）**：
   - 打开弹窗时触发 `loadItemCatalog()`，展示加载中/失败可重试三态；加载失败不阻塞搜索框、筛选按钮与自定义物品入口。
   - 列表数据 = 静态索引 + 动态目录合并后经 `filterEquipmentCatalog` 筛选取用。
   - `sourceOptions` 依赖 `equipment.some(...)`：最小索引已含 `sourceIds`，可在静态数据上计算，不受目录加载时机影响。
   - 弹窗 `selectedItem`/`varies` 校验等逻辑沿用最小索引，目录加载后补全 description 展示。
5. **双源一致性**：
   - 数据完整性测试断言生成产物与 md 对照无漂移（条目数、ID 集合、关键字段）；改 md 后必须重跑生成脚本。
   - 沿用 `sync-dmg-catalog-status.mjs`、`sync-expansion-item-indexes.mjs` 的维护方式，新增脚本与既有审计脚本并存。
6. **构建链接入**：`package.json` 增加 `generate:items` 脚本并在 `build` 前置执行（`prebuild` 或 build 命令串联），保证构建前产物最新。
7. **SSG 与缓存验证**：生产构建后主分块不再包含目录数据与解析逻辑；目录分块独立、带哈希，命中 nginx `immutable` 缓存。

## 后续来源批次准入条件

每一本 ERftLW、EGtW 或其他扩展来源只有同时满足以下条件才能标记完成：

1. 中英文名、稳定 ID、稀有度、九类目录类别、同调和来源已经核验。
2. 重印内容合并到原实体的 `sourceIds`，不创建同义重复条目。
3. 效果说明是项目原创摘要，不复制商业正文或第三方内容。
4. 数据完整性测试、筛选测试、全量测试和生产构建均通过。

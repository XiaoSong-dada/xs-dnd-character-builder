# 种族特性展示需求

> 本需求文档由用户口头需求整理而成，**本次交付仅为需求理解与现状核验，未修改任何代码**。
>
> **决策状态（2026-09-02）：第 8 节决策点已全部确认，本文件为定稿**；实施计划见《种族特性展示-更新计划.md》。
>
> **实施状态（2026-09-02）：已按计划完成并发布 v1.1.8**——race-features-2014.ts（240 条）与 background-features-2014.ts（44 条）落地，角色卡与跑团助手能力页签分组展示，类型检查、相关测试（新增 12 项）与生产构建通过。

## 1. 背景与目标

用户需求：项目中每个种族（含子种族）都有对应的特性（如矮人的黑暗视觉、矮人韧性、矮人战斗训练），但这些特性**无法显示在角色卡「能力」列表下**，只能靠描述文本查看，不便于跑团时查阅。需要补充：**让种族特性像职业特性、子职特性一样，在能力列表（角色卡「能力」页签）中逐条展示**。

经用户确认，范围扩展为：**种族特性 + 子种族特性 + 背景特性**一并纳入能力列表展示（分组展示）。

目标产物：

- 现状核验（数据层、展示层、导出层、文档资料层）。
- 定稿需求与实现边界，为实施提供输入（本次不实施）。

## 2. 现状核验（已完成）

### 2.1 数据层：种族/背景特性没有结构化注册表

- 种族数据：`app/src/rules/data/origins-2014.ts`（`races2014`，34 个基础种族 + 27 个子种族 = 61 个条目，含 DM-only）。
- 背景数据：同文件 `backgrounds2014`，**40 条**（含变体），每条有 `featureName`（背景特性中文名，如 信仰庇护/假身份/犯罪关系），特性描述在 `description` 文本中。
- `RaceRule` / `BackgroundRule` 类型（`app/src/types/rules.ts`）**没有 `features` 字段**：种族特性只存在于 `description` 原创中文描述文本中，无法逐条展示、无法按等级过滤、无法复用职业特性的展示组件。
- 对比：职业特性（`class-features-2014.ts`，158 条）与子职特性（`subclass-features-2014.ts`，588 条）均为结构化条目（`id / name / englishName / level / summary / description / kind / status / sourceIds`），由 `getClassFeatures2014` / `getSubclassFeatures2014` 挂载到职业/子职规则上。

### 2.2 文档资料层：docs 已按特性拆分（实施来源）

- `docs/species/5e-2014/`：61 个 Markdown（34 个种族主文件 + 27 个子种族文件），每个文件含「快速索引 + 特性详解」，**已定义特性 ID、等级、摘要与校验说明**（命名 `race-2014-<种族>-<特性>`，如 `race-2014-dwarf-darkvision`）。
- 种族特性规模：**约 240 条**（232 条 1 级、6 条 3 级、2 条 5 级；3/5 级特性如 天裔 光耀之魂/光耀吞噬/死灵裹尸、吉斯 灵能法术等）。其中含 `race-2014-*-ability-score-increase` 属性提升条目（已确认纳入展示）。
- `docs/backgrounds/5e-2014/`：35 个目录，每个背景文档含「背景特性」字段与「特性详解」（含英文名，如 Acolyte 的 Shelter of the Faithful）。
- 即：**文档层已经完成了特性拆分，代码层缺对应注册表**——本次实施的主要工作量是把 docs 内容落地为特性注册表。

### 2.3 展示层：能力页签没有种族/背景区块

- 角色卡「能力」页签（`app/src/views/character-builder/components/CharacterSheetStep.vue`）现有三个区块：
  1. **职业特性**（`getClassFeatures2014`，按 `level <= targetLevel` 过滤）；
  2. **子职特性**（`getSubclassFeatures2014`，同上过滤）；
  3. **专长与属性提升**（来自草稿 `selections`）。
- 无种族特性/背景特性区块；种族与背景信息只在基础信息区展示 description 文本。

### 2.4 导出层：类目已预留但暂不生成数据

- `app/src/features/character-export/build-export-data.ts` 的 `ExportFeature.category` 类型**已预留 `'race'` 与 `'background'`**（`'feat' | 'subclass' | 'class' | 'race' | 'background'`）。
- **决策 4（用户确认）：本次暂不将种族/背景特性纳入 PDF/XLSX 导出**，`ExportFeature` 的 race/background 类目保持预留，后续扩展。

### 2.5 跑团助手

- `views/session-assistant/components/SessionPanel.vue` 已有「能力」页签（`getClassFeatures2014` / `getSubclassFeatures2014` 同款展示）。
- **决策 5（用户确认）：跑团助手同步展示种族/背景特性**。

### 2.6 其他

- 种族特性为常驻/按等级自动获得，无玩家选择点；时间线目前只有「子种族选择」检查点。
- **决策 6（用户确认）：3/5 级种族特性仅按等级过滤展示，不新增时间线检查点**。

## 3. 需求内容

### 3.1 数据层：新建特性注册表

- 新建 `app/src/rules/data/race-features-2014.ts`：以 `docs/species/5e-2014/` 为来源，登记**约 240 条**种族特性（含属性提升条目）。
- 新建 `app/src/rules/data/background-features-2014.ts`：以 `docs/backgrounds/5e-2014/` 为来源，登记 **40 条**背景特性（每条 1 个特性；英文名以 docs 为准，如 Shelter of the Faithful）。
- 特性结构复用 `ClassFeature`（`id / ownerId / name / englishName / level / summary / description / kind / status / sourceIds`；`ownerId` 指向 `race-2014-*` / `background-2014-*`，子种族特性指向子种族 ID）。
- 特性 ID 沿用 docs 已定义的 `race-2014-<种族>-<特性>`；背景特性 ID 建议 `background-2014-<背景>-feature`（实施时以 docs 核对）。
- `RaceRule` / `BackgroundRule` 增加 `features` 挂载（或提供 `getRaceFeatures2014(raceId)` / `getBackgroundFeatures2014(backgroundId)` 查询函数，由 `rulesRepository` 暴露），父种族与子种族各自挂载自己的特性。
- 状态与来源：与 docs 核验状态一致（已核验为 `implemented`、待核验为 `index-only`）；来源沿用 `origins-2014.ts` 的 `sourceIds`。

### 3.2 展示层：能力页签新增分组区块

- 在 `CharacterSheetStep.vue` 能力页签增加**分组展示**区块（决策 2）：
  1. **种族特性 · <基础种族名>**（`draft.raceId` 对应特性，按 `level <= targetLevel` 过滤）；
  2. **种族特性 · <子种族名>**（`draft.subraceId` 对应特性，仅子种族自身条目；父项特性不重复展示）；
  3. **背景特性 · <背景名>**（`draft.backgroundId` 对应特性；变体背景沿用父项特性的展示规则）。
- 与职业/子职特性同形态（`ExpandableOptionCard`：名称、`N级 · EnglishName`、展开显示详情、index-only 标记）。
- 未选择种族/子种族/背景时显示空态提示（与子职未选时一致）。
- 属性提升条目（`ability-score-increase`）纳入种族特性区块（决策 3）。

### 3.3 导出层：暂不实施（决策 4）

- 本次**不**在 `resolveSelectedFeatures` 生成 race/background 条目；`ExportFeature` 类目保持预留，后续扩展。

### 3.4 跑团助手（决策 5）

- `SessionPanel.vue` 能力页签同步新增种族/背景特性分组区块，与角色卡一致。

## 4. 边界

- 仅当前运行时规则集 `5e-2014`；2024 物种（`5e-2024`）不入（未来独立规则集资料，`docs/species/5e-2024/` 不动）。
- **背景特性纳入本次范围**（决策 1）：40 个背景各 1 条特性；背景变体（如 间谍、角斗士）沿用父背景特性。
- 种族特性的 3/5 级特性按等级过滤展示，**不新增时间线检查点**（决策 6）。
- 属性提升作为特性条目纳入（决策 3），与 docs 保持一致。
- 摘要与详情为原创中文转述，不复制规则正文（遵循项目版权约定）。

## 5. 设计要点

- 继承关系：子种族沿 `parentRaceId`，展示时**分组呈现**（基础种族一组、子种族一组），子种族文件只记录相对父项新增/替换的内容，父项特性不重复登记。
- `kind` 取值沿用现有枚举（`passive` / `action` / `bonus-action` / `reaction` / `resource` / `choice`），种族特性多为 `passive` / `resource`（如 吐息、兽化、治疗之手等有限次数能力）。
- 同名特性（如多个种族的黑暗视觉）各自独立条目，不共享 ID 与数值（遵守 2014/2024 隔离与条目独立约定）。
- 展示按等级过滤复用现有 `feature.level <= targetLevel` 模式。

## 7. 完成标准

- `race-features-2014.ts` 覆盖 docs/species/5e-2014 全部特性（~240 条，含属性提升），ID 与 docs 一致；`background-features-2014.ts` 覆盖 40 个背景特性。
- 角色卡能力页签展示分组区块：种族特性 · 基础种族 / 种族特性 · 子种族 / 背景特性 · 背景；按等级过滤，可展开详情；空态提示正常。
- 跑团助手能力页签同步展示。
- TypeScript 类型检查、相关单元测试（注册表完整性、分组展示、等级过滤）与生产构建通过。
- docs 与版本公告同步更新。
- PDF/XLSX 导出本次不纳入（决策 4），类目保持预留。

## 8. 决策记录（用户 2026-09-02 全部确认）

1. **背景特性**：纳入本次范围（40 个背景，各 1 条特性；变体沿用父背景）。
2. **展示分组**：分组展示（基础种族 / 子种族 / 背景 各一组）。
3. **属性提升条目**：纳入（`ability-score-increase` 作为特性条目展示）。
4. **导出范围**：本次暂不纳入 PDF/XLSX 导出（`ExportFeature` 类目保持预留）。
5. **跑团助手**：同步展示种族/背景特性。
6. **等级特性**：3/5 级种族特性仅按等级过滤展示，不建时间线检查点。

## 1. 需求来源

用户原话：

> 1. 当前很多的角色背景，其中有一些是带有专长的，那么我希望的功能是点击对应的背景后选择对应背景的专长，最后的专长的效果与介绍会出现在对应的角色卡中。

拆成两条可验收目标：

| 编号 | 目标 | 说明 |
| --- | --- | --- |
| **R1** | **点选背景即可看到并（在需要时）选择该背景的专长** | 出身步骤选中某条背景后，立刻能看到「这条背景带来什么专长」；原书为固定授予的只需展示，原书为二选一／任选的必须在此处完成选择 |
| **R2** | **生效专长的效果与介绍出现在角色卡中** | 车卡「角色卡」步骤与跑团查看模式都要按生效专长逐条列出「名称 · 一行摘要 · 完整效果 · 来源」，且数值来源可解释 |

### 2.3 缺口清单（本需求要解决的）

| 编号 | 缺口 | 证据 | 用户可见后果 |
| --- | --- | --- | --- |
| **G-1** | 出身步骤完全不提专长 | `OriginStep.vue` 背景卡只显示 `summary · featureName · 推荐`；2024 段说明文字提到「起源专长」但没有任何专长内容 | R1 不成立：点选背景后看不到专长 |
| **G-2** | 固定授予的 77 条专长在角色卡上完全不显示 | `CharacterSheetStep.vue:463` 与 `SessionPanel.vue:202` 的「专长与属性提升」只遍历 `draft.selections`，固定授予不产生 selection | R2 不成立；且派生值（如健壮 → HP、飙速跑者 → 速度）**有数值却无来源说明**，违反「数值旁应提供来源或计算说明」 |
| **G-3** | 二选一背景的候选卡在时间线步骤显示**原始 ID** | 2024 仓库 `options` 只并入 `feats2024`（`app/src/rules/repositories.ts:83`），扩展书专长只在 `feats` 数组里；`TimelineStep.vue` 的卡片分支用 `getOption(optionId)?.name` 取标题 | 玩家在「选择起源专长」看到 `feat-2024-rthw-watchers` 这类 ID，看不到专长名与效果 |
| **G-4** | 2014 侧 14 条背景「写了给专长但没有专长」 | 背景特性／背景描述统一写着「本项不接入自动专长授予，需按原书处理器」；7 条专长条目不存在 | 2014 玩家永远拿不到这些背景承诺的专长，角色卡也没有对应条目 |
| **G-5** | 「原书任选一项起源专长」的 2 条背景没有任何选择入口 | `originFeatId` 留空且无 `originFeatOptions`，只靠描述文字 | 2024 玩家选了这两条背景等于没有起源专长 |
| **G-6** | 更换背景后旧背景的专长选择不会失效 | `getDependencyImpact()` 的 `background` 分支 `invalidated: []`（`app/src/rules/dependency.ts:171`）；而 `listFeatGrants()` 会遍历**全部** `draft.selections` 并按 `optionId` 是否为专长授予 | 从鸦阁背景换到别的背景后，旧的黑暗赠礼**仍在生效**（重复授予、派生值被污染） |
| **G-7** | 导出只认固定 `originFeatId` | `build-export-data.ts:262` | 贵族／智者用狂野天赋替换后，导出的 PDF／XLSX 仍显示原固定起源专长 |

> G-6 是**既有缺陷**，不是本需求新引入的；但本需求把「背景→专长」做成一等公民后必须一并修掉，否则 R2 会展示错误结果。
>
> G-3 的同一缺陷也会命中**物种起源专长**检查点（如 2024 人类 Versatile 的「选择额外起源专长」）：核心 10 条起源专长因已并入 `options` 而正常，扩展书起源专长同样显示原始 ID。因此修复应落在 `TimelineStep.vue` 的解析函数上（统一改为「先 `getFeat()`，再 `getOption()`」），而不是只给背景检查点打补丁。

2. **候选卡正确解析专长**（G-3）：出身步骤与时间线步骤都必须用 `getFeat()` 解析候选，显示专长名 · 英文名 · 一行摘要，展开显示完整效果与来源。
3. **角色卡与跑团面板按生效专长展示**（R2、G-2）：改为与规则层 `listActiveFeats()` 同源，并保留属性提升（`asi-*`）条目。

5. **背景切换的失效与导出一致性**（G-6、G-7）。

## 5. 数据层设计要点

### 5.1 类型（`app/src/types/rules.ts`）

- `BackgroundRule` 新增（或在实现时确认复用命名）**类别池选择规格**：
  `originFeatChoices?: { readonly count: number; readonly categories: readonly FeatCategory[] }`
  —— 与 `RaceRule.originFeatChoices` 同名同义，便于规则层与界面复用同一套渲染与门禁。
- 保留 `originFeatId`（固定）与 `originFeatOptions`（显式候选）语义不变；三者优先级：`originFeatOptions` > `originFeatChoices` > `originFeatId`。

### 5.2 检查点（`app/src/rules/timeline.ts`）

- `buildBackgroundFeatCheckpoints()` 扩展为两类来源：
  - `originFeatOptions`：候选取自显式列表（现状）。
  - `originFeatChoices`：候选取自 `getFeatPool(repository, categories, { enabledSourceIds })`（与 `buildSpeciesFeatCheckpoints()` 同一实现路径）。
- 检查点 id 保持 `${background.id}-origin-feat`，**不得改 id**（既有草稿的 `selections` 按 id 存储）。
- `optionPresentation`：该检查点候选需要读完整效果，应能展开，故需纳入可展开渲染路径（`kind: 'feat'` 目前不在 `EXPANDABLE_CHECKPOINT_KINDS`）。

### 5.3 授予与去重（`app/src/rules/feats.ts`）

- `listFeatGrants()` 增加类别池分支（未选择时回退 `originFeatId` 的既有行为保留）。
- 增加**孤立选择过滤**：`draft.selections` 中已不属于当前时间线的检查点（例如换了背景后残留的 `${旧背景.id}-origin-feat`）不得再产生授予。可选择实现方式：
  - (a) 由 `listFeatGrants()` 校验检查点是否存在于当前时间线；
  - (b) 由 `getDependencyImpact()` 在换背景时把旧检查点标为失效。
  - **建议 (b) 为主**（可解释的失效原因，符合既有 `invalidatedReason` 用法），**(a) 为兜底**（防止未来其它路径产生孤立选择）。

### 5.4 依赖失效（`app/src/rules/dependency.ts`）

- `DraftChange` 的 `background` 分支需要知道**换出**的背景：扩展为 `{ kind: 'background'; value: string; previousValue?: string }`，或在页面 hook 内用 `draft.backgroundId` 计算。
- 失效目标：`${previousValue}-origin-feat`（含 `backgroundVariantId` 同源处理），原因文案示例：「更换背景后需要重新确认起源专长」。
- `review` 列表保持现有的「背景授予的起源专长与重复选择」。

## 6. 交互设计

### 6.1 出身步骤（`OriginStep.vue`）

选中背景后，在背景列表下方新增区块**「该背景的起源专长」**，按数据分三类渲染：

| 类型 | 数据特征 | 呈现 | 可交互 |
| --- | --- | --- | --- |
| 固定授予 | 有 `originFeatId`，无候选 | 单张卡片：`专长名 · 英文名`，描述为一行摘要，展开为完整效果；徽标「由背景固定授予」 | 只读（Q2-A） |
| 候选列表 | `originFeatOptions` | 候选卡片列表（1/1 必选）：名称 · 英文名 · 摘要，展开为完整效果与来源。含二选一（鸦阁／避世潜藏／契约追寻者）与**本书候选**（德鲁斯肯瓦尔德居民 12 条） | 点选即写入 `${background.id}-origin-feat` |
| 全池任选 | `originFeatChoices` | 起源专长全池候选（带搜索与「只看当前可选」），规格与物种起源专长选择一致（神话调查员） | 点选写入同一检查点 |
| 无专长 | 三者皆无 | 说明行：「参考资料中未见该专长的独立条目，需按原书处理」 | 只读 |

- 交互细节：切换背景时区块内容随之刷新；已选专长显示为选中态并在卡片上回显「已选」。
- 组件职责：`OriginStep.vue` 只负责展示与收集输入，专长解析、可用性与来源文案全部来自 `rules` 层；候选渲染优先复用现成组件（`ExpandableOptionCard` + `ListShell`），避免新增重复卡片样式。
- 页面数据：`OriginStep.vue` 当前未接收 `selections`／`draft`，需要新增 props 与 emit（由 `character-builder/index.vue` 与页面 hook 接线）。

### 6.2 时间线步骤口径

- `${background.id}-origin-feat` 检查点**保留**（Q1-A），作为同一份选择的另一处入口与完成度显示。
- 必须修复候选解析（G-3）：候选标题／摘要／状态统一走「先 `getFeat()`，再 `getOption()`」的解析顺序，禁止再出现原始 ID。
- 若玩家已在出身步骤选完，时间线此处显示为已完成（该检查点为 1/1，计数与完成度不受影响）。

### 6.3 角色卡（车卡「角色卡」步骤 + 跑团查看模式）

- 「专长与属性提升」区块改为**规则层同源**：以 `listActiveFeats(draft, repository)` 为主体，叠加仍来自 `draft.selections` 的属性提升（`asi-*`）与专长自带属性提升子选项（`feat-bonus-*`）。
- 每条卡片：
  - 标题：`专长名 · 英文名`
  - 描述行：**一行摘要**（`feat.description`）+ **来源标签**（起源专长·《背景名》／物种／职业／时间线选择）
  - 展开：完整效果（`feat.detail`）+ 已有结构化信息（授予法术、资源、前置）
- 排序：起源专长（1 级）在前，其余按获得等级。
- 空态：区分「该角色尚未获得任何专长」与「尚未选择专长或属性提升」。
- 数量徽标：区块标题可显示 `专长 N`，便于玩家核对（可选）。

### 6.4 导出

- `buildFeatures()` 的起源专长改用 `listActiveFeats()`（或等价的授予列表），修复 G-7（替代语义、二选一选择都能正确导出）。
- 导出条目继续带「（起源专长）」标注；来源为背景时补注背景名。

## 10. 风险与注意

1. **不动检查点 ID**：`${background.id}-origin-feat` 是已发布草稿的存储键，改 id 会让老草稿的选择静默失效。
2. **两处渲染同一检查点**：出身步骤与时间线步骤必须写同一个检查点，禁止各存一份；`saveSelection()` 已按 `checkpointId` 覆盖，复用即可。
3. **2014 专长的结构复杂度差异很大**：斯翠海文学徒、高等术法入门、外层位面后裔需要「选项 + 授予法术／抗性」；神性之遇、巨人打击视原文表结构而定。允许分级落地：能结构化则结构化，不能结构化则登记为文字并在 `detail` 写明「需按原书处理」，但**必须**先建条目（否则角色卡还是空的）。
4. **2014 不该出现 `category`**：`FeatRule.category` 注释明确「2014 条目省略」，新条目不要误加 2024 类别，否则会被 2024 候选池逻辑误纳。
5. **战役先决不能硬凑**：`FeatPrerequisite` 没有战役字段，五条龙枪／异度风景／鸦阁类先决一律写文案。
6. **来源开关**：2014 这些书均为官方来源，默认开启；第三方候选仍须受 `enabledSourceIds` 过滤（类别池走 `getFeatPool` 已带过滤）。
7. **避免「顺手改」**：本次不调整既有 2014／2024 授予语义与派生口径；只新增展示与选择能力。
8. **G6 修复的回归面**：孤立选择过滤可能影响历史草稿（原本「错误生效」的专长会消失）。需在测试中固定该行为，并在更新公告中说明。

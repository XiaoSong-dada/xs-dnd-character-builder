# 子职特性展示与升级需求

## 1. 背景与目标

上一轮已完成子职覆盖：114 项子职索引、112 个玩家可用子职全部按纵向切片接入规则层（等级特性注册表、子职选择与互斥校验、子职派生钩子）。但**这些特性数据在界面层完全没有被消费**——车卡过程中玩家看不到所选子职的特性介绍，角色卡也没有特性区块。

用户需求：子职特性需要像已有的"计算属性（属性/派生计算）"与"专长（FeatChoicePanel）"一样被"升级"，即提供**特性介绍（展示）**、**特性选择**，并让可核验的特性**参与派生计算**。

目标产物：

- 车卡时间线：选中子职后即可浏览该子职的特性（按等级分组、含摘要与来源）。
- 角色卡"能力"页签：展示所选职业与子职的特性清单。
- 需要玩家选择的特性（如图腾武者熊/鹰/狼、猎人各等级三选一、战技等）提供选择入口并持久化。
- 可核验的派生效果（如术士龙族血脉的 AC/HP 加成）接入 `derive`，数值来源可解释。

## 2. 现状调查（已核验）

### 2.1 数据层（已就绪）

| 模块 | 现状 |
|---|---|
| `app/src/rules/data/subclass-features-2014.ts` | 570 条特性已登记；`SubclassRule.features` 已挂载；`getSubclassFeatures2014(subclassId)` 可按子职查询 |
| `app/src/rules/subclass-effects.ts` | `SubclassDerivedEffects`（HP/AC/攻击/伤害/法术攻击/法术DC/速度 7 项）结构就位，`getSubclassDerivedEffects` 当前返回零效果 |
| `app/src/rules/validate.ts` | `validateSubclassSelections` 已校验子职归属/等级/互斥；`requiresChoice` 特性未完成选择时发 `warning` |
| `app/src/rules/dependency.ts` | `DraftChange.kind === 'subclass'` 已支持，变更时作废含 `-subclass-` 的检查点选择 |
| `app/src/rules/timeline.ts` | `buildTimeline(classId, targetLevel, { subraceId })` 自动追加 subclass 检查点；`Context` 目前无 `subclassId` |

### 2.2 界面层（缺口）

| 界面 | 现状 | 缺口 |
|---|---|---|
| `TimelineStep.vue` | subclass 检查点用 `OptionCard` 列出子职名称，选中后 `saveTimelineSelection` 同步 `draft.subclassId` | **选中子职后不展示该子职的特性列表**；`requiresChoice` 特性（图腾/猎人选择）无选择入口 |
| `CharacterSheetStep.vue` | "能力"页签只展示豁免与技能（`derived.savingThrows` / `derived.skills`） | **无职业/子职特性区块**；专长、子职特性均不可见 |
| `FeatChoicePanel.vue` | 专长的搜索/筛选/可选性/选择 UI 完整（参照样板） | 子职特性没有类似面板 |
| `CharacterDrawer.vue` | 摘要抽屉只显示 HP/AC/先攻/速度/熟练 | 无特性（摘要可不含，属可选项） |

### 2.3 结论

- 特性**数据完备、UI 缺失**：570 条特性零界面消费。
- 特性选择**机制空缺**：`ChoiceSelection`（checkpointId + optionIds）通用结构可复用，但 `requiresChoice` 特性没有对应检查点/保存位，`validate` 只能发 warning。
- 派生升级**只差注册**：`subclass-effects.ts` 钩子已接入 `derive`，按可核验条目填充即可。

## 3. 需求项

### R1 子职特性展示（介绍）

1. **时间线**：subclass 检查点选中某个子职后，在该检查点内展示该子职的全部特性：
   - 按等级分组，展示等级徽标（如 `3级`）、中文名 + 英文名、原创摘要、来源（如 `PHB 2014` / `XGtE`）；
   - `index-only` 特性显示"仅索引/未核验"徽标（复用 `UiBadge` warning 风格）；
   - 特性数据来自 `rulesRepository.getSubclass(subclassId).features`，组件不硬编码规则。
2. **角色卡"能力"页签**：新增"职业与子职特性"区块，展示：
   - 已选子职的名称（如 `图腾武者道途`）与特性列表（按等级分组，同上）；
   - 未选子职时显示"尚未选择子职"提示；
   - 职业基础特性（如战士的"动作如潮"）目前规则层未登记，本需求不阻塞、作为后续 R4。

### R2 子职特性选择

1. **选择范围**：`requiresChoice: true` 的特性（当前含：图腾武者图腾三选一、猎人 3/7/11/15 级各选择、战斗大师战技、龙族祖先、野兽形态、巨人力量、风暴光环、剑舞战斗风格、剑圣武器、四象宗纪律、奥术射击、符文、精魂图腾、星体形态、月之形态、巨灵容器等）。
2. **选择机制（建议）**：扩展时间线——`buildTimeline` 的 `Context` 增加 `subclassId`，在 subclass 检查点之后按所选子职追加 `kind: 'subclass-feature'` 的特性检查点（`optionIds` = 特性 `optionIds`，标题 = 特性名，`minSelections/maxSelections` = 1 或多选）。收益：
   - UI（TimelineStep）、store（saveSelection）、校验（checkpoint 缺失即 error）、依赖（subclass 变更作废）全部复用现有机制；
   - `draft.selections` 无需新增字段，导入导出兼容。
3. **校验**：`validateSubclassSelections` 的 `requiresChoice` warning 保留为兼容兜底；特性检查点未完成时由常规 checkpoint 校验升级为 error。

### R3 子职派生升级

1. **原则**：只对"可核验、来源明确"的条目接入 `derive`；570 条 `index-only` 特性不虚构数值（遵守内容与版权约定）。
2. **接入点**：`rules/subclass-effects.ts` 建立"按子职+特性"的效果注册表（`Map<subclassId, effects>` 或 `Map<featureId, effects>`），`getSubclassDerivedEffects` 改为查表；`derive.ts` 已预留 7 项加成的来源项，无需改动派生结构。
3. **首批可核验条目（示例，实现时以资料核验为准）**：
   - `sorcerer-draconic-bloodline`：龙族坚韧（未着甲时 AC = 13 + 敏捷调整值；每术士等级 +1 HP）——AC/HP 两处接入；
   - `fighter-battle-master`：优势骰等级表（3 级 d8、10 级 d10、18 级 d12）可在角色卡资源区展示（不涉及属性派生）；
   - 其余条目保持零效果，随资料核验逐批填充。

### R4（后续，非本批必须）职业基础特性登记

- 职业特性（如狂暴、动作如潮、额外攻击）目前规则层无登记数据，角色卡无法展示"职业特性"。建议后续按 `dnd-classes.md` 3.3 约定在 `rules/data/class-features-2014.ts` 登记，展示逻辑与 R1 复用。本需求不阻塞 R1—R3。

## 4. 非目标与边界

- 不实现未核验的数值效果：570 条 `index-only` 特性只展示、不参与自动计算。
- 不新增 `CharacterDraft` 字段（特性选择复用 `selections`），保持存储结构兼容。
- 不修改专长/属性提升现有交互。
- DM 专用子职（死亡领域、破誓者）特性不进入普通车卡展示。

## 5. 涉及模块与依赖方向

```text
views/character-builder/components/TimelineStep.vue
  -> rules/timeline（Context 增加 subclassId；追加 subclass-feature 检查点）
  -> rules/data/subclass-features-2014.ts（特性查询）
  -> components/ui（UiBadge/OptionCard，特性卡片可复用或新建 SubclassFeatureCard.vue）

views/character-builder/components/CharacterSheetStep.vue
  -> rules/repository（按 draft.subclassId 取特性）
  -> components/ui

rules/subclass-effects.ts —— 效果注册表填充（仍是 rules 内部纯函数）
rules/validate.ts —— requiresChoice 兜底保持；checkpoint 校验自然升级
```

依赖方向不变：`views → rules → types`，rules 保持框架无关。

## 6. 验收标准

1. `pnpm test` 全量通过；新增测试覆盖：特性检查点生成（图腾/猎人）、子职变更作废特性选择、`subclass-effects` 首批条目（龙族血脉 AC/HP）、角色卡特性区块数据绑定。
2. `pnpm build`（含 `vue-tsc -b`）通过。
3. 手机宽度流程：选野蛮人 → 选图腾武者 → 时间线出现"图腾选择"检查点 → 选中熊/鹰/狼 → 角色卡"能力"页签可见图腾武者特性列表。
4. 未核验特性带"仅索引"徽标，不产生数值；`index-only` 子职特性只展示不计算。
5. 文档同步：`docs/frontend-architecture.md`（如新增组件/模块）、`docs/rules.md`（子职特性选择规则）、`docs/quick-build-implementation.md`（实施状态）；交付说明写明"已复核前端依赖拓扑"。

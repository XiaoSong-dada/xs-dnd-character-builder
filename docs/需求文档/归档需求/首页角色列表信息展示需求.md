# 首页角色列表信息展示需求

## 1. 背景与目标

用户反馈：车完卡返回首页后，角色条"等级"后面跟着一串英文（如 `sheet`、`spells`），这是 `draft.currentStep` 的**原始英文 ID**，直接渲染到界面，既不友好也不直观。

用户期望这一信息位**更灵活**：

- 车卡未完成时：显示"当前在第几步"（或已选职业）；
- 车卡完成时：显示职业；
- 并希望先分析"显示职业 vs 显示步骤"哪个对用户更友好，再确定方案。

目标产物：

- 角色条第三段信息（等级之后）展示对用户有意义的内容，不再裸显 `currentStep` 英文串；
- 完成态显示职业；进行态提供"第几步/步骤名"与"职业"的自适应组合；
- 复用项目内已有事实源（`STEP_META` 步骤文案、`rulesRepository.getClass` 职业名），组件不硬编码。

## 2. 现状调查（已核验）

| 模块 | 现状 |
|---|---|
| `StartPanel.vue:62` | `<small>{{ draft.targetLevel }}级 · {{ draft.currentStep }}</small>`——直接渲染 `DraftStep` 原始英文 ID（`setup`/`preferences`/`spells`/`sheet` 等），未做任何映射 |
| `types/character.ts:7-19` | `DraftStep` 共 11 个值：`setup → preferences → class → origin → abilities → timeline → equipment → spells → identity → validation → sheet` |
| `useCharacterBuilderPage.ts:28-40` | `STEP_META: Record<DraftStep, { eyebrow, title }>` 已含全部友好文案（`setup: 第1步/先确定冒险规模` … `sheet: 角色完成/角色卡`）——**但为 hook 私有常量，`StartPanel` 不可见** |
| `rulesRepository.getClass(draft.classId)?.name` | 可直接取得职业中文名（如"战士"）；`draft.classId` 在 `draft` 上，`StartPanel` 可访问 rules（依赖方向合规） |
| 完成判定 | `currentStep === 'sheet'` 即为车卡完成 |

**结论**：缺的不是数据，而是「展示规则 + 文案来源」。步骤文案已存在于 `STEP_META`，只需上提为公共常量；职业名已有现成查询。

## 3. 优劣分析：显示职业 vs 显示步骤（用户问题 2）

| 维度 | 方案 A：只显示步骤（第几步/步骤名） | 方案 B：只显示职业 | 方案 C：分级组合（推荐） |
|---|---|---|---|
| 未选职业时（第 1—2 步） | ✅ 唯一有意义的进度信息 | ❌ 无职业可显示，只能空着或回退 | ✅ 显示"第 N 步 · 步骤名" |
| 已选职业、车卡进行中 | ⚠️ 能告知进度，但角色辨识弱 | ✅ 身份标签直观（"战士"） | ✅ 职业 + 步骤（"战士 · 第6步"），两全 |
| 车卡完成（sheet） | ❌ "角色完成"无信息量 | ✅ 完美（用户明确要求） | ✅ 显示职业 |
| 首页"继续车卡"场景价值 | ✅ 直接回答"我停在哪" | ⚠️ 回答"我是谁"但不回答进度 | ✅ 两者兼顾 |
| 信息密度 | 低 | 低 | 中（一行小字可容纳） |
| 实现成本 | 低（复用 STEP_META） | 低（getClass + 空值回退） | 中（组合 + 空值回退） |

**结论（方案 C 已确认采用）**：**职业优先、步骤兜底、完成态显示职业**的分级规则——

1. 已完成（`currentStep === 'sheet'`）→ 只显示职业（如 `3级 · 战士`）；
2. 进行中且已选职业 → 职业 + 步骤（如 `3级 · 战士 · 第6步`）；
3. 进行中且未选职业 → 步骤（如 `3级 · 第1步 · 先确定冒险规模`）。

理由：职业是角色身份的核心标签（完成态与进行态都有辨识度），步骤是"继续车卡"的定位信息（未选职业时唯一可用）；分级组合用同一个信息位覆盖三种状态，不牺牲任何一方。纯步骤（A）在完成态无意义，纯职业（B）在未选职业时空白——两者单独都不完整。

**其他可选增强（不阻塞本需求）**：进度式文案"第6步 / 共9步"、进行中加"待补全"徽标（复用 `needsReview` 概念），可作为后续批次。

## 4. 需求项

### R1 角色条第三段信息分级展示（核心，方案已确认）

1. **文案映射**：`currentStep` 经 `STEP_META` 映射为友好文案（`eyebrow` + `title`），不再裸显英文 ID。
2. **分级规则**（用户已确认采用第 3 节方案 C）：
   - `currentStep === 'sheet'`：`{职业名}`（如 `3级 · 战士`）；
   - 已选职业（`draft.classId` 存在）且未完成：`{职业名} · {eyebrow}`（如 `3级 · 战士 · 第6步`）；
   - 未选职业：`{eyebrow} · {title}`（如 `3级 · 第1步 · 先确定冒险规模`）。
3. **空值处理**：`classId` 缺失时职业段省略（分级规则已覆盖）；职业查询不到时回退为不显示职业段。

### R2 步骤文案来源上提（支撑 R1）

- `STEP_META` 从 `useCharacterBuilderPage.ts` 私有常量**上提为公共常量**（建议 `src/constants/steps.ts` 或 `src/config` 下，随实现定），`StartPanel` 与页面 hook 共用，保持单一事实源；
- 上提后 hook 的 `stepMeta` 改为引用公共常量，行为不变。

### R3（可选，后续批次）

- 进行中草稿在角色条加"待补全"提示（复用 `selections` 失效/检查点未完成判断）；
- 步骤进度文案（"第 N 步 / 共 M 步"）与完成态"已完成"标记。

## 5. 非目标与边界

- 不改动 `CharacterDraft` 数据结构（`currentStep` 字段语义不变，仍是持久化的原始步骤值）。
- 不改变角色条"继续 ›"、"删除"按钮的行为与布局。
- 不改动车卡流程内（`index.vue` 步骤头）的步骤展示（其已用 `STEP_META`）。
- 2024 只读草稿条目不在此需求范围（已有"5e-2024 · 只读"文案）。

## 6. 涉及模块与依赖方向

```text
views/character-builder/components/StartPanel.vue
  -> rules/repository（getClass 取职业名）
  -> constants/steps（STEP_META 公共常量，R2 上提后）

views/character-builder/hooks/useCharacterBuilderPage.ts
  -> 改为引用公共 STEP_META（删除私有副本）

src/constants/steps.ts（R2 新建，如实现时选 constants 目录）
  -> 依赖 types/character（DraftStep）
```

依赖方向不变：`views → rules → types`、`views → constants → types`；R2 仅移动常量位置（新模块），需在实现时同步 `docs/frontend-architecture.md` 拓扑说明。

## 7. 验收标准

1. `pnpm test` 全量通过；新增组件测试覆盖 `StartPanel`：
   - 未选职业草稿显示"第 N 步 · 步骤名"，不出现英文步骤 ID（`setup` 等）；
   - 已选职业进行中草稿显示"职业 · 第 N 步"；
   - 完成草稿（`currentStep: 'sheet'`）显示职业；
   - `classId` 缺失/查询不到时职业段正确省略。
2. `pnpm build`（含 `vue-tsc -b`）通过。
3. 手机宽度流程：创建草稿 → 返回首页观察步骤文案；选择职业后返回首页观察"职业 · 第N步"；完成车卡后返回首页观察职业。
4. 文档同步：`docs/frontend-architecture.md`（若新增 constants 模块）、`docs/quick-build-implementation.md` 实施状态；交付说明写明"已复核前端依赖拓扑"。

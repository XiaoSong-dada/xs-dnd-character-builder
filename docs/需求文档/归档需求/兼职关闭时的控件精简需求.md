## 1. 背景与问题

职业分配控件（`ClassAllocationControl`）在第 1 步、第 3 步与角色卡「调整等级」弹窗三处共用。兼职上线后，它在**兼职关闭**（`multiclass.enabled === false`）时仍露出兼职专属元素：

- **「设置起始职业」按钮**：显示条件是 `classes.length > 0`，单职业时同样成立 → **单职业用户一直看得到**。
- **底部「取消 / 确认」**：无条件渲染 → **单职业用户一直看得到**；而在第 1 步／第 3 步里每次操作都已立即生效，这两个按钮没有任何作用（第 1 步的「取消」只把当前等级再写一次，是空操作）。
- **「本次变更」摘要**：由本地待定状态计算，内联时会在依赖确认被取消后残留（见 §4 R3）。

对单职业用户而言，这些元素既不解释任何东西，又增加了点击面积与认知负担，属于「兼职功能溢出到单职业主流程」。本次需求把这部分收回去。

## 2. 术语与边界

- **内联模式**：控件直接嵌在页面里（第 1 步、第 3 步）。每次操作**立即生效**，没有「待提交」概念。
- **弹窗模式**：控件嵌在角色卡「调整等级」弹窗内（组件 `compact` 属性）。有本地待定状态，底部「取消 / 确认」是**确定生效**与**关闭弹窗**的入口。
- 本次**不改**：开关行为、滑杆搬运规则（D14）、起始职业语义（D15—D17）、草稿字段与 schema、规则校验、导出。
- 本次**不改版本号**：1.13.0 尚未发布，公告继续描述该版本最终行为（见 §6）。

## 3. 需求一：兼职关闭时隐藏兼职专属板块（决策 D18）

**判据**：`multiclass.enabled === false` → 隐藏「设置起始职业」。

进一步收窄为**只在真正需要选择时才出现**：兼职开启但只有 1 个职业时，候选只有它自己，按钮点了也没有意义。因此显示条件定为 `multiclassActive`（＝ 开关开启 **且** 职业数 ≥ 2），与职业列表使用**同一个条件**。

> 这是对上一批「三处入口都能设置起始职业」验收标准（§6 第 6 条）的细化，不是推翻：该标准针对的是**已在兼职的角色**；职业数 < 2 时不存在可切换的对象。

同时明确：

- 「启用兼职」开关在兼职关闭时**必须保留**（它是开启兼职的唯一入口，隐藏会导致功能不可达）。
- 已隐藏的元素（职业列表、起始职业徽标、添加职业、20 级提示）**保持隐藏**，不因本次改动重新出现。
- 单职业时保留的两条说明文字（「开启兼职前，这里直接设置唯一职业的等级。」「开启『启用兼职』后可以添加第二个职业。」）不算兼职专属板块：前者是单职业主流程说明，后者解释开关作用，**保留**。

## 4. 需求二：内联模式不显示只对弹窗有意义的元素（决策 D19）

**判据**：内联模式（`compact === false`）→ 隐藏底部「取消 / 确认」与「本次变更」摘要；弹窗模式保留两者。

理由：

- 内联时每个操作立即 emit 并生效，不存在「未提交的改动」；「确认」只是把当前草稿再提交一次，「取消」在第 1 步是空操作（把当前等级再写一次）。
- 弹窗里「确认 / 取消」是**唯一**的「确定生效 + 关闭」入口（用户已确认保留）：去掉会让降级立即进入依赖确认，无法「先拖一下看看再取消」。

### R3（必须同批修）：内联不得残留未生效的显示

现状：控件保留一份本地待定草稿 `pending`，滑杆还有本地预览值 `sliderLevel`。内联时若页面弹出依赖确认而用户**取消**，`props.draft` 不变，于是：

- `sliderLevel` 停在**没有被应用**的值（例如拖到 7、取消后滑杆显示 7，而总等级行显示 5）；
- 「本次变更」摘要残留一条从未生效的「总等级 5 → 7」。

这属于同一次改动范围内的显示一致性问题，必须一起修：**内联模式不保留待定状态**——滑杆显示与摘要在提交未落地时回到已提交的草稿值。

## 5. 需求三：保留分配时给一行提示（决策 D20）

兼职关闭后职业列表会隐藏，但草稿里可能仍保留着多个职业的分配（关闭开关**不清空**职业列表数据，见上游需求 D2；例如上次关闭时取消了合并）。为避免用户以为数据丢了，在**兼职关闭且职业数 ≥ 2**时显示一行：

```text
已保留兼职分配：战士3 / 游荡者2，重新启用后可继续编辑。
```

- 只在这一种状态下出现，普通单职业用户看不到。
- 只做说明，不提供任何操作按钮（重新启用仍走「启用兼职」开关）。
- 文案里的职业构成复用统一标签口径（单职业 `战士5`；多职业 `战士3 / 游荡者2`）。

## 6. 验收标准

1. **兼职关闭 + 单职业**：控件只显示「标题 / 说明 / 启用兼职开关 / 等级滑杆 / 总等级行 / 两条说明」；**不出现**「设置起始职业」、「取消 / 确认」、「本次变更」摘要。
2. **兼职开启 + ≥2 职业**：职业列表、起始职业徽标、−/＋、添加职业、设置起始职业、设为起始职业、先决警告、移除说明全部可用；内联仍**不出现**底部「取消 / 确认」。
3. **角色卡「调整等级」弹窗**：单职业与兼职都保留底部「取消 / 确认」（弹窗模式），取消关闭弹窗、确认提交待定草稿。
4. **兼职关闭但保留 ≥2 个职业**：显示「已保留兼职分配：…」提示行；同时不显示职业列表与「设置起始职业」。
5. **内联一致性**：拖动滑杆触发依赖确认后**取消**，滑杆与总等级行都显示已提交的值，不残留未生效的显示与摘要。
6. 三处入口（第 1 步 / 第 3 步 / 角色卡弹窗）行为一致；不改动开关行为、滑杆搬运规则、起始职业语义、草稿字段、schema、校验与导出。
7. 版本号保持 **1.13.0**；不新增公告条目（理由见 §7）。
8. `npx vue-tsc -b`、`npx vitest run`、`npm run build` 全部通过；既有测试无回归。

### 7.1 R3 的实施边界（避免过度扩张）

R3 只处理**内联**模式：

- 内联以已提交的 `props.draft` 为唯一显示来源；滑杆在提交未被页面采纳（依赖确认被取消）时回到已提交值，也不再呈现任何「本次变更」摘要。
- **弹窗模式保留既有待定语义**（D19）：弹窗里的滑杆与摘要反映的是「即将提交的值」，由弹窗自己的「取消 / 确认」终结；页面级依赖确认被取消时弹窗是否同步回退，属既有行为，本轮**不改**，仅在本节记录为已知边界。
- 不改动页面 hook 的确认流程（`requestChange` / `pendingChange`），只在控件侧保证显示与已提交草稿一致。

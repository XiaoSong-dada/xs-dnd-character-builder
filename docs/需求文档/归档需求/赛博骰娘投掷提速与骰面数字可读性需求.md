# 赛博骰娘投掷提速与骰面数字可读性需求

## 1. 状态与范围

- 状态：参数已确认，已按更新计划实施。
- 对象：产品项目 `app` 的 `/dice` 页面。
- 最初仅整理需求，后续用户已授权实施；延续已实现的动画开关、音效与跨页面数据保留行为。

## 2. 已明确的需求

### R1 缩短投掷时间

- 用户反馈当前投掷过程拖沓，希望更快看到结果。
- 在保留动画的模式下缩短从点击投掷到公布数值的实际等待，同时保留可辨认的投出、滚动与停稳过程。
- 分别关注物理准备等待、动画播放、停稳后的额外等待，避免只加快滚动却让玩家继续等准备过程。
- 加速不能改变已生成的点数、结果范围或总和，也不能造成骰面与文字结果不一致。
- 音效应与缩短后的动画同步结束，不得在结果公布后继续播放。
- 「跳过动画」继续立即公布结果；离页结算与跨页面保留不受影响。

### R2 放大骰面数字

- 放大 3D 骰子表面的数字，提高默认视角、未手动缩放时的可读性，优先考虑手机端。
- 覆盖全部骰型，重点检查 d20、两位数字、d100 十位读数及 d4 的特殊标注。
- 数字应尽量利用骰面空间，保持足够字重、清晰边缘和对比度，不溢出骰面、不与相邻标注重叠。
- 保持现有数值语义，包括普通 d10 的 10、百分骰的 00 和 d100 换算；放大不能导致误读。
- 保留手动缩放能力；结果面板继续完整显示逐颗点数与总和。

## 3. 优化前现状核验

- 当前先完成 Worker 物理预演，再按轨迹时间播放动画，结果在播放结束后公布。
- 物理预演每次最多计算 8 秒模拟轨迹，最多重试 3 次。模拟时长不等同于用户实际等待时长，不据此断言用户每次等待 8 秒或 24 秒。
- 所有骰子进入休眠后仍收集 30 帧轨迹（约 0.5 秒）；当前动画没有独立播放提速策略。
- 数字使用 128×128 纹理，单字符字号 58、双字符字号 48；最终可见尺寸还受标签平面大小和镜头距离影响。
- d20、d12 与 d4 的标签平面较小，因此仅提高纹理分辨率不能保证数字看起来更大。
- 以上为代码阅读结论，尚未测量当前设备上的实际耗时或执行视觉验收。

## 4. 已确认目标

- 正常可见动画最多 1.5 秒，短轨迹不延长；总等待上限 3 秒，到期直接公布文字结果。后台浏览器暂停期间不承诺实时更新，恢复后检查经过时间。
- 仅调整数字：256×256 纹理，800 字重，单字符 220px、双字符 180px；按实际文字边界缩放并居中，数字与描边不超过纹理宽高的 84%。按后续可读性反馈适度扩大标签平面（d4：0.34、d20：0.32、d12：0.36、其余：0.42），使用不受灯光影响的深色数字；保持骰体与镜头不变。
- 本次不默认增加速度滑块或数字字号设置，优先改善默认体验。
- 高密度骰池下能否在手机全景视角直接辨认每颗数字，需要实测；不能仅凭字体变大宣称全部可读。必要时再讨论骰体大小或默认取景调整。

## 5. 后续验收标准

1. 在相同设备和相同骰池规模下，记录优化前后的准备耗时、动画耗时和总等待；常用少量骰池及最大骰池均需比较。
2. 保留动画模式明显提速，仍能辨认投掷与停稳过程；点数和总和与原始结果一致。
3. 音效与实际动画同步停止，跳过动画与离页保留回归验证通过。
4. 对各骰型的单双位数字、百分骰 00/90、d4 标注检查字号、清晰度、裁切与重叠，默认手机视角下应比当前更容易辨认。
5. 后续代码验证包括定时与完成事件、数值不变及标签布局的自动化检查；若要确认「不放大就看清」的实际视觉效果，需另行安排用户截图反馈或经用户要求的视觉验收。

# 专长与职业特性详细效果展示需求

## 1. 背景与目标

用户反馈：**专长**与**职业特性**目前只有一行摘要，没有对应的详细信息：

- 专长（42 项）在时间线选择时只能看到一句原创摘要（如"强化先攻与对突袭的应对能力。"），卡片标记"仅索引"，玩家无法了解完整效果（触发时机、资源、数值、恢复方式等）；
- 职业特性（上一轮已登记 12 职业约 140 条）与子职特性（570 条）在角色卡"能力"页签和时间线均为平铺文本列表，只有 `summary` 一句，无展开查看能力；
- 角色卡"能力"页签**不展示已选专长与属性提升**，玩家看不到自己选择了哪些专长、属性提升加到了哪项属性。

而项目已有成熟的可复用模式：`ExpandableOptionCard` 统一详细信息展开列表（法术效果、种族介绍、装备详情均已在用），数据层通过"摘要 + 详细字段"（`summary` + `description`，如 `SpellRule`/`RaceRule`）承载原创中文转述。

目标产物：

- **专长**：42 项全部登记原创中文**详细效果**，选择专长时可展开查看；不再处于"仅索引"状态（`status` 提升为 `implemented`，界面去掉"仅索引"徽标）。
- **职业特性**：12 职业全部登记 `description` 详细字段；角色卡"能力"页签与时间线的职业特性条目接入 `ExpandableOptionCard` 展开查看。
- **子职特性**：570 条**全部**登记 `description` 详细字段（一次性全量，不分批），同样支持展开查看。
- **角色卡"能力"页签展示专长与属性提升**：已选专长显示专长名并可展开查看 `detail`；已选属性提升显示提升内容（如"属性提升（智力+2）"、"属性提升（力量+1、敏捷+1）"）；变体人类 1 级专长同样展示。
- 遵守版权约定：详情为原创中文转述（参考法术/种族描述风格），不复制原书正文；只作展示，不进入自动计算。

### 2.4 结论

- 专长与特性**数据缺详情字段、界面缺展开**；`ExpandableOptionCard` 组件无需改动，直接复用。
- 专长"不再是索引状态"：登记详细效果描述后 `status` 提升为 `implemented`（数据足以支持展示与既有前置条件校验；**不参与派生计算**，遵守"未经核验的效果不得进入自动计算"边界），`validate.ts` 的 `index-only-*` warning 对专长自然消失。
- 职业特性 `ClassFeature` 增加 `description` 字段（命名与 `RaceRule`/`SpellRule` 一致）；子职特性 `SubclassFeature` 增加 `description` 字段并**全量登记**。
- 角色卡"能力"页签已有专长与属性提升的**数据来源**：`draft.selections` 中 `optionId` 以 `feat-` 开头的选择即已选专长（含变体人类 `race-2014-human-variant-feat-1` 检查点）；`asi-` 开头的选择即属性提升，可由 `decodeAbilityImprovement` 解码（`asi-str-2` → 力量+2；`asi-int-wis` → 智力+1、感知+1），只需新增展示区块。

## 3. 需求项

### R1 专长详细效果登记（核心）

1. **字段**：`FeatRule` 新增 `readonly detail: string`（原创中文**详细效果**，展开区展示）；现有 `description` 保留为卡片摘要行，职责不混淆。
2. **登记范围**：42 项专长**全部**登记 `detail`，风格参照法术 `description`（要点式转述），覆盖：获得的效果要点、触发时机（动作/附赠/反应/被动）、资源与次数、恢复方式、数值（如伤害/加值/范围）、前置条件重申（与 `prerequisite` 字段一致）。示例风格（以"幸运 Lucky"为例，非原文照抄）："获得 3 个幸运点，长休后恢复；进行攻击、属性、豁免或技能检定前可消耗 1 点令另掷一次并选用较优结果；也可在攻击被掷出后消耗 1 点令敌人重掷攻击骰并取较差结果。"——具体表述按 2014 规则转述，不复制原书正文。
3. **状态提升**：42 项专长 `status` 由 `index-only` 改为 `implemented`；`sourceIds` 更新为 `['basic-rules-2014', 'phb-2014-index']`（SRD 可核验部分注明 Basic Rules，转述依据 PHB 索引）。
4. **校验联动**：`validate.ts` 的 `index-only-*` warning 逻辑保留（其他索引条目仍适用），专长选择不再触发该 warning；`feats-2014.test.ts` 增加"全部专长 `detail` 非空且 `status === 'implemented'`"断言。
5. 详情为只读展示数据，不进入自动计算；不新增 `CharacterDraft` 字段。

### R2 职业特性与子职特性详细效果登记

1. **字段**：`ClassFeature` 新增 `readonly description: string`（详细效果，展开区展示）；`SubclassFeature` 新增 `readonly description: string`；`summary` 保留为摘要行。
2. **职业特性登记范围**：12 职业约 140 条**全部**登记，内容在现有 `summary` 基础上扩展为要点式转述（触发时机、资源消耗与恢复、数值、持续/范围），与 R1 风格一致。示例（战士"回气 Second Wind"）：summary 为"以附赠动作恢复 1d10 + 战士等级的生命值；短休或长休后恢复使用次数。"，description 展开补充判定边界（如"仅在你的回合可用；使用后短休或长休恢复"）。
3. **子职特性登记范围**：570 条**全部**登记 `description`（一次性全量），风格与职业特性一致；`index-only` 条目同样登记详情（详情与状态分离：有详情不自动提升状态，状态提升仍需资料核验）。
4. 详情为只读展示数据，不进入自动计算。

### R3 角色卡"能力"页签展示专长与属性提升（新增区块）

1. **数据来源**：从 `draft.selections` 中读取（不新增草稿字段）：
   - **专长**：`optionIds` 中以 `feat-` 开头的选择（来源检查点包括 `ability-improvement` 检查点选择专长、变体人类 `race-2014-human-variant-feat-1` 检查点）；
   - **属性提升**：`optionIds` 中以 `asi-` 开头的选择，通过 `decodeAbilityImprovement(optionId)` 解码出模式与属性（`asi-str-2` → 单项力量+2；`asi-int-wis` → 智力+1、感知+1）。
2. **展示位置**：角色卡"能力"页签新增"专长与属性提升"区块，放在"职业特性"区块之后：
   - 专长条目：显示等级（检查点 `level`）+ 专长中文名 + 英文名，可展开查看 `detail`（`expandedLabel = "专长效果"`）；
   - 属性提升条目：显示等级 + 提升内容文案，格式为"属性提升（智力+2）"或"属性提升（力量+1、敏捷+1）"（复用 `ABILITY_LABELS` 中文名），不展开（无详情内容）；
   - 变体人类 1 级专长同样展示（等级 1）。
3. **排序与空态**：按等级升序排列；没有任何专长/属性提升时显示空态提示（如"尚未选择专长或属性提升"）。
4. 该区块为只读展示，不提供修改入口（修改仍在时间线完成）。

### R4 界面接入（复用法术/种族展开样式）

`ExpandableOptionCard` 组件与视觉/交互基线完全复用（右侧 `›` 箭头、双击展开、单击选择、键盘可达、展开状态局部 UI 不持久化），三处界面接入：

1. **`FeatChoicePanel.vue`**：专长列表由 `OptionCard` 换为 `ExpandableOptionCard`：
   - `title = 专长名 · 英文名`，`description = 现有摘要行`，`expandedLabel = "专长效果"`，展开区注入 `feat.detail`；
   - 移除"仅索引"徽标（`available` 时不再显示 warning 徽标；`不可选`时仍显示 error 徽标与 `disabled-reason`）；
   - 选择、搜索、筛选、"只看当前可选"行为不变。
2. **`CharacterSheetStep.vue` 能力页签**：
   - **职业特性区块**：平铺 `<li>` 换为 `ExpandableOptionCard`，`expandedLabel = "特性详情"`，展开区注入 `feature.description`；等级徽标与"需选择"标记保留（可移至 `suffix` 位）；

3. **`TimelineStep.vue`**：
   - 职业特性列表（首个职业检查点）与子职特性列表（subclass 检查点）的平铺条目换为 `ExpandableOptionCard`（或同视觉展开条目），展开区注入详情；`index-only` 特性带"仅索引"徽标逻辑保留；

## 4. 非目标与边界

- **不进入自动计算**：专长/特性的详细效果为只读展示数据；专长无派生效果接入，特性派生仍只由 `subclass-effects` 等既有机制负责。
- **不复制原书正文**：详情均为原创中文转述，遵守内容与版权约定；`detail`/`description` 字段不用于搜索之外的任何逻辑。
- **子职特性状态不因详情提升**：570 条子职特性全部登记 `description`，但 `index-only` 条目保持 `index-only` 状态（详情与状态分离；状态提升仍需资料核验）。
- **不新增 `CharacterDraft` 字段**：展开状态为局部 UI 状态，不持久化，导入导出兼容；角色卡专长/属性提升区块只读展示 `draft.selections`，不新增存储。
- **不修改 `ExpandableOptionCard` 组件本身**（复用现成能力；如确有需要仅做向后兼容扩展）。
- **不改变专长/特性的选择、校验、前置条件、资源与派生行为**。
- 不涉及 2024 规则；专长仍只在"属性提升或专长"检查点选择（变体人类 1 级专长不变）。

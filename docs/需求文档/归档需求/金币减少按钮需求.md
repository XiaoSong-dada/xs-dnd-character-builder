# 金币减少按钮需求

> 实施状态：**已实现**（v0.5.2，2026-08）。实施与验收见《金币减少按钮-更新计划.md》。

## 1. 背景与目标

用户反馈：角色卡"物品"页签的金币面板目前靠**输入负值再点「添加」**实现扣减（负值即扣减，见《角色卡物品与金币需求》R5 既有设计），但手机端数字键盘（`inputmode="numeric"`）**无法便捷输入负号（`-`）**，导致手机上扣减金币操作不友好。用户已确认方案：**新增一个「减少」按钮**——输入框只输入正数，点「减少」即按该数值扣减，不再依赖负号输入。

本次任务的产出（已确认）：

- 金币面板在「添加」「设置」旁新增**「减少」按钮**：将输入框数值作为扣减量从持有总额中扣除；
- 扣减的校验与错误提示复用现有逻辑（必须为整数、扣减后持有总额不得为负）；
- 输入框引导文案同步调整（去掉"可为负"引导，移动端不再暗示输入负号）；
- 数据模型、事件链路、导出格式**均不变**（仍以 `adventureGold` 为冒险净增金币的唯一事实源）；
- 桌面端既有**负号输入路径保留**（向后兼容，不破坏现有测试与已归档需求的行为约定）；
- 不做二次确认（扣减是数值调整而非删除，且可再添加回来，不属于不可逆操作）。

## 2. 现状调查（已核验）

| 层 | 位置 | 现状 |
|---|---|---|
| 金币面板 UI | `app/src/views/character-builder/components/CharacterSheetStep.vue` 719–730 行 | 展示持有总额 `currency.gp + adventureGold` GP；输入框（`inputmode="numeric"`，placeholder「输入金币数（添加可为负）」）+「添加」「设置」两个按钮 |
| 金币调整逻辑 | 同文件 `applyCurrency`（294–312 行） | `mode === 'add'` 时 `adventureGold += 输入值`（输入负值即扣减）；`mode === 'set'` 时直接设置持有总额（`净增 = 输入值 - 起始金币`）；校验 `/^-?\d+$/`，持有总额 `< 0` 提示「金币不能为负」 |
| 事件链路 | `CharacterSheetStep.vue` emit `changeAdventureGold` → `index.vue`（198 行）`@change-adventure-gold` → `useCharacterBuilderPage.ts` `updateAdventureGold`（415–416 行）→ `store.updateDraft({ adventureGold })` | 已有现成通道，「减少」按钮复用即可，无需新增事件或 store 改动 |
| 现有测试 | `app/test/components/CharacterSheetStep.test.ts` 861–906 行 | 已覆盖「添加（增量）」「设置（持有总额）」「负数总额被拒」「非整数被拒」；其中 `setValue('-5')` 后点「添加」= 扣减的用例依赖负号输入路径，本需求保留该路径 |

**结论**：

- 缺口只在一处：金币面板缺少显式"扣减"按钮，扣减能力被隐式绑定在"输入负号"上，移动端键盘无法满足。
- 「减少」按钮在实现上等价于 `applyCurrency('add')` 传负值，可复用同一函数（内部把输入值取负后走 `add` 分支），**无需改动规则层与数据层**；本次不改变任何规则行为，`docs/rules.md` 无需更新。

## 3. 需求项

### R1 界面：金币面板新增「减少」按钮（必须）

`CharacterSheetStep.vue` 金币面板操作区（`character-sheet__coin-actions`）在「添加」之后、「设置」之前（或「设置」旁，按钮顺序实现时按现有按钮样式自然排布）新增按钮：

- 按钮文案：**「减少」**；
- 复用现有按钮样式（`character-sheet__coin-actions button`，与「添加」「设置」一致，触控面积与现有按钮相同）；
- `aria-label="减少金币"` 或与现有按钮一致通过可见文案可达（屏幕阅读器可辨识），与「添加」「设置」保持同类可达性。

### R2 扣减逻辑（必须）

点击「减少」时，将输入框数值作为**扣减量**执行，等价于输入负值后点「添加」：

1. 输入为空或非整数（不匹配 `/^-?\d+$/`）：提示「请输入整数金币数」，不写入（复用现有校验）；
2. 输入为负值时按「添加」负值语义处理（`nextGold = adventureGold + 输入值`，即实际效果为扣减），与现状一致、不特殊处理；
3. 输入为 0：不产生变化（`adventureGold` 不变），可正常完成而不报错；
4. 计算扣减后持有总额 = `currency.gp + nextGold`，若 `< 0` 提示「金币不能为负」，不写入；
5. 合法时 `emit('changeAdventureGold', nextGold)`，并清空输入框与错误提示（与现有「添加」行为一致）。

实现建议：`applyCurrency` 增加 `mode: 'add' | 'set' | 'decrease'`（`decrease` 分支对输入值取负后并入 `add` 计算），保持单一校验出口，避免重复校验代码。

### R3 输入框引导与校验（必须）

- placeholder 由「输入金币数（添加可为负）」改为**「输入金币数」**——移动端不再引导输入负号；
- `inputmode="numeric"` 保持（手机弹出数字键盘，输入正数即可配合「减少」按钮使用）；
- 校验正则 `^-?\d+$` **保持兼容负号**（桌面端仍可输入负值点「添加」扣减，行为与已归档需求《角色卡物品与金币需求》R5 及现有测试一致，不破坏向后兼容）。

### R4 边界与一致性（必须）

- 持有总额下限为 0（与现有约束一致），**可减到 0**，不允许为负；
- 扣减仅作用于 `adventureGold`，不触碰 `currency.gp`（起始金币）、不触碰 `cp/sp/ep/pp`（保持现状）；
- 「减少」**不做二次确认**：扣减是数值调整、可逆（可再添加回来），不属于删除类不可逆操作；删除类操作才需确认（见《物品删除与数量调整需求》R3）；
- 不变更 `schemaVersion`、导出 JSON 结构、`InventoryEntry`/`CurrencyWallet` 类型。

| 用例 | 断言 |

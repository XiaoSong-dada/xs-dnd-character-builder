# 赛博骰娘移动端手势优化需求

## 1. 文档状态

- 需求版本：`v1.2`
- 当前状态：已评审（全部待确认事项已确认，可进入实施）
- 对应页面：`/dice`
- 前置需求：[`赛博骰娘需求.md`](./赛博骰娘需求.md)（R10 手机端视图缩放与移动，v1.1 已实现）
- 本文需求对象：移动端（手机、平板）浏览器下骰盘手势与页面手势的冲突治理

## 2. 背景与目标

`/dice` 页面 v1.1 已实现 R10 的"结果公布后双指缩放、双指平移、按钮等价操作"。真机使用反馈出现以下问题：

1. 手机端与 iPad 端浏览器中，手指双击会触发浏览器页面级放大缩小；
2. 手指左右移动骰盘视图不友好、且有时完全无法正常移动（不跟手或没有响应）；
3. 添加、减少骰子时，快速连续点击也容易触发页面放大缩小，操作被吞。

本阶段目标是治理浏览器原生手势与骰盘 3D 手势之间的冲突，做到：

- 骰盘交互与按钮操作时，浏览器双击缩放、捏合页面缩放不再介入或干扰；
- 结果公布后，双指平移与缩放跟手、可正常移动；
- 页面自身滚动能力保留；不全局禁用系统缩放（保留可访问性）。

## 3. 问题现象与根因分析

### 3.1 现象与根因对照

| # | 用户现象 | 根因 |
|---|---|---|
| 1 | 双击骰盘或任意位置触发页面放大缩小 | canvas 使用 `touch-action: pan-y`，该关键字**不禁用双击缩放**；iOS Safari / iPadOS 在 `pan-y` 元素上双击仍会缩放页面 |
| 2 | 手指左右移动不友好、无法正常移动 | 单指不控制相机（`touches.ONE = null`），且 `pan-y` 只允许纵向滚动；横向手势被浏览器忽略并进入双击判定等待，表现为"卡顿、无响应" |
| 3 | 双指平移视图不跟手、有时无法移动 | OrbitControls 的双指手势需要 `touch-action: none` 才能独占手势；`pan-y` 下 Safari 与 OrbitControls 竞争判定，`DOLLY_PAN` 跟手性差，双指捏合还可能直接缩放页面 |
| 4 | 添加/减少骰子时容易放大缩小 | 骰型卡片、骰池增减、投掷等按钮未声明 `touch-action: manipulation`，快速连点两次被浏览器判定为双击缩放手势，第二次点击被吞掉 |

### 3.2 代码依据（已核实）

- `app/src/views/dice/engine/dice-renderer.ts`：构造函数中 `controls.touches.ONE = null`、`controls.touches.TWO = TOUCH.DOLLY_PAN`、`canvas.style.touchAction = 'pan-y'`；`setInteractionEnabled` 在结果公布后启用、投掷/清空时复位。
- `app/src/views/dice/components/DiceTray.vue`：`viewControlsEnabled = status === 'complete' && Boolean(presentation)`，与交互启用状态对齐；放大/缩小/复位按钮已满足 44px 触控目标。
- `app/src/views/dice/components/DiceTypeSelector.vue`、`DicePoolPanel.vue`：按钮无 `touch-action` 声明。
- `app/index.html`：viewport 为 `width=device-width, initial-scale=1.0`，未使用 `user-scalable=no`（正确，保留不动）。

### 3.3 方案方向

采用**局部 `touch-action` 方案**，不依赖 `user-scalable=no`：

- 骰娘页面主体与全部可点击控件声明 `touch-action: manipulation`：整页禁用双击缩放、消除点击延迟，同时**保留双指捏合缩放**（可访问性不受损）；
- 骰盘 canvas 按交互状态切换：交互禁用期 `manipulation`（页面可滚动、禁双击缩放）；交互启用期 `none`（手势全部交给 3D 控件，浏览器缩放与滚动不介入）；
- 手势语义保持 v1.1 现状：双指捏合缩放、双指拖动平移，**不开放单指拖动**；
- 结果公布进入交互启用态时，在骰盘内展示双指操作提示，降低发现成本。

## 4. 已确认需求

1. 骰娘页面（含骰盘手势区与全部可点击控件）上，浏览器双击缩放不得触发；页面其他区域的双指捏合缩放保留。
2. 结果公布后，双指平移与缩放必须跟手，无浏览器手势竞争。
3. 手势语义保持双指：双指捏合缩放、双指拖动平移；不开放单指拖动，不改变 v1.1 既有语义。
4. 进入视图交互状态时展示双指操作提示，帮助用户发现手势。
5. 页面纵向滚动能力在非交互期保留；不全局禁用系统缩放（可访问性要求，WCAG 1.4.4）。
6. 视图缩放/平移仍然只改变摄像机，不改变物理世界、随机结果与总和（沿用 R10 约束）。

## 5. 功能需求

### R1 页面级双击缩放禁用（P0）

- 骰娘页面主体（含骰盘、按钮、结果区）在双击时不得触发浏览器页面缩放。
- 通过页面主体与控件统一的 `touch-action: manipulation`（或等价行为）实现；不得使用 `user-scalable=no` 或 `maximum-scale=1`。
- **双指捏合缩放必须保留**：页面文本与内容仍可通过捏合放大，不损害可访问性（WCAG 1.4.4）。

### R2 骰盘手势区 `touch-action` 状态机（P0）

- 视图交互禁用期（`idle` / `preparing` / `rolling`）：骰盘区域允许页面纵向滚动，同时禁止双击缩放。
- 视图交互启用期（`complete` 且存在展示结果）：骰盘区域手势全部交给 3D 视图控件，浏览器页面缩放、滚动、双击均不介入。
- 状态切换必须即时生效：进入 `complete` 后手势立即可用；开始新一轮投掷或清空骰池时立即恢复滚动与防双击状态。
- 手势区之外（结果区、骰池区）的页面滚动行为不得受影响。

### R3 按钮快速连点每次生效（P0）

- 骰娘页全部可点击控件至少包括：骰型卡片、骰池增减按钮、投掷、再次投掷、清空骰池、视图控制按钮（放大/缩小/复位）。
- 快速连续点击同一控件，每次点击都必须生效（如连点十次 `+`，数量增加十次），不得被双击手势吞掉，也不得触发页面缩放。
- 点击不得出现可见延迟（消除双击判定等待）。
- 键盘操作、焦点状态、禁用状态与读屏语义不得改变。

### R4 视图移动跟手性（P0）

- 双指平移与双指捏合缩放必须跟手，无浏览器手势竞争或吞事件。
- 现有缩放范围（全景为最小、最大为全景 3 倍）与平移边界限制保持与 R10 一致。
- 放大、缩小、复位按钮与手势行为一致，且与手势共用同一交互启用状态。
- 手势语义保持双指：单指行为与 v1.1 一致（单指用于滚动页面，不控制相机）。

### R5 双指操作提示（P0）

- 进入视图交互启用态（结果公布后）时，在骰盘内展示双指操作提示，告知玩家可用双指拖动/捏合查看骰盘。
- 提示文案默认建议："双指拖动移动视图 · 双指捏合缩放"（最终文案以实际体验为准）。
- 提示展示方式：骰盘内浮层，不阻断任何操作；短暂展示后自动消失（建议 3—5 秒），不反复打扰。
- 提示不得遮挡骰子结果或视图控制按钮的可操作区域；`prefers-reduced-motion` 下不播放动画。
- 提示应通过 `role="status"` 或等价方式对读屏柔和播报，不抢占焦点。

### R6 状态与生命周期一致性（P0）

- 手势启用期间修改骰池或开始新一轮投掷：自动复位视图，并恢复页面滚动与防双击状态（现有复位逻辑需与 `touch-action` 切换同步）。
- 新一轮结果公布再次进入交互启用态时，双指提示按 R5 规则重新展示。
- 组件卸载或页面离开：清除全部手势监听与 `touch-action` 覆盖，不残留影响其他页面。

### R7 桌面端与键盘等价（P1）

- 桌面端滚轮/触控板缩放、拖动平移与按钮操作行为不变。
- 视图控制按钮的 `focus-visible` 焦点样式、禁用状态保持不变。

### R8 真机验证矩阵（P1）

- 至少覆盖：iPhone（Safari）、iPad（Safari）、Android（Chrome）各一台真机。
- 双指捏合、双指平移、双击、按钮连点、提示展示五类场景在矩阵内全部验证。

## 6. 验收标准

### 6.1 自动化验证

1. 若引入可测试的手势状态逻辑（如交互状态到 `touch-action` 的映射），必须有单元测试覆盖三种状态的映射与切换。
2. 双指提示的展示与消失逻辑（含自动消失计时、新一轮结果重新展示）必须有单元测试。
3. 现有 R10 相关测试保持通过：缩放和平移只改变摄像机状态，不改变物理轨迹、随机结果或总和。
4. TypeScript 类型检查、相关测试和生产构建通过。

### 6.2 人工验证

1. 手机真机：结果公布后双击骰盘区域，页面不缩放；双击任意按钮，页面不缩放且每次点击都生效。
2. 结果公布后双指平移骰盘视图跟手；双指捏合缩放正常且页面本身不缩放。
3. 连续快速点击 `+` 十次：骰池数量正确增加十次，页面不缩放、无点击丢失。
4. 交互启用期之外（投掷中、未投掷）：单指上下滑动页面正常；交互启用期结束后滚动恢复正常。
5. 结果公布后出现双指操作提示，几秒后自动消失；提示存在期间按钮与手势均可正常操作；新一轮投掷结果公布后提示重新出现。
6. iPad 真机：上述 1—5 全部通过；页面双指捏合缩放仍可用（未被全局禁用）。
7. 开始新一轮投掷或清空骰池后：视图自动复位，页面滚动立即恢复，提示随交互状态正确隐藏。
8. 从骰娘页切换到其他页面再返回：无残留手势监听、无 `touch-action` 残留、无浏览器控制台错误。

## 7. 非目标

- 全局禁用浏览器缩放（`user-scalable=no`、`maximum-scale=1`）。
- 改变现有手势语义（如单指旋转相机、单指拖动视图、三指手势、双击复位）或新增手势。
- 修改物理模拟、随机结果、总和计算、20 秒超时降级等既有逻辑。
- 修改骰盘布局、骰子外观或视图控制按钮的位置与样式。

## 9. 已确认实现决策

1. 使用局部 `touch-action` 方案治理手势冲突，不动 viewport meta，不全局禁用缩放。
2. 骰娘页面主体与全部可点击控件统一声明 `touch-action: manipulation`，整页禁用双击缩放并保留捏合缩放；若项目需要，可沉淀为通用样式约定，但不得影响其他页面现有行为。
3. 骰盘 canvas 按交互状态切换 `touch-action`：交互禁用期 `manipulation`，交互启用期 `none`。
4. 手势语义保持 v1.1：双指捏合缩放 + 双指拖动平移，单指不控制相机；不新增拖动模式开关。
5. 手势启用状态继续以现有 `viewControlsEnabled`（`status === 'complete'` 且有展示结果）为唯一事实源，避免引入第二套状态。
6. 双指操作提示与交互启用态绑定：进入启用态展示、自动消失、新一轮结果重新展示；提示只做引导，不阻断操作。
7. 状态切换与现有复位视图逻辑在同一时机执行，保证视图与手势状态不出现中间态。
8. 兼容底线为 `iOS 15+` 与对应 Android Chrome，不兼容 iOS 15 以下旧版本；验收以该底线执行。

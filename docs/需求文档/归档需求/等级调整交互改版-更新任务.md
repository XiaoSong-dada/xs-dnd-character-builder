### 6.3 实施期发现并处理的问题

| 编号 | 问题 | 处理 |
| --- | --- | --- |
| 1 | `useModalLayer` 初版签名 `() => boolean` 与调用点 `toRef(props, 'open')` 不兼容（TS2345） | 签名改为 `Readonly<Ref<boolean>>`，两个弹窗传 `toRef(props, 'open')` |
| 2 | jsdom 下读不到 scoped CSS 的 `z-index`，层级断言无从下手 | 层级改为**内联 style**（`ComputedRef<{ zIndex }>`），断言读 `element.style.zIndex`；同时删除两处 CSS 固定值，避免双份来源 |
| 3 | 层级测试之间 Teleport 到 body 的节点互相干扰 | 测试内 `afterEach(() => { document.body.innerHTML = '' })`，并按标题定位节点 |
| 4 | 确认弹窗内「调回已提交值」后弹窗停留在旧待定值 | `requestChange` 的「无需确认」分支原先不清理 `pendingChange`；改为在该分支一并清空（变更已直接生效，旧待定已被取代） |
| 5 | 「完全无变化」的提交（滑杆松手回原位、重复选值）也会弹确认 | 新增 `isSameAllocation()`（职业集合/等级/子职、兼职开关、起始职业）；无变化时仍走轻量路径，保住「没有待办项就清空过期引导条」的既有行为 |
| 6 | 等级表格若随 `min/max` 变化会改变高度 | 固定渲染 1—20，越界用 `disabled` 表达；职业表格上限由 `getMaxClassLevel` 决定（兼职 19、单职业 20） |
| 7 | `<label>` 内不能放按钮（既有约定） | 展开按钮与 `LevelGrid` 均放在 `.allocation__slider`（`<label>`）之外；滑杆只在第 1／3 步渲染，弹窗形态无此约束冲突 |
| 8 | `normalizeMulticlass` 单遍钳制会把单职业 20 压成 19 | 改为两遍：先收集（含去重与合法性过滤），再按**最终职业数**取上限后钳制 |
| 9 | 关闭兼职原先「先写 `enabled=false` 再确认」，角色卡路径下确认弹窗随父弹窗卸载而消失 | 结构性修掉：控制内不再有合并确认弹窗，关闭即提交合并草稿，明细由页面确认弹窗的「本次变更」呈现（也消除了无谓的中间写入） |

### 6.5 剩余问题

1. **无职业（第 1 步尚未选职业）时仍走 `target-level` 轻量路径**（计划假设 A1）：此时不存在「职业与等级分配」可确认的内容，弹窗标题也不同；若希望也一律确认，需单独决策。
2. **确认弹窗内只提供 `±1` 续调**（不嵌表格）：连续大跨度调整仍需回到「调整等级」弹窗用等级表格；如需要可后续把表格放进弹窗（受弹窗高度限制）。
3. **历史保留态**（`enabled=false` 且多职业，D20 收窄前的草稿）仍只有只读提示与「重新启用」，没有一键合并入口。
4. 等级表格与卡片头部在极窄屏（<360px）的排版需真机确认；本项目按约定不做人工视觉验收，逻辑与结构已由组件用例覆盖。

### 7.2 已有角色卡「法术加不上也删不掉」（读写口径不对称）

| 环节 | 位置 | 判定 |
| --- | --- | --- |
| 读（事实源） | `rules/spellcasting.ts` `getClassSpellSelections()` | 只要该职业有分桶就以分桶为准（与职业数量无关） |
| 写（法术步骤） | `SpellcastingStep.vue` `emitScopeChange()` | 仅在施法职业数 > 1 时写分桶，否则写顶层数组 |
| 写（角色卡／跑团助手／抄录／预留） | `CharacterSheetStep.vue`、`useSessionPanel.ts`、`rules/spellbook.ts`、`rules/spellcasting.ts` | 一律直接改顶层数组 |

`services/draft-storage.ts` 的 v10 迁移原先只要草稿有 `classId` 就给起始职业建分桶 → **每张旧卡都恰好带一个分桶** → 单职业卡「读分桶、写顶层」，改动不可见（新建卡无分桶，因此正常）。

处理：
1. 新增 rules 写入口 `applyClassSpellSelections(draft, classId, next)`（单职业写顶层并顺手清掉遗留分桶；多职业以分桶为事实源、先补齐各职业分桶再写、最后刷新顶层并集镜像）；
2. 新增 `normalizeSpellSelectionBuckets(draft)`（幂等）：单职业折回顶层、多职业裁掉已移除职业的分桶；接入 `draft-storage.normalizeDraft`（**加载即修复旧卡**）与页面 `applyClassAllocation` 写入路径；
3. 迁移修正：只有真正的兼职（职业数 > 1）才建分桶；
4. 所有写入点改走统一入口（法术步骤、角色卡法术页签准备切换、跑团助手准备、法术抄录、法术精通／招牌法术预留）；
5. 附：法术名额已满时点击候选项不再静默无效，聚焦「当前名额已选满」提示。

测试：新增 `test/rules/spell-selection-buckets.test.ts`（11 项）、`test/components/SpellcastingStep-bucket-sync.test.ts`（3 项：新增／移除／满额反馈）；改写 `draft-storage-v10.test.ts` 两条锁定旧行为的断言并新增旧卡修复用例；`CharacterSheetStep.test.ts` 新增「带残留分桶的准备切换」。**强度抽验**：把 `emitScopeChange` 临时改回旧写法，新增／移除两个用例双双失败。

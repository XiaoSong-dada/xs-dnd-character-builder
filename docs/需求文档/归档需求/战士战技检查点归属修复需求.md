# 战士战技检查点归属修复需求

## 1. 背景与目标

用户反馈：选择战士职业、子职选择**非战斗大师**（如勇士 Champion）时，进入时间线（车卡"能力与专长"选择步骤）仍会出现**战斗大师专属的"选择战技"检查点**，且未完成时校验报 `error`、角色卡显示"待补全"，导致非战斗大师战士也被强制要求选择战技。用户怀疑"战斗大师的职业特性被放到了所有战士职业选择上"。

排查结论：**怀疑成立**，根因已核验（见 2.2）。本需求目标：

- 战技检查点只对战斗大师子职生效；勇士、奥法骑士等非战斗大师战士不再被要求选择战技。
- 顺带登记排查中发现的相关问题（战技数量已核验与 PHB 一致、数据冗余、测试锁定错误行为），按决策项处理。

## 2. 现状调查（已核验）

### 2.1 发现的问题清单

| 编号 | 问题 | 严重度 | 性质 |
|---|---|---|---|
| **P1** | 战斗大师的战技检查点被定义为战士**职业级无条件检查点**，所有战士（含勇士/奥法骑士）都被强制要求选择战技，校验拦截、角色卡"待补全" | 高（功能错误） | 本需求必须修复 |
| **P2** | 战技数量核验（2026-08 对照 PHB 2014 原文）：官方标准为 3 级 3 项、7/10/15 级各 +2（合计 9），当前代码与 `docs/classes/subclasses/fighter/fighter-battle-master-2014.md` 资料**一致，无需修复数量**；但 `subclass-features-2014.ts`"战斗超驰"摘要写"四项战技选择"，与"3 级 3 项"表述矛盾，属文案笔误（应为"三项"），随 R1 同步修正 | 低（文案） | 文档/数据同步修正 |
| **P3** | 数据冗余与测试锁定：`fighter.ts` 子职检查点 `optionIds` 写死仅战斗大师（运行时被 `buildSubclassCheckpoint` 覆盖，误导维护者）；9 个测试文件断言"战士时间线无条件含战技检查点"（`timeline-2014.test.ts` 13—18 行等），锁定错误行为 | 低—中 | 随 R1 一并清理 / 更新 |

### 2.2 P1 根因证据链（已核验）

1. **数据层** `app/src/rules/data/fighter.ts`：`fighterRule.checkpoints` 中 4 个 `kind: 'maneuvers'` 检查点（`fighter-2014-maneuvers-3/7/10/15`，`required: true`，`minSelections: 3/2/2/2`）与技能、战斗风格、子职、属性提升检查点**平级**存在，无任何子职归属条件。
2. **装配层** `app/src/rules/timeline.ts`：`buildTimeline` 对 `classRule.checkpoints` 全部条目仅按 `targetLevel` 过滤，**不按 `context.subclassId` 过滤**；子职特性检查点（`subclass-feature-*`）才按 `subclassId` 追加。故任何战士都会拿到 4 个战技检查点。
3. **校验层** `app/src/rules/validate.ts`（196—205 行）：`checkpoint.required && count < minSelections` → 报 `error`；战技唯一性校验（253—254 行）按 `kind === 'maneuvers'` 跨检查点查重。
4. **界面层** `app/src/views/character-builder/components/TimelineStep.vue`（27 行）：`buildTimeline(...)` 渲染全部检查点并要求选择。
5. **反向印证**：`subclass-features-2014.ts` 战斗大师"战斗超驰"（`fighter-battle-master-combat-superiority`）已登记 `requiresChoice: true` 与 11 项战技 `optionIds`，但 `timeline.ts` 的 `SUBCLASS_FEATURE_CHECKPOINT_EXCLUSIONS` 将其排除（注释"已由职业时间线检查点承接选择"）——设计意图是战技选择由检查点承接，但承接载体放错了层级（职业级而非战斗大师专属）。

### 2.3 相关机制现状

- `app/src/rules/dependency.ts`（76—88 行）：换子职（`change.kind === 'subclass'`）只作废 `-subclass-` 与 `subclass-feature-` 前缀的选择；**`fighter-2014-maneuvers-*` 前缀不在作废范围**（换子职后旧战技选择残留不失效）。
- `dependency.ts`（93—101 行）：升降级按 `buildTimeline` 新旧时间线计算 `added`/`invalidated`，含战技数量 `reviews`（"战技数量由 3 项减少为 2 项"）。
- 战技 11 项全部 `index-only`（`maneuver-*`，PHB 索引），只保存选择不参与派生计算。

## 3. 需求项（要修复的问题）

### R1 战技检查点只对战斗大师生效（修复 P1，必须）

1. 勇士、奥法骑士等非战斗大师战士：时间线**不得出现**战技检查点；校验不拦截；角色卡不显示"待补全"。
2. 战斗大师子职：仍要求完成战技选择（3/7/10/15 级各 3/2/2/2 项，已核验与 PHB 2014 一致）。
3. 保持既有语义：跨等级战技不可重复（`validate` 唯一性校验）、升级/降级影响计算（`dependency` 的 `added`/`invalidated`/战技数量 `reviews`）在战斗大师下正确。
4. 修复方案二选一（或分两步，见第 5 节决策点）：
   - **方案 A（推荐）**：战技检查点子职特性化——从 `fighter.ts` 职业级 checkpoints 移除 4 个 `maneuvers` 检查点；`subclass-features-2014.ts` 为战斗超驰/额外战技特性补充多选规格（`minSelections`/`maxSelections`）；`timeline.ts` 的 `buildSubclassFeatureCheckpoints` 支持按特性多选生成检查点并移除排除项；`validate.ts` 唯一性校验适配新检查点。顺带收益：换子职时 `dependency` 的 `subclass-feature-` 前缀作废逻辑自动覆盖旧战技选择。
   - **方案 B（最小止血）**：`buildTimeline` 中 `kind === 'maneuvers'` 检查点仅当 `context.subclassId === 'subclass-2014-fighter-battle-master'` 时保留。改动小，但数据语义仍错位、换子职旧选择残留不失效。

### R2 回归测试（必须）

1. `test/rules/timeline-2014.test.ts`：勇士/奥法骑士时间线无 `maneuvers` 检查点；战斗大师时间线有且数量正确。
2. `test/rules/validate.test.ts`：非战斗大师战士未选战技 → 无战技检查点 error；战斗大师未选满 → 仍报 error。
3. `test/rules/dependency.test.ts`：换子职为勇士后旧战技选择按方案作废/失效；降级战技数量审查仅在战斗大师下出现。
4. 逐一核对 9 个引用 `fighter-2014`/maneuvers 的测试文件（`CharacterSheetStep`、`FeatChoicePanel`、`useCharacterBuilderPage`、`class-features-2014`、`dependency`、`derive`、`timeline-2014`、`validate`、`character-drafts`），更新锁定了无条件战技检查点的断言。

### R3 文档同步（必须）

1. 本文件末尾登记实施状态；`docs/rules.md`（如规则行为变化：战技选择归属约定）、`docs/dnd-classes.md`（如子职资料变更）、`docs/frontend-architecture.md`（如新增模块/组件）同步更新；`docs/classes/subclasses/fighter/fighter-battle-master-2014.md` 已核验与 PHB 一致，无需修改。
2. 交付说明写明"已复核前端依赖拓扑，已更新/无需更新"。

### R4 数据清理（修复 P3，随 R1 一并处理）

- `fighter.ts` 子职检查点 `optionIds` 与 `buildSubclassCheckpoint` 覆盖逻辑消除重复来源（保留装配层为唯一事实源，或移除写死的 optionIds）。

## 4. 非目标与边界

- **不调整战技效果数据**：11 项战技保持 `index-only` 索引，不进入自动计算。
- **不修改其他职业时间线结构**：仅战士存在 `maneuvers` 类检查点，本需求只收束战士。
- **战技数量不修改**：已对照 PHB 2014 核验——官方标准即 3 级 3 项、7/10/15 级各 +2（合计 9），当前实现与资料一致；仅随 R1 修正"战斗超驰"摘要文案"四项战技"→"三项战技"。
- 不改变"换子职作废/保留"的既有总体约定；`dependency` 作废范围仅在方案 A 下顺带覆盖战技前缀。

## 5. 已确认决策（2026-08 用户确认）

1. **修复方案**：采用方案 A（完整修复——战技检查点子职特性化，数据语义正确），不做方案 B 止血过渡。
2. **战技数量**：已对照 PHB 2014 核验——官方标准为 3 级 3 项、7/10/15 级各 +2（合计 9），与当前实现一致，**不修复数量**；仅同步修正"战斗超驰"摘要文案"四项战技"→"三项战技"。
3. **验收范围**："能力与专长页面"按时间线步骤（交互选择）与角色卡"能力"页签（只读展示）两面验收。

## 6. 验收标准

1. `pnpm test:run` 全量通过（R2 用例覆盖合法输入、非战斗大师无战技检查点、战斗大师必选、跨检查点不重复、升级/降级/换子职边界）。
2. `pnpm build`（`vue-tsc -b && vite build`）通过。
3. 手机宽度流程走查：
   - 战士 + 勇士（3 级）：时间线无"选择战技"检查点，校验通过，角色卡无"待补全"；
   - 战士 + 战斗大师（3 级）：时间线有战技检查点，未选满报可理解的中文错误，选满后通过；
   - 战士 + 战斗大师升至 10 级：新增战技检查点出现在升级"待补全"引导中；
   - 战斗大师换子职为勇士：旧战技选择按方案作废/失效提示，新时间线无战技要求；
   - 战士 + 奥法骑士：与勇士一致无战技检查点。
4. 无浏览器控制台错误。

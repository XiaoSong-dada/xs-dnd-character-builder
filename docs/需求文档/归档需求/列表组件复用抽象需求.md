# 列表组件复用抽象需求

## 1. 背景与目标

职业、种族、背景、法术、专长、装备等**卡片列表**遍布车卡流程各步骤，条目渲染已统一使用全局组件（`ExpandableOptionCard`/`OptionCard`），但**列表容器层没有任何抽象**：搜索框、分类筛选、空状态、滚动容器、计数徽章、标题等外壳能力在每个页面各自手写，类名不统一、样式易漂移（`AddItemModal` 滚动列表布局 bug 即为手写容器各写各的代价），新增同类列表时无法复用。

目标产物：

- 新增全局**容器壳组件 `ListShell`**（无业务感知），统一提供：可选标题与计数徽章、可选搜索框、可选分类筛选 chips、空状态、可选滚动容器、条目网格容器。
- 条目层保持不变：`ExpandableOptionCard`/`OptionCard` 原样复用，状态映射、过滤逻辑、分组结构、上限逻辑、suffix/展开内容等业务差异**全部留在调用方**。
- 试点迁移 3 处（`FeatChoicePanel`、`OriginStep`、`SpellcastingStep`）覆盖全部外壳能力面，验证方案后推广到其余列表。

## 2. 现状调查（已核验）

### 2.1 条目层：已全局抽象

| 组件 | 用途 | 能力 |
|---|---|---|
| `components/ui/ExpandableOptionCard.vue` | 7 处（职业/种族/背景/法术/装备/角色卡物品/添加物品弹窗） | `title/description/expandedLabel/state(7 态)/disabledReason/expandOnSelect`；`select/toggle` 事件；`suffix/expanded` 插槽；单击选择（250ms 双击判定）、箭头展开、锁定禁用、✓ 标记、选中/推荐视觉 |
| `components/ui/OptionCard.vue` | 3 处（专长/时间线/Setup） | `title/description/state/disabledReason`；单击即选；`suffix` 插槽 |

### 2.2 容器层：全部手写，无统一组件

| 能力 | 现状（已核验的页面） |
|---|---|
| 容器 | 全部 `display: grid; gap`，类名各自为政（`__list`/`__options`/`__level`） |
| 搜索框 | 仅 `OriginStep`（中英文名过滤）、`FeatChoicePanel` 有，手写 `label+input`，样式不统一 |
| 分类筛选 chips | 仅 `FeatChoicePanel`（6 个：战斗/施法/属性/探索/支援） |
| 空状态 | 仅 `FeatChoicePanel`（带"清除筛选"按钮）、`AddItemModal` 有 |
| 滚动容器 | 仅 `FeatChoicePanel`（max-height 30rem）、`AddItemModal` 有 |
| 计数徽章/完成度 | `SpellcastingStep`（已选/需求）、`EquipmentStep`（完成度）手写 |
| 分组标题 | 按环级/基础-分支/装备组/checkpoint 各自手写 |

### 2.3 共性（可抽象）与差异（抽象边界）

**可抽象**：搜索框、筛选 chips、空状态、滚动容器、计数徽章、列表网格容器——纯 UI 结构，无业务语义。

**差异（应留在调用方）**：

- 状态语义：法术书用 `complete`（绿）、专长用 `incompatible`（仅索引可点）/`locked`+动态原因、时间线锁定逻辑最复杂、职业用 `recommended`。
- 分组：法术按环级、种族/背景按基础-分支、装备按装备组、时间线按 checkpoint。
- 过滤规则：中英文名搜索（Origin）vs 分类+可用性（Feat）vs 无过滤（Class/Spell/Timeline/Equipment）。
- 上限逻辑：法术三档数量、时间线 `maxSelections`、语言上限、装备 picker 计数。
- suffix/展开区内容：徽章/纯文本/数量按钮/成长列表/详情+meta。

## 3. 需求项

### R1 新增全局容器壳组件 `ListShell`（核心）

新增 `app/src/components/ui/ListShell.vue`，**无业务感知**，只做 UI 结构与状态透传：

| Props | 说明 |
|---|---|
| `title?: string` | 列表标题（可选） |
| `count?: number` / `countLabel?: string` | 计数徽章（如"已选 3/5"，可选） |
| `searchable?: boolean` | 显示统一搜索框；`searchPlaceholder?` 自定义占位 |
| `query: string` | 搜索词，`v-model:query` 双向绑定（**过滤逻辑由调用方 computed 执行**） |
| `filters?: readonly {id; label}[]` | 分类筛选 chips 配置 |
| `filter: string` | 当前筛选，`v-model:filter` 双向绑定 |
| `emptyText?: string` | 空状态文案（默认"没有匹配的条目"） |
| `maxHeight?: string` | 设置后内部提供滚动容器（**滚动容器在最外层**，避免滚动 grid 行高退化问题） |
| `grid?: boolean`（默认 true） | 插槽外自动包 `display: grid; gap: 0.5rem` 容器；分组场景可关闭自行布局 |

Slots：`default`（条目，继续用 `ExpandableOptionCard`/`OptionCard` 填充）、`header`（自定义头部）、`empty`（自定义空状态）。

**边界约束**：

1. 组件不感知业务数据：不内置过滤/排序/状态映射，全部由调用方通过 `v-model` 与插槽完成。
2. 条目层组件（`ExpandableOptionCard`/`OptionCard`）不改动。
3. 滚动容器实现沿用已验证模式：**外层滚动 + 内层非滚动 grid**（与 `AddItemModal.__list-scroll` 同构），展开条目行高按内容正常计算。

### R2 试点迁移 3 处（验证方案）✅ 已完成（2026-08-12）

1. **`FeatChoicePanel.vue`**（能力最全）✅：搜索框、分类 chips、可用性 checkbox（header 插槽）、滚动容器、空状态（empty 插槽，保留"清除筛选"按钮）、计数徽章全部接入 `ListShell`。
2. **`OriginStep.vue`**（搜索 + 分组）✅：种族/背景两段搜索接入 `searchable`；子种族/变体的金色边框分组与语言选择保持调用方原样（无搜索需求，`ListShell` 无收益）。
3. **`SpellcastingStep.vue`**（计数 + 多段）✅：戏法/法术书/按环分组三区各用 `ListShell`（`title` + `count` 徽章）；三档上限、`complete` 状态映射、suffix 文本、页面级 header 计数零改动。

试点验收（已通过）：三处页面行为不变（选中/展开/上限/过滤逻辑零改动），仅结构与样式来源切换；`FeatChoicePanel.test.ts`/`OriginStep.test.ts`/`SpellcastingStepBard.test.ts` 全绿；无头 Chrome 视觉回归通过（Origin 搜索过滤+展开、Feat 6 chips/滚动/空态/42 卡片、Spell 三区标题计数+展开）。

- **`EquipmentStep`** ✅：装备分支选项列表与 picker 列表接入 `ListShell`（picker 的"已选 x/y"文本改用 `count` 徽章）。

验证（已通过）：`pnpm test:run` 43 文件 250 tests 全绿；`pnpm build` 成功；无头 Chrome 回归（角色卡 items 两区块展开、弹窗搜索+chips+添加生效、时间线 checkpoint 列表、装备步骤 4 个 ListShell）全部通过。测试选择器统一限定 `.ui-modal` 内解决弹窗与角色卡 `ListShell` 的选择器歧义。

## 4. 决策记录

- 抽象粒度：**容器壳 `ListShell`**（用户确认 2026-08-12）；不采用数据驱动 `ExpandableList`（状态语义差异大，配置面过宽）。
- 迁移范围：**试点 2-3 处再推广**（用户确认 2026-08-12）。
- 条目层 `ExpandableOptionCard`/`OptionCard` 保持不动。

- 必选项由玩家选择，系统自动校验并派生合法选择的常驻数值、法术与次数。临时状态只展示规则条件，不新增回合、化形、位移、伤害或治疗引擎。

## 4. 限定工具契约（A5 落地）

拟扩展 `RaceRule.toolProficiencyChoices`：保留 `count`，新增可选 `optionIds` 和 `required`。未声明候选时沿用原工具池；未声明必选时沿用旧种族缺选提示级规则，不把历史草稿突然变为必选阻塞。

- 半羊人 `count: 1`、`required: true`，候选引用 `equipment-2014.ts` 的十种具体乐器，不使用抽象「一种乐器」选项。装备ID为 `lute`、`bagpipes`、`drum`、`dulcimer`、`flute`、`horn`、`lyre`、`pan-flute`、`shawm`、`viol`；生成选择ID时使用项目实际注册格式，不混淆装备ID与规则选项ID。
- 原始选择继续保存到 `raceToolChoice`。非法工具、缺选、来源停用分别校验；来源停用保留原始值但不授予熟练，恢复来源后重新验证。
- `origins.getSpeciesProficiencyBlockers` 当前在无技能选择规格时提前返回，必须拆开技能/工具校验，保证只有工具必选的半羊人也能阻塞。旧吉斯洋基人技能/工具互斥仍独立回归。
- `OriginStep.vue` 工具候选按有效来源链和限定池解析，不能只按泛工具前缀筛选；必选任务的完成状态与最终校验一致。
- 拟新增纯规则解析入口 `getSpeciesToolProficiency(draft, repository)`，返回有效具体工具及授予来源；缺选/失效不输出收益。角色卡、跑团助手及共享导出使用同一结果显示具体名称，不单独猜测。
- `count > 1` 不在本批存储改造范围；十选一不需要更改现有草稿标量字段。日后真实消费者需要多工具时另定兼容方案。

## 5. 种族选择契约（B4 落地）

拟在 `RaceRule` 增加声明式选择规格，复用检查点现有的 `id/level/required/minSelections/maxSelections/optionIds` 与 `parentCheckpointId/parentOptionId`。效果声明引用选择ID和选项ID，仅允许已有的技能、戏法、特性、资源等白名单效果，不引入任意表达式执行器。

原始值仍存入 `CharacterDraft.selections`。检查点ID采用 `race-2014-motm-<slug>-<choice>`，不复用2024或旧版ID；技能/法术等候选需按规则集与有效来源解析。实施采用既有时间线收集声明式种族选择，避免在起源页复制检查点引擎；按等级取得的必选项进入相应等级任务，不让未达等级阻塞低级角色。

| 种族 | 主选择 | 依赖与生效边界 |
| --- | --- | --- |
| 化兽者 | 1级四种化形之一 | 野兽本能四技能选一独立于化形；化形资源按熟练次数，四种临时效果只展示 |
| 狗头人 | 1级三种龙裔遗赠之一 | 技艺分支五技能选一；抗惧分支无子任务；龙裔法术分支术士戏法及智/感/魅必选，离开该分支后子选择保留但停用 |
| 阿斯莫 | 3级三种天启之一 | 1—2级不要求天启；光亮术固定魅力，不因天启创造自由施法属性；天启单次长休，选择在3级固定，不套用2024每次使用时选择 |
| 雅灵 | 1级季节及智/感/魅选择 | 妖精步3级附加效果使用所选属性；季节改变提示需完成出神；本期不增加休息状态机，也不把每次释放效果变成永久选择 |

纯规则解析统一输出有效选择、检查点与非法原因，供 timeline/origins/validate、熟练、法术、特性和资源消费。不得由 UI 与 derive 各写一套分支条件。

解析顺序：有效种族及来源 → 等级 → 父选择唯一且合法 → 本选择数量/重复/候选合法 → 派生效果。缺选、非法选择、等级不足或来源失效均不授予该项收益；无效值不删除，不映射成默认有效分支。分支切换、降级、停用及恢复来源均保持存储原值并重新解析。永久授予去重，临时出神熟练只记说明。

## 6. 逐授予施法契约（B3 落地）

当前 `SpeciesSpellGrant` 只有逐法术免材料字段，`collectSpeciesSpellGrants(race, level)` 尚不接受草稿依赖选择。拟增加草稿级有效授予解析入口，供现有聚合管道使用；保留旧调用者的兼容路径，不能让法术资源、列表与展示分别判定来源。

拟增加的逐授予字段：

- 成分豁免集合，值为语言/姿势/材料；旧 `waivesMaterialComponents` 映射为材料豁免，未声明则不豁免。仍保留法术原始成分、专注及施法时间。
- 明确 `canCastWithSpellSlots`；新 MotM 条目逐项显式声明。旧条目未声明时沿用原行为，不通过缺省值静默禁止旧法术。
- 无次数消耗路径标志 `atWill` 与目标限制声明（本期需要「仅蛇」及「自身」）及中文说明；前者不是有限资源，后者不提供自动场景目标验证引擎。
- 每次施放先选授予来源及路径：有限免费、合适法术位、无限次不耗位。免费只扣该授予独立次数；法术位只扣相应法术位；无限次不扣资源。没有许可不得借种族授予打开法术位路径。
- 施法属性从当前有效授予解析；职业与种族同名法术可以共享列表显示，不能合并属性、免成分、次数或目标限制。免成分说明适用于通过该特质施放的路径，不污染职业施法。
- 非施法职业也展示种族施放入口；没有法术位就不提供法术位操作。使用普通法术位和契约法术位均验证环级与项目现有规则。

## 7. 天生护甲契约（B5 落地）

拟为 `RaceRule` 增加结构化 `naturalArmor`：基础值、是否加入敏捷、允许穿甲/屏蔽穿甲收益、允许盾牌。当前需求只声明蜥蜴人和龟人的公式；禁止解析描述文本来计算 AC。

1. 根据有效来源、等级、装备及各公式自身条件构造候选：普通无甲、已装备护甲、有效职业无甲防御、自然护甲等。各候选独立计算，不把两个基础值或属性相加。
2. 蜥蜴人自然候选为 `13 + Dex`，合法时与穿甲及职业公式比较。龟人自然候选为固定17、不加敏捷；保留穿甲记录并提示非法着甲，忽略其护甲AC和依赖穿甲的收益，其他合法无甲公式仍按自身条件比较。
3. 2026-10-08 复核修正：基础护甲公式不叠加。蜥蜴人合法穿甲时，即便使用天生基础公式，仍保留满足「穿着护甲」条件的防御风格、强化防御灌注与魔法护甲加值，各加一次；不能将穿甲条件误写成「必须使用穿甲基础公式」。龟人非法穿甲不授予这些收益。通用魔法护甲未声明具体底甲时不猜测底甲；本阶段仅保证天生护甲拥有者的明确魔法加值。
4. 盾牌只按手动装备状态及版本/公式适用条件加入。武僧无甲防御有盾时不是合法候选；野蛮人按现有合法条件处理。魔法盾牌及盾牌灌注不得重复计算。
5. 选择最终合法候选，人工 AC 修正最后仅加一次。明确持盾与双手武器冲突继续保留持盾AC并提示，不自动卸装备。

龟壳防御的临时 +4、卧倒与行动限制只展示，不制造常驻加值或次数资源。自然护甲来源停用时立即不生效，装备与人工修正原值保留。

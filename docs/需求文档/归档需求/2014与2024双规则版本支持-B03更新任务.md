## 1. 目标与范围

B02 已让纯规则层识别两个版本，但 `CharacterDraft` 仍固定 `5e-2014`、存储只写 v7 键。本批只解决“原始选择与版本存得住、取得回、导得出”，为 B04—B09 提供安全的数据底座。

- 本次范围：草稿类型与格式、迁移、存储键、导入导出、跑团状态与图片引用回归。
- 规则版本：`5e-2014` 保持现状；`5e-2024` 仅数据层（服务、存储、测试）可用。
- 完成里程碑：与 B02 共同满足 M1“基础隔离可验证”，仍不代表可以完整车卡。

确认记录：D2、D3、D4、D7 于计划评审时确认；D1、D5、D6 于 2026-09-11 确认。实现开始前不再变更本表；如需调整，先修订本节并说明影响的步骤与测试。

D1 理由：若沿用 schema 7 只加 `ruleset` 字段，旧部署版本（当前线上构建）会按 `isDraft` 过滤掉 2024 记录，并在任何一次 `saveAll` 中把该键整体覆盖，造成 2024 草稿静默丢失；升 v8 并换键后，新旧版本各自读写自己的键，互不破坏。单数组的理由：草稿列表、删除、图片清理、跑团状态与导出都按草稿 id 工作；版本是角色事实（需求 5.1），放在记录内可避免“键与字段两个事实源不一致”，也让两版共存时的保存是原子操作。

## 5. 数据格式、迁移与错误处理

### 5.1 v8 草稿

- 字段变化仅两处：`schemaVersion: 8`；`ruleset: RulesetId`（创建后不可修改，`updateDraft` 继续排除）。
- 其余字段与 v7 完全一致；`media` 仍只保存引用，二进制仍在 IndexedDB。
- 2024 默认值：`targetLevel: 10`、`abilityMethod: 'standard-array'`、默认属性数组与 2014 相同、`enabledSourceIds: []`。

### 5.2 存储与迁移

| 键 | 用途 |
| --- | --- |
| `dnd-character-builder:drafts:v8` | 当前读写键，两版草稿同一数组 |
| `dnd-character-builder:drafts:v7`—`v2` | 只读迁移来源（v2—v7 均为 2014），保留不删除 |
| `dnd-character-builder:drafts:v1` | 旧 2024 只读隔离区，`loadLegacy` 与 `exportLegacyDraft` 不变 |
| `dnd-character-builder:drafts:unsupported:v1` | 无法识别条目的隔离区：`{ fingerprint, raw, reason, detectedAt }`，按 `fingerprint` 去重 |

- `migrateDraftToV8`：接受 v2—v7 且 `ruleset === '5e-2014'` 的记录，补齐缺省字段后写 `schemaVersion: 8`；保留 `migrateDraftToV7`／`v6`／`v5` 兼容别名，避免无意义改名扩散。
- `isDraft`：`schemaVersion === 8` 且 `isRulesetId(ruleset)` 且 `id` 为字符串。
- 迁移只发生在读取路径，不重写旧键；首次 `saveAll` 后数据同时存在于旧键与 v8 键。

### 5.3 导入错误与中文原因

| 输入情形 | 处理 | 中文原因 |
| --- | --- | --- |
| v8 + `5e-2014`／`5e-2024` | 接受 | — |
| v2—v7 + `5e-2014` | 迁移后接受 | — |
| v2—v7 + `5e-2024` | 拒绝 | 该文件是旧版 2024 草稿格式，暂不支持导入；请保留原文件作为备份。 |
| v8 + 未知 `ruleset` | 拒绝 | 不支持的规则版本：{值}。 |
| 缺少或类型错误的 `ruleset` | 拒绝 | 角色文件缺少有效的规则版本。 |
| 未知 `schemaVersion` | 拒绝 | 角色文件版本不受支持。 |
| 缺 `id`／`baseAbilities`／`selections` | 拒绝 | 角色文件缺少必要字段。 |
| 损坏 JSON | 拒绝 | 文件不是有效的 JSON。 |
| 当前键中的非法条目 | 隔离保留 | 与上表同因由，写入隔离区 |

- 错误输入不得新增草稿、不得覆盖隔离区以外的任何记录；隔离区写入失败（例如存储已满）时，无法解析的条目会暂存并由 `saveAll` 回写当前键，避免静默丢失。

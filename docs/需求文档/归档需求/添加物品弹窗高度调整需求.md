# 添加物品弹窗高度调整需求

> 2026-08-26 制定。本需求为 v0.9.1 添加物品弹窗（布局固定 + 按钮式筛选 + 目录延迟加载）之后的体验迭代，仅调整弹窗高度，不改变已确认的交互与加载行为。
>
> 实施更新（2026-08-26）：`UiScrollModal` 已新增 `maxHeight` 属性（默认 `min(80dvh, 42rem)` 不变），“添加物品”弹窗传入 `min(96dvh, 60rem)`，随 v0.9.2 发布；抄录法术书未传该属性，行为不变。

## 1. 背景与目标

“添加物品”弹窗基于 `UiScrollModal` 容器，其内容区最大高度当前为 `min(80dvh, 42rem)`（42rem = 672px）。在桌面与平板设备上，弹窗偏矮，浏览长物品列表时可视条目少、频繁滚动；移动端小屏下 80dvh 也仍有提升空间。

目标产物：

- 调高“添加物品”弹窗高度，移动端接近占满屏幕，桌面端显著提高。
- 必要时允许弹窗占满整个屏幕。
- 保持 v0.9.1 已确认行为不回归：标题、搜索框、筛选按钮行与展开面板、底部数量与添加按钮固定，仅物品结果列表滚动；按钮式筛选与目录按需加载行为不变。
- 不影响 `UiScrollModal` 其他调用方（抄录法术书弹窗保持现状）。

## 2. 已确认方案

`UiScrollModal` 新增可配置属性 `maxHeight`（CSS `max-height` 值），默认值保持现有 `min(80dvh, 42rem)`；“添加物品”弹窗传入调高后的值。抄录法术书不传该属性，继续使用默认高度。

建议目标值（可在实施时按视觉效果微调）：

- 移动端：约 `96dvh`（接近占满屏幕，保留少量视觉边距）。
- 桌面端：约 `60rem`（960px，相比当前 672px 提高约 43%）。
- 组合表达式：`min(96dvh, 60rem)`。

若后续需要真正“占满屏幕”，同一机制下传入 `100dvh` 即可，不新增结构。

## 3. 需求点

### R1 高度可配置

1. `UiScrollModal` 支持 `maxHeight?: string` 属性，透传到内容区 `section` 的 `max-height`。
2. 默认值必须保持现有 `min(80dvh, 42rem)`，未传属性的调用方（抄录法术书）视觉零变化。

### R2 添加物品弹窗调高

1. `AddItemModal` 传入调高后的 `max-height`（目标 `min(96dvh, 60rem)`）。
2. 弹窗高度变化不影响内部布局：搜索框、筛选按钮行、展开面板与底部操作区仍固定，只有物品结果列表滚动。

### R3 全屏预案

1. 同一 `maxHeight` 机制支持 `100dvh` 全屏；本轮不强制全屏，仅保证机制可用。

### R4 不回归

1. 抄录法术书弹窗高度与滚动行为不变化。
2. 筛选交互、目录延迟加载、加载失败重试、自定义物品入口等行为不变化。

## 4. 验收标准

1. 添加物品弹窗在手机尺寸下高度明显提升并接近占满屏幕；桌面尺寸下明显高于 672px。
2. 弹窗内仅结果列表区域滚动，搜索框、筛选按钮与展开面板、底部操作区固定。
3. 抄录法术书弹窗高度与滚动行为与改动前一致。
4. 类型检查、相关自动化测试与生产构建通过。

## 5. 涉及模块

- `app/src/components/ui/UiScrollModal.vue`（新增 `maxHeight` 属性，默认值不变）
- `app/src/components/AddItemModal.vue`（传入调高后的值）

依赖方向不变：`components/AddItemModal -> components/ui/UiScrollModal`。

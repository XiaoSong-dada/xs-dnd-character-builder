1. **先读**：改规则先读 `docs/rules.md`；改背景／专长资料先读 `docs/dnd-backgrounds.md` 与 `docs/dnd-feats.md` 的字段约定；2014 专长内容一律回 CHM 原文（`.chm_output/DND.26.09.13/`），禁止回译或编造。

3. **最小范围**：不顺手改动无关代码；范围外发现只登记，不动手。
4. **断言口径**：覆盖度／下界写法，不硬编码总数（如「至少 77 条固定授予可解析」「候选 ≥ 9」）。
5. **收尾**：`vue-tsc -b` → `vitest run` → `npm run build`；如新增汉字重跑字体子集。
6. **汇报**：交付说明写明「已复核前端依赖拓扑，已更新／无需更新」。

## 6. 风险与注意

1. **检查点 id 不可变**：`${background.id}-origin-feat` 是已发布草稿的存储键。
2. **孤立选择过滤要保守**：只处理 `*-origin-feat` 结尾的检查点，避免影响历史草稿中其它已移除检查点的既有行为；该行为变化需在更新公告中说明。
3. **两处渲染同一检查点**：出身步骤与时间线步骤写同一 `checkpointId`，禁止各存一份；`saveSelection()` 已按 id 覆盖。
4. **2014 专长结构复杂度分层**：斯翠海文学徒（学院 + 法术表）、高等术法入门（月亮 + 法术表）、外层位面后裔（位面 + 抗性 + 戏法）优先结构化；神性之遇、巨人打击视原文表结构而定；不能结构化时以文字登记但**必须**建条目。
5. **2014 条目不得带 `category`**：否则会被 2024 候选池逻辑误纳。
6. **战役先决不硬凑**：`FeatPrerequisite` 无战役字段，一律写文案。
7. **第三方边界不变**：第三方专长的未核验效果不进入自动计算，角色卡展示已登记的原创摘要与「按原书处理」提示。
8. **不做范围外顺手改**：神话调查员属性任选（X-1）、德鲁斯肯瓦尔德居民工具候选口径（X-2）只登记不动手。
9. **一次只改一个文件族**：避免并行代理与批处理脚本同时改写同一文件（G3 教训）。

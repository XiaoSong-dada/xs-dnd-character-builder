## 1. 目标与范围

目标：法术书相关的列表在角色卡与跑团助手中稳定按「环级升序 + 同环规则表顺序」展示，并补齐环级小标题；不改变草稿存储顺序。

范围内：

| 位置 | 现状 | 目标 |
| --- | --- | --- |
| 角色卡「未准备法术（法术书中未准备）」 | 点选顺序，扁平列表 | 环级升序 + 同环规则表顺序，带环级小标题 |
| 角色卡「法术书」 | 点选顺序，扁平列表 | 同上 |
| 角色卡「未写入法术书」 | 规则表顺序（无契约），扁平列表 | 显式排序 + 环级小标题 |
| 跑团助手「未准备法术（法术书中未准备）」 | 候选池顺序 + 人工添加追加在末尾 | 环级升序 + 同环规则表顺序，带环级小标题 |

范围外（按 R1 非目标）：`SpellcastingStep` 选择交互、角色卡「已准备/已掌握」「未准备（prepared 职业）」「全部职业法术」等既有分组区块、草稿结构与导入导出。

## 2. 设计

### 2.1 排序与分组口径（U01-01）

在 `app/src/rules/spellcasting.ts` 新增纯函数（规则层，框架无关）：

```ts
export interface SpellLevelGroup {
  readonly level: number
  readonly spells: readonly SpellRule[]
}

/** 环级升序；同环内按规则表（仓库登记）顺序。 */
export function groupSpellsByLevel(spells: readonly SpellRule[], ruleset: RulesetId): readonly SpellLevelGroup[]
```

- 同环次级键 = 该规则集 `repository.spells` 的登记下标，按规则集惰性缓存一次索引（数据为静态注册表，缓存安全）。
- 不在仓库中的法术（防御性分支）排序键为 `Number.MAX_SAFE_INTEGER`，排在组内末尾；`Array.prototype.sort` 稳定，保持其相对顺序。

**关键事实（已核验，作为 Q-1 的实现依据）**：2014 的 `spells2014` 按「基础规则在前、扩展书（XGtE／TCoE 等）在后」分批登记，同环内**并非**纯英文名字母序——已核验 20 处同环逆序，例如 0 环 `Vicious Mockery → Control Flames`、3 环 `Wind Wall → Catnap`。2024 的 `spells2024` 同环内为字母序（0 处逆序）。

因此：

- 以决策 Q-1 的主结论「保持规则表数据顺序」实现，**不做** `englishName` 排序，也不引入 `localeCompare`。
- 需求文档 Q-1 括号中「等价英文名字母序」仅对 2024 数据成立；2014 扩展法术按登记顺序展示（基础规则法术先于扩展法术），本计划按此实现并在此登记差异。

## 4. 验证

1. 单测（`test/rules/spellcasting-2014.test.ts`）：
   - 乱序输入（3 环 → 1 环 → 2 环）输出 1/2/3 环升序；
   - 同环内按规则表顺序（构造与输入顺序相反的数据）；
   - 空输入返回空数组。
2. 组件测试：
   - 角色卡：`spellbookSpellIds` 故意写成 `[3环, 1环, 2环]`，断言「法术书」区块内卡片标题顺序为 1→2→3 环，且出现 `1环 · 1 个` 之类小标题；「未准备法术（书中未准备）」「未写入法术书」同样断言环级升序。
   - 跑团助手：`spellbookSpellIds` 乱序（含人工添加法术），断言「未准备法术」区块环级升序与小标题。
3. 回归：现有法术展示、候选池、抄录相关用例保持通过（顺序断言不受影响）。
4. `vitest run` 全量、`vue-tsc -b`、`vite-ssg build` 全部通过。

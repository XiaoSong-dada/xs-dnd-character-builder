# 职业特性登记与展示需求

## 1. 背景与目标

用户反馈：角色卡与车卡时间线中**只有"子职特性"的介绍与展示，看不到所选职业自身的"职业特性"**。例如战士的"回气、动作如潮、额外攻击"、野蛮人的"狂暴、鲁莽攻击、危险感知"、法师的"法术书、奥术回想"等基础职业特性在界面中完全没有介绍入口——`docs/需求文档/子职特性展示与升级需求.md` R4（职业基础特性登记）此前被列为后续批次，至今未实现。

目标产物：

- 数据层：为 12 个 2014 基础职业登记完整的等级特性清单（原创中文摘要 + 等级 + 类型 + 来源），复用子职特性的登记与挂载模式。
- 规则层：`ClassRule` 增加 `features` 挂载，提供按职业查询特性的纯函数；需要玩家选择的职业特性沿用既有 `checkpoints` 机制，不重复实现选择逻辑。
- 界面层：角色卡"能力"页签新增"职业特性"区块（按等级分组，含等级徽标、中英文名、摘要、来源、未核验徽标）；时间线在选中职业后展示该职业的特性列表（只读展示，不要求玩家确认，符合"自动获得的能力只展示"的既有约定）。
- 不新增草稿字段、不改变存储结构，保持 JSON 导入导出兼容。

### 2.2 界面层

### 2.3 资料文档现状

- `docs/dnd-classes.md` 3.3 节已定义职业特性字段约定（稳定 ID、名称、来源职业、获得等级、用途、玩家选择、资源、前置条件、派生值影响、动作类型、实现状态），第 6 节有单项特性记录模板，但 **12 个职业的等级特性清单尚未登记**。
- `docs/classes/subclasses/<职业ID>/<职业ID>-2014.md` 为各职业基础资料入口，目前只记录职业 ID、子职等级、ASI 等级与简短说明（如野蛮人仅 5 行），**没有逐条列出各等级职业特性**，需按本需求补充或引用。

### 2.4 结论

- 职业特性**数据与界面双缺失**：子职特性已有完整"登记 → 挂载 → 展示 → 选择"链路，职业特性可以完全复用同一模式，无新机制需要发明。
- 职业特性的"玩家选择"（战斗风格、专家技能、法师抄录、魔能祈唤等）**已由各职业 `checkpoints` 覆盖**，本需求只补"介绍展示"，不重复建设选择机制。
- 需要玩家选择的职业特性是否登记进 `features` 并在展示区标注"需选择"（与子职 `requiresChoice` 徽标一致），是唯一需要与既有交互对齐的展示决策（见 R1/R2 说明）。

## 3. 需求项

### R1 数据层：新增职业特性类型与注册表（必须）

1. `app/src/types/rules.ts` 新增 `ClassFeature` 接口，字段与 `SubclassFeature` 对齐，仅将 `subclassId` 换为 `classId`：

```ts
export type ClassFeatureKind = SubclassFeatureKind // 复用 passive/choice/resource/action/bonus-action/reaction

export interface ClassFeature {
  readonly id: string
  readonly classId: string
  readonly name: string
  readonly englishName: string
  readonly level: number
  readonly summary: string
  readonly kind: ClassFeatureKind
  readonly requiresChoice?: boolean
  readonly status: CompatibilityStatus
  readonly sourceIds: readonly string[]
}
```

   说明：`requiresChoice` 标记该特性在既有 `checkpoints` 中已有对应选择（如战士"战斗风格"、游荡者"专精"、法师"法术书"），展示区据此显示"需选择"徽标并引导到时间线；`ClassFeature` 不携带 `optionIds/optionLabels`（选择数据已在 checkpoints 中，避免双份维护）。

2. 新增 `app/src/rules/data/class-features-2014.ts`，登记 **12 个 2014 基础职业全部等级特性**（野蛮人、吟游诗人、牧师、德鲁伊、战士、武僧、圣武士、游侠、游荡者、术士、邪术师、法师），导出：
   - `classFeatures2014: readonly ClassFeature[]`；
   - `getClassFeatures2014(classId: string): readonly ClassFeature[]`（`Map` 索引，模式与 `subclass-features-2014.ts` 733–735 行一致）。
3. 特性 ID 规则：`<职业slug>-2014-class-<特性slug>`（如 `fighter-2014-class-action-surge`）；`classId` 使用既有职业 ID（`class-2014-fighter` 等）。
4. 登记原则（遵守内容与版权约定）：
   - 每个职业按 PHB 2014 等级表登记特性（含升级项，如战士"额外攻击"仅登记一次、用 `level` 取首次获得等级 5；"不屈"登记 9 级，升级描述在摘要中说明 13/17 级次数增加）；
   - `summary` 为**原创中文摘要**（用途、触发时机、资源恢复要点），不复制原书正文；
   - 来源与核验状态：2014 Basic Rules / SRD 5.1 可核验条目标记 `implemented` + `sourceIds: ['basic-rules-2014']`；仅 PHB 索引的条目标记 `index-only` + `sourceIds: ['phb-2014-index']`（与子职特性注册表同一套取值约定）。
5. `ClassRule`（`app/src/types/rules.ts`）新增可选字段 `readonly features?: readonly ClassFeature[]`，`repository.ts` 的 classes 装配处（约 47–50 行）将 `getClassFeatures2014(item.id)` 挂载到每个职业对象（`?? []` 兜底，保持 `ClassPreview` 兼容）。

### R2 界面层：职业特性展示（必须）

1. **角色卡"能力"页签**（`CharacterSheetStep.vue`）：
   - 在"豁免/技能"区块之后、"子职特性"区块之前，新增"职业特性"区块：
     - 标题"职业特性 · {{ 职业名 }}"；有未核验条目时显示"仅索引 · 未核验"徽标（复用现有 `UiBadge` warning 风格与 `character-sheet__subclass-features-note` 同类样式）；
     - 按等级分组展示等级徽标（`{{ level }}级`）、中文名 + 英文名、摘要、来源；`requiresChoice` 特性显示"需选择"标记（复用现有 `character-sheet__feature-choice` 样式）；
     - 与子职特性一致，只展示 `level <= draft.targetLevel` 的特性；
     - 数据来源：`getClassFeatures2014(draft.classId)`，组件不硬编码任何职业规则文案。
   - 职业特性与子职特性区块的 SCSS 可共用同一组类名（`character-sheet__feature*`），或在两者间做最小样式复用，禁止复制大段样式。
2. **时间线**（`TimelineStep.vue`）：
   - 选中职业后（class 检查点或首个职业检查点展开时），在检查点内容区展示该职业的等级特性列表（只读，按等级分组，样式与子职特性列表 `timeline-step__subclass-features` 对齐）；
   - 只展示"自动获得"的特性（`requiresChoice` 为假），避免与已有选择检查点重复；`requiresChoice` 特性不在此处展示（其选择入口已在对应检查点）；
   - 数据来源：`getClassFeatures2014(classId)`，不要求玩家确认（符合 `docs/rules.md` "自动获得的能力只展示，不要求玩家重复确认"）。
3. 非施法职业、`index-only` 职业同样展示其已登记特性；未登记任何特性的职业显示空态提示（如"该职业暂无已登记特性"），不允许报错。

## 4. 非目标与边界

- **不实现职业特性的玩家选择交互**：战斗风格、专家技能、魔能祈唤、契约恩赐、法师抄录等选择已由各职业 `checkpoints` 覆盖，本需求只做介绍展示；`requiresChoice` 仅作为展示标记。
- **不登记未核验的具体数值效果**：`index-only` 特性只展示摘要，不参与派生计算（遵守内容与版权约定；派生计算仍由 `derive.ts` 与职业既有逻辑负责）。
- **不新增 `CharacterDraft` 字段**：职业特性为纯派生展示数据，不持久化，JSON 导入导出兼容。
- **不改变子职特性现有行为**：现有子职特性注册表、挂载、展示、选择链路保持不变。
- **不登记 2024 职业特性**：全部条目 `ruleset: '5e-2014'`，与当前唯一规则集一致。
- **不实现"资源/恢复"展示**：狂暴次数、回气次数、法术位等资源数量展示不在本需求范围（法术位已有独立需求承接；职业资源展示属后续批次）。

# 角色卡候选法术展示需求

## 1. 背景与目标

用户反馈：像牧师、圣武士这类**法术可以更换**的职业（以及法师的法术书/准备体系），角色卡目前只展示"已选法术"，玩家在游戏内长休更换法术时，角色卡上看不到**可选但未选**的候选法术，无法对照哪些法术可以换进来。

目标产物：

- 角色卡"法术"页签为"可更换法术"职业展示**候选法术池**（当前等级可用、尚未选择），与已选法术并列，按环级分组。
- 玩家打开角色卡即可对照：当前准备/掌握了哪些、还能换入哪些。
- 候选池数据来自规则层（复用 `getAvailableSpells`），组件不硬编码。

## 2. 现状调查（已核验）

### 2.1 各职业施法模式与"可更换性"矩阵（2014 规则语义）

| 职业 | 施法模式 | 施法开始 | 规则上的更换方式 | 候选池是否有意义 |
|---|---|---|---|---|
| 牧师 | `prepared`（准备） | 1 级 | **长休可换**：从牧师职业法术池重选准备列表 | ✅ 核心 |
| 德鲁伊 | `prepared`（准备） | 1 级 | **长休可换**：从德鲁伊职业法术池重选准备列表 | ✅ 核心 |
| 圣武士 | `prepared`（准备） | 2 级 | **长休可换**：从圣武士职业法术池重选准备列表（誓约法术常备） | ✅ 核心 |
| 法师 | `spellbook`（法术书+准备） | 1 级 | 准备列表**长休可换**（从法术书中选）；法术书在升级时扩充，平时不可换 | ✅ 核心（两层候选） |
| 术士 | `known`（已知） | 1 级 | 仅升级时可替换一个已知法术 | ⚠️ 边界（平时不可换） |
| 吟游诗人 | `known`（已知） | 1 级 | 仅升级时可替换一个已知法术 | ⚠️ 边界 |
| 邪术师 | `pact`（契约） | 1 级 | 仅升级时可替换一个已知法术 | ⚠️ 边界 |
| 游侠 | `known`（已知） | 2 级 | 仅升级时可替换一个已知法术 | ⚠️ 边界 |
| 战士/野蛮人/武僧/游荡者 | 无 | — | — | 无 |

**结论：具备"长休可更换"特性的职业 = 牧师、德鲁伊、圣武士（`prepared`）+ 法师（`spellbook`），共 4 个职业。** 术士/吟游诗人/邪术师/游侠（`known`/`pact`）只有升级时才能替换一个已知法术，不构成"可更换池"，本需求不为其展示候选池。

### 2.2 候选池数据源（已就绪）

| 模块 | 现状 |
|---|---|
| `rules/spellcasting.ts` `getAvailableSpells(draft, config)` | 返回 `config.classSpellIds` 中 `level <= getMaximumSpellLevel(...)` 的全部法术（含戏法）——**这就是候选池的现成数据源**，目前仅施法步骤使用，角色卡未消费 |
| `rules/spellcasting.ts` `getMaximumSpellLevel` | 按职业等级表给出当前最高可用环级 |
| `SpellSelections` | `cantripIds` / `knownSpellIds` / `preparedSpellIds` / `spellbookSpellIds` 四字段已覆盖全部模式，候选池 = 职业池 − 已选 |

### 2.3 角色卡法术页签现状（上轮已实现）

- 已选展示：戏法、已准备/已掌握（按环级分组）、法术书（法师）——完整但**只有已选**。
- 无任何"可选未选"区块；玩家无法在角色卡上对照可更换的候选项。

### 2.4 已知数据缺口（不影响 R1，影响展示完整性）

- 牧师、德鲁伊的 `SpellcastingConfig` 未配置 `cantripsKnownByLevel`（戏法数量为 0）；戏法在 2014 规则中**不可更换**，本需求不涉及，缺口另行跟进。
- 圣武士"誓约法术"（Oath Spells）仅登记为 `index-only` 子职特性（`subclass-features-2014.ts`），**无具体法术列表数据**；2014 规则中誓约法术为常备（不占准备数量），后续批次登记。
- 邪术师"秘法奥秘"未接入（`SpellcastingStep` 提示语已注明），与本需求无关。

## 3. 需求项

### R1 角色卡展示"候选法术"（核心）

1. **适用职业**：`prepared`（牧师/德鲁伊/圣武士）与 `spellbook`（法师）模式。
2. **候选池定义**（规则层纯函数，组件不硬编码）：
   - `prepared` 职业：候选 = `getAvailableSpells` 中 `level >= 1` 且不在 `preparedSpellIds` 的法术（按环级分组）。
   - 法师：候选分两层——
     - **候选写入法术书**：`level >= 1` 且不在 `spellbookSpellIds` 的职业法术（升级时可扩充入书）；
     - **候选准备**：在 `spellbookSpellIds` 中但不在 `preparedSpellIds` 的法术（长休可从书中换入准备）。
3. **展示方式**：法术页签在已选区块之后新增"可选法术"区块，按环级分组，每项标注状态（如"未准备"/"未写入"），与已选法术的计数风格一致；法师的两层候选分别展示。
4. **候选池数量提示**：如候选池较大（牧师/法师全池数十项），展示计数并保持移动端可滚动浏览，不改变现有已选区块结构。
5. **戏法处理**：2014 规则戏法不可更换，**不进入候选池**；已选戏法保持现状展示。

### R2（已确认）角色卡点击准备 / 取消准备

角色卡法术页签支持直接点击切换"已准备 ↔ 候选池"，写回 `SpellSelections`（经页面 hook → `store.updateDraft`），无需返回施法步骤。

1. **取消准备**：点击"已准备/已掌握"区块中的任一法术 → 从 `preparedSpellIds` 移除，移入候选池。无数量限制，随时可取消。
2. **准备（加入候选）**：点击候选池中的法术 → 加入 `preparedSpellIds`，**前提：已准备数量 < `getRequiredSpellCount`（准备上限）**；达到上限时该操作不可用，显示"已满"提示（与施法步骤一致）。
3. **适用职业**：`prepared`（牧师/德鲁伊/圣武士）与法师（`spellbook`）。`known`/`pact` 职业不提供（2014 规则平时不可更换，见边界）。
4. **法师两层候选的交互**：
   - **候选准备**（书中未准备）：可点击"准备"加入 `preparedSpellIds`——长休可换，核心交互；
   - **候选写入**（未写入法术书）：**默认只读展示**（2014 规则法术书仅在升级时扩充，角色卡查看场景不提供写入点击）；如后续需要点击写入，另行确认。
5. **写回与校验**：点击后经 `CharacterSheetStep` emit → `useCharacterBuilderPage` 更新 `spellSelections`；候选池与已准备列表立即重算。取消准备后若准备数低于上限，角色卡"待补全"徽标与校验提示出现属预期行为（与施法步骤校验一致）。
6. **辅助说明**：候选项与已选项的操作目标保持 44 px 触控面积；点击行为对已准备/候选做显式区分（如"取消准备"/"准备"文字标注），不依赖颜色。

### R3（后续批次，不阻塞 R1—R2）

- 圣武士誓约法术列表数据登记（常备、不占准备数量，角色卡单独列出）。
- 牧师/德鲁伊 `cantripsKnownByLevel` 数据补齐（与本需求无关，属施法步骤数据完善）。
- 邪术师秘法奥秘、仪式法术（法师可无准备施放书中的仪式法术）等资源类展示。

## 4. 非目标与边界

- `known`/`pact` 职业（术士/吟游诗人/邪术师/游侠）**不展示候选池**：2014 规则中其已知法术平时不可更换，展示职业全池会造成"可随意换"的错误暗示；仅升级时可替换一个的交互属后续（如需）。
- 戏法不进入候选池（2014 规则不可更换）。
- 不新增 `CharacterDraft` 字段：候选池是 `getAvailableSpells` 的派生视图，`SpellSelections` 四字段不变，导入导出兼容。
- 不改动 `SpellcastingStep` 施法选择步骤与 `rules/spellcasting.ts` 既有函数（候选池计算如需新纯函数，新增于 `spellcasting.ts`，保持框架无关）。
- `known`/`pact` 职业（术士/吟游诗人/邪术师/游侠）不提供候选池展示与点击交互（2014 规则平时不可更换）。
- 法师"候选写入"层默认只读（法术书仅升级时扩充），不提供点击写入。
- 不实现 R3 誓约法术/秘法奥秘/仪式法术。

## 5. 涉及模块与依赖方向

```text
views/character-builder/components/CharacterSheetStep.vue
  -> rules/spellcasting（getAvailableSpells / getMaximumSpellLevel / getRequired*，候选池派生与上限判断）
  -> rules/repository（getSpell / getClass）
  -> components/ui（StatTile / UiBadge；候选区块样式沿用现有 scoped SCSS）
  -> emits：新增法术变更事件（如 changeSpellSelections），携带更新后的 SpellSelections

views/character-builder/hooks/useCharacterBuilderPage.ts
  -> 接收角色卡法术变更事件，经 store.updateDraft({ spellSelections }) 写回（复用现有路径）

rules/spellcasting.ts —— 如需候选池纯函数（候选准备 / 候选写入），新增于此（仍是 rules 内部纯函数）
```

依赖方向不变：`views → rules → types`，rules 保持框架无关；不新增页面私有组件则 `docs/frontend-architecture.md` 拓扑无需调整。

## 6. 验收标准

1. `pnpm test` 全量通过；新增测试覆盖：
   - 候选池计算：牧师（候选 = 职业池 − 已准备）、法师两层候选（未写入书 / 书中未准备）；
   - 组件测试：`prepared`（牧师）与 `spellbook`（法师）角色卡法术页签可见"可选法术"区块与分组，`known`/`pact` 职业不出现候选区块；
   - 点击交互：点击已准备法术 → 移入候选池；候选未满时点击候选项 → 加入已准备；**已满时点击候选项不生效**（含边界：准备数 = 上限 − 1 时点击成功，= 上限时被拒）。
2. `pnpm build`（含 `vue-tsc -b`）通过。
3. 手机宽度流程：牧师 3 级角色卡法术页签可见已准备 + 候选池（1 环分组），点击候选法术准备、点击已准备取消均即时生效；法师 3 级可见已准备 + 法术书 + 候选准备（可点击）+ 候选写入（只读）。
4. 戏法不出现于候选池；候选池数量与环级随等级变化正确（如 5 级出现 3 环候选）。
5. 文档同步：`docs/quick-build-implementation.md` 实施状态、需求文档 6a；交付说明写明"已复核前端依赖拓扑"。

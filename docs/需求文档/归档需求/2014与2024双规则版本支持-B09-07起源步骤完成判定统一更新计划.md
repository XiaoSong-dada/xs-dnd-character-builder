# B09-07 起源步骤完成判定统一与语言门禁修复 · 更新计划

- 制定日期：2026-09-15。
- 对应问题：用户实际使用 2024 法师＋精灵＋学者时，选完 2 门语言后起源步骤「下一步」无法点击（阻断使用）。
- 定位结论：**门禁口径分叉**。起源步骤"下一步"仍用 2014 语义 `draft.languages.length === background.languageChoices`，而 2024 背景该字段恒为 `0`、必选语言数由 `getRequiredLanguageCount` 返回 2（＋职业特性追加）。三处口径不一致（界面 2／校验 2／门禁 0），失败点为 `src/views/character-builder/hooks/useCharacterBuilderPage.ts:126`。
- 依据：本轮问题分析（证据见第 1 节）；[B09 更新计划](2014与2024双规则版本支持-B09更新计划.md) 第 5 节统一验收门槛；[B00 更新计划](2014与2024双规则版本支持-B00更新计划.md) 第 2.2／2.6 节。
- 状态：已完成（见 [B09-07 更新任务](2014与2024双规则版本支持-B09-07起源步骤完成判定统一更新任务.md)）。

## 1. 问题与证据（已核对代码）

| 位置 | 现状 | 问题 |
| --- | --- | --- |
| `src/views/character-builder/hooks/useCharacterBuilderPage.ts:126` | 起源门禁：`draft.languages.length === background.languageChoices` | 2014 语义；2024 背景字段为 0，选满 2 门反而判定失败（0 门才通过） |
| `src/rules/data/origins-2024.ts:42` | 2024 背景统一 `languageChoices: 0` | 2024 语言规则不在此字段表达 |
| `src/rules/languages.ts:37-49` | `getRequiredLanguageCount`：2024 为 2＋职业特性追加（游荡者 +1） | 界面与校验的真实口径 |
| `src/views/character-builder/components/OriginStep.vue:57、350` | 语言界面用 `getRequiredLanguageCount` | 提示"选择 2 种语言" |
| `src/rules/validate.ts:203-210` | 语言校验用 `getRequiredLanguageCount` | 校验页不报语言错误，与门禁相互矛盾 |
| `src/views/character-builder/index.vue:243` | `:primary-disabled="!canContinue"` | 用户感知到的"卡住" |
| `src/rules/validate.ts:62` | "选择2014种族和背景。" 固定文案 | 2024 措辞错误（顺带修正） |

影响范围：所有 2024 草稿的起源步骤（选满必选语言即卡住；0 语言反而放行）；游荡者需 3 门同样卡住；2014 不受影响（其 `languageChoices` 与必选数一致）。

根因归类：**步骤完成判定缺少单一来源**，同一条规则在"门禁／界面／校验／进度"四处各写一份，2024 入口开放（B09-01）后暴露。

## 2. 目标与范围

### 2.1 目标

1. 起源步骤的完成判定收敛到**一个规则层函数**，供步骤门禁、起源页提示、完成校验与进度显示共用，消除口径分叉。
2. 解除当前 2024 阻断，并让"按钮为何不可点"可见。
3. 覆盖 2014 回归，既有草稿行为不变。

### 2.2 范围（按优先级）

- **P0 语言门禁修复**：门禁改用统一判定中的语言项（与界面／校验同源）。
- **P1 起源步骤完成项收敛**：把起源页实际采集且在 `validateDraft` 中为**错误级**的项目纳入统一判定：物种、血统（`requiresSubrace`）、血统归属、背景、语言（含重复）、物种技能选择数、物种工具选择、物种体型（`sizeChoices`）、背景属性分配（`getBackgroundAllocationIssue`）。
- **P2 进度口径对齐**：`src/stores/character-drafts.ts` 的 `completion` 第 4 项由 `Boolean(raceId && backgroundId)` 改为统一判定（进度百分比与门禁一致）。
- **顺带修正**：`validate.ts:62` 起源缺失文案按版本措辞。

### 2.3 明确不包含

- 提示级（warning）项目**不**纳入门禁（保持 B09 的"提示不阻断"原则，如诡术师法师之手）。
- 物种施法属性选择（2024 精灵等）：属于时间线检查点（`src/rules/timeline.ts:163-174`），仍归时间线步骤，不在起源页拦截。
- 其他步骤门禁：B09-02 已复核为版本感知（职业／属性／时间线／装备／法术／身份），本次不改。
- 校验页错误体系重构、B07-05、B10、B11。

## 3. 设计（推荐做法）

### 3.1 单一来源：规则层阻塞项函数

位置：`src/rules/origins.ts`（既有起源纯函数模块，已依赖 `repositories`／`source-books`）。

```ts
export interface OriginStepBlocker {
  readonly id: string            // 与 validateDraft 的 issue id 对齐，如 'background-languages'
  readonly message: string       // 复用校验文案，保证三处一致
  readonly resolution: string    // 供起源页提示与校验页共用
}
export function getOriginStepBlockers(draft: CharacterDraft, repository: RulesRepository): readonly OriginStepBlocker[]
export function isOriginStepComplete(draft: CharacterDraft, repository: RulesRepository): boolean
```

判定项与数据来源（不写 2024／2014 分支，全部用版本仓库与既有规则函数）：

| id | 判定 | 数据来源 |
| --- | --- | --- |
| `origin-required` | 未选物种或背景 | `draft.raceId`／`draft.backgroundId` |
| `subrace-required` | `requiresSubrace` 且未选血统 | `getDraftSpeciesRules` |
| `subrace-mismatch` | 血统不属于当前物种 | `getDraftSpeciesRules` |
| `background-languages` | 语言数 ≠ `getRequiredLanguageCount` 或有重复 | `languages.ts` |
| `species-skill-required` | 物种技能选择数 ≠ `skillProficiencyChoices.count` | `getDraftSpeciesRules` ＋ `raceSkillChoices` |
| `species-tool-required` | 物种工具规格存在但未选 | `getDraftSpeciesRules` ＋ `raceToolChoice` |
| `species-size-required` | `sizeChoices` 存在但未选或不合法 | `getDraftSpeciesRules` ＋ `speciesSizeChoice` |
| `background-ability-allocation` | 背景属性分配未完成 | `getBackgroundAllocationIssue` |

### 3.2 三处消费

1. **步骤门禁**：`useCharacterBuilderPage` 起源分支改为 `isOriginStepComplete(draft, repositoryFor(draft))`，删除对 `background.languageChoices` 的引用。
2. **起源页提示**：新增 `blockers` prop；在起源页底部（sticky 操作栏之上）用 `UiNotice` 列出"还差什么"，每项显示 `message` 与 `resolution`；列表为空时不渲染。
3. **完成校验**：`validateDraft` 中对应 origin 错误改为消费 `getOriginStepBlockers`（同 id、同 message、同 resolution），保留 `step: 'origin'` 与 severity 判定（这些项目仍为 `error`）。
4. **进度**：`completion` 第 4 项改用 `isOriginStepComplete`（P2）。

### 3.3 文案规范

- 2024 起源缺失文案使用"物种与背景"；2014 使用"种族与背景"（由 `draft.ruleset` 决定，避免再次出现固定 2014 措辞）。
- 新增文案（阻塞清单标题、分隔）计入 PDF 字体子集重建范围。

## 5. 测试

新增 `test/rules/origin-step-completion.test.ts`：

1. **当前缺陷回归**：2024 法师＋精灵（高等精灵血统）＋学者，语言 0／1／2 门 → `isOriginStepComplete` 分别 `false`／`false`／`true`；2 门时 `blockers` 为空。
2. **职业追加**：2024 游荡者语言 2 门 → `false`（需 3），3 门 → `true`。
3. **血统与体型**：精灵未选血统 → `false`；2024 人类（`sizeChoices`）未选体型 → `false`，选中型 → `true`。
4. **物种技能／工具**：精灵未选敏锐感官技能 → `false`；选满 → `true`。
5. **背景属性分配**：2024 学者属性分配未完成 → `false`；完成 +2/+1 → `true`。
6. **2014 回归**：侍僧（2 门语言）、罪犯（0 门语言）、士兵（0 门）在既有选择下判定结果与现状一致。
7. **一致性**：`getOriginStepBlockers` 的 id 集合与 `validateDraft` 中 `step === 'origin'` 的错误级 issue id 集合一致（防止再次分叉）。

扩展既有测试：

- `test/hooks/useCharacterBuilderPage.test.ts`：2024 起源步骤 `canContinue` 三态（0／1／2 门语言），以及 2014 既有用例保持通过。
- `test/components/OriginStep.test.ts`：阻塞清单渲染（含 `resolution` 文案），为空时不渲染；窄屏（375px）下清单与操作栏不重叠。

门槛：`vue-tsc -b`、`vitest run`（全量）、`vite-ssg build`、`git diff --check`；新增中文文本后执行 `app/tools-subset/make-subset.py` 并重跑 `test/services/pdf-font.test.ts`。

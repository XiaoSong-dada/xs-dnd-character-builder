## 阶段 2：界面与逻辑实现（绿）

**`app/src/views/character-builder/components/CharacterSheetStep.vue`**：

1. **`applyCurrency` 增加 `decrease` 模式**（294–312 行）：
   - 校验不变：`/^-?\d+$/` 不匹配 → 「请输入整数金币数」；
   - `decrease` 分支：**对输入值取绝对值作为扣减量**——`nextGold = adventureGold - Math.abs(value)`（输入 `-5` 点「减少」实际扣 5，与需求文档 R2 表述一致；输入 `0` 不产生变化）；
   - 总额非负校验复用：`startingGold + nextGold < 0` → 「金币不能为负」；
   - 合法时 `emit('changeAdventureGold', nextGold)` 并清空输入与错误提示。
2. **模板新增按钮**（723–726 行 `character-sheet__coin-actions` 内）：
   - 按钮文案「减少」，`type="button"`，`@click="applyCurrency('decrease')"`；
   - 顺序建议「添加」「减少」「设置」（扣减与添加相邻，操作直觉一致）；
   - placeholder 改为「输入金币数」，`inputmode="numeric"` 保持。
3. **样式**：
   - `&__coin-actions` grid 列由 `minmax(0, 1fr) auto auto` 调整为 `minmax(0, 1fr) auto auto auto`（914–917 行）；
   - 按钮直接复用现有 `button` 规则（`min-height: 2.75rem` ≥ 44px 触控标准、`min-width: 4.5rem`），无需新增样式；
   - 若 4 列在手机宽度过挤（输入框被压缩过窄），备用方案：按钮区整体换行成两行（`grid-template-columns` 调整或操作区 `flex-wrap`），见"待执行时确认点 1"。

- 完成检查：`pnpm test:run` 该文件全绿；`pnpm exec vue-tsc -b` 无类型错误。

## 已确认决策（用户确认）

1. **只加「减少」按钮**：不引入负号快捷输入、不改造键盘方案；手机端通过按钮扣减。
2. **保留负号输入兼容**：桌面端输入负值点「添加」仍可扣减（现有测试与已归档需求行为不变）。
3. **不做二次确认**：扣减是数值调整且可逆，不属于删除类不可逆操作。
4. **扣减量取输入值绝对值**：`decrease` 分支 `nextGold = adventureGold - Math.abs(value)`；输入 0 无变化、输入负值按扣减处理。

## 待执行时确认点

1. **按钮区布局**：4 列（输入框 + 3 按钮）在 375px 宽度是否过挤；过挤则按钮区换行两行排布（实现时按实际渲染定）。
2. **按钮顺序**：默认「添加」「减少」「设置」；如视觉上希望「设置」靠近输入框可调整，不影响功能与测试。
3. 「减少」按钮无需独立 `aria-label`（可见文案「减少」已可被读屏识别），与「添加」「设置」保持一致即可。

# 名称译名规范化 · 更新计划

> 依据《docs/需求文档/名称译名规范化需求.md》制定。本文件为实施计划存档，同时作为**译名核验 TODO 清单**，执行时按阶段推进；核验中发现遗漏条目可随时补入对应清单。

## 目标与范围

- **根因**：法术名约 14 处与官方简体中文术语/用户指定译名不一致，另有 Message/Sending 同名冲突；扩展书法术约 9 处与社区主流译名有差异。
- **已确认方案**：仅改 `spells-2014.ts` 的 `name` 展示字段；`id`（基于英文名）、`englishName`、`description`、`summary` 均不动 → 草稿存档、导入导出完全兼容；展示层与导出（PDF/XLSX）自动跟随。
- **不改动范围**：description/摘要文本、职业/子职/专长/种族/背景/装备/特性名称（已核验与官方一致）、2024 规则数据。

## 关键实施细节（已核验）

1. **兼容性**：`id = spellId(englishName)`，改名不影响 id；测试按 id 断言（已 grep 核验，仅 `class-features-2014.test.ts:89` 锁定职业特性名「法术书」，不在本次范围）；src 组件无中文名硬编码。
2. **改名位置**：`spells-2014.ts` `spellSeeds` tuple 第二项（`['English Name', '中文名', level, ...]`）。
3. **来源分级**：R1 1—12 条 = 官方书版术语（高置信）；13—14 条 = 用户指定（电爪/繁彩球）；R2 = 社区主流（5e.tools 中文/果园，中等置信，需逐条定稿）。
4. **核验边界**：项目环境无法联网，核验基于知识库（官方书版 / BG3 简中 / 5e.tools 中文 / 果园）；**阶段 0 产出定稿清单，请用户复核确认后进入实施**。

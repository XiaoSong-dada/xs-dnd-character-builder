## 1. 背景与问题

### 1.1 用户报告

> 「当我在角色卡的调整等级中添加一个新的兼职时，比如加入了一个新的职业，那么就会有新的特性需要选择，但是事实上并没有进入到选择进入特性的页面。」

### 1.2 实测取证（2026-10-14，一次性探针，验证后已删除，未改动产品代码）

| 场景 | 实测结果 |
| --- | --- |
| **A. 角色卡 → 调整等级 → 开启兼职 → 添加「游荡者」→ 确认** | 确认弹窗出现（标题「调整职业与等级分配」），并列出**待补全**：`1级 · 选择4项游荡者技能`、`1级 · 选择2项专精`；`affected` 为空。**确认后 `step` 仍是 `sheet`、`levelAdjustNotice` 为 `null`**——既不跳转第 6 步，也没有引导条。数据本身正确：总等级 6、`[战士5, 游荡者1]` |
| **B. 角色卡滑杆单纯升级 5 → 6** | **连确认弹窗都不弹**（`alwaysConfirm: false` 且无失效项）→ 直接生效；`levelAdjustNotice` 仍为 `null`，`6级 · 属性提升或专长` 完全没有被提示 |
| **C. 对照：`page.adjustLevel(6)`** | 弹确认 → 确认后 `step = timeline`，引导条 =「等级提升至 6 级，请完成新增检查点：6级 · 属性提升或专长」（`step: 'timeline'`）——**机制本来存在且仍然可用** |
| **D. 兜底：`startReedit()`** | 跳转 `timeline`；兼职口径能找到新增职业的未完成检查点 |
| **E. 战士4/游荡者1（总等级 5、起始职业检查点全部完成）** | 角色卡徽标口径未完成 = `[]`（**不显示「待补全」徽标**）；兼职口径未完成 = `[1级 · 选择4项游荡者技能, 1级 · 选择2项专精]` |

**结论：问题真实存在**——缺陷在「引导与跳转」层，不在数据层（新增检查点确实进入了时间线，已有选择也没有丢失）。

| 编号 | 位置 | 现状 |

### 1.4 触发面

`applyClassAllocation`／`applyTotalLevel` 共三个入口：角色卡调整等级弹窗（`index.vue:397-404`）、第 1 步（`index.vue:208-209`）、第 3 步（`index.vue:220-221`）。**只有角色卡弹窗这条路径实际受害**：第 1／3 步后面本就线性走到第 6 步；而角色卡步骤隐藏了抽屉与吸底栏（`index.vue:182` 的 `:has-drawer`／`:has-actions`），可走的出口只剩「重新编辑」（`CharacterSheetStep.vue:1284`，可能被 P6 漏报误导）与走到第 11 步看校验。

| 术语 | 含义 |
| --- | --- |
| 新增检查点 | 本次分配／等级变更后，新时间线中尚未完成的检查点（`DependencyImpact.added`） |

## 3. 需求一：角色卡调整后必须给出补全引导

### 3.1 R1 确认路径：升级自动跳转 + 引导条（决策 D28）

在**角色卡步骤**提交职业／等级分配并确认后：

| 变更结果 | 引导条 | 跳转 |
| --- | --- | --- |
| 存在新增未完成检查点 | success：「等级提升至 X 级，请完成新增检查点：…」（`step: 'timeline'`） | 自动切到第 6 步「完成等级时间线」 |
| 无新增检查点但法术配置有缺口 | success：「…请完成：…」（`step: 'spells'`） | 自动切到法术步骤 |
| 两者都没有 | 不产生引导条（并清掉上一条过期的引导条） | 不跳转 |

- 引导条文案复用既有 `buildLevelAdjustNotice()`（`useCharacterBuilderPage.ts:339-374`）与 `DependencyImpact` 的既有字段，**与确认弹窗同源，不新增第二套口径**。
- 确认路径即用户在弹窗里已经看过「待补全（新增检查点）」清单并点下「确认调整」，因此自动跳转是「按用户确认的意图继续」，不是意外导航。

### 3.2 R2 降级：只出复查引导条，不强制跳转（决策 D28）

- 降级／移除职业后出 **warning** 引导条（「等级降至 X 级，需复查：…」，含 `invalidatedDetails` 与 `reviews`；有法术归档时提示移入停用记录），`step` 取 `timeline`（有归档法术时取 `spells`）。
- **不自动跳转**——沿用 `adjustLevel` 既有语义（原实现只在 `direction === 'up'` 时跳转），避免把正在看角色卡的用户强行带走。

### 3.3 R3 滑杆路径：必须提示，但不强制跳转（决策 D29）

- 保持上游 §3.4 的**轻量确认策略不变**：仅当有选择将失效时才弹确认；单纯升级不弹确认。
- 但**只要本次提交产生新增未完成检查点或法术配置缺口，就必须写引导条**（可点击前往），不得静默应用。
- 滑杆可能被连续拖动微调，因此**不自动跳转**；角色卡弹窗保持打开，用户关闭弹窗后即可看到引导条。

### 3.4 R4 第 1／3 步不新增引导与跳转（决策 D30）

- 引导条与自动跳转**只在角色卡步骤（`step === 'sheet'`）产生**。
- 理由：第 1／3 步属于线性车卡流程，后面本就会经过第 6 步；从第 1 步跳走会跳过起源与属性；且 `UiNotice` 没有关闭按钮，在车卡早期反复出现不可关闭的提示条会干扰。
- 第 1／3 步的确认弹窗（「待补全（新增检查点）」清单）行为保持不变。

## 4. 需求二：引导条的可点击性跟随目标步骤（决策 D31）

### 4.1 R5 有步骤才可点击

- `levelAdjustNotice.step` 存在：显示「点击前往对应步骤处理。」+ 手型光标，点击跳转并清除引导条（既有 `goToLevelAdjustStep` 行为）。
- `levelAdjustNotice.step` 缺失：**不显示该提示文案**、不显示手型光标、不做跳转（防御性不变式，防止再次出现「点了没反应」）。

### 4.2 R6 起始职业变更的引导条补齐目标步骤与准确文案

- 目标步骤补为 **`equipment`**（起始装备需要在该步骤重新选择）。
- 文案不再声称起始装备已被重算，改为：「已更换起始职业：A → B。1 级生命值与豁免熟练已按新起始职业重算；起始装备需在装备步骤重新选择。」
  - 依据见 §7.2：实测起始装备**并未**随之重算。

## 7. 边界与不做

### 7.1 边界

- 不改规则数值、派生、schema、导出；不改校验语义（`validate.ts` 的检查点 error 与 `starting-equipment-incomplete` error 保持现状，它们是最终兜底）。
- 不改确认弹窗的分节与字段口径（`pendingChange.impact.added` 语义不变，仍是「新时间线中未完成的检查点」）。
- 不改第 1／3 步的线性流程与滑杆的轻量确认策略。
- 不改版本号：`app/package.json`、`CHANGELOG.md`、`app/src/constants/update-notices.ts` 均保持 **1.13.0**（该版本尚未发布）。
- 不引入新依赖。

### 7.2 已记录、本批不做的相邻问题：更换起始职业不重算起始装备

- 实测（2026-10-14，一次性探针）：把起始职业从「战士」换成「游荡者」后，`startingEquipmentSelections` 与 `inventory` **完全不变**（13 条 → 13 条）、`equipmentNeedsReview` 仍为 `false`，而 `classId` 已指向新起始职业；`applyClassAllocation`（`useCharacterBuilderPage.ts:457-527`）不像 `selectClass`（`:576-584`）那样重建装备。
- 兜底存在：`validate.ts:74-81` 会因新起始职业的装备组未选而报 `error`「职业起始装备选择尚未完成。」并指向装备步骤，因此不是静默数据错误。
- **本批只把引导条的目标步骤与文案改准确（R6），不改变装备数据行为**——「是否随起始职业变更清空并重建起始装备，还是保留旧物并标记需复核」需要单独决策，已在代码中留下 `TODO(primary-class-equipment)` 标记，后续批次处理。

### 7.3 已记录、本批不做的相邻问题：角色卡另有三处按「单职业 + 总等级」展开时间线

- `CharacterSheetStep.vue` 的 `selectedOptionEntries`（`:354`）、`featureChoiceLabel`（`:412`）、`featAndAsiEntries`（`:545`）仍然调用 `buildTimeline(draft.classId, draft.targetLevel, {...})`：既不传 `classes`（看不到其它职业的检查点），又把**起始职业的等级当成总等级**（兼职时会把未解锁的职业级检查点当成已解锁）。
- 本批只按 D32 收紧了 `needsReview`（它决定「待补全」徽标，直接影响本缺陷的可见性）；其余三处涉及角色卡特性列表与完成度徽标的展示口径，改动会影响既有断言，需单独批次复核。
- 已在 `CharacterSheetStep.vue:354` 留下 `TODO(multiclass-timeline-scope)` 标记。

### 7.4 实施期发现并一并修掉的既有缺陷：分配变更的失效标记被覆盖

- `applyClassAllocation` 原先**先**调 `store.invalidateSelections()`、**再**用变更前的草稿快照 `...rest` 调 `store.updateDraft()`；而 `rest.selections` 指向失效标记写入前的旧数组，第二次写入把刚写下的 `invalidatedAt` 覆盖掉。
- 结果：在角色卡上用分配控件降级／移除职业时，确认弹窗和引导条都列了「将失效」的选择，但应用后草稿里这些选择**并没有被标记失效**（`target-level`、换职业、换种族等路径不在 patch 里带 `selections`，因此只有分配变更路径受影响）。
- 处理：调整为先写草稿、再标记失效，并在迁移后的降级用例中锁定断言（详见[更新任务](角色卡等级调整后的检查点引导-更新任务.md) §6.3）。这属于「引导指向的状态必须真实存在」，因此纳入本批。

## 8. 验收标准

1. 角色卡 → 调整等级 → 添加一个新职业并点「确认」后：自动进入第 6 步「完成等级时间线」，顶部出现「请完成新增检查点：…」引导条；新增职业的检查点（技能、专精、子职特性等）在时间线中可见。
2. 角色卡滑杆把总等级从 5 提到 6（无失效项）：不弹确认、**出现引导条**（含 `6级 · 属性提升或专长`），不自动跳转；点击引导条可到第 6 步。
3. 角色卡降级（确认后有效）：出现 warning 复查引导条、**停留在角色卡步骤**；点击引导条可到对应步骤。
4. 第 1 步／第 3 步提交分配：不出现引导条、不跳转（流程与现状一致）。
5. 引导条只有在有目标步骤时才显示「点击前往对应步骤处理。」与手型光标；无目标步骤时不显示该文案、点击无动作。
6. 更换起始职业：引导条指向装备步骤且文案不再声称起始装备已重算。
7. 战士4/游荡者1（总等级 5，起始职业检查点已全部完成）时角色卡显示「待补全」徽标。
8. `adjustLevel` 已从页面 hook 移除且无引用；其 5 类行为的测试在新的真实入口下继续通过。
9. `npx vue-tsc -b`、`npx vitest run`、`npm run build` 全部通过；既有测试无回归（改写的断言需说明理由）。
10. 版本号保持 1.13.0；依赖拓扑若有变化同步 `docs/frontend-architecture.md`。

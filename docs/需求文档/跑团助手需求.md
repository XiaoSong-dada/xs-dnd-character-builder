# 跑团助手需求

> 分支：`feat/session-assistant`。本文档为"局内看卡"功能的需求基线。
> 实施状态：**已实现**（v0.6.0，2026-08）。实施与验收见《跑团助手-更新计划.md》。

## 1. 背景与目标

用户反馈：一局跑团开始后，玩家需要一个**局内角色状态管理页面**——目前底部导航第 2 项"职业介绍"仅是开发中占位页（`/classes`，无实际功能），期望将其改造为"局内看卡"功能，并已确认命名：**「跑团助手」**。

核心使用场景（跑团进行中）：

- 增减**当前血量**（手机端触控，不依赖负号输入）；
- 增减**金币**（复用既有冒险净增金币链路）；
- 增减**法术位**（按环记录已用/总量）；
- 查看已装备**武器的伤害骰、伤害类型与攻击加值**；
- 给自己**挂/摘 debuff**（5e 2014 状态）；
- 一键**短休息 / 长休息**：回血、回法术位（长休息同时清除 debuff）。

本次任务的产出（已确认决策，用户 2026-08 拍板）：

1. **命名**：底部导航第 2 项由「职业介绍」改为**「跑团助手」**；
2. **短休息简化**：一键回 50% 当前已损失血量（向上取整）+ 恢复邪术师契约法术位；不做生命骰投骰；
3. **长休息**：回满血量 + 恢复全部法术位 + 清除全部 debuff；
4. **局内状态独立存储**：当前 HP、已用法术位、debuff 存入独立"局内状态"，**不写入车卡草稿 JSON、不影响导出、不触发车卡校验**；
5. **金币写回 `adventureGold`**：复用既有 `changeAdventureGold` 链路，与角色卡物品页签金币面板共享同一事实源；
6. **角色选择**：进入页面先展示本地草稿角色列表，选择后进入该角色的局内面板；MVP 每次只操作一个角色，可切换；
7. **物品管理复用现有能力**：跑团助手的物品新增/修改直接复用既有功能（`AddItemModal` 新增弹窗、`AdjustItemModal` 数量调整弹窗及 `addAdventureItem` 等纯函数）；必要时将弹窗组件**抽象为公共能力**（预计后续会继续升级物品新增/修改功能，当前为 MVP 版本）；
8. **MVP 不做自动金币结算**：局内售卖不介入——玩家自行加减物品、自行写金币；购买/出售自动扣款/返款属后续批次。
9. **页面布局（参考角色卡页）**：局内面板上方为**基础信息区**（角色基本信息、当前 HP 与增减、金币与增减、短休/长休/撤回入口、已挂载状态 tag），下方为**Tab 页签区**（总览 / 战斗 / 物品 / 状态）；
10. **休息撤回**：短休/长休影响面大（一次性改变 HP/法术位/debuff），结算后提供**撤回**能力（快照回滚，仅保留最近一次）；其余操作不做撤回；
11. **角色来源与切换**：跑团助手可选择/切换的角色 = 本地草稿（车卡流程产出的角色）+ **JSON 导入**的角色；导入复用既有 `store.importDraft` / `CharacterJsonService.importDraft` 能力；
12. **状态 tag 联动与力竭层数**：状态页签中挂载的 debuff，会在上方基础信息区（角色基本信息旁）显示对应 **tag 标签**；普通 debuff 点一下新增、再点一下删除；**力竭特殊处理**——用类似金币的「−/+」增减**层数**（0—6 层，层数 > 0 时显示 tag「力竭 ×N」）；**tag 可点击查看对应状态的详情**（状态名 + 原创转述）；
13. **物品弹窗抽象位置**：`AddItemModal` / `AdjustItemModal` 抽象后放 **`src/components`**（跨功能复用组件目录，用户确认）。

> 补充说明（金币与物品互通的理解）：跑团助手与角色卡页共享**同一份草稿数据**（`inventory` + `adventureGold`），两处操作实时一致、共用同一套组件与结算函数；但不做“加物品自动扣钱、删物品自动返钱”的自动结算（决策 8）。

## 3. 需求明细

### R1 命名与路由（必须）

1. 底部导航 label：「职业介绍」→ **「跑团助手」**（`useBottomNavigation.ts`，iconId 沿用 `navigation-classes`，不新增图标）；
2. 路由 meta.title：「职业介绍 | D&D车卡辅助」→ **「跑团助手 | D&D车卡辅助」**；
3. 占位 hook（`useClassesPage.ts`）随功能实现移除或改为跑团助手 hook；
4. 路由路径：**建议 `/classes` → `/assistant`**（语义跟随功能；见"待执行时确认点 1"）；
5. 同步 `docs/router-layout-requirements.md`、`docs/seo-requirements.md` 对应条目（若改路径，sitemap/预渲染路由同步）。

### R2 局内状态模型与存储（必须）

新增独立局内状态，**不写入 `CharacterDraft`、不提升 `schemaVersion`、不参与 `validateDraft`**：

```ts
interface SessionState {
  readonly draftId: string
  /** 当前生命值；首次进入初始化为最大 HP，恒满足 0 ≤ currentHp ≤ maxHp（maxHp 以派生为准，状态中不缓存）。 */
  readonly currentHp: number
  /** 各环已用法术位，key 为环级（1—9），value 为已用数量；首次进入全 0。 */
  readonly usedSpellSlots: Readonly<Record<number, number>>
  /** 力竭层数（0—6，0 = 无力竭）；作为特殊状态单独保存，不进入 debuffs 列表。 */
  readonly exhaustionLevel: number
  /** 已挂载的 debuff 状态 ID 列表（见 R6）。 */
  readonly debuffs: readonly string[]
  /** 上次休息前的状态快照（用于撤回）；未执行过休息或无可用快照时为 undefined。 */
  readonly lastRestSnapshot?: {
    readonly currentHp: number
    readonly usedSpellSlots: Readonly<Record<number, number>>
    /** 力竭层数（0—6，0 = 无力竭）；作为特殊状态单独保存，不进入 debuffs 列表。 */
    readonly exhaustionLevel: number
    readonly debuffs: readonly string[]
    readonly at: string
  }
  readonly updatedAt: string
}
```

> 上方 `lastRestSnapshot` 内含 `exhaustionLevel`（撤回时一并恢复）。

- 存储：新增 `app/src/services/session-state-storage.ts`（localStorage 独立 key，参照 `DraftStorageService` 模式），按 `draftId` 读取/保存；
- 角色升级/重新编辑后最大 HP 变化：当前 HP 自动钳制到新上限（读取时 `min(currentHp, maxHp)`）；
- 角色删除/草稿不存在时，局内状态视为无效，页面引导回列表。

### R3 血量管理（必须）

局内面板血条区：

- 展示「当前 HP / 最大 HP」与血条进度；最大 HP 来自 `deriveCharacter(draft).hitPoints.value`；
- 操作：**「−」按钮、数字输入框、「＋」按钮**三件套（移动端无负号键盘，参照金币减少按钮的交互决策）；
  - 「＋」：输入值为 0 或空时按 **1** 处理？—— 统一约定：空输入点击按 1 增减，输入数字按该数值增减；
  - 「−」同理扣减；
  - 钳制：结果恒在 `[0, 最大HP]`，越界时提示中文原因（如"生命值不能低于 0"）并回退到边界值；
- 进入页面首次显示时 `currentHp = maxHp`（自动初始化并保存）。

### R4 金币管理（必须）

- 展示持有总额 = `currency.gp + adventureGold`（来源说明「起始金币 X GP」）；
- 复用 `applyCurrency` 交互：输入框 + 「添加」「减少」「设置」按钮（金币减少按钮已实现的形态直接复用）；
- 写回 `adventureGold`（单一事实源，与角色卡页共享），扣减后总额非负约束不变；
- 事件通道：`CharacterSheetStep` 的 `changeAdventureGold` 链路为页面私有实现，跑团助手页需**独立接线**到 `store.updateDraft({ adventureGold })`（规则层无需改动）。

### R5 法术位管理（必须）

- 展示各环法术位：按环列出「已用 / 总量」，总量来自 `spell-slots-2014.ts` 对应职业表（`getSpellSlots`，按职业/等级派生）；
- 契约法术位（邪术师）：单独展示为「契约位 已用/总量（环级 n）」；
- 操作：每环「−」/「＋」按钮（空输入按 1），钳制 `[0, 总量]`；越界提示中文原因；
- 短休息/长休息按 R8 自动结算已用数量。

### R6 装备与物品区（必须）

**6.1 装备与攻击展示（只读）**

- 展示**已装备**（`equippedQuantity > 0`）的物品，武器条目显示：
  - 名称、伤害骰（`damageDice`，两用武器同时显示双手骰 `versatileDamageDice`）、伤害类型（`damageType`）、射程（`range`）；
  - **攻击加值**：武器攻击 = `attackBonus`（派生）；**伤害加值** = `attackDamageBonus`；
  - 护甲条目显示 AC 相关字段（`armorBase`/`addsDexterityToArmor` 等已有数据，展示摘要即可）；
- 只读展示，不做攻击掷骰与伤害结算（后续批次）；
- 非武器/护甲的装备（工具、道具、魔法物品）展示名称与数量即可。

**6.2 物品管理（MVP：复用现有能力）**

- 跑团助手物品区提供与角色卡物品页签一致的**新增与数量调整/删除**能力：
  - 新增物品：复用 `AddItemModal`（内置物品库搜索/分类/自定义物品）；
  - 数量调整/删除：复用 `AdjustItemModal`（减少/增加/删除全部 + 删除二次确认）；
  - 数据写入：复用 `addAdventureItem` / `decreaseAdventureItem` / `increaseAdventureItem` / `removeAdventureItem` 纯函数（`app/src/rules/starting-equipment.ts`，规则层已是公共能力），经 `changeInventory` 语义写入草稿；
- **实现方式**：将 `AddItemModal` / `AdjustItemModal` 抽象为公共能力（**位置：`app/src/components`**，决策 13），跑团助手与角色卡页共用同一套组件；角色卡页引用路径同步切换（不复制实现）；
- **MVP 不做自动金币结算**：新增/删除物品不自动扣款/返款（玩家自行调整金币）；购买/出售自动结算、价格字段补全属后续批次（见 §4）；
- 起始装备条目（`class`/`background`）不提供调整（与角色卡页既有边界一致）。

### R7 Debuff 管理（必须）

- 预置 5e 2014 状态列表（状态 ID + 中文名 + 一句原创转述）：目盲、魅惑、耳聋、恐慌、擒抱、无力、失能、石化、中毒、倒地、束缚、震慑、昏迷（13 项普通状态，与项目版权约定一致使用原创摘要）；**力竭不在此列表**（单独处理，见下）；
- **普通 debuff 交互**（状态页签）：状态卡片网格；点击一下**挂载**、再点一下**摘除**；已挂载卡片显示选中态；
- **顶部 tag 联动**（决策 12）：所有已挂载状态（含力竭层数 > 0）在上方基础信息区（角色基本信息旁）显示对应 **tag 标签**（普通状态显示状态名；力竭显示「力竭 ×N」，N 为层数）；
- **tag 详情**（决策 12）：点击顶部任意状态 tag 弹出详情（复用 `UiModal`）：标题为状态名（力竭含当前层数），正文为该状态的**原创转述**——普通状态为预置效果摘要（同状态页签卡片）；力竭展示**力竭规则转述**（叠层机制与 1—6 层效果要点：1 层察觉检定劣势、2 层速度减半、3 层攻击检定与豁免劣势、4 层生命值上限减半、5 层速度降为 0、6 层死亡）；关闭路径：遮罩/Esc/关闭按钮；
- **力竭特殊处理**（决策 12）：状态页签中力竭行采用类金币的**「− 层数 ＋」**控件（输入框 + 减/加按钮或仅按钮，参照金币面板交互）；
  - 层数范围 **0—6**（2014 规则力竭 6 级，MVP 只记层数不实现各层效果）；层数 0 = 未挂载，tag 消失；层数 > 0 顶部显示「力竭 ×N」tag；
- 长休息清除全部普通 debuff 且**力竭层数归零**（R8）；休息撤回时力竭层数随快照一并恢复；
- 不做状态时效与叠加规则计算（展示性挂载）。

### R8 休息结算与撤回（必须）

**休息结算**：

- **短休息**（一键）：
  - 回血：简化 `当前HP += ceil((最大HP − 当前HP) / 2)`（回一半损失量，向上取整）；
  - 法术位：邪术师**契约法术位**归零已用；其他职业法术位**不恢复**（2014 规则）；
  - debuff：不清除；
  - 结算前若已满血且无法术位可回，提示「当前无需休息」（轻提示，不弹确认）；
- **长休息**（一键）：
  - 回满 HP、全部法术位已用归零、清除全部普通 debuff、**力竭层数归零**；
  - 触发前**二次确认**（一次性重置多项状态，防误触，参照物品删除确认先例）。

**撤回机制**（用户确认：休息影响面大，需考虑操作误差）：

- 执行短休/长休结算**前**，将当前 `currentHp / usedSpellSlots / exhaustionLevel / debuffs` 写入 `lastRestSnapshot`（覆盖上一次快照，仅保留最近一次）；
- 结算后休息区显示**「撤回上次休息」**入口（存在快照时显示）；点击后：恢复快照中的三项状态并**清除快照**（入口消失），点击即执行不弹确认（恢复属安全操作），结果轻提示；
- 快照随局内状态**持久化**（localStorage）：刷新/关闭页面后仍可撤回；再次执行休息会覆盖快照；
- 撤回后用户再手动调整 HP/法术位/debuff，属新状态，不再与上次休息关联；
- 其他操作（HP/金币/法术位手动增减、debuff 挂摘）**不做撤回**（决策 10）。
- 休息结算为纯函数（`applyShortRest` / `applyLongRest` / `restoreLastRest`），便于单元测试。

### R9 页面与导航（必须）

- 页面结构：`views/session-assistant/index.vue` + 页面私有 hooks（路由 `/assistant`，已确认）：
  - **角色列表视图**（角色来源 = 本地草稿 + JSON 导入，决策 11）：
    - 本地草稿卡片：`store.drafts` 列表（名称、职业/等级/种族摘要、完成状态），点击进入局内面板；无草稿时展示空状态引导去车卡；
    - **JSON 导入入口**：「导入 JSON」按钮 + 文件输入（`accept="application/json,.json"`，参照 `StartPanel.vue` 的读取模式：`file.text()`）；
    - 导入流程：`CharacterJsonService.importDraft` 校验（错误时展示中文原因，如「文件不是有效的 JSON。」「当前仅支持 5e-2014 角色文件」）→ `store.importDraft(raw)` 生成新 id 并加入草稿列表（随草稿持久化）→ **导入成功直接进入该角色的局内面板**（已确认）；

## 6. 验收标准

- 底部导航显示「跑团助手」，路由 title 同步；
- 从草稿列表进入局内面板：首次进入当前 HP = 最大 HP、法术位已用全 0、无 debuff；
- 角色列表展示本地草稿；「导入 JSON」可导入角色文件（非法文件展示中文错误，合法文件进入局内面板）；局内面板可返回列表切换角色（含刚导入的角色）；
- 手机端（无负号键盘）：血量、金币、法术位均可用「＋/−」按钮操作；
- 短休息：损失血量回升一半（向上取整）、邪术师契约位清零、其他法术位不变；
- 长休息（确认后）：满血、全部法术位清零、debuff 清空；
- 休息后出现「撤回上次休息」入口，点击恢复到休息前状态（HP/法术位/debuff/力竭层数），入口消失；刷新后撤回仍可用；
- 状态页签挂载 debuff 后，上方基础信息区出现对应 tag；再点摘除后 tag 消失；力竭用「−/+」叠层数，tag 显示「力竭 ×N」，长休息后层数归零且 tag 消失；
- 点击顶部状态 tag 弹出对应状态详情（状态名 + 效果转述），可正常关闭；
- 局内面板按 Tab 分栏（总览/战斗/物品/状态），切换正常，单页不超长；上方为基础信息区（角色基本信息/HP/金币/休息/状态 tag）；
- 局内状态刷新/关闭后保留；草稿删除后状态不残留展示；
- 金币操作与角色卡页共享 `adventureGold`，两端数值一致；
- 类型检查、全量测试、生产构建通过；无浏览器控制台错误。

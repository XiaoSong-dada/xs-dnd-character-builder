# 角色卡编辑模式需求

> 目标版本：**v1.0.0**  
> 实施状态：**已实现并通过自动化、构建与浏览器交互验收**。
>
> 本文只定义产品行为、数据语义、同步范围与验收标准，不代表相关代码已经实现。

## 1. 背景与目标

当前角色卡主要用于展示由车卡草稿和 D&D 5e 2014 规则自动计算得到的结果。玩家在实际跑团中可能因魔法物品、临时或长期奖励、模组规则、DM 裁定等原因，需要直接修正角色卡数值或获得职业列表以外的法术。

本功能在角色卡中增加一个显式开启的“编辑模式”：玩家先开启编辑模式，再通过双击对应数值区域进行就地编辑；退出编辑模式后，角色卡恢复当前的只读展示。人工修正不得覆盖或破坏原始车卡选择，而应作为独立调整叠加在最新规则计算结果之上。

本功能同时把“禁止手机端浏览器双击放大”提升为整个应用的全局交互要求，保证手机端双击数值能够稳定进入编辑，而不会触发页面缩放。

## 2. 范围

### 2.1 本次包含

- 角色卡“总览”“战斗”“能力”“法术”四个页签的数值编辑；
- 最终六项属性及熟练加值变化后的依赖重算；
- 派生数值的独立人工调整；
- 从当前规则集的整个系统法术库添加职业列表以外的法术；
- 一键移除全部人工修改并恢复系统计算结果；
- 角色卡、角色摘要、跑团助手和 PDF/XLSX/JSON 导出的统一同步；
- 全应用手机端双击放大禁用，同时保留双指捏合缩放。

### 2.2 本次不包含

- 修改职业、子职、种族、背景、专长、装备等原始车卡选择；
- 编辑职业特性、子职特性、专长、法术效果等规则文字；
- 创建系统法术库中不存在的自定义法术；
- 把物品页签纳入本次角色卡编辑模式；
- 把 2024 法术或其他规则集内容混入当前 `5e-2014` 角色。

## 3. 编辑模式交互

### R1 显式开启与退出

- 角色卡默认保持现有只读模式；
- 角色卡提供“编辑”按钮，点击后开启编辑模式；
- 编辑模式下，可修改的数值区域必须有可感知的编辑状态，例如边框、编辑图标或“可双击编辑”提示，不能只依赖颜色；
- 电脑端双击、手机和平板端快速双击同一数值区域，进入该字段的就地编辑；
- 键盘用户聚焦可编辑区域后可按 Enter 进入编辑；
- 进入字段编辑后，原展示值替换为数字输入框并自动选中；
- Enter 或焦点移出输入框时确认合法输入；Esc 放弃当前尚未确认的字段输入；
- 点击“完成编辑”退出编辑模式，页面恢复现有只读展示；
- 退出编辑模式不撤销已经确认的修改；每次合法修改都持久化到当前角色草稿；
- 查看模式下双击数值不进入编辑，也不触发浏览器页面放大。

### R2 输入约束

人工修正允许突破 D&D 5e 2014 的通常规则上限，但仍需保证数据可计算：

- 所有数值只接受有限整数，不接受空值、非数字或小数；
- 最终属性最低为 1，不设上限；
- 最大生命值最低为 1，不设上限；
- 速度与法术位数量最低为 0，不设上限；
- 法术豁免 DC 最低为 0，不设上限；
- 攻击、伤害、技能、豁免、先攻和熟练加值允许负数，不设上限；
- 非法输入不得写入草稿，应保留上一个合法值并给出中文原因。

## 4. 人工调整与重新计算

### R3 差值模型

人工修改不得保存为永久覆盖系统计算的绝对值，而应保存为相对于当前系统值的独立调整：

```text
人工调整值 = 用户填写值 - 当前未叠加本字段人工调整的计算值
最终显示值 = 最新计算值 + 人工调整值
```

例如：

```text
系统计算 AC = 18
玩家填写 AC = 20
保存的 AC 人工调整 = +2

之后敏捷变化使系统重新计算 AC = 19
最终显示 AC = 19 + 2 = 21
```

再次编辑同一字段时，应以当时最新的未叠加该字段人工调整的计算值重新求差，不能在旧人工调整上重复累计。

### R4 上游与下游计算顺序

最终属性与熟练加值属于上游输入，其人工调整必须先参与依赖重算；其余派生字段的人工调整最后叠加：

```text
原始车卡选择
  → 规则计算六项最终属性与熟练加值
  → 叠加六项属性与熟练加值的人工调整
  → 使用有效属性和有效熟练加值重新计算全部派生结果
  → 叠加每个派生字段自身的人工调整
  → 得到最终角色卡
```

例如，系统智力为 16，玩家改为 18，则保存智力人工调整 `+2`。有效智力 18 必须重新影响智力调整值、智力豁免、智力技能、以智力施法时的法术攻击和法术豁免 DC。若法术 DC 本身另有人工调整，则在重新计算后继续叠加。

### R5 来源说明

- 人工修改过的数值必须明确标记“人工调整”；
- 数值详情应能区分系统计算值、人工调整值和最终值；
- 未修改字段继续使用原有规则来源说明；
- 人工调整不能伪装成职业、种族、装备或其他规则来源。

## 5. 可编辑字段

### R6 总览页签

必须支持编辑：

- 护甲等级（AC）；
- 最大生命值；
- 先攻；
- 速度；
- 熟练加值；
- 力量、敏捷、体质、智力、感知、魅力的最终属性值。

六项属性调整值继续由有效最终属性自动计算，不单独提供人工编辑。玩家若只想改变某项技能、豁免、攻击或法术数值，应直接修改对应派生字段。

### R7 战斗页签

必须支持编辑：

- 武器命中加值；
- 武器伤害加值。

当前战斗页展示的是主要武器的公共派生结果。人工修改应作为全局武器命中或伤害调整，同步应用到角色卡及 PDF/XLSX 中可计算的每件武器，避免页面与导出不一致。

### R8 能力页签

必须支持编辑：

- 六项豁免加值；
- 全部 18 项技能加值；
- 被动察觉。

被动察觉的系统值为 `10 + 察觉技能加值`。感知、熟练加值或察觉技能变化时先重新计算被动察觉，再叠加被动察觉自身的人工调整。

职业特性、子职特性、专长、属性提升记录和已选选项详情均保持只读。

### R9 法术页签数值

必须支持编辑：

- 法术攻击加值；
- 法术豁免难度（DC）；
- 戏法以外每个已登记环级的法术位总数。

法术攻击和法术 DC 先根据有效施法属性与有效熟练加值重新计算，再叠加各自人工调整。无系统施法能力的角色可直接人工填写法术攻击和法术 DC。

法术列表数量、已选数量、职业特性等级等由实际列表或规则结果统计，不作为可直接填写的数值。

## 6. 人工添加法术

### R10 候选范围

- 法术候选为当前 `5e-2014` 规则集中已经登记的整个系统法术库；
- 不限制当前职业法术列表、正常已知/准备数量或法术书升级名额；
- 候选项展示中英文名、环级、来源和效果摘要；
- 不允许重复添加同一个法术；已存在法术应引导玩家调整其状态；
- 系统法术库之外的自定义法术不在本次范围。

### R11 按职业施法模式选择加入效果

玩家添加法术时，需要根据当前职业施法模式选择该法术的归属状态，不同职业展示不同结果：

| 施法模式 | 可选加入效果 |
|---|---|
| 已知施法者（如吟游诗人、术士） | 加入“已掌握法术” |
| 契约施法者（邪术师） | 加入“已掌握契约法术” |
| 准备施法者（如牧师、德鲁伊） | 加入额外可准备列表，或加入并立即准备 |
| 法术书施法者（法师） | 加入法术书，或加入法术书并立即准备 |
| 无施法职业 | 作为人工获得法术加入，并由玩家选择是否标记为已准备 |

- 无施法职业允许添加任意系统法术；
- 无施法职业的法术攻击与法术 DC 默认未设置，玩家可在编辑模式中人工填写；
- 人工添加法术不占正常职业的已知、准备或法术书数量上限；
- 人工添加法术必须标记“人工添加”，并记录其加入状态；
- 玩家可单独移除人工添加法术；正常车卡选择、职业法术和法师抄录法术不得通过该操作误删；
- 人工添加法术必须同步进入角色卡、跑团助手和 PDF/XLSX/JSON 导出。

## 7. 一键恢复系统默认

### R12 恢复入口与范围

- 编辑模式提供“一键恢复系统默认”按钮；
- 操作必须二次确认，并明确说明将移除全部人工修改；
- 确认后一次性清除：
  - 六项最终属性与熟练加值的人工调整；
  - AC、最大生命值、先攻、速度的人工调整；
  - 武器命中与伤害的人工调整；
  - 全部技能、豁免和被动察觉的人工调整；
  - 法术攻击、法术 DC 和全部环位数量的人工调整；
  - 所有通过编辑模式人工添加的法术及其状态；
  - 将来明确纳入本编辑模式的其他人工调整字段；
- 清除后立即根据原始车卡选择重新计算并同步全部使用方。

### R13 恢复时必须保留

一键恢复不得清除或改写：

- 职业、等级、子职、种族、背景、专长、属性提升等原始车卡选择；
- 正常车卡流程选择的戏法、已知法术和准备法术；
- 法师正常获得或付费抄录的法术；
- 装备、物品、金币和工匠灌注；
- 跑团助手的状态、力竭和休息快照等局内记录。

## 8. 跑团助手同步

### R14 最大生命值变化

跑团助手使用编辑后的最大生命值，并在最大生命值变化时保持已损失生命值不变：

```text
已损失生命值 = 旧最大生命值 - 旧当前生命值
新当前生命值 = clamp(新最大生命值 - 已损失生命值, 0, 新最大生命值)
```

例如，旧最大生命值 30、当前生命值 20，人工把最大生命值改为 40 后，当前生命值变为 30，仍然损失 10 点。恢复系统默认导致最大生命值变化时也使用同一规则。

### R15 法术位变化

- 跑团助手的每环法术位上限使用编辑后的最终总数；
- 增加上限时保留该环已消耗数量，因此新增部分立即可用；
- 降低上限时保留已消耗数量，但若已消耗数量超过新上限，则钳制到新上限，保证可用数量不为负；
- 一键恢复系统默认导致环位上限变化时使用同一规则。

### R16 其他同步值

跑团助手中的 AC、先攻、速度、熟练加值、攻击、伤害、技能、豁免、被动察觉、法术攻击和法术 DC 均使用编辑后的最终值。人工添加法术按照其加入状态进入对应法术分组并可正常选择法术位。

## 9. 导出与持久化

### R17 统一结果

以下使用方必须读取同一套最终结果，不能分别重新实现人工调整逻辑：

- 角色卡查看模式；
- 角色列表与角色摘要；
- 跑团助手；
- PDF 角色卡；
- XLSX 自动计算卡；
- JSON 导入与导出。

JSON 必须保留人工调整与人工添加法术的来源信息，使导入后能继续重新计算、编辑和一键恢复；不能只导出已经失去来源的最终绝对值。

## 10. 全局禁止手机端双击放大

### R18 全应用触控策略

- 整个应用的所有当前页面及后续新增页面统一禁止手机、平板浏览器原生双击放大；
- 范围包含页面空白区、卡片、按钮、数值区域、输入区域和导航；
- 保留页面滚动与双指捏合缩放；
- 不使用 `user-scalable=no`、`maximum-scale=1` 等禁止全部缩放的 viewport 配置；
- 不影响电脑端鼠标双击；
- 不影响编辑模式对数值区域的双击识别；
- 不影响按钮快速连续点击，不得吞掉第二次点击；
- 赛博骰娘交互画布已有的动态 `touch-action` 策略继续保留，不能破坏骰盘拖拽、缩放和平移。

当前项目只有跑团助手和赛博骰娘页面局部使用 `.touch-manipulation`。实施时应将禁用双击放大提升到应用全局作用域，而不是继续要求每个页面分别声明。

## 11. 验收标准

### 11.1 编辑与计算

- 未开启编辑模式时，全部字段保持现有只读行为；
- 开启编辑模式后，电脑双击、手机快速双击和键盘 Enter 均能进入字段编辑；
- 属性或熟练加值变化后，所有依赖字段即时重新计算；
- 派生字段自身的人工差值在上游变化后继续正确叠加；
- 同一字段反复修改不会重复累计旧差值；
- 人工修改字段能看到系统值、人工调整与最终值来源；
- 数值允许突破规则上限，非法非整数输入不会污染草稿。

### 11.2 法术与恢复

- 任意职业（包括无施法职业）均可从整个 2014 系统法术库添加法术；
- 不同施法模式展示正确的加入效果；
- 人工法术不占正常数量上限，并明确标记来源；
- 一键恢复经二次确认后清除全部人工调整和人工添加法术；
- 一键恢复不影响正常车卡选择、法师抄录法术、装备和局内状态。

### 11.3 同步

- 角色卡、角色摘要、跑团助手和三种导出使用一致最终数值；
- 最大生命值变化时跑团助手保持已损失生命值；
- 环位上限变化时已消耗数量按 R15 保留或钳制；
- JSON 导出再导入后，人工来源、重算和恢复行为不丢失。

### 11.4 移动端

- iPhone Safari、iPad Safari、Android Chrome 双击应用任意区域均不触发页面放大；
- 双指捏合缩放、页面纵向滚动正常；
- 编辑模式中双击数值稳定进入编辑，查看模式中双击数值不编辑；
- 快速连续点击普通按钮时每次点击均生效；
- 主要触控目标不小于 44px，焦点状态与键盘操作可用；
- 赛博骰娘画布交互无回归。

### 11.5 工程验证

- 相关规则计算、人工差值、依赖重算、恢复、生命值与环位同步均有自动化测试；
- TypeScript 类型检查、自动化测试和生产构建通过；
- 无浏览器控制台错误；
- 实施时复核前端依赖拓扑，并按项目约定决定是否更新 `docs/frontend-architecture.md`。

## 12. 已确认决策

1. 六项属性编辑的是角色卡最终属性，不修改基础属性或原始来源。
2. 总览中的生命值编辑对象是最大生命值。
3. 最大生命值变化后，跑团助手保持已损失生命值不变。
4. 人工添加法术来自整个当前规则集系统法术库，可超过职业列表和正常数量限制。
5. 玩家添加法术时根据职业施法模式选择加入效果；无施法职业也允许添加，并可人工填写法术攻击与法术 DC。
6. 法术攻击、法术豁免 DC 和各环法术位均可人工修改。
7. 人工数值允许突破规则上限。
8. 一键恢复系统默认会移除全部人工调整和全部人工添加法术，但保留原始车卡数据与正常抄录法术。
9. 所有最终修改同步到角色卡、角色摘要、跑团助手及 PDF/XLSX/JSON 导出。
10. 编辑模式必须先显式开启；开启后双击数值编辑，退出后恢复当前只读模式。
11. 整个应用禁止手机端双击放大，同时保留双指捏合缩放。

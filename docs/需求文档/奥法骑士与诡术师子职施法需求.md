# 奥法骑士与诡术师子职施法需求

## 1. 背景与目标

用户反馈：战士的子职业"奥法骑士"（Eldritch Knight）原则上可以学习法术，但当前系统中**无法学习法术**。

官方规则核对结论（2014《玩家手册》，与用户判断一致）：

- **奥法骑士**（PHB p.74）：3 级获得施法（Spellcasting）——**1/3 施法者**、智力为施法属性、**已知法术制**（无法师法术书、非准备制）；3 级掌握 2 个戏法 + 3 个 1 环法师法术（其中 **2 个必须来自防护或塑能学派**）；10 级获得第 3 个戏法；此后 4/7/8/10/11/14/16/19 级各学 1 个新法术（已知法术共 11 个）；新增/替换法术限防护、塑能学派，**8/14/20 级可学任意学派**（且可替换 3/8/14/20 级获得的任意学派法术）；法术位按 **1/3 施法者表**推进。
- **诡术师**（Arcane Trickster，PHB p.98）：结构完全相同——1/3 施法者、智力施法、已知法术制，学派限制为**幻术或惑控**（8/14/20 级自由）。

两者属于"子职业提供施法能力"（2014 中与圣武士/游侠的"职业级半施法"不同，是子职级施法），当前系统**完全没有该能力路径**。

目标：让奥法骑士（战士子职）与诡术师（游荡者子职）接入与 2014 规则一致的施法机制（法术位、已知法术选择、施法属性、角色卡展示），并修正排查中发现的数据错误。

## 2. 现状调查（已核验）

### 2.1 系统缺口清单

| 缺口 | 证据 | 影响 |
|---|---|---|
| 无 1/3 施法者法术位表 | `app/src/rules/data/spell-slots-2014.ts` 仅三张表（全施法者/半施法者/契约） | EK/AT 无法得到正确法术位 |
| 施法配置只挂职业级 | `SpellcastingConfig` 挂在 `ClassRule.spellcasting`（`types/rules.ts` 65 行）；8 个施法职业全部职业级挂载 | 子职级施法（EK/AT）无挂载点 |
| 施法流程全部从职业读配置 | `SpellcastingStep.vue`（21—22 行 `classRule.spellcasting`）、`derive.ts`（188—189 行）、角色卡法术页签均职业级 | 战士/游荡者职业无配置 → 无施法步骤、无法术位/法术选择 |
| 法术数据无学派字段 | `SpellRule`（`types/rules.ts` 82—90 行）无 `school`；`spells-2014.ts` 无 | 防护/塑能、幻术/惑控学派限制无法表达 |
| EK/AT 子职为 `index-only` | `fighter.ts` 奥法骑士 `status: 'index-only'`；游荡者诡术师同（`martials-2014.ts`） | 可浏览但界面标记"仅索引" |
| **EK"施法"特性摘要错误** | `subclass-features-2014.ts` 62 行摘要写"拥有法术书，准备法术数量…" | 2014 EK 是**已知法术制、无法术书**，该描述误用 2024 规则（对照：诡术师 105 行摘要"选择已知法术"才是正确表述） |

### 2.2 相关机制现状

- 已知法术制已有现成实现：术士/吟游诗人（`mode: 'known'`，`spellsKnownByLevel`）、邪术师（`mode: 'pact'`）；候选池 `getSpellCandidates`、数量校验 `getRequiredSpellCount`、角色卡"已掌握/可选法术"均已支持 known 模式——**子职施法可复用这些机制**。
- 法术位派生 `getSpellSlots`（`rules/spellcasting.ts`）按 `slotsByClassLevel` 表返回，新增 1/3 表即可接入。
- 施法步骤进入判定：第 7 步"配置施法（若职业具备）"（`docs/rules.md` 车卡顺序），界面/hook 按职业配置决定是否展示，需扩展为"职业或子职具备施法"。

## 3. 需求项

### R1 数据层：1/3 施法者表与 EK/AT 施法数据（必须）

1. `app/src/rules/data/spell-slots-2014.ts` 新增 **1/3 施法者法术位表**（EK/AT 共用，来源 PHB 2014）：
   - 3 级 2×1 环 → 4 级 3×1 → 5 级 3×1+1×2 → 6 级 3×1+2×2 → 11 级起 3×2 环 → 14 级 2×3 环 → 19 级 1×4 环（1—20 级逐级登记，与既有三张表同构）。
2. 新增 1/3 施法者"最大可用环级"数组（`maxSpellLevelByClassLevel`，与表对齐）。
3. EK 已知法术数量（3/4/7/8/10/11/14/16/19 级 +1，共 11）与戏法数量（3 级 2 个、10 级 3 个）；AT 同构——按 `mode: 'known'` 的 `spellsKnownByLevel`/`cantripsKnownByLevel` 登记。
4. 法术池：EK/AT 均从**法师法术列表**（`class-2014-wizard` 的法术）中选择；**本批全池可浏览**，界面标注 DM 提示（学派过滤属后续批次，见 R5）。

### R2 类型与挂载：子职施法配置（必须）

1. **类型扩展**：`SubclassRule`（`types/rules.ts` 115—127 行）新增可选字段 `spellcasting?: SpellcastingConfig`——与职业级 `ClassRule.spellcasting` 同构（规则数据为 TS 对象字面量，非 JSON；类型声明是数据装配的前提）。
2. **数据装配**：在子职数据条目中填入施法配置对象（与 `arcane-casters-2014.ts` 法师配置写法一致）：奥法骑士 `mode: 'known'`、`ability: 'int'`、`startsAtLevel: 3`、1/3 表、法师法术池；诡术师同构。
3. 配置解析优先级：子职有施法配置时优先子职，否则职业（兼容现状）。

### R3 规则层：施法派生与校验适配（必须）

1. `rules/spellcasting.ts`：`getSpellSlots`/`getRequiredCantripCount`/`getRequiredSpellCount`/`getSpellCandidates`/`getMaximumSpellLevel` 的配置来源改为"子职优先、职业兜底"（或显式传入）。
2. `rules/derive.ts`（188—240 行）：法术攻击/法术豁免 DC 的施法属性取子职配置（`int`），来源说明标注"子职施法属性"。
3. 校验：`validateSpellSelections`/时间线检查点按子职施法数量约束生效；EK/AT 未选子职时无施法要求。

### R4 界面层：施法步骤与角色卡（必须）

1. `SpellcastingStep.vue`（21—22 行）与角色卡法术页签（`CharacterSheetStep.vue`）配置来源同步改为子职优先。
2. 施法步骤进入条件：战士+奥法骑士、游荡者+诡术师在第 7 步展示施法配置；未选对应子职的战士/游荡者不展示（现状不变）。
3. EK/AT 子职状态：**施法特性**（`fighter-eldritch-knight-spellcasting`、`rogue-arcane-trickster-spellcasting`）提升为 `implemented`（法术位表、已知法术数量、施法属性为可核验规则结构）；**子职整体保持 `index-only`**（其余特性未经核验，界面保留"仅索引"徽标；warning 不阻塞生成角色卡）。

### R5 学派限制（后续批次，不阻塞本批；本批全池可浏览 + DM 提示）

本批实现：候选池**不按学派过滤**，界面在施法步骤与角色卡提示"2014 规则限防护/塑能（奥法骑士）或幻术/惑控（诡术师）学派，请 DM 确认"。

后续批次（独立需求）：

1. `SpellRule` 新增 `school` 字段并登记 489 条法术的学派（防护/塑能/幻术/惑控/咒法/预言/死灵/变化）。
2. EK 候选池按"防护∪塑能（+8/14/20 级自由学派位）"过滤；AT 按"幻术∪惑控（+8/14/20 级自由位）"过滤。
3. 替换法术（升级时替换一个已知法术）的学派校验。

### R6 测试（必须）

1. 1/3 施法者表逐级断言（关键等级 3/5/11/14/19 与既有三张表一致性测试同构）。
2. EK/AT 已知法术数量、戏法数量（3/10 级）、`getRequiredSpellCount` 与候选池。
3. 法术攻击/DC 派生使用智力（来源说明含"子职施法属性"）。
4. 角色卡法术页签：EK/AT 展示戏法、已掌握、候选（known 模式）；未选子职的战士不出现施法内容。
5. 校验：子职施法数量不足报 error；无子职时无施法校验。

### R7 文档同步（必须）

1. `docs/rules.md`：子职施法约定（1/3 施法者、子职配置优先、学派限制口径）。
2. **修正 `subclass-features-2014.ts` 62 行 EK 施法特性摘要**："拥有法术书，准备法术数量…" → "选择已知法术，可用环级按 2014 奥法骑士施法表推进，初始限防护与塑能学派"（与诡术师表述一致；纯数据文案修正，不改变行为）。
3. 本需求文件登记实施状态；`docs/frontend-architecture.md` 如有新增模块登记拓扑。

## 4. 非目标与边界

- **不实现 2024 规则**：EK 的 2024 版（法术书/准备制）不属于当前规则集；资料文件 `docs/classes/subclasses/fighter/fighter-eldritch-knight.md` 为 2024 内容，仅作未来来源，不参与 2014 实现。
- **不实现职业资源交互**：EK/AT 无独立资源（法术位长休恢复），不涉及。
- **不处理 DMG/XGtE 扩展法术池**：法术池按现有 489 条法师法术。
- 学派限制（R5）**本批不实施**：候选池全池可浏览并提示 DM 确认，不静默限制；学派过滤为后续批次独立需求。
- 不改变既有 8 个施法职业的行为（子职配置缺省时完全走职业配置）。

## 5. 涉及模块与依赖方向

```text
app/src/rules/data/spell-slots-2014.ts     新增 1/3 施法者表 + 1/3 最大环级
app/src/rules/data/subclasses-2014.ts 或子职数据文件   EK/AT 挂接 spellcasting 配置（SubclassRule.spellcasting）
app/src/types/rules.ts                     SubclassRule 新增可选 spellcasting；SpellRule 新增 school（后续批次 R5）
app/src/rules/data/spells-2014.ts          school 字段登记（后续批次 R5）
app/src/rules/spellcasting.ts              配置来源子职优先
app/src/rules/derive.ts                    施法属性取子职配置
app/src/views/character-builder/components/{SpellcastingStep,CharacterSheetStep}.vue  配置来源与进入条件
app/src/views/character-builder/hooks/useCharacterBuilderPage.ts  施法步骤进入判定（如涉及）
app/test/rules/{spell-slots-2014,spellcasting,derive}.test.ts 等   测试扩展
docs/rules.md / docs/frontend-architecture.md / 需求文档 6a          文档同步
```

依赖方向不变：`views → rules → types`，`rules` 保持框架无关。

## 6. 验收标准

1. `pnpm test:run` 全量通过（R6 用例覆盖 1/3 表、已知数量、候选、派生、界面、校验）。
2. `pnpm build`（`vue-tsc -b && vite build`）通过。
3. 手机宽度流程：
   - 战士 + 奥法骑士（3 级）：第 7 步出现施法配置，可选戏法 2 个、已知法术 3 个（1 环），角色卡法术页签展示"已掌握"与候选、法术位"1环×2"；
   - 奥法骑士升至 5 级：法术位 1环×3+2环×1、已知法术 +1（4 个）；
   - 游荡者 + 诡术师：同样可施法（学派提示按 R5 决策）；
   - 战士 + 勇士/战斗大师：无施法步骤与法术内容（现状不变）；
   - 未选子职的战士：施法步骤不出现。
4. 无浏览器控制台错误；错误与提示为玩家可理解的中文。

## 7. 已确认决策（2026-08-17 用户确认）

3. **施法配置挂载**：两步走——先类型扩展（`SubclassRule.spellcasting?: SpellcastingConfig`），再在子职数据文件装配配置对象（与职业级 `ClassRule.spellcasting` 同构；规则数据为 TS 对象字面量，非 JSON；"数据装配"即数据文件内赋值，"类型扩展"即类型声明允许该字段）。

## 0. 结论摘要

1. 不全书 v2025.11.8 中「使用《玩家手册2024》规则」的扩展内容集中在**「破解奥秘（UA）」9 篇文章**与**「新贤者谏言（SAE）2025」**；另有「线上发布」中的《冒险地图匣：葬仪社》为 DM 向补充。真正的 2025 正式扩展书（《被遗忘的国度：英雄费伦》《艾伯伦：工匠的熔炉》等）**尚未收上书**，目录中只有对应 UA 试玩稿。
2. UA 内容按性质分为三类：
   - **新职业**：奇械师 2024（艾伯伦 UA）、灵能使/灵能（灵能 UA 与灵能 II）；
   - **新子职与 2014 子职的 2024 修订版**：被遗忘的国度、可怖、奥术、奥术 II、浩劫、子职业更新，共 43 条子职身份（含修订，去重后 42 条概念）；
   - **配套角色选项**：龙纹专长 28 项、狂野天赋专长约 10 项、新法术与职业法术列表、奇械师魔法物品 9 项。
3. UA 是**游玩测试内容，不是官方正式资源**，且存在「灵能 → 灵能 II」「奥术子职 → 奥术子职 II」「可怖咒剑宗主 → 奥术咒剑宗主」等修订替代关系。产品若要引入，必须先定「是否引入 UA、默认开关、修订替换、正式书替换」四项政策，否则会产生重复选项与返工。
4. 建议采用**双轨方案**：
   - 近期：先做来源模型与元数据收口（不产出玩家可见选项），把 2024 来源开关、游玩测试标记、修订映射与文档接口准备好；
   - 中期：按「奇械师 2024 → 被遗忘的国度子职 → 子职业更新（与 B13 合并）→ 其余 UA 子职 → 灵能使 → 专长/法术/物品」分批接入，每批独立验收；
   - 正式书可用后，用正式版替换同概念的 UA 数据，保持稳定 ID 与草稿兼容。
5. 本文列出 8 个待确认决策（D-01—D-08），需要产品负责人在进入实施批次前确认。

## 1. 背景与现状

### 1.1 当前 2024 支持范围（v1.3.0）

依据 [rules.md](../rules.md) 与 [B12 支持清单](2014与2024双规则版本支持-B12支持清单与验收.md)：

- 12 个基础职业、48 个核心子职（1—20 级单职业）。
- 16 个背景、10 个主物种与 8 个血统、75 项专长、391 道法术。
- PHB 2024 普通装备与起始装备、348 条 DMG 2024 魔法物品（209 `selectable`／139 `index-only`）。
- 跑团助手 2024 资源结算、JSON／ZIP／PDF／XLSX 导出。
- 未被装配的 2024 内容：怪物数据（MM 2025，影响荒野变形、召唤、坐骑、同伴）、DMG 2024 的 DM 向系统（超自然赠礼、据点、宝藏表）。

### 1.2 现有规则集与来源机制

- `RulesetId` 目前只有 `5e-2014` 与 `5e-2024` 两个版本边界，定义于 `app/src/types/character.ts`。
- 2024 来源表 `app/src/rules/data/sources-2024.ts` 只有 `source-2024-phb` 与 `source-2024-dmg`，均为 `category: 'core'`、`selectable: false`，即**始终启用、不进入来源开关**；文件注释已预留「后续批次按需追加扩展书条目」。
- 2014 的扩展来源开关由 `SELECTABLE_SOURCE_IDS` 驱动；`app/src/rules/source-books.ts` 的 `getSelectableSources()`、`getDefaultEnabledSourceIds()`、`normalizeEnabledSourceIds()` 目前**硬编码 2014 来源**。
- 2024 草稿创建与改版时 `enabledSourceIds` 固定为空数组：`app/src/stores/character-drafts.ts` 两处 `ruleset === '5e-2014' ? getDefaultEnabledSourceIds() : []`。
- 来源页面 `app/src/views/character-builder/components/SourcesStep.vue` 对 2024 显示提示「2024 暂不提供扩展书开关……后续扩展书将在对应批次接入」。
- `isSourceEnabled()` 已支持按传入 `repository` 判定核心来源；但按来源过滤的候选池与草稿规范化仍需 2024 扩展来源接入后才完整成立。

### 1.3 缺口

- 2024 没有「扩展来源」这一层，无法表达「官方核心 / 扩展书 / UA 游玩测试」三档内容。
- 2024 没有 UA 内容的元数据、稳定 ID 前缀、修订关系与完成度标记。
- 现有 2024 数据文件按核心书组织（`feats-2024.ts`、`spells-2024.ts`、`equipment-2024.ts`、`magic-items-2024.ts`、各职业 `*-2024.ts` 等），尚无扩展目录约定。
- 2014 扩展书（XGtE、TCoE 等）的子职已有 2014 运行时条目，但 2024 版本只有 UA 试玩稿，两者必须在数据与 ID 上保持独立。

### 1.4 B13 边界

B13 处理的是「旧 2014 内容适配到 2024」与「旧 2024 隔离草稿转换」，本质是**同一概念的跨版本适配**；本文处理的是「2024 规则集下新增的扩展书／UA 内容」，本质是**新增内容**。两者共享来源模型、稳定 ID 与修订替换机制，实施时应在同一套模型上分批推进，不重复造两套机制。

### 2.2 不全书自身的版本标记规则（`写在前面.md`）

- `new!`：本版本新增资源。
- `（旧版）` 或 `Legacy`：已停止更新或已有新版本替代；不进速查，但经 DM 同意仍可使用。
- WotC 归类为「2014 only」的资源只会在资源封页单独标注，不从速查删除。
- 破解奥秘（UA）：官方不定期专栏，明确「不是官方资源，只是测试」，使用时需 DM 同意。
- 分区：速查&指南、核心三宝书、扩展&资源、合作内容、旧版资源、其余杂项；扩展基本按出版顺序。

## 5. 功能需求

### R1 来源模型与开关

1. `sources-2024.ts` 增加 2024 扩展来源条目，至少覆盖：奇械师（艾伯伦 UA）、被遗忘的国度子职、可怖子职、灵能、奥术子职、浩劫子职、子职业更新；正式书到达后增加对应正式来源。
2. `RuleSource` 或配套元数据需能表达：`category: 'core' | 'supplement'`、`selectable`、来源简称、完整书名、规则版本与内容性质（正式扩展 / UA 游玩测试）。
3. `app/src/rules/source-books.ts` 的来源选择、默认值与规范化必须按规则集解析，禁止继续硬编码 2014 来源集合。
4. 2024 草稿创建、改版与迁移时的 `enabledSourceIds` 默认值按 D-02 决定；核心来源始终启用。
5. 关闭来源采用既有非破坏语义：保留原始选择，候选池、派生与导出按来源判定，重新开启后恢复。

### R2 规则集与内容隔离

1. 2024 扩展内容全部标记 `ruleset: '5e-2024'`；不得写入或复用 `5e-2014` 条目。
2. 2024 扩展 ID 使用带来源前缀的稳定字符串，例如 `class-2024-ua-artificer`、`subclass-2024-ua-wizard-conjurer`、`feat-2024-ua-dragonmark-detection`、`spell-2024-ua-telekinetic-fling`；正式书版本可改用 `class-2024-eberron-artificer` 之类的前缀，但同概念 ID 一旦发布不得重命名。
3. 同一概念在两版规则下必须使用不同 ID、不同来源与独立数据；禁止隐式共享特性、属性或数值。
4. 2014 条目命名与新条目接近时（如骑兵／骁骑士、醉拳宗／醉拳武者），界面必须显示来源与规则版本，避免误认。

### R3 修订与替代

1. 建立 2024 扩展内容的修订登记：同一概念的多期 UA 只登记一条可选条目，数据取最新一期；被替代关系写入元数据与文档。
2. 「灵能 → 灵能 II」「奥术子职 → 奥术子职 II」「可怖咒剑宗主 → 奥术咒剑宗主」必须在数据层明确指向唯一有效版本。
3. 已被正式书发布的 UA 概念，以正式版数据替换，并在来源字段记录「UA 试玩稿 → 正式书」。
4. 旧草稿若引用了被替换前的数据，仍能解析（稳定 ID 不变）；若机制变化导致原选择不合法，按既有规则保留并标记失效，给出中文原因。

### R4 职业与子职

1. 新职业按纵向切片实现：核心特质、1—20 级特性表、熟练、起始装备、施法配置、职业资源、子职选择等级、检查点、派生钩子与角色卡展示。
2. 奇械师 2024 需要独立处理：施法（智力准备制、半施法位向上取整）、`仿制魔法物品`、`魔法物品工艺师`、`灵光一闪`、`储法物品`、`奇械之魂`；不得复用 2014 奇械师灌注模型。
3. 灵能使需要独立处理：灵能骰资源、灵能才赋选择、施法配置与子职法术；两期数据只保留一版。
4. 子职按职业归并到对应职业的时间线；已有 2014 子职的 2024 版本使用独立子职 ID，并单独登记等级特性、必选项、资源与派生。
5. 破誓者若沿用「DM 选项」语义，不得进入普通玩家默认候选，UI 给出中文提示。

### R5 专长

1. 龙纹专长登记类别（龙纹／通用／传奇恩惠）、前置（艾伯伦战役、等级、已有龙纹）、可重复规则、属性提升上限与法术授予。
2. 狂野天赋专长登记「不具有其他狂野天赋专长」互斥、技能/属性增益、固定法术授予与施法属性选择（智力／感知／魅力）。
3. 专长授予的起源专长替代语义（如贵族、智者背景）必须结构化，不得只写在摘要中。
4. 专长候选池按来源、规则集与前置过滤；UA 专长在来源关闭或未启用时不可选。

### R6 法术与法术列表

1. 每个扩展法术登记稳定 ID、中英文名、环级、学派、职业归属、来源、原创中文摘要与升环信息。
2. 职业法术列表更新（奇械师、灵能使）不得覆盖核心职业法表；通过追加来源过滤实现。
3. 区分「加入职业法表」「始终准备」「额外已知」「不占已知上限」等语义；重名或重印法术只保留一个有效版本。
4. 2 期灵能法术的重名条目按最新版处理，旧版不作可选候选。

### R7 装备与魔法物品

1. 奇械师 UA 魔法物品登记名称、类别、稀有度、同调、充能／恢复与可自动计算字段；未核验效果保持展示级。
2. 奇械师起始装备按 2024 规则登记 A/B 方案与金币。
3. 不实现 DM 奖励类护咒与怪物数据；相关条目保持索引或后续需求。

### R8 完成度与校验

1. 沿用 `implemented`／`selectable`／`index-only`／`dm-only`／`unavailable` 状态语义。
2. UA 条目在 UI 必须显示「游玩测试内容，需 DM 同意」的统一标记，并与正式扩展、核心内容视觉区分（不能只依赖颜色）。
3. 未满足前置、来源关闭、跨版本引用必须返回玩家可理解的中文原因与返回步骤。
4. 完整性校验必须检查子职特性的必选项与资源，不能因顶层出现在下拉列表就判定完成。

### R9 UI 与移动端

1. 来源页面为 2024 启用扩展书开关，替换现有「暂不提供扩展书开关」提示；列出核心来源、可选扩展来源与各自内容性质。
2. 职业、子职、专长、法术、物品列表与详情显示来源简称与「游玩测试」标记；UA 条目不默认出现在候选池。
3. 长列表沿用搜索与筛选；新增来源筛选只影响视图，不改变草稿来源开关。
4. 移动端保持既有展开卡片、时间线与 44px 触控目标规范。

### R10 草稿、跑团与导出

1. 草稿继续只保存原始选择；来源开关与 UA 选择进入 `enabledSourceIds` 与既有选择结构。
2. 来源关闭、职业／子职／等级变更后，UA 选择保留并标记失效；重新开启恢复。
3. JSON／ZIP 往返必须保留 UA 来源与选择；旧草稿不带这些字段时安全加载。
4. 页面角色卡、PDF、XLSX 共用 `buildCharacterExportModel`；UA 内容需要进入职业特性、专长、法术与物品区块，并携带来源提示。
5. 跑团助手对 UA 资源（如灵能骰、仿制魔法物品）按现有资源结算模型处理；无法自动结算的效果给出提示。

### R11 文档、译名与版权

1. 规则行为变化同步更新 `docs/rules.md`；职业／子职变化同步更新 `docs/dnd-classes.md` 与对应资料文件；专长、法术、装备、背景、物种分别更新对应索引。
2. 新增、删除或移动模块时同步更新 `docs/frontend-architecture.md`。
3. 中文译名以项目内《5E 不全书》为对齐基准（与现有法术、子职译名策略一致）；同一概念在 2014 与 2024 下译名不同时保持一致映射记录。
4. 只登记必要机械字段、稳定 ID、原创中文摘要与来源索引；不复制 CHM 或规则书正文。
5. UA 内容在文档中必须标注「游玩测试」与被替代关系。

### R12 SAE 规则核对

1. 将 SAE 2025 作为 2024 规则的官方裁定基线，逐条比对现有 2024 实现（尤其职业特性、专长、装备、施法、魔法物品）。
2. 存在差异的条目登记为勘误或回归测试，不擅自改口径；与不全书口径冲突时先记录差异。
3. SAE 核对可独立于扩展内容接入分批执行。

## 7. 验收标准

### 7.1 数据完整性

1. 每个已接入来源都有逐条内容清单，清单与代码注册表数量一致。
2. 每条规则显式标记 `ruleset: '5e-2024'` 与有效来源；无重复稳定 ID、无悬空来源、无重复修订候选。
3. `implemented` 条目的必选子项齐全；未完成条目保持明确非完整状态。
4. 2014 与 2024 数据互不引用；同概念不同版本 ID 分离。

### 7.2 规则行为

1. 新职业/子职在正确等级进入时间线，必选项、互斥、跨等级去重与前置正确。
2. 来源开关正确影响候选池、派生、校验与导出，且非破坏。
3. UA 条目的游玩测试标记、DM 提示与不可用原因清晰可读。
4. 修订替代后，同一概念只出现一个有效选项；旧草稿仍可解析。

### 7.3 兼容与导出

1. 既有 2014 草稿与 2024 核心草稿无需迁移即可继续读取与编辑。
2. JSON／ZIP 往返保留来源与原始选择；页面、PDF、XLSX 结果一致。
3. 导出包含 UA 来源提示，不因来源关闭静默删除关键能力。

### 7.4 工程验证

1. TypeScript 类型检查通过。
2. 全部自动化测试通过，新增数据完整性、合法输入、边界、缺项、互斥与回归测试。
3. 生产构建通过。
4. 交付说明写明「已复核前端依赖拓扑，已更新／无需更新」。

## 8. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| UA 内容随时被修订或废弃，导致返工 | 单一稳定 ID＋最新版数据＋修订元数据；正式书到达后替换；默认关闭降低影响面 |
| UA 内容强度与核心内容混杂，破坏平衡预期 | 独立来源、默认关闭、统一游玩测试标记、详情说明强度水平 |
| 2014 与 2024 同名子职/专长混淆 | 版本化 ID、独立数据、来源与版本提示 |
| 选项数量膨胀导致移动端难用 | 来源开关＋搜索筛选＋分批接入；不默认展示 UA |
| 版权越界 | 只登记必要机械字段与原创摘要；不复制正文；UA 亦不例外 |
| 与 B13 重复建设 | 共用来源与修订模型；子职业更新类条目与 B13-02 合并 |
| MM 2025 未装配导致变形/召唤特性无法数值化 | 保持提示级，不伪造数据；登记为独立缺口 |

# 角色卡导出（PDF / XLSX / JSON）· 更新计划

> 依据《docs/需求文档/角色卡导出需求.md》制定。**V3（2026-08-20）**：中文模板已由用户自制完成（`docs/export-templates/`），实施目标收敛为「读取模板 → 填入数值 → 用户下载」。V1 自绘实现已完成，V2 模板自制阶段取消。

## 目标与范围（V3）

- **三种导出**：PDF（pdf-lib 填充用户自制中文模板）、XLSX（exceljs 读取用户自制中文模板，按"字段映射"表写入输入单元格）、JSON（已有，不变）。
- **模板**：用户自制，位于 `docs/export-templates/`：
  - `5e2014_中文原创角色卡_PDF模板.pdf`（3 页中文版面）
  - `5e2014_中文自动角色卡_参考版.xlsx`（6 表：角色卡/人物资料/法术卡/配置数据/字段映射/使用说明）
- **运行时不制作、不排版模板**：只填值并保存下载。

## 模板核查结论（2026-08-20 已核验）

### XLSX（✅ 可填充，有填充契约，公式/下拉/合并已实测保留）

- **问题**：WPS 导出带 `x:` 命名空间前缀（`<x:workbook xmlns:x=...>`），exceljs 4.4.0 解析报错 `Cannot read properties of undefined (reading 'sheets')`。
- **修复（已验证）**：预处理脚本去掉 XML 标签/属性 `x:` 前缀并转为默认命名空间后，exceljs 读取成功——6 张表、中文界面、公式完整。
- **填充契约（用户已定义）**：「字段映射」工作表 275 行：43+ 字段（`character_name → 角色卡!A4`、`str_score → A12`、`save_str_prof → J11`、`skill_acrobatics_prof → J26` 等）+ 「使用说明」：**浅黄色 = 需写入单元格、浅蓝色 = 公式自动计算（不覆盖）**、技能标记 `●=熟练 ◆=专精`。
- **读写往返实测（已验证）**：exceljs 读模板 → 填值 → 写回后：**33 个公式、26 个 dataValidation（下拉）、183 个合并单元格全部保留**，填值正确（A4/A12 实测）。
- 补充信息：「配置数据」表提供职业/种族/背景/阵营/等级候选值；「法术卡」表有 `spellcasting_class → 法术卡!I4`、`spellcasting_ability → Q4`，法术列表填充结构待实施阶段逆向。
- **填值规则**：映射字段对应的目标单元格若已有公式（浅蓝区），则**跳过不覆盖**（由公式自动计算）；仅写空白输入格（浅黄区）。

### PDF（⚠️ 可填充，但需坐标绘制）

- 3 页、219KB、中文文本型版面（44 个 BT..ET 文本块、CID 子集字体、完整坐标），**无 AcroForm 表单字段**（pdf-lib 字段数 = 0）。
- **填充路线**：坐标绘制——从 Contents 流提取每个填写位坐标（文本块坐标/字号已完整），运行时用 pdf-lib 在指定坐标绘制中文文本（需运行时注册中文字体，如 Noto Sans SC 子集或思源黑体子集）。
- 备选：请用户在 WPS/Adobe 中为 PDF 添加表单域后另存，则转为表单填充（更简单但依赖用户操作）。
- 原始 Contents 流已存档：`docs/export-templates/pdf_contents_raw.txt`（坐标逆向资料）。

## V3 实施阶段

### 阶段 0：模板落地与预处理（一次性）

**XLSX**：编写预处理脚本（python/node）：
1. 修复命名空间（去 `x:` 前缀，已验证方案）；
2. 校验：exceljs 可读、公式不丢失、中文无乱码；
3. 产出运行时模板 `app/public/templates/character-sheet-zh.xlsx`（原件保留在 `docs/export-templates/`）。

**PDF**：编写坐标逆向脚本：
1. 解析 Contents 流（对象 33 + 其余两个 Contents 对象 5/21，ASCII85+Flate 解码），提取全部文本块坐标/字号/内容；
2. 与模板版面人工对照，生成填写位坐标映射 `docs/export-templates/pdf-field-mapping.md`（字段 → 页/坐标/字号）；
3. 中文字体：选定运行时嵌入字体（Noto Sans SC 子集，评估体积；或模板已嵌入字体时复用其 CID 映射——优先复用模板字体避免二次嵌入）。

- 完成检查：xlsx 可被 exceljs 读写且公式在；PDF 映射表覆盖角色卡必填字段（名称/职业/等级/种族/属性/技能/豁免/AC/HP/物品）。

### 阶段 1：XLSX 填充服务（改造 `src/services/export-xlsx.ts`）

1. **运行时读取模板的「字段映射」表**自动构建「字段 Key → 工作表!单元格」映射（不硬编码，用户改模板无需改代码）；
2. 填充逻辑：把角色数据（`buildCharacterExportData` 或直接 rules 派生）映射为字段 Key 值，写入浅黄输入单元格；浅蓝公式区不写；
3. 技能/豁免熟练标记转换：`●`（熟练）/`◆`（专精）由 derive 来源推导；
4. 输出：另存 `.xlsx` 下载，文件名 `角色名-dnd5e.xlsx`；
5. 单测：`test/services/export-xlsx.test.ts` 改造——真实模板填充后读回断言输入单元格值与页面一致、公式单元格未覆盖、中文无乱码。

### 阶段 2：PDF 填充服务（新增 `src/services/export-pdf.ts`）

1. 加载模板 → 按坐标映射表在对应位置绘制文本（pdf-lib `drawText`，嵌入中文字体）→ 保存下载，文件名 `角色名-dnd5e.pdf`；
2. 字体：优先复用模板 CID 字体映射（零体积增量）；不可行时运行时注册中文字体子集；
3. 多行文本（物品/特性/备注）按字号与可用宽度自动换行；
4. 单测：填充后 pdf-lib 读回页面绘制内容断言关键字段存在（文本提取受 CID 限制时，改断言绘制操作与坐标）或使用黄金文件对比。

# 弹窗标题栏固定与内容区滚动（UiModal 布局修复）· 更新计划

> 目标版本：**v1.1.1**
> 实施状态：**已完成**（618 测试通过、类型检查与生产构建通过；版本已同步至 v1.1.1，待提交）。

## 背景与问题

「编辑角色形象」等弹窗内容过长时，弹窗标题与关闭按钮会随内容一起滚动出视野。

根因：通用弹窗组件 `UiModal.vue` 的 `section` 是**整个弹窗（header + body + footer）的唯一滚动容器**（`overflow: auto` + `max-height: min(80dvh, 42rem)`），header（title + × 关闭）位于滚动容器内部，内容长时随内容滚动。

项目已有正确实现先例：`UiScrollModal.vue`（抄录法术书、添加物品等长内容弹窗）采用 `section: flex column + overflow: hidden`、header/footer `flex-shrink: 0` 固定、仅 `__body`（`flex: 1; min-height: 0; overflow-y: auto`）滚动，注释明确说明与 UiModal 的差异。**UiModal 的整体滚动是历史遗留缺陷，本次将正确模式补到 UiModal 上（方案一）。**

## 目标

- 所有 UiModal 弹窗的标题栏（title + 关闭按钮）与页脚固定，不随内容滚动；
- 仅内容区（`__body`）在弹窗高度上限内滚动；
- 短内容弹窗视觉与行为零变化；UiModal 与 UiScrollModal 布局模式统一。

## 实施步骤

### 阶段 1：UiModal.vue 布局改造（唯一代码改动面，约 6 行 CSS）

1. `section`：`overflow: auto` → `overflow: hidden`，增加 `display: flex; flex-direction: column;`（保留 `width: min(100%, 30rem)` 与 `max-height`）；
2. `header, footer`：增加 `flex-shrink: 0`（现有 flex 布局保留）；
3. `__body`：增加 `flex: 1; min-height: 0; overflow-y: auto;`（保留 padding）——与 UiScrollModal 的 `__body` 实现一致。

模板与 props 不动（`title`、`close`、`slot`、`footer`、`Teleport`、`role`、类名均不变）。

### 阶段 2：使用方与测试回归检查

1. 8 个使用点逐一点检：短内容弹窗（删除确认、收款码、调整数量等）在内容不超高时不出现滚动条，布局无变化；
2. 测试无需改动：现有断言基于 `.ui-modal` 类名与文本（如 `.ui-modal button`、`document.body.textContent`），无滚动/布局断言，布局改动不影响；
3. 若发现个别弹窗依赖"整体滚动"（如 body 内元素高度依赖滚动容器），单独评估调整，不改变组件语义。

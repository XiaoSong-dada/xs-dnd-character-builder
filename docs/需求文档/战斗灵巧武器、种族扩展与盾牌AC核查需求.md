# 战斗灵巧武器、种族扩展与盾牌 AC 核查需求

登记日期：2026-10-06。状态：调查与实施前置准备已完成，产品功能尚未实施。

分批计划：[战斗灵巧武器、种族扩展与盾牌 AC 分批计划](战斗灵巧武器、种族扩展与盾牌AC分批计划.md)。2026-10-06 用户已确认力量/敏捷参考卡、盾牌默认不装备且手动装备后计算 AC、官方/合作/UA 全部纳入，并补充装备后无法取消装备的问题；对应计划 D1—D4。仍处于文档阶段，产品实现未开始。

## 1. 目标与边界

本轮按用户要求，只核查问题、记录需求、准备后续实施依据。产品对象为 `app/`，不修改原型项目、规则数据、产品代码、草稿格式、版本号或更新公告。

用户提出的三项需求：

1. 战斗页新增标题为「使用灵巧武器」的卡片，结构与「主要武器」一致，包含武器命中加值和武器伤害加值两个格子，用于查看敏捷攻击数值。
2. 对照本地《5e 不全书》，调查幻身灵等种族及种族扩展书的缺项。
3. 不再默认把盾牌加到 AC，盾牌相关收益由玩家自行调节，并检查其他职业是否同样受影响。
4. 补充：解决装备后无法取消装备，卸下只改变装备状态，不删除物品。

核查同时覆盖 `5e-2014` 与 `5e-2024`；两版资料分别登记。文档中的后续方案与验收条件不代表本轮已实现。

## 3. R1：灵巧武器卡片与攻击计算

### 3.1 已确认的现状

| 位置 | 证据与结论 |

| `app/src/rules/derive.ts:391` | 通用攻击属性按职业决定：2014 游荡者、武僧、游侠使用敏捷，战斗铁匠的特定魔法武器使用智力，其余通常使用力量；未按具体武器 `finesse` 或远程词条选择属性 |

| 2014 | +2 / +0 | 敏捷，+5 / +3 | 数值不一致 |

### 3.2 规则与产品口径

不全书章节 3947（`玩家手册/装备/武器.html`）明确：灵巧允许力量或敏捷，攻击与伤害必须选择同一个属性。因此不能把「灵巧强制使用敏捷」写成 D&D 规则。

用户已确认「主要武器」展示力量参考，「使用灵巧武器」展示敏捷参考，两组独立手动调整；主要卡不再沿用按职业切换属性的旧算法。不要把逐武器的较高值选择与固定属性参考混为同一语义；跑团与导出的实际武器仍按该武器及职业规则计算。

### 3.3 实施前准备

- 保留现有两格布局、来源说明、编辑模式、触控尺寸和 SCSS 约定；规则计算放在纯函数中。
- 优先复用 `weapon-attacks.ts` 的熟练与武器属性判断，复核战斗铁匠、武僧及其他特殊攻击属性的适用条件。该函数目前并未完整复用 `derive.ts` 的灌注和特殊攻击属性，不应直接替换全部攻击派生。
- 先定义新数值是否为通用敏捷参考，还是绑定具体灵巧武器。具体武器绑定时需处理未装备武器、多个已装备武器、非熟练武器和魔法武器；当前「第一件已装备武器」不等价于玩家明确选择的主手。
- 两组格子如均可手动编辑，人工修正必须独立；现有 `ManualDerivedField` 只有一组攻击字段，新增字段需同步 `manual-edits.ts` 的白名单、草稿读取/导入归一化、编辑 hook 和恢复默认行为。
- 跑团助手和导出需核查数值一致性；通用敏捷参考卡不能自动作为每件武器的最终攻击数值。

### 3.4 后续验收用例

1. 战斗页出现「主要武器」与「使用灵巧武器」，后者包含同样的命中、伤害两格。
2. 上述两版圣武士用例的敏捷参考为命中 +5、伤害 +3，来源注明敏捷和熟练。
3. 力量高于敏捷时仍能区分力量攻击与敏捷参考；不能宣称固定敏捷值为唯一合法灵巧数值。
4. 属性与熟练人工调整生效；两组独立修正不串值，刷新、JSON 导入导出、恢复默认符合字段契约。
5. 逐件武器检查涵盖非熟练、普通远程、非灵巧近战、魔法武器和特殊职业属性，跑团助手与导出不出现同一武器不同数值。

## 5. R3：盾牌默认 AC 与职业影响

### 5.1 根因与复算

`starting-equipment.ts:83` 的 `applyRecommendedEquipment` 独立装备第一件护甲、第一面盾牌和第一件武器。它不判断双手占用；从装备列表获得盾牌，即可能自动标记 `equippedQuantity: 1`。

`derive.ts:248` 找到第一面已装备盾牌，`:295` 读取盾牌加值，`:297` 直接叠加到 AC。未读取双手武器词条，也未校验手部占用。`validate.ts` 仅检查物品数量关系等，未阻断此组合。

两版均复现：无防御风格、无种族/子职/人工加值，链甲 + 已装备巨剑 + 已装备普通盾牌 → AC 18；把盾牌装备数量改为 0 → AC 16。

2014 圣武士的「一件军用武器和盾牌」选项允许选择巨剑，它是拥有装备的选项，不意味着可以同时持用盾牌和双手攻击。2024 圣武士起始包为长剑而不是巨剑，不能把该包登记成错误；后续改用巨剑时仍会遇到共享计算问题。

不全书 3947 的双手词条、3946 的盾牌规则，以及 4043/4045 的 2024 装备规则为核验入口。双手是攻击时的持用要求，仅拥有或携带巨剑不能自动判定玩家正在双手攻击；当前草稿没有独立持用模式。

### 5.2 其他职业检查

| 规则集 | 有自动装备盾牌的起始路线 | 核查结果 |

| 2024 | 圣武士、牧师、德鲁伊装备 A | 三个路线均自动装备盾牌；普通起始包中的单手武器与盾牌组合本身合法，但玩家改用双手武器后的冲突未处理 |
| 两版共享计算 | 任何职业手动装备盾牌后 | 运行时 13 个 2014 职业及 14 个 2024 职业记录均走该链；同样的链甲 + 巨剑 + 盾牌输入全部返回 AC 18，并含 `shield` 来源 |

最后一行是用于证明共享计算路径的诊断输入，不表示所有职业都拥有链甲或盾牌熟练，也不表示所有职业默认起始装备都有盾牌。2024 盾牌受训限制亦需在后续规则核验中检查；不能照搬 2014 的条件。

额外复现：上述七条起始路线在把盾牌卸下后再次调用 `buildStartingEquipmentState`，盾牌全部重新变为已装备。装备选项与背景变更均存在重建调用入口，因此单纯移除初次自动装备还不够，必须保留玩家手动选择。

### 5.3 用户要求与方案边界

已确认产品目标：不因获得盾牌而默认增加 AC，让玩家手动处理盾牌收益；该目标适用于共享链，而不是仅对圣武士打补丁。

用户已确认采用装备/卸下控制表达明确持盾选择：默认拥有但不持用，明确装备并符合条件时再计入盾牌收益。角色卡现有 AC 手动编辑仍可用于额外临时调整。

不采用「永久删除自动盾牌收益、只允许编辑 AC」方案。实施需同时处理盾牌魔法加值/灌注、无甲防御持盾条件与 2024 受训限制；来源说明必须对应实际收益。本轮尚不修改产品规则基线。

### 5.4 实施前准备与验收

- 需要区分「尚未选择装备状态」和「玩家明确卸下」；当前 `equippedQuantity: 0` 不能区分这两种情况。优先检查是否可以取消盾牌推荐装备而无需新增草稿字段；若需要新增状态，先规划归一化和旧草稿兼容。
- 已有草稿可能含自动装备的盾牌和手动 AC 修正，不能自动猜测它们是否真实持盾，也不能批量清零盾牌状态。须制定保留原选择并提示复核的兼容策略。
- 保留普通持盾的合法收益、野蛮人允许持盾的无甲防御、武僧持盾限制、防御风格与护甲公式；明确装备与卸下后分别按适用条件重新计算。
- 验收至少覆盖七条起始路线、获得盾牌但未持用、明确单手持盾、巨剑/巨斧/长弓、长剑单手与双手模式区别、背景/装备重建、旧草稿、AC 人工修正、魔法盾牌/灌注及导出。
- 核心期待：新建链甲 + 巨剑角色不因背包里的盾牌得到 +2；玩家卸下盾牌后重新计算、改背景、刷新和导入均不自动持盾；页面、摘要、跑团助手、PDF/XLSX 的 AC 一致。

## 6. R4：装备后无法取消装备（补充核查）

用户于 2026-10-06 补充此问题。代码核查结果：

- `EquipmentStep.vue:107` 有 `toggleEquipped`，已装备按钮再次点击会将装备数量改为 0，但显示「已装备」没有直接表达卸下动作。
- `CharacterSheetStep.vue:1093` 与 `SessionPanel.vue:727` 的物品列表没有装备/卸下操作；添加物品时可以选择直接装备，之后缺少对应取消入口。
- 两页「调整」仅开放给冒险物品，用于数量增减/删除，不能只改变装备状态；起始物品缺少该入口。
- 已有纯函数 `starting-equipment.ts:158` 的 `updateEquippedQuantity` 支持装备数量归零，可以复用；另有 R3 的重建再次自动装备问题。

需求：角色卡和跑团助手的物品页提供可装备条目的装备/卸下操作，覆盖职业、背景、旧草稿和冒险物品；车卡步骤明确显示卸下动作。卸下保留拥有数量、条目 ID、来源和绑定记录，不要求删除物品或返回重新车卡。普通物品不提供装备操作；来源关闭不激活效果。

验收：两版均能卸下起始盾牌和冒险护甲/武器，并再次装备；已装备分组随状态更新，AC 与相关派生一致，刷新/导入导出及重建保留选择。已有多件装备的条目可完整卸下，装备数量不超过拥有数量。详见分批计划 C01-A/C01-B。

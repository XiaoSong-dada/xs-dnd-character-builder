# 主页站点信息配置需求

## 1. 背景与目标

用户需求：主页（草稿首页）需要**通过环境变量配置**站点信息——GitHub 链接、作者是谁等，避免把这些信息硬编码在组件里，便于他人 fork/部署时改自己的署名。

目标产物：

- 环境变量驱动的主页站点信息（作者、GitHub 链接，可扩展标语/版本）；
- 首页以合理且美观的方式展示这些信息，不干扰车卡主流程；
- 遵循项目约定：`src/config` 为环境变量唯一读取入口，`import.meta.env` 不在业务模块直接读取。

## 2. 现状调查（已核验）

| 模块 | 现状 |
|---|---|
| `app/src/config/setting.ts` | **空文件**——环境变量读取入口已预留但未实现 |
| `app/src/env.d.ts` | 仅有 `.vue` 模块声明，**无 `ImportMetaEnv` 类型扩展**（`import.meta.env` 为隐式 any） |
| 根 `.env.example` | 仅 `APP_PORT=8080`（Docker 端口），无 `VITE_` 站点变量示例 |
| `StartPanel.vue` | 首页结构：hero 区（◇ 徽标 + "D&D 5e · 2014" + "从一个英雄想法开始" + 说明小字）→ 创建按钮 → 角色列表 → 导入入口；**无页脚、无作者/链接信息** |
| `views/profile` | "个人中心"占位页（`useProfilePage.ts` 返回固定文案），与站点作者信息无关 |

**结论**：基础设施（config 目录）已预留，缺实现；需要新增环境变量定义、类型声明、config 读取模块与首页展示位。

## 3. 环境变量设计

### 3.1 变量清单（Vite 约定 `VITE_` 前缀，构建时注入）

| 变量 | 必填 | 说明 |
|---|---|---|
| `VITE_AUTHOR_NAME` | 否 | 作者名（如 "小明"） |
| `VITE_GITHUB_URL` | 否 | GitHub 主页或仓库链接（如 `https://github.com/foo/bar`） |
| `VITE_AUTHOR_TAGLINE` | 否 | 可选一句话署名/标语（如 "用爱发电的车卡小工具"） |
| `VITE_APP_VERSION` | 否 | 可选版本号（如 `0.1.0`），不配则回退 `package.json` 的 version |

均为可选：**未配置的项不展示对应内容**（见 4.2），保证空配置时首页与现状完全一致。

### 3.2 类型安全（`env.d.ts` 扩展）

```ts
interface ImportMetaEnv {
  readonly VITE_AUTHOR_NAME?: string
  readonly VITE_GITHUB_URL?: string
  readonly VITE_AUTHOR_TAGLINE?: string
  readonly VITE_APP_VERSION?: string
}
```

### 3.3 读取归一化（`src/config/site.ts`）

- `src/config` 是 `import.meta.env` 的**唯一读取入口**（AGENTS.md 约定）；
- 导出 `siteConfig`：把原始环境变量归一化为 `{ authorName?, githubUrl?, tagline?, version? }`（空串视为未配置），业务组件只消费 `siteConfig`，不直接碰 `import.meta.env`；
- `setting.ts` 为空文件，语义与"站点信息"不符，新建 `site.ts` 承载，`setting.ts` 保持不动（或后续清理，本需求不涉及）。

### 3.4 示例文件与部署

- 根 `.env.example` 追加 `VITE_` 变量示例（含注释说明用途），本地开发模板为 `app/.env.example`；
- 注意：Vite 默认从**运行目录**（`app/`）加载 `.env`，若 `.env` 放在仓库根需在 `vite.config.ts` 配置 `envDir`，或统一放 `app/.env`——实现时按现有部署方式（`docker-compose.yml` / `deploy.sh`）确认注入路径，文档同步记录。
- **Docker 部署（已实现）**：`docker-compose.yml` 将根 `.env` 的 4 个 `VITE_*` 变量经 `build.args` 传入；`app/Dockerfile` builder 阶段以 `ARG`/`ENV` 接收并注入 `pnpm build`（Vite 构建期静态替换）；runtime 为 nginx 静态服务无需运行时变量。未配置的变量传空串，署名行自动隐藏。

## 4. 展示设计（如何合理且好看）

### 4.1 位置方案对比

| 方案 | 描述 | 优点 | 缺点 |
|---|---|---|---|
| A1. 紧贴标题下方 | 在 h1 下、说明小字上插一行作者 | 首屏可见 | 打断"徽标→标题→说明"的视觉层级；标题下方是焦点区，放次要信息喧宾夺主 |
| **A2. hero 底部署名（推荐）** | 说明小字**之后**加一行"由 X 制作 · GitHub"，muted 极小字 | 首屏可见（署名曝光高）；"产品说明→署名"是自然递进，不打断层级；hero 现有 19rem 留白容纳一行不拥挤；个人作品"落款"感强 | 仍在首屏内容区（可接受，用户明确期望首屏可见） |
| B. 页面底部页脚 | 首页最底部 footer：作者 + 链接 + 版本 | 最保守传统，完全不干扰主视觉 | 首屏不可见；移动端角色列表较长时需滚动很久才看到（与用户"希望被看到"的诉求冲突） |
| C. hero 头像/作品签名 | hero 放作者头像与签名 | 作品感强 | 需头像资源，过度设计 |

**推荐方案 A2（hero 底部署名行）**：用户诉求是**首屏可见的署名**（个人开发者希望"这是谁做的"被看到），页脚在该诉求下曝光不足；A2 在满足首屏可见的同时，用"说明小字之后的落款"位置避免打断 hero 层级，样式与现有说明小字同层级（`--color-text-muted` 极小字），视觉上是产品 slogan 的落款。

### 4.2 仅主页可见的决策依据（已确认）

站点信息**刻意只放主页**，其他页面（车卡流程、角色卡、个人中心、职业/骰子/设置页）零改动：

- 车卡流程与角色卡是**任务型页面**，底部有 `StickyActionBar` 操作栏，加页脚会与操作冲突、增加滚动负担；
- 主页是唯一"浏览型"页面，署名/链接放这里即满足"能找到作者"的诉求；
- 全站可见的替代方案（主导航抽屉/设置区加一行）会改动 `MainLayout` 外壳、影响所有页面，与本需求"不影响其他页面"的边界冲突，不做；
- 将来如需全站可见，复用 `siteConfig` 单独加轻量入口即可，不属本需求。

### 4.2 页脚内容与缺省规则

- 单行居中，`--color-text-muted` 小字，与现有 hero 说明风格一致；
- 组成（按配置存在与否逐段拼接）：
  - 作者：`由 {VITE_AUTHOR_NAME} 制作`（未配置则省略）；
  - GitHub：`GitHub` 链接（`target="_blank" rel="noopener noreferrer"`，内联 SVG 图标可选加分），未配置则省略；
  - 版本：`v{VITE_APP_VERSION}`（或回退 package.json version），未配置则省略；
- **全部未配置时整行不渲染**，首页与现状完全一致（干净降级）；
- 链接触控目标 ≥ 44px（移动端约定）；链接用主色 + 下划线区分，不依赖颜色之外无状态提示（有 href 即跳转）。

### 4.3 好看细节

- 分隔符用 `·` 与现有"等级 · 步骤"文案风格统一；
- GitHub 用内联 SVG 图标（不引入依赖，符合"先用现有能力"约定）；
- 署名行与 hero 说明小字同层级（`--color-text-muted` 极小字），与 hero 之间留 `0.5rem` 左右间距，不贴边。

## 5. 需求项

### R1 环境变量定义与类型声明

- `env.d.ts` 扩展 `ImportMetaEnv`（4 个 `VITE_` 变量，均可选）；
- 根 `.env.example` 追加变量示例与注释。

### R2 `src/config/site.ts` 读取归一化

- 唯一读取 `import.meta.env` 的模块，导出 `siteConfig`（空串归一化为 undefined）；
- 版本回退逻辑：`VITE_APP_VERSION` 未配置时读 `package.json` version（经 vite 注入或运行时 import，实现时选可行方案）。

### R3 首页 hero 底部署名行展示

- `StartPanel.vue` hero 区说明小字之后新增署名行（方案 A2），按 `siteConfig` 分段渲染：`由 {作者} 制作`、`GitHub` 链接、`v{版本}`；
- 全部未配置时隐藏整行；链接安全属性齐全；样式与 hero 说明小字同层级（muted 极小字）。

### R4（可选，后续）站点信息复用

- 角色卡页、导航抽屉等如需展示同一组信息，复用 `siteConfig`（本需求只做主页，不扩散）。

## 6. 非目标与边界

- 只改**主页**（StartPanel）展示；角色卡、个人中心等页面不新增站点信息。
- 不引入图标库或新依赖（GitHub 图标用内联 SVG）。
- 不改 `setting.ts` 现有空文件（避免影响未开始的环境配置工作）；如清理属独立事项。
- 不实现作者头像、备案号、多语言等扩展。
- 环境变量均**可选**，空配置首页零变化（向后兼容）。

## 7. 涉及模块与依赖方向

```text
src/config/site.ts（新建）
  -> 唯一读取 import.meta.env（Vite 注入），导出 siteConfig

src/env.d.ts
  -> ImportMetaEnv 类型扩展（VITE_* 变量）

views/character-builder/components/StartPanel.vue
  -> src/config/site.ts（消费 siteConfig，不直接碰 import.meta.env）

.env.example（根）
  -> VITE_* 变量示例
```

依赖方向合规：`views → config → env`，config 是环境变量唯一入口；不新增其他跨层依赖。新增 `src/config/site.ts` 需同步 `docs/frontend-architecture.md` 拓扑（AGENTS.md 修改流程 7）。

# B02双版本基础输入清单

日期：2026-09-10。来源为B01首批核验矩阵；用于制定B02任务，不表示下列运行时结构已经实现。

## 必须建立的基础契约

- `RulesetId`支持`5e-2014 | 5e-2024`，规则版本与草稿`schemaVersion`保持两个独立概念。
- 所有规则仓库查询显式接收规则版本；没有版本或未知版本时返回可解释错误，不回退到2014数据。
- 运行时ID包含版本。首批固定采用：`class-2024-fighter`、`subclass-2024-fighter-champion`、`class-2024-wizard`、`subclass-2024-wizard-evoker`、`source-2024-phb`。
- 其他条目沿用`<domain>-2024-<english-slug>`格式；B01的CF／FT／SP／EQ／RT编号只作为证据追踪字段，不作为保存关联键。
- 新角色选择的规则版本写入原始草稿；派生、候选、验证、保存和导出均从草稿版本选择对应仓库。

## 最小负向样例

- 用`5e-2024`角色引用`class-2014-fighter`、2014专长或2014法术时必须拒绝，并返回版本不匹配原因。
- 未提供规则版本、使用未知版本、规则ID不存在或条目规则版本与仓库不符时必须失败，不能静默回退。
- 2024法师准备数不得使用2014的“等级＋智力调整值”公式。
- 非法背景属性、4级前通用专长、未满足获得时先决和不可复选专长重复取得必须拒绝。
- 祈愿复制法术只引用效果，不把法术加入法术书、准备池或独立免费资源。
- 治疗药水、法术卷轴及未完成生物数据不得进入首批正常装备或召唤候选。

## 数据保护与兼容输入

- 现有`CharacterDraft` schema v7固定为`5e-2014`，B02只建立类型与规则层基础；草稿迁移和双版本保存由B03决定并实现。
- 现有2014仓库、派生结果和自由购点保持字节级输入语义不变；不得通过共享无版本ID实现复用。
- 旧2024隔离记录继续只读；B02不得把它升级为新2024可编辑草稿。
- B02完成时至少验证上述正负样例和现有2014规则测试，之后才允许进入完整数据装配。

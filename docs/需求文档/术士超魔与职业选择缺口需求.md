# 术士超魔与同类职业选择缺口需求

## 1. 背景与目标

用户反馈：术士职业到达选择超魔的等级（5e 2014 规则为 3 级）时，角色卡能力页签只有"需选择"索引标记，**没有可以选择超魔的界面**；期望与战士子职战斗大师的战技选择一样，在时间线中可交互选择。

本次任务的产出：

- 核验术士超魔缺口是否真实存在（结论：**存在，且比用户描述的更彻底——无检查点、无选项数据、无校验拦截**）；
- 以战斗大师战技为完整实现基线、邪术师魔能祈唤为索引级基线，梳理超魔需求的完整实现链路；
- 全量排查其他职业/子职是否存在同类"声明了选择但没有选择入口"的缺口（结论：**另有吟游诗人、法师共 6 处同类缺口，一并纳入本次实施**）；
- 整理成需求文档供后续实施，**本次不修改代码**。

**已确认的实施决策**（用户拍板）：

1. **全部实施**：术士超魔、吟游诗人魔法奥秘与专精强化、法师法术专精与招牌法术的缺口一次全部补齐，不再分期；
2. **超魔选项直接核验为 `implemented`**：10 项超魔的原创中文摘要完整登记，不做 `index-only` 过渡；
3. **按名称规范化流程对齐译名**：超魔等新增条目的中文名以官方简体中文术语与社区主流译名为准，实施前逐条核验。

## 2. 现状调查（已核验）

### 2.1 术士超魔现状链路

| 层 | 位置 | 现状 |
|---|---|---|
| 特性注册表 | `app/src/rules/data/class-features-2014.ts` 167—169 行 | `sorcerer-2014-class-metamagic`（3 级）、`-metamagic-2`（10 级）、`-metamagic-3`（17 级）均标记 `requiresChoice: true`、`status: 'implemented'`，但**无 `optionIds`** |
| 职业检查点 | `app/src/rules/data/full-casters-2014.ts` 79—85 行 | 术士 checkpoints 只有 1 级技能、1 级子职、4/8/12/16/19 级属性提升，**无超魔检查点** |
| 时间线 UI | `app/src/views/character-builder/components/TimelineStep.vue` 43 行 | `classFeatures` 过滤掉 `requiresChoice` 特性（只展示自动获得特性），超魔选择入口完全不存在 |
| 角色卡 UI | `app/src/views/character-builder/components/CharacterSheetStep.vue` 367、390 行 | 能力页签对 `requiresChoice` 特性仅显示"需选择"徽标，**不可操作**（即用户看到的"只有索引"） |
| 校验 | `app/src/rules/validate.ts` 197—207 行 | 只校验 timeline 检查点；超魔不在其中 → **未选超魔也能通过校验完成角色卡** |

**结论**：术士超魔是"三无"状态——无选项数据、无检查点、无校验。比邪术师魔能祈唤（至少有检查点 + 3 个 index-only 选项可浏览）更缺失。

### 2.2 参照基线

**A. 完整实现基线——战斗大师战技（战士子职）**

- 选项常量 `BATTLE_MASTER_MANEUVER_OPTION_IDS`（11 项 `maneuver-` 前缀）+ 中文标签映射（`app/src/rules/data/subclass-features-2014.ts` 1—21 行）；
- 特性带 `requiresChoice + optionIds + minSelections/maxSelections`（战斗超驰 3 级 3 项、7/10/15 级各 2 项）；
- `buildTimeline` → `buildSubclassFeatureCheckpoints` 自动生成 `subclass-feature-*` 检查点（`app/src/rules/timeline.ts`）；
- TimelineStep 通用 `OptionCard` 渲染选项（名称/描述/选中/锁定/仅索引状态）；
- 跨检查点查重：`TimelineStep.isUniqueOptionUsedElsewhere` 按 `maneuver-` 前缀禁止跨等级重复选择；
- `validate.ts` 检查点通用校验（数量不足报 error）。

**B. 索引级基线——邪术师魔能祈唤**

- 检查点 `warlock-2014-invocations-2`（2 级，min 2 / max 2）+ 3 个 `invocation-*` 前缀的 `index-only` 选项（`app/src/rules/data/arcane-casters-2014.ts` 25—27、47 行）——**可浏览可预览，不参与自动计算**，符合项目"纵向切片"约定。

### 2.4 官方规则依据（5e 2014）

2014《玩家手册》（PHB p.101—102）术士超魔法：

- **3 级**获得超魔法特性，选择 **2 项**超魔法；**10 级**再学 **1 项**；**17 级**再学 **1 项**（共 4 项）；同一超魔不可重复选择。
- 每次施法只能应用一种超魔（除非该超魔另有说明）；孪生施法不能用于以自身为目标、范围效果或影响多目标的法术。

## 3. 需求明细

### R1 超魔选项数据（优先）

- 在规则数据层新增超魔选项目录（建议独立文件 `app/src/rules/data/metamagic-2014.ts`，或并入现有施法职业数据文件），每条 `RuleOption`：`metamagic-` 前缀稳定 ID、中文名、英文名、`ruleset: '5e-2014'`、来源、**原创中文摘要**（效果要点转述，不复制原书正文，遵循版权约定）、**`status: 'implemented'`（已确认直接核验，不做 `index-only` 过渡）**。
- 注册进 `app/src/rules/repository.ts` 的 `options` 聚合（供 `getOption` 与 TimelineStep 通用渲染使用）。
- 术法点消耗仅作摘要展示，**不做施法时消耗的自动计算**（超出当前项目派生范围）。

### R2 超魔检查点（术士职业数据）

- `app/src/rules/data/full-casters-2014.ts` 术士 checkpoints 追加 3 个检查点：
  - `sorcerer-2014-metamagic-3`：3 级，`kind: 'class-choice'`，`minSelections: 2`、`maxSelections: 2`，选项 = 全部超魔；
  - `sorcerer-2014-metamagic-10`：10 级，`minSelections: 1`、`maxSelections: 1`；
  - `sorcerer-2014-metamagic-17`：17 级，`minSelections: 1`、`maxSelections: 1`。
- 时间线渲染与保存无需新增组件：TimelineStep 通用检查点渲染 + `saveTimelineSelection` 已覆盖。

### R3 跨等级查重

- 超魔选项跨检查点不可重复选择（3 级选过的不允许在 10/17 级再选）。
- 复用 `TimelineStep.isUniqueOptionUsedElsewhere` 的机制：当前按 `maneuver-` 前缀与 `expertise` kind 判定，需扩展支持 `metamagic-` 前缀（建议抽象为统一的"前缀唯一选项"判定，避免继续叠分支）。

### R4 校验与升级引导

- `validate.ts` 检查点通用校验自动覆盖超魔检查点（未完成报 error，含"返回法术步骤/时间线"指引），无需新增逻辑；
- **复用此前已实现的等级调整引导**：`getDependencyImpact` 升级方向的 `added` 会包含新增超魔检查点（升级到 3/10/17 级时自动提示并引导进入时间线补全）；
- 补充回归测试：术士 2→3、9→10、16→17 级升级时 `added` 包含对应超魔检查点。

### R5 展示

- 角色卡能力页签：超魔特性条目已存在（"需选择"徽标将随选择完成消失），选择结果建议在能力页签或法术区块以"已选超魔：谨慎法术、孪生法术"形式只读展示（与专长/属性提升展示模式一致，数据来自草稿 `selections`）。

### R6 同类缺口（本次全部实施，按依赖顺序分批次推进）

以下 6 处缺口与术士超魔一并纳入本次实施。批次仅表示实施先后，**全部在本需求范围内**，每批次独立验收：

**批次 1：术士超魔（即 R1—R5 全部内容）**

**批次 2：吟游诗人·专精（强化）10 级**

- 新增检查点 `bard-2014-expertise-10`：10 级，`kind: 'expertise'`，`minSelections: 2`、`maxSelections: 2`，选项为已熟练技能/乐器；
- 直接复用 3 级专精检查点机制（`isExpertiseLocked` 未熟练锁定、跨检查点查重 `isUniqueOptionUsedElsewhere` 已按 expertise kind 处理）。

**批次 3：吟游诗人·魔法奥秘 10/14/18 级**

- 新增 3 个检查点 `bard-2014-magical-secrets-10/14/18`：各选 2 个法术；
- **动态候选池**：候选为项目已登记的全部 1 环及以上法术（环级 ≤ 吟游诗人当前可用最高环）。现有检查点 `optionIds` 为静态数组，法术级候选池（数百项）不宜静态展开，需扩展检查点支持动态候选池（如 `candidateKind: 'all-spells'` 由规则层按等级生成，或选项走独立选择面板），实施计划中确定；
- **结果归属**：规则上所选法术"对吟游诗人而言是吟游诗人法术"，需计入已知法术的数量与角色卡法术展示（当前 `spellSelections.knownSpellIds` 是已知法术唯一事实源）。实施需确定存储方式（并入 `knownSpellIds` 或独立字段后参与派生合并），并保证旧草稿兼容。

**批次 4：法师·法术专精 18 级、招牌法术 20 级**

- 新增检查点 `wizard-2014-spell-mastery-18`（法术书中选 1 个 1 环 + 1 个 2 环法术）与 `wizard-2014-signature-spells-20`（法术书中选 2 个 3 环法术）；
- 候选池限定为**当前法术书（`spellSelections.spellbookSpellIds`）中对应环级的法术**，同样需要动态候选池支持；
- 规则约束（行为要求）：法术专精所选法术可随时以最低环级施放且不消耗法术位；招牌法术长休后各免费施放一次、始终可作为 3 环准备且不计入准备数量。**这两条仅作为规则摘要展示与选择约束，不做施法资源模拟**（与超魔一致，超出派生范围）。

每批次均需同步：检查点校验（未完成报 error）、升级引导（`added` 覆盖新检查点）、角色卡展示（已选结果只读展示）、回归测试。

## 4. 验收标准

术士超魔：

1. 术士时间线在 3/10/17 级出现超魔检查点，可多选、可保存、刷新恢复、可修改；
2. 同一超魔不可跨检查点重复选择（10/17 级候选中被禁用并提示原因）；
3. 未完成超魔选择时，校验报 error 并指引返回时间线；角色卡流程不可完成；
4. 升级到 3/10/17 级时，等级调整确认弹窗与提示条引导补全超魔检查点；
5. 角色卡能力页签展示已选超魔；
6. 测试覆盖：选项数据完整性、检查点构建、跨等级查重、校验、hooks 升级引导流程。

同类缺口（吟游诗人、法师）：

7. 吟游诗人 10 级专精强化检查点出现，未熟练选项锁定，与 3 级专精跨检查点不重复；
8. 吟游诗人 10/14/18 级魔法奥秘检查点出现，候选为全法术池且环级上限正确；所选法术计入已知法术数量与角色卡法术展示；
9. 法师 18/20 级检查点出现，候选仅法术书内对应环级法术；
10. 升级到对应等级（吟游诗人 10/14/18 级、法师 18/20 级）时升级引导 `added` 包含新检查点；
11. 以上全部选项中文名通过名称规范化核验；新增/修改数据遵守 2014 与 2024 隔离约定。

文档同步：`docs/rules.md` 调整等级/职业章节、`docs/dnd-classes.md` 术士章节（含 2014 与 2024 区分说明）、`CHANGELOG.md` 与版本号。

## 5. 范围外（明确不做）

- 超魔效果的自动计算（施法时术法点消耗、与法术的兼容性判定等）——需逐项规则核验后另行立项；
- 法术专精/招牌法术的施法资源模拟（免费施放次数、不计准备数量等），仅做规则摘要展示与选择约束；
- 18 条子职 index-only 特性的资料补全（属资料核验批次，选择链路已存在）；
- 2024 术士（2 级超魔）与 2024 版 docs 资料整理。

# 子职特性多选校验适配 · 更新计划

> 依据排查结论制定（2026-08-17 排查：《战士战技检查点归属修复》完成后，战斗大师选满战技仍无法通过校验）。

## 目标与范围

- **现象**：战士选择战斗大师并完成 3 项战技选择后，进入规则校验页面报 error——"子职特性「战斗超驰」的选项互斥。每个特性只能选择其中一项。"（另有 7/10/15 级额外战技同报），角色卡无法生成。
- **根因**（已核验）：`app/src/rules/validate.ts` 的 `validateSubclassSelections`（335—358 行）硬编码"每个 `requiresChoice` 特性只能选一项"：
  ```ts
  const selectedOptionIds = new Set(draft.selections.filter((item) => !item.invalidatedAt).flatMap((item) => item.optionIds))
  for (const feature of features) {
    if (!feature.requiresChoice || !feature.optionIds?.length) continue
    const chosen = feature.optionIds.filter((optionId) => selectedOptionIds.has(optionId))
    if (chosen.length === 0) { /* warning 需要选择一项 */ }
    else if (chosen.length > 1) { /* error 选项互斥 */ }
  }
  ```
  缺陷：
  1. **多选误判**：不读取特性的 `minSelections`/`maxSelections`，选满 3 项战技必然 `chosen.length > 1` → 报互斥；
  2. **跨特性串扰**：用全局选项集按特性过滤，而战斗超驰与 3 个额外战技**共享 11 项战技选项** → 选任意战技后 5 个特性全部命中，一次报 4 个互斥 error；
  3. **未解锁等级误报**：`features` 不按 `targetLevel` 过滤，3 级玩家会收到 7/10/15 级额外战技的校验提示。
- **存量 bug**：`git show HEAD` 核对——该逻辑在《战士战技检查点归属修复》之前即存在（当时战技选项同样被全局收集），此前无任何测试覆盖"战斗大师选满战技后校验通过"（`validate.test.ts` 无战技/互斥用例），长期潜伏。
- **方案（已确认方向）**：`validateSubclassSelections` 改为**按检查点粒度统计 + 等级过滤 + 读取 min/max 判定**；单选特性的"互斥"语义保持不变；多选特性的不足/超选与检查点校验（`validate.ts` 196—205 行，已按 min/max 报 error）口径一致。

## 关键实施细节（已核验）

1. 检查点校验（196—205 行）已覆盖多选检查点的 `count < minSelections || count > maxSelections` → error，无需改动；本次只修 `validateSubclassSelections`。
2. 单选特性（其余 14 个 `requiresChoice` 特性，如图腾之灵、奥术射击）`minSelections`/`maxSelections` 缺省 1/1，按检查点统计后语义不变。
3. 战技跨检查点重复由 `duplicate-maneuver` 校验（253 行，`maneuver-` 前缀判定）负责，与本次改动无关。
4. 降级/换子职时超限检查点选择由 `dependency` 标记 `invalidatedAt`，`find(… && !item.invalidatedAt)` 不计入统计，无需额外处理。

## 阶段 1：规则层

`app/src/rules/validate.ts` `validateSubclassSelections`（335—358 行）替换为：

```ts
const features = getSubclassFeatures2014(draft.subclassId)
for (const feature of features) {
  if (!feature.requiresChoice || !feature.optionIds?.length) continue
  // 未解锁等级的特性不校验（与时间线检查点按等级过滤一致）。
  if (feature.level > draft.targetLevel) continue
  const min = feature.minSelections ?? 1
  const max = feature.maxSelections ?? 1
  const checkpointId = `subclass-feature-${feature.id}`
  const count = draft.selections
    .find((item) => item.checkpointId === checkpointId && !item.invalidatedAt)
    ?.optionIds.length ?? 0
  if (count < min) {
    issues.push({
      id: `subclass-feature-choice-${feature.id}`,
      step: 'timeline',
      severity: 'warning',
      message: `子职特性「${feature.name}」需要选择${min === max ? min : `${min}—${max}`}项。`,
      resolution: '完成子职特性选择后角色资料才完整。',
    })
  } else if (count > max) {
    issues.push({
      id: `subclass-feature-exclusive-${feature.id}`,
      step: 'timeline',
      severity: 'error',
      message: max === 1
        ? `子职特性「${feature.name}」的选项互斥。`
        : `子职特性「${feature.name}」最多只能选择 ${max} 项。`,
      resolution: max === 1 ? '每个特性只能选择其中一项。' : `请移除多余选项，仅保留 ${max} 项。`,
    })
  }
}
```

要点：
- **按检查点统计**：从 `draft.selections` 中取 `checkpointId === 'subclass-feature-' + feature.id` 的选择计数，消除跨特性/跨等级串扰；
- **等级过滤**：`feature.level > targetLevel` 跳过（未解锁特性不提示）；
- **min/max 判定**：不足 → warning（含数量文案）；超选 → error（单选保留"选项互斥"原文案，多选给"最多只能选择 X 项"）；
- 删去全局 `selectedOptionIds` 收集。

- 完成检查：3 级战斗大师选满 3 项战技 → 无 `subclass-feature-choice-*` / `subclass-feature-exclusive-*` 报错；仅保留战技 `index-only` warning。

## 已确认决策（2026-08-17 排查确认）

1. **修复方式**：按检查点粒度统计 + 等级过滤 + min/max 判定（方案 A），不采用"仅跳过 max > 1 特性"的最小改法（后者保留全局选项集统计的跨特性串扰隐患）。
2. **单选语义保持**：`max === 1` 特性的互斥报错文案不变；多选超选给新文案"最多只能选择 X 项"。
3. **不足的提示级别**：沿用现有 warning（宽松提示），严格的 error 由检查点校验承担，与现状一致。

## 待执行时确认点

1. 超选文案：多选特性超选时同时存在检查点 error（"尚未完成"）与新互斥 error 两条，确认文案不冲突（可接受或实施时收敛为一条，以最小改动为准）。
2. `chosen` 语义变化：原实现对"选择不在任何检查点中的孤儿选项"也会计数，新实现只认对应检查点——孤儿选项本应由时间线校验拦截，确认无副作用。

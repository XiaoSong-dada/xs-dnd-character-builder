## 1. 背景与问题

### 1.1 第 6 步检查点头部的等级徽章塞不下职业名

`TimelineStep.vue` 的检查点头部结构是「圆形徽章 + 标题块 + 计数徽章」：

```text
[ 战士 3 级 ]  选择武术范型                    [0/1]
  ^^^^^^^^^^ 2.25rem（36px）的圆形徽章，font-size 0.72rem
```

- 徽章样式写死为圆形：`> span { width: 2.25rem; height: 2.25rem; border-radius: 50%; font-size: 0.72rem }`。
- 文本来自 `checkpointLevelLabel()`：有归属职业时返回 `${职业名} ${等级} 级`（如「战士 3 级」），否则返回 `${等级} 级`。
- 兼职批次（MC-E04）加上职业名是为了消除「3 级是总等级还是职业等级」的歧义，但职业名一长（如「奇械师」「吟游诗人」，或第三方职业的更长名称）就会在 36px 圆内换行／溢出，挤压右侧标题，且与其他检查点参差不齐。

### 1.2 数值 tile 的说明文字没有行数上限

角色卡总览、战斗、能力、法术页签以及跑团助手总览使用 `EditableStatTile`（角色卡）与 `StatTile`（跑团助手）展示数值，第三个位置是**说明文字**（`<small>{{ note }}</small>`）。

- 说明文字由 `sourceNote(sources)` 生成：把来源逐条拼成 `${label} ${±value}` 再用 ` · ` 连接。
- **生命值来源是逐级一条**（`rules/derive.ts`：起始职业 1 级 + 第 2…N 级 + 子职/专长/物种加成），20 级角色有 20+ 条 → 「最大生命值」tile 的说明会撑到十几行，把 tile 拉得很高、破坏网格对齐。
- 每条来源还带一个 `detail`（如「战士 d10 最大值 + 体质调整值」），但 `sourceNote()` 只用了 `label + value`，**这些来源说明目前在界面上看不到**。
- 跑团助手的豁免／技能 tile 同样把来源链拼成长说明（`sources.map(detail).join(' · ')`），存在同一问题。

## 3. 需求一：第 6 步检查点头部改为「数字徽章 + 职业 tag」

### 3.1 R1 圆形徽章只显示「N级」（决策 D22，2026-10-12 用户修订）

- 徽章文本为**「等级数字 + 级」**（如 `3级`、`12级`），**不含职业名**；尺寸、颜色、圆形样式保持不变。
- 数字取该检查点的**归属职业等级**（`classLevel`），无归属职业时取角色等级（`level`）——取值口径不变，只改显示形态。
- 修订说明：最初按用户第一条建议实现为**纯数字**（`3`），用户在实际界面确认后改为「`3级`」——纯数字缺少单位，玩家需要猜它是等级还是序号；加上「级」后最直观。36px 圆内「12级」约 24px 宽，仍然放得下（1—20 级均不会溢出）。

### 3.2 R2 归属职业以 tag 放在右侧标题行（决策 D22）

- 有归属职业的检查点，在**标题右侧**显示职业 tag（复用 `UiBadge`，`tone="primary"`）。
- tag 与标题同一行；标题过长时标题优先收缩，tag 不换行、不被截断（`flex: none`）。
- 无归属职业的检查点（起源、种族、背景、专长、属性提升等）**不显示 tag**。

### 3.3 R3 信息量不减少（可访问性）

「职业 + 等级」是 MC-E04 为消除歧义引入的信息，本次只改位置、不减信息：

- 徽章保留可读文本（数字），并补充 `title` 与 `aria-label`，内容为「职业 第 N 级」（无归属职业时为「第 N 级」），避免读屏只读出「3」；
- tag 自身文本即职业名，读屏可读到；
- 检查点头部的 `aria-expanded` 等既有语义不变。

### 3.4 不做

- 不改单击展开／收起的交互，也不给检查点头部新增双击行为（避免与既有单击语义冲突；项目内「双击展开」的既有约定属于 `ExpandableOptionCard`）。
- 不改检查点的排序、分组与计数徽章。

## 4. 需求二：说明区两行截断 + 双击查看明细

### 4.1 R4 说明区最多两行（决策 D23）

- 说明文字最多显示 **2 行**，超出部分以省略号结尾（`-webkit-line-clamp: 2` + `overflow: hidden`）。
- tile 的 `min-height: 4rem` 与网格对齐不变；**说明再长也不再撑高 tile**。

### 4.2 R5 仅在实际被截断时可交互（决策 D24）

- 只有当说明**真的超过两行**（`scrollHeight > clientHeight`）时，该 tile 才：
  - 在非编辑态响应「查看明细」操作；
  - 成为可聚焦元素（`role="button"` + `tabindex="0"` + `aria-label="查看<名称>的说明"`）。
- 未被截断的说明：不响应双击、不可聚焦、不显示任何提示。
- 溢出判定需要在挂载后测量，并在**容器尺寸变化**（响应式断点、列表折叠）与**说明内容变化**时重测。

### 4.3 R6 非编辑态双击打开明细弹窗（决策 D25）

| 状态 | 双击行为 |
| --- | --- |
| 非编辑态（且说明被截断） | 打开明细弹窗 |
| 编辑态 | **保持现状**：双击进入该数值的编辑输入（含既有触屏双击判定与「双击编辑」提示） |

- 输入方式：鼠标双击（`dblclick`）、触屏双击（沿用 `EditableStatTile` 既有的 250ms 双击判定窗口，保证移动端可用）、键盘 `Enter` / `Space`。
- 编辑态不绑定「查看明细」，避免与「双击编辑」冲突。

### 4.4 R7 弹窗内容按来源逐条列出（决策 D26）

- 标题：`<名称>`（如「最大生命值」），并显示当前值。
- 正文：按来源**逐条一行**，格式为「`label` `±value`」，并在有 `detail` 时附上来源说明（如「第 2 级生命值 +7 · 战士 d10 最大值 + 体质调整值」）。
- 无来源明细时（如「当前职业无施法能力」这类固定文案）显示说明原文。
- 弹窗用既有 `UiModal`，提供关闭按钮与遮罩关闭；不做嵌套弹窗。

### 4.5 R8 覆盖范围（决策 D27）

- **角色卡**：总览（护甲等级、最大生命值、先攻、速度、熟练加值、六项属性）、战斗、能力（豁免／技能／被动察觉）、法术页签的全部数值 tile。
- **跑团助手**：总览的数值 tile（同一组件、同样的长说明）。
- **不包含**：本来就有展开区的长文本（职业/子职特性、法术描述、物品说明、专长详情）；`CharacterDrawer`（车卡吸底摘要）的 5 个 tile 未传说明，不受影响。

### 4.6 R9 说明数据同源（消除两套文案）

- tile 的说明入参由单个字符串改为**明细数组**；组件内部把明细拼成单行说明用于两行截断显示，弹窗直接用同一数组逐条列出。
- 保证「截断显示的文字」与「弹窗里的明细」来自同一份数据，不会出现两处文案不一致。

## 5. 边界与不做

- 不改草稿字段、schema、规则计算、校验与导出；`sourceNote` 的拼接口径若保留，必须与明细数组同源。
- 不改 `UiModal`、`UiBadge`、`StatTile` 的既有对外语义中与本次无关的部分。
- 不改版本号：`app/package.json`、`CHANGELOG.md`、`app/src/constants/update-notices.ts` 均保持 **1.13.0**（理由同上一批：该版本尚未发布，公告继续描述最终行为）。
- 不引入新的第三方依赖（溢出检测用原生 `ResizeObserver` / DOM 度量）。

## 6. 验收标准

1. 第 6 步检查点徽章只显示「N级」（如 `3级`）；归属职业以 tag 显示在标题右侧；无归属职业不显示 tag。
2. 长职业名（如 6 字以上）不再撑破徽章，标题区不被挤压；徽章尺寸与配色与改动前一致。
3. 徽章与 tag 的合成语义可通过 `title` / `aria-label` 获得，读屏不会只读出一个数字。
4. 说明文字超过两行时以省略号结尾，tile 高度不再随说明增长；未超过两行时不出现省略号。
5. 非编辑态：**被截断**的 tile 双击 / 触屏双击 / 键盘 Enter·Space 打开明细弹窗；**未截断**的 tile 不响应。
6. 编辑态：双击仍然是进入数值编辑；「双击编辑」提示与既有行为不变。
7. 明细弹窗按来源逐条列出（含来源说明），无明细时显示原文；弹窗可关闭。
8. 角色卡与跑团助手表现一致。
9. `npx vue-tsc -b`、`npx vitest run`、`npm run build` 全部通过；既有测试无回归（被改写的断言需说明理由）。
10. 版本号保持 1.13.0；新增模块（如新增共享组件）同步更新 `docs/frontend-architecture.md`。

# 角色卡导出需求（PDF / XLSX / JSON）

> 状态：**V4 重构已实现（2026-08-20）**——PDF/XLSX 已统一消费 `CharacterExportModel`，XLSX 升级为 v4 公式缓存契约，PDF 已覆盖三页；自动化、构建与 Excel 验证通过。按最新要求跳过全部视觉校验；WPS/LibreOffice 兼容性仍待具备对应软件时补验。
> V1 已确认决策：角色卡必须中文；仅中文；免费工具；导出入口仅角色卡页内。
> V2 变更点：PDF 与 XLSX 改为运行时把角色数据直接写入模板文件（用户自制中文模板）。
> V3 确认点：① PDF 采用**坐标绘制**填充（无表单字段，按坐标映射绘制中文文本）；② 模板「经验值」字段**填 0**（草稿无 XP 数据）。

## 1. 背景与目标

用户需要：角色完成后点击「导出」，可以导出 **PDF 角色卡 / XLSX 自动计算卡 / JSON 数据文件**，便于线下跑团打印、在 Excel 中继续编辑或备份迁移。

**V2 变更背景（2026-08-20）**：用户确认 V1 自绘版面不符合实际需求——导出产物必须**直接写入模板文件**（PDF 模板 / Excel 自动计算卡模板），即模板是静态文件资产、运行时只填数据；且**模板卡面必须为中文**。V1 已实现的自绘方案（print CSS / exceljs 自生成）作为过渡，按 V2 改造或移除（见 6a）。

目标产物：

- 一份已核验的免费模板清单与字段/结构逆向资料（本阶段已完成，含 `official_pdf_fields.txt`）。
- 一份可执行的需求文档：模板填充路线、中文模板方案对比、授权合规边界、验收标准。
- 明确留给用户决策的路线选项（中文模板来源、自绘实现处置）。

### 2.2b 模板可行性核查（V2 已核验，2026-08-20）

**官方 5e 2014 填表 PDF**（`docs/export-templates/dnd_5e_charactersheet_formfillable.pdf`）：

- 含 **334 个 AcroForm 表单字段**，pdf-lib 可读取字段名并程序化填充（字段清单已存档 `docs/export-templates/official_pdf_fields.txt`）。
- 字段名完整覆盖：`CharacterName / ClassLevel / Background / Race / Alignment / STR~CHA / STRmod~CHamod / ProfBonus / AC / Initiative / Speed / HPMax / HPCurrent / HDTota / 18 项技能 / 六项豁免 / Wpn1-3 Name/AtkBonus/Damage / Passive / CP/SP/EP/GP/PP / Equipment / ProficienciesLang` 等。
- ⚠️ 卡面标签为**英文**（官方无中文版）；运行时填充中文值可填，但卡面仍英文。

**DRA6N Excel 自动计算卡**（`docs/export-templates/Automated_5e_Character_Sheet_v1.05.xlsm`，MIT）：

- 15 个工作表；Main 主卡为「输入少量单元格 + 公式自动计算」结构（角色名/职业/种族/背景/等级/属性输入后，调整值、豁免、技能、AC、生命骰等由公式派生）；Spells/Class Info 等表联动。
- ⚠️ 界面为**英文**，且自动化依赖英文下拉选择值（公式文本匹配，如 `IF(S2="Barbarian",...)`）；直接填中文值会破坏公式匹配。
- exceljs 可读 .xlsm 并写回单元格（保留公式，宏部分不保留）；精确输入单元格映射需实施阶段逆向（有合并单元格与隐藏表）。

### 2.4 关键结论

- **PDF 官方模板可用**：官方 2014 填表 PDF 带表单字段，pdf-lib 可填；但版面为英文、A4/信件纸，字段名需逆向导出。
- **XLSX 开源模板可用**：DRA6N 的 xlsm 是 MIT 协议，含公式自动计算；但浏览器端写 xlsx 不保留 VBA 宏，需验证公式保留情况。
- **中文方案空白已由 V2 补位**：官方无简体中文填表 PDF；自制中文模板（一次性制作、运行时只填充）是零授权风险且满足「模板填充 + 中文」双要求的中文路线（见 7b）。
- **版权底座**：SRD 5.1 为 CC BY 4.0，卡面字段、数据口径均可基于它设计并署名。

## 3. 需求项

### R1 JSON 导出（已有，补齐入口）

- 在导出菜单中提供「导出 JSON」，复用 `CharacterJsonService.exportDraft`，文件名为 `角色名-dnd5e-v3.json`（含 schemaVersion 后缀便于识别）。
- 不改变 schema、不改导入逻辑；2024 旧草稿继续走现有只读隔离导出路径。

### R2 PDF 导出（V3 已确认：用户自制模板 + 坐标绘制填充）

导出内容（数据范围）：

1. 基础信息：角色名、职业（等级）、种族/出身、阵营、备注；
2. 六项属性与调整值、熟练加值、被动感知；
3. 生命值、AC、先攻、速度；
4. 技能熟练/专精列表；
5. 攻击与法术攻击、法术豁免 DC、法术位摘要；
6. 已选法术（按环级分组，与角色卡页签一致）；
7. 背包与金币；
8. 数值必须与页面派生结果一致（同一派生函数输出）。

实现要点（V3 坐标绘制路线，已确认）：

1. **模板文件作为静态资产**（`app/public/templates/`）携带；运行时用 pdf-lib 打开用户自制中文模板、按坐标映射表在指定位置绘制文本、导出填充后的 PDF；不做运行时排版。
2. **填充方式（已确认）：坐标绘制**——模板无表单字段（已核验），实施阶段先从 Contents 流逆向填写位坐标生成 `pdf-field-mapping.md`（请用户核对后生效）；中文字体优先复用模板 CID 字体映射，否则运行时嵌入字体子集（`StandardFonts` 不含中文）。
3. 多行文本（物品/特性/备注）按字号与可用宽度自动换行；
4. 未确认选择的角色不允许导出（复用现有校验）。

> V1 自绘方案（print CSS + `window.print()`）已实现；按 7b-3 处置（默认移除，只保留模板填充）。

### R3 XLSX 自动卡导出（V3 已确认：用户自制模板 + 字段映射表填充）

1. 导出 `.xlsx`：运行时打开**用户自制静态模板文件**（`app/public/templates/`），按模板自带「字段映射」表写入输入单元格（浅黄区），公式区（浅蓝）由 Excel 自动计算；不做运行时排版；
2. **映射读取（已确认）：运行时读取模板「字段映射」工作表自动构建字段映射**（`character_name → 角色卡!A4` 等 43+ 字段），不硬编码——用户改模板无需改代码；技能/豁免熟练标记按使用说明转换（`●`熟练 / `◆`专精）；
3. **经验值（已确认）：填 0**（模板 `experience → 角色卡!O8`；草稿无 XP 数据，不引入新规则数据）；
4. 需验证：Excel / WPS / LibreOffice 打开兼容性、中文无乱码、公式重算正常；
5. WPS 命名空间兼容：模板经预处理（去 `x:` 前缀，已验证）后作为运行时模板。

> V1 自绘方案（exceljs 自生成 + `build-export-data`）已实现；按 7b-3 处置（默认移除）。
> DRA6N xlsm 为英文界面，仅作参考，不使用。

## 4. 非目标与边界

- 不引入后端服务；导出全部在浏览器端完成。
- 不做多职业、2024 规则导出（当前仅 5e-2014 单职业）。
- 不复制官方模板的版权设计资产用于商业发布；本产品为免费工具。运行时模板为用户自制中文模板（见「7b」）；官方英文 PDF 仅作字段逆向参考（334 字段清单已存档），不作为运行时模板；DRA6N xlsm 为 MIT 可作参考，但英文界面不符合中文要求，不使用。
- 不开发个人中心导出入口（仅角色卡页内导出）。
- 不导出 DM 房规、未完成的半成品草稿（仅导出通过校验或显式确认的角色）。
- 中文社区角色卡 PDF 授权不明，本阶段不采用。

## 6. 验收标准（实施阶段生效）

1. 三种导出入口在手机宽度下可操作；导出文件名含角色名与版本标记。
2. PDF：填充后模板卡面为中文、关键字段与页面一致、可正常打印；中文无乱码。
3. XLSX：模板公式自动重算后属性调整值、熟练加值、HP/AC、法术位等值与页面一致；中文无乱码。
4. JSON：导出文件可被 `CharacterJsonService.importDraft` 原样导入，schemaVersion 不变。
5. `pnpm test`、`pnpm build` 通过；新增导出服务的单元测试覆盖字段映射完整性与非法角色拒绝导出。
6. 授权合规：产物内/说明内满足署名要求（CC BY 4.0 署名 SRD、MIT 保留版权声明）；运行时模板按 7b 方案确定，官方英文 PDF 不进入运行时。

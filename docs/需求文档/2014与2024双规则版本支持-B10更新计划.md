## 1. 目标与边界

### 1.1 目标

1. 跑团助手对两版角色都能正确执行：短休（花生命骰治疗、恢复短休资源）、长休（回血、恢复生命骰、力竭消退）、撤回上次休息。
2. 2024 职业资源、可消耗骰池、免费施法与魔法物品充能在跑团面板中可消耗、可按恢复时机回充，且**不会重复应用**。
3. 情境规则（武器精通、擒抱／推撞、突袭、施法限制）在界面中有正确提示，不被误加为永久修正。
4. 角色编辑（升级／降级／改职业／改装备）后，跑团当前值与上限协调一致，已消耗语义保留。
5. 两版并存：切换角色、刷新、2014 回归全部通过。

### 1.2 明确不包含

- 战斗流程自动化（攻击／伤害／先攻的逐轮结算）、随机表、遭遇生成。
- 生物数据（变形形态、召唤物、坐骑数据卡）。
- 导出承载与跨会话完整性（B11）；2014 职业资源的结构化登记（见 Q-B10-1）。
- B07-05 的 2014 物品库版本化与来源关闭。

## 5. 状态与结算设计

### 5.1 `SessionState` v2（草案）

```ts
interface SessionState {
  draftId: string
  currentHp: number
  usedSpellSlots: Record<number, number>
  /** 生命骰：总数（职业等级）与已花费数量；非 dX 骰面不变，仅存数量。 */
  hitDice?: { readonly total: number; readonly spent: number }
  /** 职业资源／免费施法／物品充能：key = 稳定标识，value = 已用数量。 */
  resourceUsage?: Readonly<Record<string, number>>
  exhaustionLevel: number
  debuffs: readonly string[]
  lastRestSnapshot?: SessionRestSnapshot   // 同步扩展上述字段
  updatedAt: string
}
```

- 标识规则：职业资源与骰池用 `feature.id`；免费施法用 `spellGrant:<featureId>:<spellId>`；物品充能用 `item:<inventoryEntryId>`。稳定标识保证编辑角色后仍能对应。
- 旧状态（v1）迁移：新字段缺省 `hitDice.total = 职业等级`、`spent = 0`、`resourceUsage = {}`；不重置既有 HP／法术位。

### 5.2 结算约定（不重复应用）

- 单一 reducer：消耗／恢复均走 `applyResourceDelta(state, key, delta, max)`，越界裁剪到 `[0, max]`，并在 `updatedAt` 变化时幂等返回。
- 休息结算顺序固定：①记录快照 ②生命骰治疗 ③短休资源回充 ④(长休) 生命骰恢复／力竭消退／法术位与资源回充；每次操作只结算一次。
- 「撤回上次休息」按快照整体回滚（含新字段）。

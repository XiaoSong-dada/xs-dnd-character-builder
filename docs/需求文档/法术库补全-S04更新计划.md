按需求文档 §3.4 表合并，目标职业 ID 为 `class-2024-bard`／`class-2024-cleric`／`class-2024-sorcerer`／`class-2024-warlock`／`class-2024-wizard`／`class-2024-ua-artificer`。要点：

## 3. 2024 旧扩展层（S04-03）

### 3.1 集合口径

- 不全书 2024 职业速查页附录 = **128 个唯一法术**，来源标签为 XGE／TCE／FTD／SCC／AI／BMT／AAG／SO／冰风谷／夸力许。
- 生成规则（可复现）：取 2014 目录中 `sourceIds` 命中上述 10 类旧扩展来源的法术，**排除英文名已存在于 PHB 2024（`spells-2024.ts`）的条目**（这些已由 PHB24 条目覆盖，如 心灵之楔、亡者丧钟、召唤野兽等），即得 128 条。
- 其中 108 条为既有 2014 条目，20 条为 S01 新增（含 `银光锐语` 等）；`思想编码`（无职业）不在 128 条内（速查页附录也没有它）。

### 3.3 镜像条目（`spell-2024-legacy-*`）

- 一条镜像 = 稳定 ID（`spell-2024-legacy-<英文名小写连字符>`）、中英文名、环级、`ritual`、`classIds`（由 2014 的 `class-2014-*` 映射为 `class-2024-*`）、`sourceIds`（对应 `source-2024-legacy-*`）、`summary`、`description`（复用 2014 摘要）、可选字段、`ruleset: '5e-2024'`。
- 生成方式二选一（实施时定稿）：
  - **建议**：脚本 `app/scripts/build-legacy-spell-catalog-2024.mjs` 从 `spells-2014.ts` 派生并输出 `app/src/rules/data/generated/spells-2024-legacy.ts`（人工复核后提交；与 `build-spell-catalog-2024.mjs` 的既有做法一致）；
  - 或静态手工文件 `app/src/rules/data/spells-2024-legacy.ts`（128 条体量可控，但需保证与 2014 数据同步）。
- `思想编码`等 `classIds: []` 条目按「无 2024 职业归属」保留在 2014，不进入 2024 镜像。

### 3.4 职业法表装配

- 现状：每个 2024 职业用 `spells2024.filter(classIds.includes(classId))` 派生 `classSpellIds`。
- 需改为能读取 UA 法术与旧扩展镜像（如按 `draft.classId` 从 2024 仓库 `spells` 统一过滤，或在 `repositories.ts` 装配时把 UA／镜像法术按 `classIds` 合并进各职业 `classSpellIds`）。
- 不论方案：候选池必须经 `isSourceEnabled` 过滤；关闭来源后不进候选；旧草稿已选条目保留并由校验给出「来源已关闭」提示（沿用既有语义）。
- 需回归：准备/已知/法术书数量校验、抄录、导出（PDF／XLSX／JSON／ZIP）、跑团助手。

### 3.5 不改动项

- 不把旧扩展设为默认开启；不改 2014 目录；不为旧扩展新建 UI 组件（复用现有法术条目展示 + 标签）；不做自动比对校验。

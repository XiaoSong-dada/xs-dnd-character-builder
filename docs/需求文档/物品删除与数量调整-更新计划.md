# 物品删除与数量调整 · 更新计划

> 依据《docs/需求文档/物品删除与数量调整需求.md》制定。本文件为实施计划存档，执行时按阶段推进。

## 目标与范围

- **规则层**：新增 3 个纯函数——`removeAdventureItem`（删整条）、`decreaseAdventureItem`（按指定数量扣减）、`increaseAdventureItem`（按指定数量追加）。
- **界面层**：`CharacterSheetStep` 物品页签，冒险获得条目（`sourceKind === 'adventure'`）新增**数量调整入口**——弹层内"减少（输入数量）/ 增加（输入数量）/ 删除全部"。
- **确认**：删除整条与"扣减至 0"触发二次确认；不返还金币。
- 起始装备条目不提供调整；复用 `changeInventory` 通道，不动 `index.vue`/store。

## 阶段 1：规则层（先于界面）

`app/src/rules/starting-equipment.ts` 新增三个纯函数（参照 `addAdventureItem` 158–185 行的模式）：

| 函数 | 行为 |
|---|---|
| `removeAdventureItem(inventory, entryId)` | 按 `entry.id` 移除；非 adventure 条目原样返回 |
| `decreaseAdventureItem(inventory, entryId, count)` | `quantity -= count`；`equippedQuantity = min(equippedQuantity, 新 quantity)`；`quantity ≤ 0` 整条移除；非 adventure 原样返回 |
| `increaseAdventureItem(inventory, entryId, count)` | `quantity += count`，`equippedQuantity` **不变**（追加只入物品栏）；非 adventure 原样返回 |

- 完成检查：函数可独立编译，抽样调用结果正确（用 node 直接跑或阶段 2 测试验证）。

## 阶段 2：测试层（先于界面，遵守"先测试后界面"）

`app/test/rules/starting-equipment-2014.test.ts` 扩展（现有文件已有 `addAdventureItem` 测试先例，141–180 行）：

| 用例 | 断言 |
|---|---|
| 删除冒险条目 | 按 id 移除，其余保留 |
| 删除非 adventure 条目 | 原数组返回 |
| 减少指定数量（如 3） | quantity 减 3；equippedQuantity 收缩（5 件装备 3 → 减 3 后 2/1） |
| 扣减至 0 或以下 | 整条移除 |
| 增加指定数量（如 3） | quantity 加 3，equippedQuantity 不变 |
| 增减非 adventure 条目 | 原数组返回 |
| 不变量 | 所有操作后 `equippedQuantity ≤ quantity` |

- 完成检查：`pnpm test:run` 该文件全绿。

## 阶段 3：界面层

**`CharacterSheetStep.vue` 物品页签**（已装备区约 495–515 行、物品栏区约 510–525 行）：

1. **操作区显示条件**：`entry.sourceKind === 'adventure'` 才显示"调整"按钮；起始装备条目不显示（保持现状，可加"起始装备"来源徽标）。
2. **数量调整弹层**（新增页面私有组件 `AdjustItemModal.vue`，或行内展开区——推荐独立弹层，参照 `AddItemModal` 模式）：
   - 标题含物品名与当前数量（如"长剑 · 当前 ×3（装备 2）"）；
   - 数量输入框（数字 ≥ 1，默认 1）；
   - 三个操作：「减少」「增加」「删除全部」；「删除全部」无需输入数量；
   - 关闭/取消路径（Esc、遮罩、取消按钮）。
3. **二次确认**：删除整条（含"输入数量 ≥ 当前数量"的扣减）先弹确认（`UiModal`，文案含"不返还金币"）；普通扣减与增加不弹确认。
4. **事件**：复用 `changeInventory`——`emit('changeInventory', removeAdventureItem(...) / decreaseAdventureItem(...) / increaseAdventureItem(...))`。
5. 按钮样式沿用 `suffix` 操作位（`character-sheet__spell-action` 先例）。

**组件测试**（`CharacterSheetStep.test.ts` 扩展）：
- adventure 条目显示调整入口，非 adventure 不显示；
- 弹层"减少"emit 且数量正确扣减；"增加"emit 且装备数量不变；
- "删除全部"先弹确认——取消不移除、确认后条目消失；
- 输入数量 ≥ 当前数量的扣减触发确认流程。

- 完成检查：组件测试全绿。

## 已确认决策（2026-08 用户确认）

1. **删除范围**：只允许调整"冒险获得"（`sourceKind === 'adventure'`）物品；起始装备由重新编辑流程管理。
2. **指定数量**：减少/增加均支持输入指定数量（`decreaseAdventureItem` / `increaseAdventureItem` 的 `count` 参数）。
3. **不返还金币**：删除/丢弃不返还金币（出售/折价属后续批次）。

## 待执行时确认点

1. **数量调整弹层形态**：独立弹层（`AdjustItemModal.vue`，页面私有组件）——比行内展开更清晰，与 `AddItemModal` 交互一致；如需行内展开区可调整。
2. **"增加"只加物品栏数量**（装备数量不变）——如需"增加并自动装备"需追加交互。
3. 起始装备条目在物品页签**完全不显示调整入口**（保持现状展示）。

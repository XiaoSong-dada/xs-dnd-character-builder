# 法术效果展开展示需求

## 1. 背景与目标

用户反馈：全职业法术列表在车卡过程中**只显示法术名称**（外加一句占位性环级说明），没有任何实际介绍与效果描述。新玩家无法判断"这个法术是干什么的、值不值得选"，选择只能靠名称猜测，信息不明确。

现状根因（已核验）：规则数据层 `spells-2014.ts` 按版权约定只登记了选择所需元数据（名称、环级、职业归属、来源索引），`SpellRule.summary` 为统一占位文本（如"1环法术；元数据条目，效果以规则来源为准。"），没有效果内容；两个法术列表界面（车卡施法步骤、角色卡法术页签）都只展示该占位文本。

目标产物：

- 全职业法术条目升级为**可展开的卡片列表**：默认只显示名称等摘要信息，点击**右侧三角形**展开当前法术的效果；**双击卡片**同样可展开/收起。
- 法术效果文本为**原创中文摘要**（版权合规，不复制原书正文），首批覆盖常用法术（`basic-rules-2014` 法术池，约 361 条），其余批次补齐。
- 覆盖范围：车卡施法步骤（`SpellcastingStep`）与角色卡法术页签（`CharacterSheetStep`，含已选、法术书与候选池区块）统一使用该交互。

## 2. 现状调查（已核验）

### 2.1 数据层：无效果内容（核心缺口）

| 模块 | 现状 |
|---|---|
| `app/src/rules/data/spells-2014.ts` | 全量法术表（约 477 条：`basic-rules-2014` 约 361、`xgte-2017-index` 约 95、`tcoe-2020-index` 约 21）；`spellSeeds` 为 tuple 数组（英文名/中文名/环级/职业/来源），导出时统一生成占位 `summary` |
| `app/src/types/rules.ts` `SpellRule`（77–87 行） | 字段：`id / ruleset / name / englishName / level / classIds / summary / status / sourceIds`；`summary` 语义为"环级说明"，无效果字段 |
| 版权边界 | `docs/rules.md` 与工作区约定：不复制未开放商业规则书完整正文；法术只保存选择所需元数据、**原创摘要**与来源索引；未经核验的具体效果不得进入自动计算。效果摘要只能原创转述，不能照搬原文 |

### 2.2 界面层：两个法术列表均无效果展示

| 界面 | 现状 | 缺口 |
|---|---|---|
| `SpellcastingStep.vue`（车卡施法步骤） | 戏法区 / 法术书区 / 按环分组区全部使用 `OptionCard` 渲染，`description` 显示 `英文名 · summary`；整卡为单个 `<button>`，单击 = 选择/取消 | 无效果内容；卡片无展开结构 |
| `CharacterSheetStep.vue`（角色卡法术页签） | 戏法、已准备/已掌握（按环分组）、法术书（法师）、候选池（可选法术/候选准备/未写入法术书）区块均为平铺列表项 | 同上；候选池法术同样无法判断效果 |
| `components/ui/OptionCard.vue` | 通用选项卡片：`title / description / state / disabledReason` + `select` 事件，整卡 `<button>` | 无展开插槽、无三角形指示、无双击区分 |

### 2.3 结论

- 数据层缺少效果摘要字段与内容（首批需登记 `basic-rules-2014` 约 361 条原创中文摘要）。
- 界面层两个法术列表共用展示缺口，需一个**可展开卡片**能力（含展开状态、三角形指示、双击判定），并在两处接入。
- 选择交互（单击选择/取消、计数、上限、校验）现状正确，本需求不得改变。

## 3. 需求项

### R1 数据层：新增法术效果摘要（核心）

1. `SpellRule` 新增效果摘要字段（建议命名 `description`，与 `summary` 并存；`summary` 保留现有环级元数据说明，字段职责互不混淆）。
2. 摘要内容为**原创中文简述**，覆盖该法术的核心信息以便决策：施法时间、射程、持续时间/专注与否、动作效果要点（伤害/治疗/控制/增益等）与豁免/攻击类型。示例风格（以"火焰箭 Fire Bolt"为例，非原文照抄）："施法时间 1 动作，射程 36 米，对目标进行一次远程法术攻击，命中造成 1d10 火焰伤害；5、11、17 级时伤害骰增加。"——具体表述由实现批次按版权合规转述，不复制原书正文。
3. **分批登记（2026-08 已全部完成）**：
   - 首批：`sourceIds` 含 `basic-rules-2014` 的全部法术（361 条）；
   - 后续批次：`xgte-2017-index`（95 条）、`tcoe-2020-index`（33 条）等扩展法术已全部补齐——当前 **489/489 条法术全部有原创摘要**，不再存在空摘要法术。
4. 摘要字段为**只读展示数据**，不进入自动计算；不新增 `CharacterDraft` / `SpellSelections` 字段，导入导出兼容。
5. 摘要登记采用与现有 `spellSeeds` 一致的方式（按条目扩展），保持数据文件结构统一；类型与数据文件同步更新。

### R2 可展开法术卡片交互（核心）

法术列表中的每条法术升级为**可展开卡片**，默认收起只显示名称与现有摘要行（环级/英文名等），展开后显示效果摘要（R1 的 `description`）。

1. **展开/收起触发方式**（两种都支持）：
   - **点击右侧三角形指示**（▶ 展开 / ▼ 收起）：三角形为独立可点击区域；
   - **双击卡片**任意非交互区域：展开/收起。
2. **与现有选择交互的区分**（必须明确，避免误触）：
   - **单击卡片主体（非三角形区域）= 选择/取消**，保持现有行为（计数、上限"已满"、写回逻辑不变）；
   - **双击判定采用短延迟**（如 250ms 内第二次点击视为双击）：双击生效时**抑制该次点击的选择副作用**，只切换展开状态；单击行为不受双击延迟明显影响（延迟仅用于区分，不引入明显卡顿）。
   - 展开/收起**不改变选择状态**；选择/取消**不改变展开状态**。
3. **可访问性**：三角形区域为独立可聚焦 `<button>`（键盘 Tab 可达），Enter/Space 切换展开；展开状态用 `aria-expanded` 标注；展开区内容可被辅助技术读取。
4. **触控与布局**：三角形点击区域 ≥ 44 px 触控面积；卡片展开不挤压相邻卡片（展开区自然撑开，页面可滚动）；移动端默认宽度下展开区文本可读、不横向溢出。
5. **展开状态管理**：展开状态为组件内/页面局部 UI 状态，不写入草稿、不持久化；默认全部收起；展开区随卡片重渲染保持（如切换选择后不自动收起）。
6. **空摘要占位**：`description` 未登记（后续批次法术）时展开区显示"暂无摘要，效果以规则来源为准"。
7. **视觉基线（2026-08 确认）**：展开交互视觉对齐职业卡片 `ClassOptionCard`（车卡职业步骤的"1—20级成长速览"展开设计）——卡片容器 `grid + overflow: hidden` 无内边距；头部为透明无边框主按钮（`min-height 4.25rem`、focus-visible 主题色轮廓）+ 窄箭头（2.4rem、无边框、字符 `›`、展开时 `rotate(90deg)` 过渡、`aria-expanded`/`aria-label`）；标题行右侧为徽标位（承接角色卡行内操作按钮与状态徽标）；摘要行单行省略；展开区用 `border-top: 1px dashed` 分隔 + `--color-gold-soft` 柔和背景 + 标题行（如"法术效果"）。

### R3 接入位置（两处界面统一）

1. **`SpellcastingStep.vue`**：戏法区、法术书区（法师）、按环分组区全部法术卡片接入展开能力。
2. **`CharacterSheetStep.vue`**：已选区块（戏法/已准备/已掌握/法术书）、候选池区块（可选法术/候选准备/未写入法术书）全部法术条目接入展开能力。
3. **实现形态建议**：在 `components/ui` 新增可展开卡片能力（如 `ExpandableOptionCard.vue`，复用现有 `OptionCard` 视觉与状态，增加展开区 slot、三角形按钮与双击判定），`OptionCard` 本身不改动或仅做向后兼容扩展；依赖方向仍为 `views → components/ui`，展开内容（摘要文本）由调用方传入，ui 组件不直接依赖 rules。
4. 两个界面的卡片选择/候选交互（角色卡"准备/取消准备"、候选"准备/已满"等）行为保持不变，仅增加展开维度。

## 4. 非目标与边界

- **不复制法术原书正文**：摘要为原创转述，遵守版权约定；不引入任何外部法术效果 API。
- **不改变选择逻辑**：计数、上限、失效校验、写回路径、候选池规则均不动。
- **不持久化展开状态**：不新增草稿字段；导入导出完全兼容。
- **不一次性登记全量摘要**：首批仅 `basic-rules-2014`（约 361 条）；扩展书法术摘要按后续批次登记，未登记时显示占位。
- 不实现法术效果的结构化字段（施法时间/射程/持续时间为独立字段等）——首批以一段文字摘要承载；若后续需要按字段展示/筛选，另行立项。
- 不实现法术搜索、收藏、对比等列表增强。

```text
app/src/types/rules.ts
  SpellRule 新增 description（效果摘要）字段

  首批登记 basic-rules-2014 法术的原创中文摘要；类型与数据同步更新

components/ui/ExpandableOptionCard.vue（新增，可展开卡片）
  -> 复用 OptionCard 视觉与状态约定；展开区内容由 slot 注入，不依赖 rules

views/character-builder/components/SpellcastingStep.vue
  -> ExpandableOptionCard（戏法/法术书/按环分组接入展开）

views/character-builder/components/CharacterSheetStep.vue
  -> ExpandableOptionCard（已选/法术书/候选池区块接入展开）
  -> rules/repository（getSpell 读取 description，不变）
```

依赖方向不变：`views → components/ui + rules → types`，rules 保持框架无关；新增页面私有组件或公共 ui 组件后，按 `docs/frontend-architecture.md` 拓扑规则复核并在交付说明写明"已复核前端依赖拓扑，已更新/无需更新"。

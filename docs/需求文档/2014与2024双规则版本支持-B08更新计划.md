## 1. 目标、交付物与边界

### 1.1 目标

按职业逐项把 2024 职业与子职接入纯规则层与车卡步骤，使已交付职业能够：按等级展开正确检查点、完成必选选择与前置校验、从原始选择重算派生值、保存恢复并在降级／改选后保持一致。职业范围以外仍由后续批次控制。

### 1.2 本批交付物

- 共享能力：2024 职业装配（特性随职业数据内联）、版本无关时间线与子职解析、武器训练与武器精通职业授权、资源登记口径、通用校验路径。
- 每职业一个更新任务（沿用 [B06 更新任务](2014与2024双规则版本支持-B06更新任务.md) 模板），包含数据、检查点、测试、文档同步与结果回填。
- 每批完成后形成可追踪证据：数据完整性测试、时间线快照、边界与改选测试、类型检查、完整测试、生产构建、`git diff --check`。

### 1.3 明确不包含

- DMG 魔法物品、同调、充能与资源结算（B07-04；消耗结算归 B10）。
- 跑团助手资源消耗与恢复、休息结算（B10）。
- JSON／ZIP／PDF／XLSX 导出适配（B11）。
- 第一页版本选择和完整产品入口开放（B09）；本批不修改 `OPEN_RULESETS`。
- 2014 适配、旧草稿转换与扩展书（B13、B00-05）。
- 多职业。

## 4. 共享基础设施（B08-01 先行，后批复用）

### 4.1 2024 职业装配（决定 1）

- 按职业拆文件、特性内联：`data/sources-2024.ts`（来源表，从 `rules-2024-sample.ts` 拆出）、`data/skill-options-2024.ts`（共享技能选项）、`data/fighter-2024.ts`（战士 `ClassRule` + 检查点 + 内联 `features` + 勇士 `SubclassRule` 与内联子职特性）、`data/wizard-2024.ts`（法师同结构）、`data/classes-2024.ts`／`data/subclasses-2024.ts`（装配列表，供 `repositories.ts` 引用）。
- 不新增 `classFeatures` 共享通道：`ClassRule.features`、`SubclassRule.features` 由各职业文件直接提供（2014 仍由 `repository.ts` 挂载），`repository.getClass(id)?.features` 对两个版本一致可用；`rules-2024-sample.ts` 迁移完成后移除。
- 数据约定沿用 2014 规则：稳定 ID（`<职业slug>-2024-class-<特性slug>`、`subclass-2024-<职业>-<子职>-<特性slug>`）、`ruleset: '5e-2024'`、原创中文摘要与详情、`requiresChoice` 标记选择项、未经核验效果保持 `index-only`。

### 4.2 时间线与子职

- `timeline.ts`：`buildSubclassCheckpoint` 改为从 `repository.subclasses` 过滤 `classId` 与玩家可用性；`buildSubclassFeatureCheckpoints` 改为读 `repository.getSubclass(subclassId)?.features`（2014 子职已挂载 features，行为不变）。
- 子职检查点标题按职业数据或按版本补充标题表；`subclassTitles` 不得只含 2014 ID。
- `TimelineStep.vue` 改为按 `props.draft.ruleset` 取仓库；职业／子职特性从仓库读取，移除对 `getClassFeatures2014`、`getSubclassFeatures2014` 的直接依赖（决定 5：B08-01 内完成共享层改造，视觉细节归 B09）。
- 候选渲染按 `candidateKind` 分支：`spell*` 走法术列表；`weapon-mastery` 走装备列表（显示武器名、精通词条摘要与选择数量），通过 `repository.getEquipment` 与 `repository.getWeaponMastery` 解析；其他候选保持现有路径。

### 4.3 武器训练与武器精通授权

- `ClassRule` 增加武器训练字段（类别 + 指定武器 ID），2024 战士＝简易＋军用，法师＝简易；`weapon-attacks.ts` 改为按草稿 `ruleset` 取仓库，2024 用新字段，2014 回退现有硬编码映射（不回归）。
- 战士武器精通检查点（决定 2）：等级 1 建立单一检查点，数量由 `getCheckpointSelectionBounds` 新增动态来源按职业等级映射 3／4／5／6（1／4／10／16 级解锁），候选为当前规则集全部带 `masteryId` 的武器；重复、非武器 ID、版本外武器由 B07-A 的 `validateWeaponMasterySelection` 拦截，并在 `validate.ts` 接线。
- 持有或熟练武器不自动获得精通；长休替换不在车卡阶段实现，仅在特性详情说明。

### 4.4 资源登记口径（决定 3）

- 给 `ClassFeature`／`SubclassFeature` 增加最小结构化字段：上限数组（如 `maxByLevel`）与恢复类型（`short`／`long`／`none`／`special`），仅用于展示；复杂资源（奥术回想的槽组合、超限导能的累积反噬、英雄激励等外部资源）用 `special` + `description` 表达，不强行建模。
- 回气、动作如潮、不屈、奥术回想等数值在 B08 登记；**消耗与恢复结算归 B10**，B08 不实现跑团结算。

### 4.5 校验与派生

- `validate.ts`：子职特性选择改用仓库；`subclass-index-only` 等文案去掉写死的 2014；武器精通选择纳入通用检查点校验（非法候选 + 重复）。
- `getCheckpointSelectionBounds`（`feats.ts`）：新增武器精通的按等级数量来源（3／4／5／6，按 `draft.targetLevel` 计算，决定 2）；`validate.ts` 与完成度计算共用该函数，自动获得一致结果。
- `derive.ts`：职业资源与 AC 公式（野蛮人、武僧）需版本化，避免 2014 硬编码判断；首批战士、法师不涉及新 AC 公式。

### 4.6 组件与导出边界

- 本批保证时间线、角色卡能力页签能读取 2024 特性；入口未开放，验证以单元／组件测试为主。
- `AddItemModal`、角色卡物品查询、导出名称解析的版本化保持 B07-05／B09／B11 归属，不在 B08 顺手改动；如 B08 需要触碰共享组件，先确认不扩大范围。

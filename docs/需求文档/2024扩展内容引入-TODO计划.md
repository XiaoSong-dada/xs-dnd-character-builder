## 1. 使用方式与计划边界

- 工作对象为 `app` 产品项目；不修改原型图项目与第三方内容。
- 每个 `Exx-nn` 是一个可独立展开的更新任务；后续更新任务必须引用对应编号，并在任务文档中写明范围、不包含项、验证与文档同步。
- 一批只改一类内容或一条用户流程：先来源模型，再新职业，再子职批次，最后专长／法术／物品与 SAE 核对，禁止「一次性把 43 条子职全部录入」的巨型任务。
- 所有批次共享同一条规则边界：只登记 `5e-2024` 内容，只保存必要机械字段与原创中文摘要，不复制 CHM 或规则书正文，不把未核验效果接入自动计算。
- 所有批次完成标准都包含：类型检查、相关测试、生产构建通过，并复核前端依赖拓扑。
- 未获得用户明确要求，不执行 `git commit`、`git push` 或分支合并；发布登记只在 E09 由用户确认后执行。

### 1.1 编号与勾选约定

- `Exx` 为批次，`Exx-nn` 为可追踪 TODO；细拆沿用父编号加后缀（如 `E05-03a`）。
- `[ ]` 未完成；只有交付物存在且完成标准通过才改为 `[x]`。
- 「已制定更新任务」不等于「TODO 已完成」。
- 决策未确认时，依赖该决策的 TODO 保持未勾选，并在任务文档中标注「决策门」。

- 记录日期：2026-09-28
- 规则集范围：`5e-2014` 与 `5e-2024`（两版分别解析，不混用）
- 产品范围：出身授予专长、法术选择、角色重新编辑、等级调整、法师高等级首次车卡、角色卡人工专长
- 状态：已完成（2026-09-30）；3 项产品决策与 F01—F06 全部落地，随 v1.11.0 登记
- 更新计划：[《车卡法术与专长编辑协调更新计划》](车卡法术与专长编辑协调更新计划.md)

## 1. 需求来源

用户提出四类问题：

> 1. 出身自带的魔法学徒没有办法选择法术以及戏法。
> 2. 重新编辑时更换职业，或降低角色等级后，旧职业／高等级法术仍保留在 JSON 中；高等级法术还会阻塞低等级角色完成。
> 3. 首次创建 18 级以上法师时，法术精通发生在学习法术之前，导致没有候选并卡住流程；希望精通选择与后续学习法术联动。
> 4. 编辑角色卡时，希望在能力页人工添加专长。

本需求将其收束为四个可验收目标：

| 编号 | 目标 | 结果定义 |
| --- | --- | --- |
| **R1** | 出身授予的魔法学徒可以完整配置 | 固定授予专长不要求重新选择专长本身，但玩家能完成法术表、施法属性、戏法和一环法术等必选子项 |
| **R2** | 换职业、降级后的法术状态合法且可解释 | 不再让旧职业或当前等级不可用的法术污染有效角色，也不要求玩家先恢复旧职业／高等级才能处理 |
| **R3** | 18—20 级法师首次车卡不被法术精通／招牌法术阻塞 | 时间线中的高等级法术选择能预选并联动写入后续法术书 |
| **R4** | 角色卡能力页支持人工授予专长 | 编辑模式下可添加、配置和移除当前规则集专长，并在角色卡、跑团助手和导出中保持一致 |

## 2. 当前行为与问题定性

### 2.1 出身固定授予的魔法学徒

2024 魔法学徒已经登记四类结构化子选择：

1. 施法属性：智力、感知或魅力；
2. 法术表：牧师、德鲁伊或法师；
3. 从所选法术表选择 2 道不同戏法；
4. 从所选法术表选择 1 道一环法术。

当前仅当玩家在一个父检查点中主动选中专长时，时间线才会生成专长子检查点。背景通过 `originFeatId` 固定授予专长时：

- 出身步骤把专长显示为“自动获得、无需额外选择”；
- 不生成可承载子选择的父检查点；
- 魔法学徒的施法属性、法术表、戏法和一环法术因此没有操作入口；
- 侍僧、向导、学者等背景限定的法术表目前主要存在于描述文本中，缺少可供规则层消费的结构化预设。

该问题是**授予实例与子选择装配缺失**，不是单纯的界面漏按钮。

2014 魔法学徒目前只有专长说明，尚未登记与 2024 同等粒度的法术表、戏法和一环法术子选择，因此 2014 侧还包含数据结构缺口。

### 2.2 换职业后的旧法术

当前车卡页面的正常“更换职业”入口已经清空职业施法选择：

- 戏法；
- 已知法术；
- 准备法术；
- 法术书；
- 抄录记录；
- 子职额外入书记录。

以下内容仍会保留：

- 带 `invalidatedAt` 的旧时间线选择，符合现行“保留历史、不静默删除”的约定；
- 人工添加法术，现行规则明确要求换职业时保留；
- 由背景、物种或专长独立授予的法术，因为其来源不是旧职业，不应随换职业删除。

因此，“换职业后 JSON 仍有法术”需要按字段判定：

| 数据位置 | 当前含义 | 是否应随换职业失效 |
| --- | --- | --- |
| `spellSelections` 中的职业法术 | 当前职业施法原始选择 | 是 |
| `selections` 中已失效的旧选择 | 可恢复历史 | 不再生效，但当前仍保存在草稿 JSON |
| `manualEdits.addedSpells` | 玩家人工添加 | 否，除非玩家手动移除 |
| 背景／物种／专长授予法术 | 独立来源法术 | 否 |

主入口已具备清空行为，但缺少覆盖“换施法职业 → 非施法职业 → JSON／导出／派生”的完整回归测试，也需要防止导入、旧草稿或其它写入路径绕过协调逻辑。

### 2.3 降级后的高等级法术

时间线选择支持 `invalidatedAt`，但 `spellSelections` 仍是多个法术 ID 数组，不能表达“保留但暂时失效”。降级后：

- 超过新等级最高法术环级的法术仍留在原数组；
- 已知／准备数量可能超过新等级上限；
- 法术书、抄录或子职额外入书可能包含当前等级不可用法术；
- 最终校验会将这些条目判为不可用并阻塞角色完成。

现有法术页已具备“当前已选”区块和点击移除能力，但没有完整覆盖降级场景，也没有统一的数据协调模型。用户不应被要求先升回原等级才能取消高等级法术。

### 2.4 18—20 级法师首次创建

当前流程顺序为：

```text
等级时间线
  -> 18级法术精通
  -> 20级招牌法术
  -> 装备
  -> 法术步骤（写入法术书、准备法术）
```

法术精通候选只从当前 `spellbookSpellIds` 中读取。首次创建高等级法师时，法术书尚未填写，因此候选为空，必选检查点无法完成。

同一循环依赖还会影响首次创建 20 级法师时的招牌法术：招牌法术要求从法术书中选择两道三环法术，而法术书同样尚未建立。

### 2.5 能力页人工添加专长

角色卡人工编辑目前支持：

- 属性和派生数值差值；
- 法术位差值；
- 人工添加法术。

现有 `CharacterManualEdits` 没有人工专长字段，规则层的专长授予来源也只识别背景、物种、职业和子职。能力页只能展示规则正常授予的专长，不能添加或移除人工授予项。

## 3. 统一产品原则

### 3.1 有效选择与历史记录分离

- 当前角色计算、校验、角色卡、跑团助手和导出只能消费**当前有效选择**。
- 为升级恢复而保留的旧选择必须拥有明确的失效状态、失效原因和来源，不得继续混在有效数组中。
- 界面必须区分“当前有效”“暂时失效”“人工添加”，不能只靠是否存在 ID 判断。
- 任何失效数据都不得阻塞与其无关的当前合法角色完成。

### 3.2 授予实例优先于专长 ID

专长可能来自背景、物种、职业、子职或人工添加，同一可重复专长还可能获得多次。子选择不能只挂在 `featId` 上，必须挂在唯一的**授予实例**上。

每个授予实例至少需要表达：

- 稳定实例 ID；
- `featId`；
- 来源类型与来源 ID；
- 获得等级；
- 是否人工授予；
- 是否当前生效；
- 对应子选择。

固定背景专长可以使用由背景和专长稳定推导的实例 ID；人工专长必须使用独立实例 ID，以支持重复获得同一可重复专长。

### 3.3 规则集隔离

- 2014 草稿只能添加与解析 2014 专长和法术。
- 2024 草稿只能添加与解析 2024 专长和法术。
- 同名专长不能跨规则集复用 ID、子选择或规则效果。
- JSON 导入时发现跨规则集 ID，必须标记为无效并给出中文原因，不得静默回退到另一版。

### 3.4 单一事实源

以下消费者必须使用同一份有效授予和有效法术结果：

- 车卡步骤门禁；
- 最终校验；
- 角色卡；
- 跑团助手；
- PDF／XLSX／JSON／ZIP 导出；
- 免费施法与跑团资源；
- 角色重新编辑与等级调整提示。

## 4. R1：出身魔法学徒完整配置

### 4.1 固定授予不等于无子选择

- 背景固定授予的专长本身不可更换，继续显示“由背景固定授予”。
- 如果该专长定义了必选子项，出身步骤必须追加“配置专长”任务。
- 未完成必选子项时，出身步骤不得继续，最终校验给出具体缺失项。
- 子选择写入授予实例，不能伪造一次“玩家重新选择了该专长”的记录。

### 4.2 2024 魔法学徒

固定背景魔法学徒需要依次完成：

1. 读取背景预设法术表；
2. 选择施法属性；
3. 选择 2 道不同戏法；
4. 选择 1 道一环法术。

背景预设法术表应结构化登记：

| 背景类别 | 预设法术表 |
| --- | --- |
| 侍僧及明确写明“魔法学徒（牧师）”的背景 | 牧师 |
| 向导、月井朝圣者等明确写明“魔法学徒（德鲁伊）”的背景 | 德鲁伊 |
| 学者、巨灵接触者、仪式专家等明确写明“魔法学徒（法师）”的背景 | 法师 |

- 预设法术表只读展示，不允许改成其它表。
- 戏法和一环法术候选只来自预设表、当前规则集和当前启用来源。
- 一环法术视为始终准备，拥有每长休一次的免费施放，也可使用已有法术位施放。
- 专长法术不占职业戏法、已知法术、准备法术或法术书数量。
- 施法属性必须进入法术攻击、法术 DC 和免费施法来源说明。

### 4.3 2014 魔法学徒

- 补齐“选择一个施法职业／法术表、2 道戏法、1 道一环法术”的结构化子选择。
- 星界浪客固定要求牧师来源，法术表不可更换。
- 受宠者选择魔法学徒后，由玩家按 2014 专长规则选择合法施法职业／法术表。
- 免费施放与恢复按 2014 规则单独登记，不复用 2024 专长 ID 或效果定义。

### 4.4 交互要求

- 出身步骤的固定专长卡下方显示子任务入口和完成进度。
- 候选卡显示法术名称、英文名、环级、学派、来源和效果摘要。
- 更换背景时，旧背景授予实例及其全部子选择一起失效。
- 如果新背景授予相同专长，也必须建立新的来源实例，不得复用旧背景实例。
- 刷新页面后恢复当前子任务和已选内容。

### 4.5 验收标准

1. 2024 学者背景可以选择施法属性、2 个法师戏法和 1 个法师一环法术，并完成角色。
2. 2024 侍僧不能选择德鲁伊或法师表法术。
3. 2024 向导不能选择牧师或法师表法术。
4. 未完成任一必选子项时，出身步骤与最终校验显示具体中文原因。
5. 非施法职业通过背景获得魔法学徒时，能看到和使用专长法术，但不会因此获得职业法术位。
6. 更换背景后，旧魔法学徒法术不再派生、展示、导出或提供免费施法。
7. 2014 与 2024 的魔法学徒选择、ID 和效果完全隔离。

## 5. R2：换职业与降级后的法术协调

### 5.1 换职业

确认更换职业后，系统必须按来源分类处理：

| 法术来源 | 处理方式 |
| --- | --- |
| 旧职业戏法、已知／准备／契约法术 | 从有效选择移出 |
| 旧职业法术书升级法术 | 从有效选择移出 |
| 旧职业抄录法术 | 转为失效历史或按 Q1 决策处理，不得继续作为新职业有效法术 |
| 旧子职额外法术／额外入书 | 随旧子职失效 |
| 背景、物种、专长授予法术 | 保留并继续生效 |
| 人工添加法术 | 默认保留，标注“人工添加” |

- 从施法职业切换到非施法职业后，法术步骤自动跳过。
- 旧职业法术不得进入派生、角色卡有效法术区、跑团施法资源或导出有效法术清单。
- 确认弹窗必须列出“职业法术选择将失效／移出”的影响。
- 所有职业变更入口、JSON 导入后的归一化以及旧草稿迁移必须走同一协调函数。

### 5.2 降级分类

降级后法术分为三类：

| 分类 | 示例 | 处理要求 |
| --- | --- | --- |
| 当前仍合法 | 5级法师降到4级后保留的一、二环法术 | 继续生效 |
| 当前不可用 | 5级法师降到4级后原有三环法术 | 标记暂时失效，不阻塞完成 |
| 数量超限 | 已知法术上限从6降到5，但现有6个均为合法低环 | 进入复查任务，由玩家在当前等级直接移除多余项 |

还必须分别处理：

- 戏法数量下降；
- 已知法术数量下降；
- 准备数量下降；
- 契约法术数量或最高环级下降；
- 法术书中的当前不可用高环法术；
- 抄录法术；
- 子职额外入书；
- 始终准备和免费施法来源失效。

### 5.3 低等级直接修正

- 法术步骤的“当前已选”必须展示所有需要处理的旧法术，包括当前候选池之外的高环法术。
- 玩家可以在当前低等级直接移除这些条目。
- 禁止要求玩家升回旧等级、恢复旧职业或重新打开已不存在的检查点。
- 提示文案必须说明失效原因，例如“当前4级最高可用二环法术，该三环法术暂不生效”。
- 当只剩暂时失效历史、有效选择已满足新等级要求时，角色可以完成。

### 5.4 JSON 与导出

- 有效字段不得继续混入当前不可用法术。
- 如果保留恢复历史，必须放入独立的失效结构，至少记录：法术 ID、原目标字段、失效时间、失效原因、原职业和原等级。
- 角色卡、跑团助手、PDF 和 XLSX 不输出失效历史。
- 普通 JSON／ZIP 是否包含独立失效历史按 Q1 决策执行，但必须与有效选择明确分区。
- JSON 导入遇到旧格式中的不可用法术时，应在归一化阶段迁移为失效历史或清理，不得继续污染有效字段。

### 5.5 验收标准

1. 施法职业切换为非施法职业后，正常职业法术不再生效、不再导出，角色可以完成。
2. 背景魔法学徒、物种法术和人工法术不会被误删。
3. 已知施法者降级后可直接在低等级移除多余法术。
4. 高于新等级最高环级的法术不阻塞角色完成。
5. 法师降级后，高环法术书内容不会被当成当前可准备法术。
6. 再次升级时，若采用保留历史方案，系统可以提示并恢复仍合法的旧选择，但不得自动超出新上限。
7. JSON 往返后，有效／失效状态、来源和原因不丢失。
8. 关闭并重开页面后，复查任务和失效提示保持一致。

## 6. R3：法师高等级首次车卡联动

### 6.1 适用检查点

| 规则集 | 等级 | 检查点 |
| --- | --- | --- |
| 2014 | 18 | 一环法术精通、二环法术精通 |
| 2014 | 20 | 两道三环招牌法术 |
| 2024 | 18 | 一环动作法术精通、二环动作法术精通 |
| 2024 | 20 | 两道三环招牌法术 |

### 6.2 候选来源

- 已存在法术书时，优先从当前有效法术书中生成候选。
- 首次车卡、法术书尚未完成时，从当前等级可学习的法师职业法术池生成候选。
- 候选必须满足规则集、职业归属、环级、来源开关和检查点附加限制。
- 2024 法术精通继续限制为施法时间为“动作”的一环／二环法术。
- 2014 按 2014 法术精通规则，不隐式套用 2024 动作限制。

### 6.3 预选与法术书联动

- 时间线选择法术精通或招牌法术后，建立“法术书预选”记录。
- 进入法术步骤时，预选法术自动出现在法术书中。
- 预选法术计入正常升级学习名额，不额外增加法术书总量。
- 法术书任务的已选计数必须包含这些预选法术，并清楚标注来源。
- 玩家不能直接从法术书移除仍被法术精通／招牌法术引用的法术；必须先修改对应时间线选择。
- 修改时间线选择时，旧预选法术只有在没有其它来源、且未被玩家作为普通学习法术保留时，才从法术书预选中移除。
- 法术精通与招牌法术继续按现有规则处理“始终准备”和免费施放，不占普通准备数量。

### 6.4 升级场景

- 17→18 级升级且已有法术书时，只能从法术书内合格法术中选择精通。
- 如果法术书内没有合格的一环或二环法术，应引导玩家先补足／调整法术书，不提供越过规则的候选。
- 19→20 级时，招牌法术只能从法术书内合格三环法术中选择。
- “首次创建高等级角色的预选”与“已有角色升级”必须是两种明确状态，不能统一放宽为任意职业池。

### 6.5 验收标准

1. 首次创建18级2014或2024法师时，两个法术精通检查点均有合法候选。
2. 完成精通选择后进入法术步骤，所选法术已经写入法术书并计入正常法术书名额。
3. 2024 护盾术等非动作法术不会出现在2024法术精通候选中。
4. 首次创建20级法师时，招牌法术不会因空法术书而卡住。
5. 17→18级已有角色仍只从现有法术书选择精通。
6. 删除或更换被引用法术时不会产生悬空的精通／招牌法术 ID。
7. 最终校验、角色卡、免费施法资源与导出均使用同一联动结果。

## 7. R4：能力页人工添加专长

### 7.1 入口与候选

- 入口位于角色卡“能力”页签的“专长与属性提升”区块。
- 仅在角色卡编辑模式下显示“添加专长”按钮。
- 点击后打开专长选择弹窗，候选只来自当前草稿规则集。
- 候选支持中英文名搜索、类别筛选和来源展示。
- 人工授予用于 DM 奖励、房规或导入缺口，不占职业时间线的专长／属性提升次数。
- 专长前置条件以警告形式展示，但默认不阻止人工授予；界面明确标记“人工授予可越过常规前置条件”。
- `unavailable` 条目不可添加；仅索引或未自动实现的条目可以展示，但必须标记“仅记录，不参与自动计算”。

### 7.2 数据模型

`CharacterManualEdits` 增加人工专长授予列表。每条记录至少包含：

- 人工授予实例 ID；
- `featId`；
- 添加时间；
- 可选备注；
- 子选择引用或内嵌子选择。

不得只保存 `addedFeatIds: string[]`，原因是：

- 魔法学徒等专长具有多个必选子项；
- 可重复专长可能获得多次；
- 相同专长的不同授予实例必须拥有独立法术表、属性或其它选择。

旧 JSON 没有人工专长字段时默认迁移为空数组，不能影响既有草稿。

### 7.3 添加流程

- 无子选择专长：确认后立即添加。
- 有必选子选择专长：必须在弹窗内或后续明确任务中完成配置；未完成前标记为“待配置”，不允许当成完整有效专长。
- 结构化效果已实现的专长进入正常派生管道，例如生命值、属性、熟练、护甲训练、速度、法术和免费施法。
- 只有文字效果或 `index-only` 条目只做展示，不编造自动计算。
- 非可重复专长已经生效时，不允许再添加第二份。
- 可重复专长允许多个授予实例，但仍需遵守专长内部的互斥规则；如魔法学徒复选时必须使用不同法术表。

### 7.4 展示、移除与来源

- 能力页、跑团助手与导出显示来源标签“人工添加”。
- 人工专长与规则正常授予的同 ID 专长不得无来源地合并；至少要能展开查看全部来源。
- 移除人工专长时，只移除目标授予实例及其子选择、派生效果和免费施法资源。
- 不得误删背景、物种、职业或子职正常授予的同名专长。
- 移除前若会影响属性、生命值、法术或跑团资源，确认弹窗列出主要影响。
- “恢复全部人工编辑”同时清除人工专长；确认文案必须把人工专长列入清理范围。

### 7.5 验收标准

1. 编辑模式下能力页可以搜索并添加当前规则集专长。
2. 非编辑模式不显示添加和移除入口。
3. 添加健壮等已实现专长后，派生数值与来源说明同步更新。
4. 添加魔法学徒时必须完成其法术子选择，且免费施法进入跑团资源。
5. 添加未自动实现的专长时明确显示“仅记录”，不会产生虚假的数值变化。
6. 非可重复专长不能人工重复添加；可重复专长拥有独立实例和子选择。
7. 移除人工专长不会删除正常授予的同名专长。
8. JSON／ZIP 往返、刷新页面、角色卡、跑团助手、PDF 和 XLSX 对人工专长保持一致。

## 8. 范围与非目标

### 8.1 本次范围

1. 两版出身魔法学徒必选子项的可达性与校验。
2. 职业、等级变化后的法术有效性协调。
3. 两版法师18级法术精通和20级招牌法术的首次车卡联动。
4. 角色卡能力页人工专长的增删、配置、派生、展示与导出。
5. 旧草稿和 JSON 导入的兼容归一化。
6. 对应规则、组件、Store、服务和导出回归测试。

### 8.2 非目标

- 不开放多职业。
- 不提供规则集原地切换。
- 不实现通用 DM 房规编辑器。
- 不为只有文字资料的专长编造自动计算效果。
- 不自动模拟法术在战斗中的完整效果。
- 不改变人工添加法术的既有保留语义，除非用户明确要求。
- 不把2014与2024同名专长或法术合并为同一规则条目。

## 9. 涉及模块与依赖边界

```text
types/character
  -> 授予实例、失效法术、人工专长数据类型

rules/data
  -> 背景魔法学徒预设、2014魔法学徒子选择、法师检查点约束

rules/feats + rules/timeline
  -> 固定授予实例、专长子检查点、人工专长授予汇总

rules/spellcasting + rules/dependency + rules/validate
  -> 有效法术、等级/职业协调、法师预选联动、最终校验

stores/character-drafts
  -> 草稿变更的统一协调入口

services/draft-storage
  -> 旧草稿迁移、JSON归一化与往返

views/character-builder
  -> 出身子任务、法术复查、法师预选展示、能力页人工专长交互

features/character-export + session-assistant
  -> 导出与跑团模式消费统一有效结果
```

- 规则判断必须位于 `src/rules`，Vue 组件只展示和收集输入。
- 草稿迁移和 JSON 边界必须位于 `src/services`。
- 跨页面共享的有效授予与法术结果不得在角色卡组件内重复计算。
- 如果新增模块或改变依赖方向，实施时必须同步更新 `docs/frontend-architecture.md`。

## 10. 测试矩阵

### 10.1 规则测试

- 固定背景专长能生成授予实例和全部子选择。
- 背景预设法术表限制正确。
- 更换背景后授予实例和子选择失效。
- 换职业只失效职业来源法术，不误伤其它来源。
- 各施法模式在降级后的环级、数量和失效处理。
- 首次18／20级法师候选、预选入书和计数。
- 已有法术书升级时不放宽候选。
- 人工专长重复、前置警告、子选择和派生效果。
- 2014／2024 ID 隔离。

### 10.2 组件测试

- 出身页固定魔法学徒的配置任务和进度。
- 法术页显示并可移除当前候选池外的旧法术。
- 能力页编辑模式的添加／配置／移除专长。
- 来源标签、仅记录提示和影响确认文案。
- 手机宽度下弹窗、任务列表和主要操作可用。

### 10.3 服务与集成测试

- 旧 schema 缺少新字段时安全迁移。
- JSON／ZIP 往返保留授予实例、失效原因和人工专长。
- 施法职业 → 非施法职业 → 导出。
- 高等级施法者 → 降级 → 修正 → 完成角色。
- 18级法师首次创建全流程。
- 人工魔法学徒 → 免费施法资源 → 长休恢复。

### 10.4 完成门槛

- 相关单元测试、组件测试和回归测试通过。
- `vue-tsc -b` 通过。
- 生产构建通过。
- 规则行为变化同步更新 `docs/rules.md`。
- 职业／背景／专长资料结构变化同步更新对应专项文档。
- 新增、删除或移动模块时复核并更新前端依赖拓扑。

## 12. 完成定义

本需求只有在以下条件全部满足后才算完成：

1. 四个目标 R1—R4 均达到各自验收标准。
2. 不存在必须切回旧职业或升回旧等级才能修正角色的路径。
3. 固定授予、正常选择、人工授予和失效历史均有可解释来源。
4. 当前有效角色数据与历史保留数据明确分离。
5. 两规则集不发生隐式混用。
6. 角色卡、跑团助手和全部导出结果一致。
7. 类型检查、相关自动化测试和生产构建通过。
8. 规则文档、专项资料、更新公告和版本号按实际实施范围同步维护。

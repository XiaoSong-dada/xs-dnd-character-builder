# 关于本站需求文档

> 本文档持续记录“个人中心”调整为“关于本站”的需求澄清过程。
> 后续开始设计或开发前，必须以“已确认结论”为实现基线；“建议方案”和“待确认事项”不视为已授权功能。

## 1. 背景与目标

现有一级导航“个人中心”及 `/profile` 页面仍是开发中占位页。“个人中心”通常表示登录账号、个人资料、偏好设置或云端数据管理，与计划展示的内容不一致。

新页面定位为站点与项目的公开信息入口，主要承载：

- 项目介绍与必要说明；
- B 站、GitHub 与 QQ 群等公开入口；
- “请杯咖啡”自愿打赏入口；
- 本站永久免费声明与问题反馈方式。

本需求的目标是明确页面名称、信息架构、内容维护方式、外部链接行为、隐私边界、SEO 与验收标准，为后续设计和开发提供依据。本轮只整理需求文档，不修改产品代码。

## 2. 已确认结论

### 2.1 页面定位与名称

- 原“个人中心”不再承担用户账号或个人资料功能。
- 页面名称采用“关于本站”。
- 页面服务于所有访客，无需登录。
- 页面不展示作者介绍、作者简介或作者头像区块。
- 页面首版覆盖项目介绍、公开入口、请杯咖啡、永久免费声明与问题反馈；赞助鸣谢和友情链接均从首版范围移除。
- 公开入口首版包括：
  - B 站个人空间：`https://space.bilibili.com/122674342`（实现时去除原链接中的 `spm_id_from` 跟踪参数）；
  - QQ 交流群：`831306509`；
  - GitHub 项目仓库：`https://github.com/XiaoSong-dada/xs-dnd-character-builder`。
- 不实现赞助鸣谢、赞助榜、赞助记录或赞助者名单。
- “请杯咖啡”作为独立的自愿打赏入口，同时展示微信支付和支付宝收款码。
- 页面必须明确声明：“本站永久免费。所有功能均可免费使用；‘请杯咖啡’仅为自愿打赏，不会解锁额外功能，也不会影响正常使用。”
- 问题反馈入口统一使用 QQ 交流群 `831306509`。
- 两张收款码属于部署者本地素材，不得提交或上传到 GitHub 仓库；页面通过本地配置读取对应资源地址。
- 底部导航文字确定为“关于”，页面主标题为“关于本站”；正式路由直接改为 `/about`，路由名改为 `about`，不保留 `/profile` 兼容重定向。
- 导航图标改为信息类图标，不再使用用户头像语义。
- “关于本站”是公开稳定的信息页，允许搜索引擎收录。
- 如果未来增加登录、用户资料、云端角色或账户设置，应另建独立“个人中心”，不得重新混入“关于本站”。

### 2.2 当前范围边界

- 本页面不涉及 D&D 角色规则、角色草稿和派生计算。
- 本页面不读取或修改用户的本地角色数据。
- 本页面不是社交动态流，不在站内复制 B 站视频、评论或私信能力。
- 本页面首版不展示友情链接，也不提供友链申请能力。
- 本页面不展示、收集或维护任何赞助者信息与打赏记录。
- 首版不实现后台管理、在线友链申请、站内支付或第三方赞助平台接口。

## 3. 首版功能建议

以下为建议方案，需经用户确认后才能成为实施基线。

### R1 项目介绍区（已确认首版纳入）

页面顶部只展示本站与项目的核心信息：

- 页面标题“关于本站”；
- 一段简短的项目介绍，说明本站解决的问题和适用人群；
- 可选展示当前版本号，但不在此处重复完整更新日志。

项目介绍建议文案为：“一个面向 D&D 5e 2014 玩家、尤其是新手的免费车卡与跑团辅助工具。通过分步引导、自动计算和规则校验，帮助你更轻松地创建并使用角色卡。”

页面不展示作者姓名、头像、个人简介或创作经历。移动端首屏优先让访问者快速理解“这是什么、是否收费、如何使用与反馈”。

### R2 相关入口与问题反馈（已确认首版纳入）

以链接卡片或按钮展示项目相关入口：

- B 站个人空间：跳转至 `https://space.bilibili.com/122674342`；
- GitHub 项目：跳转至 `https://github.com/XiaoSong-dada/xs-dnd-character-builder`；
- QQ 交流群：同时作为交流与问题反馈入口，展示群号 `831306509`，提供“复制群号”按钮和复制成功提示；在未提供腾讯官方加群链接前，不实现伪造或不稳定的一键加群跳转；
- 数据结构允许以后增加其他公开平台，但未配置的平台不显示；
- 每项包含平台名称、用途说明、链接和图标；
- 外部链接在新标签页打开，并使用安全的 `noopener noreferrer` 关系；
- 链接文字必须能够独立表达去向，不能只显示无语义图标。

首版只提供“前往平台”，不拉取粉丝数、视频列表或平台动态，避免第三方接口、跨域、缓存和隐私问题。

### R3 请杯咖啡（已确认首版纳入）

提供简短说明与自愿打赏入口：

- 明确展示：“本站永久免费。所有功能均可免费使用；‘请杯咖啡’仅为自愿打赏，不会解锁额外功能，也不会影响正常使用。”；
- 同时展示微信支付与支付宝两张收款码，并清楚标注支付平台；
- 区块名称使用“请杯咖啡”；
- 收款码允许点击查看大图，移动端不得强制用户在过小尺寸下扫码；
- 图片提供“微信支付收款码”“支付宝收款码”等替代文本；
- 不在本站直接处理支付、订单、退款和付款人身份信息；
- 打赏不产生会员身份、功能权益、内容解锁、优先服务或其他回报承诺；
- 不使用“赞助”“赞助榜”“赞助鸣谢”等容易暗示名单或权益的功能名称。

收款码本地配置方案：

- 原始收款码图片保留在仓库外，不把用户提供的图片复制进受 Git 追踪目录；
- 实施时建立被 `.gitignore` 排除的本地静态资源目录，例如 `app/public/local-assets/tips/`；
- 部署者自行将微信、支付宝图片放入该目录，并在 `app/.env.local` 中配置对应 URL，例如：

```dotenv
VITE_TIP_WECHAT_QR_URL=/local-assets/tips/wechat.jpg
VITE_TIP_ALIPAY_QR_URL=/local-assets/tips/alipay.jpg
```

- 环境变量必须由 `src/config` 统一读取，页面不得直接访问 `import.meta.env`；
- `.env.local`、本地资源目录和实际收款码图片不得进入 Git；`.env.example` 只登记变量名称与示例占位值，不包含真实收款码；
- 任一收款码未配置或文件缺失时，不渲染损坏图片；两者均未配置时隐藏二维码列表，并显示“当前暂未开放打赏入口”或等价提示；
- GitHub CI 或远程构建无法读取开发者电脑上的绝对路径。若生产站点由远程环境构建，必须在部署流程中安全地额外注入图片，或把 URL 配置为部署服务器上不属于 Git 仓库的静态资源地址；
- 收款码不进入 Git 只解决仓库泄露问题。页面公开展示后，访问者仍然可以查看或保存图片，这一点属于功能本身的公开属性。

### R4 赞助功能（已确认移除）

不展示赞助鸣谢、赞助榜、昵称、赞助时间、金额或任何打赏记录；不建立对应数据结构、配置、空状态或管理入口。“请杯咖啡”仅负责展示自愿打赏声明和本地配置的收款码。

### R5 友情链接（已确认移出首版）

首版不展示友情链接、不保留空区块，也不实现友链申请、分类、搜索或管理能力。未来如重新提出友链需求，应单独补充条目字段、内容审核和维护方式。

### R6 项目说明与页尾信息（建议首版纳入）

页面底部提供必要的项目边界说明：

- 本站为非官方社区工具，与 Wizards of the Coast 等权利方不存在官方隶属关系；
- 项目使用的规则范围、原创转述和来源索引继续以项目既有版权约定为准；
- 明确声明本站永久免费，自愿打赏不影响功能与内容；
- 问题反馈统一引导至 QQ 交流群 `831306509`；
- GitHub 项目入口已在相关入口区展示，可选提供更新日志和隐私说明入口；
- 不展示私人联系方式，公开联系与问题反馈统一使用 QQ 交流群。

### R7 内容维护方式（建议首版纳入）

首版内容建议采用项目内静态配置：

- 公开链接和收款码 URL 配置与页面模板分离；
- 各条目使用稳定字符串 ID，不使用显示名称作为关联键；
- 未配置的可选字段不渲染空占位；
- URL 在开发期进行格式校验，错误链接不能进入正式构建内容；
- 不新增后端、数据库、登录状态或第三方 API 依赖。

该方式适合当前低频人工维护，不为本页面增加后台或远程数据源。

## 4. 页面信息架构建议

建议采用以下移动端单列结构：

```text
关于本站
├─ 项目介绍与永久免费声明
├─ 相关入口
│  ├─ B站个人空间
│  ├─ GitHub项目
│  └─ QQ交流群（交流与问题反馈）
├─ 请杯咖啡（自愿打赏，微信 / 支付宝收款码）
└─ 项目声明
```

区块较少且内容量可控，使用自然滚动，不增加页内标签页、折叠、分页或名单区块。

## 5. 路由、导航与图标（已确认）

- 底部导航文字由“个人中心”改为“关于”，页面内主标题为“关于本站”；
- 正式地址由 `/profile` 直接改为 `/about`，路由名由 `profile` 改为 `about`；
- 原 `/profile` 占位路由直接删除，不提供兼容重定向；访问 `/profile` 时按普通未知地址进入现有 404 页面；
- 页面目录由 `src/views/profile/` 调整为 `src/views/about/`，页面 Hook 对应改名；
- 原“用户头像”导航图标改为信息类图标，避免继续传达账号功能。

## 6. SEO 与可访问性建议

页面正式上线后应同步处理既有 SEO TODO：

- 浏览器标题建议为“关于本站 | D&D车卡辅助”；
- 路由增加独立 description，例如“了解免费的 D&D车卡辅助工具，获取 B站、GitHub 与 QQ 交流群入口。”；
- `/about` 加入 sitemap 与预渲染清单；robots 不再保留原 `/profile` 占位页限制；
- canonical URL 使用正式 `/about`；旧 `/profile` 不收录；
- 页面使用 `main`、`section`、标题层级和链接等语义化元素；
- 图标与头像提供适当替代文本，纯装饰图标对辅助技术隐藏；
- 主要链接和按钮保持至少 44px 触控区域，键盘焦点清晰，不能依赖悬停查看必要信息；
- 外部链接应明确提示将离开本站，但不建议用频繁弹窗打断访问。

## 7. 非功能要求

- 移动端优先，375px 与 430px 宽度下不得出现横向滚动；
- 页面内容应在无 JavaScript 第三方接口的情况下完整展示；
- 外部图片加载失败时不影响名称、说明和链接使用；
- 不因外部平台数量变化而修改页面模板；
- 所有公开文案、Logo、链接和收款码由站点维护者确认有权展示；
- 不展示用户私有数据，不设置用于该页面业务的 Cookie 或本地持久化数据。

## 9. 验收标准草案

以下验收标准按已确认需求执行：

1. 底部导航不再显示“个人中心”，访问者能从“关于”进入“关于本站”；
2. 页面展示项目简介、永久免费声明、B 站、GitHub、QQ 群和“请杯咖啡”，不出现作者介绍、赞助鸣谢、友情链接或未配置内容的空卡片；
3. B 站和 GitHub 外部链接地址正确、可通过键盘访问、在新标签页打开并带安全关系属性；QQ 群号显示正确且可复制，复制后有用户可见反馈；
4. 页面明确说明本站永久免费、打赏完全自愿且不解锁任何功能或内容；不展示或维护任何打赏者信息、打赏金额与打赏记录；
5. 配置完整时正确显示微信和支付宝收款码；缺少单项配置时只隐藏对应项；两项均缺失时不出现损坏图片；
6. `git ls-files`、待提交变更和最终 GitHub 仓库均不包含真实收款码、`.env.local` 或本地打赏资源目录；
7. 375px 与 430px 宽度下内容无横向滚动，主要操作目标不小于 44px，收款码可查看大图；
8. `/about` 直接访问、刷新和预渲染正常；`/profile` 不再匹配业务路由并进入 404 页面；
9. 页面 title、description、canonical、sitemap、robots 与预渲染配置一致；
10. TypeScript 类型检查、自动化测试和生产构建通过；
11. 页面不引入用户账号、角色草稿读写、站内支付、赞助名单或未确认的第三方接口；
12. 实施完成后复核并同步 `docs/router-layout-requirements.md`、`docs/seo-requirements.md`、`docs/frontend-architecture.md`、README 和必要的版本记录。

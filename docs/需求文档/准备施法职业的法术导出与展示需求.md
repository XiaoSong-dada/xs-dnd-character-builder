# 准备施法职业的法术导出与展示需求

## 1. 背景与目标

用户诉求：牧师等准备施法职业在长休时更换已准备法术，行为上与法师法术书"相似"；期望提供类似法术书的功能（在法术列表中准备与切换），并希望 **PDF 导出全部法术、已准备法术带标记**。

本次任务的产出：考察 2014 规则确认"法术书"机制是否适用于准备施法职业，核实现状交互，整理需求文档（**本次不修改代码**）。

## 2. 规则考察结论（已核验，2014 PHB）

| 施法模式 | 职业 | 规则机制 | 长休行为 |
|---|---|---|---|
| `prepared`（准备施法） | 牧师、德鲁伊、圣武士、游侠 | 直接知晓**整个职业法术列表**，按公式（施法属性调整值 + 等级或半等级）准备子集 | **长休可更换准备列表**，准备来源始终是完整职业列表 |
| `spellbook`（法术书） | 法师 | **学习**法术写入法术书（数量按表），再从书中准备子集 | 长休可从书中更换准备 |
| `known`（已知法术） | 术士、吟游诗人、奥法骑士、诡术师 | 固定已知法术数量，升级时可替换 | 平时不可更换 |
| `pact`（契约魔法） | 邪术师 | 已知法术制 | 平时不可更换 |

**结论：准备施法职业（prepared）在 2014 规则下没有"习得/法术书"中间层**——他们的"全部法术"就是整个职业法术列表（当前可达环级），由候选池动态计算，无需（也不应）持久化一个"法术池"。"类似法师法术书的功能"若指持久化法术池，**与规则不符，不写该需求**；其合理内核是以下两点：

1. **交互**：在法术列表中准备与切换（现状已实现，见 §3）；
2. **导出**：PDF/XLSX 展示全部法术并标记已准备（现状缺失，见 §3，需求见 §4 R1）。

## 3. 现状核实（已读代码）

### 3.1 准备/切换交互：已实现

- **法术步骤**（`SpellcastingStep.vue`）：prepared 模式展示已准备列表与候选池（职业池 − 已准备），可点选切换；
- **角色卡法术页签**（`CharacterSheetStep.vue`）：prepared 模式现有两个区块——"已准备"（每项带"取消准备"按钮）与"可选法术"（按环级分组，带"准备"按钮，数量未满时可准备，满时显示"已满"）；按 R2 将重组为三块布局并新增"全部法术"只读参考块；
- 切换逻辑 `togglePrepare` 与数量上限 `canPrepareMore` 已就绪；数据仍为 `spellSelections.preparedSpellIds`（不引入新持久化字段）。

### 3.2 导出：存在缺口

- `build-export-data.ts` 的 `spellList`：**prepared 模式只导出 `preparedSpellIds`（已准备法术）**，PDF/XLSX 法术表看不到"全部职业法术 + 准备标记"；
- 对照先例：**spellbook 模式（法师）已导出法术书内全部法术，并用 `prepared` 标记区分已准备**（`prepared: prepared.has(id)`）；
- 即用户诉求的"导出全部法术、准备法术带标记"在法师身上已成立，prepared 职业缺失。

## 4. 需求明细

### R1 导出：prepared 模式法术表 = 全部可达职业法术 + 准备标记（核心需求）

- `spellList` 的 prepared 分支改为：**已学戏法（`cantripIds`）+ 全部可达环级职业法术**（`getAvailableSpells`，环级 ≤ 当前最高环，与候选池同源），每项 `prepared: preparedSpellIds.includes(id)`（戏法无准备概念，标记恒为 false）；
- 行为与 spellbook 模式一致：PDF/XLSX 法术表展示完整职业列表，已准备项带标记（PDF 模板既有法术表渲染与容量诊断机制沿用，超容时按既有诊断提示）；
- 已知（known）、契约（pact）模式维持现状（只导出已选法术，2014 规则下无"全列表参考"需求）；
- 导出模型测试补充：prepared 职业导出全部职业池法术（含已学戏法）且标记正确。

### R2 角色卡法术页签：三块式布局（已确认，prepared 与 spellbook 模式）

整体法术卡布局固定为三块：

1. **第一块·已准备法术**：展示当前已准备的法术；每项带"取消准备"按钮；
2. **第二块·未准备法术**：展示已学/已抄录但未准备的法术（prepared 模式 = 可达环级职业列表 − 已准备；spellbook 模式 = 法术书 − 已准备）；每项带"准备"按钮，**准备法术未满时可用**，已满时按钮禁用并提示"已满"；
3. **第三块·全部法术**：只读参考列表，每项可展开查看法术效果，不提供操作；**命名按施法模式区分（已确认）**：
   - prepared 模式（牧师/德鲁伊/圣武士/游侠）标题为"**全部职业法术 · Z**"——这些职业在 2014 规则下没有"书"概念，直接知晓整个职业法术列表，不应称"法术书"；
   - spellbook 模式（法师）保留标题"**法术书 · X / Y**"——法术书是法师的规则实体，称"法术书"没有问题；
   - 内容：prepared 模式 = 已学戏法（`cantripIds`）+ 全部可达 1+ 环职业法术（已确认全列表含已学戏法）；spellbook 模式 = 法术书全部（戏法由独立区展示，不重复）。

交互联动（单向数据流，`preparedSpellIds` 为唯一事实源）：

- 第一块点击"取消准备" → 该法术从 `preparedSpellIds` 移除 → **自动出现在第二块**（未准备）；
- 第二块点击"准备"（未满时） → 该法术加入 `preparedSpellIds` → **自动移入第一块**；
- 三块数量实时联动（已准备 X/上限、未准备 Y、全部 Z）；
- 切换逻辑复用既有 `togglePrepare` 与 `canPrepareMore`，数据仍为 `spellSelections.preparedSpellIds`，不新增持久化字段；
- 与 spells 步骤共享同一候选数据源（`getSpellCandidates` / `getAvailableSpells`）。

### R3 导出排序：已准备法术优先（新增需求）

背景：R1 全列表导出后，prepared 模式法术表可达百项以上；当前排序为“环级 + 名称”（`spellList` 的 `sort`），PDF 法术表按环位分区且容量有限，当某环级法术较多时，该环位格子不足会导致**该环级后段的已准备法术被截断看不到**。

要求：

- `spellList` 排序改为**已准备优先**：`prepared === true` 的法术排在 `false` 之前；组内仍按“环级 + 名称”排序（`left.level - right.level || left.name.localeCompare(right.name, 'zh-CN')`）；
- 排序对 prepared 与 spellbook 模式统一生效（两者均为“全列表 + 准备标记”导出）；known/pact 模式无准备概念（标记恒 false），排序结果与原逻辑等价；
- 目的：PDF/XLSX 按序渲染时，已准备法术始终位于列表前部、优先进入模板容量，**常规情况下必可见**；
- 容量诊断机制（警告可下载、阻断不下载）与截断提示不变。

边界：不保证极端情况（如法术书/职业池中某环级全部为已准备且数量仍超该环位容量时，截断仍可能发生）；不改变法术环位分区渲染逻辑。

## 5. 验收标准

1. 牧师/德鲁伊/圣武士/游侠导出 PDF/XLSX：法术表包含已学戏法与当前可达环级的全部职业法术，已准备项带标记（戏法标记恒 false），数量与 `preparedSpellIds` 一致；
2. 导出容量超限时沿用既有诊断提示（警告可下载、阻断不下载），不新增错误路径；
3. 导出排序：全部 `prepared: true` 的法术排在 `false` 之前（组内按环级 + 名称），导出模型测试断言排序结果；
4. 角色卡法术页签三块布局（prepared 与 spellbook 模式）：第一块已准备（可取消准备）、第二块未准备（未满时可准备、满时禁用提示）、第三块只读参考——prepared 模式标题"全部职业法术"、内容含已学戏法，spellbook 模式标题"法术书"、内容为书内全部；取消准备/准备操作后法术在两块间实时联动，数量与 `preparedSpellIds` 一致，刷新恢复一致；
5. 回归：known/pact 模式导出与展示行为不变；校验与法术步骤不受影响；
6. 测试覆盖：导出模型（prepared 全列表 + 标记 + 排序）、三块布局联动、既有全量回归。

## 6. 范围外（明确不做）

- **不为 prepared 职业引入持久化"法术池/法术书"**（2014 规则下不成立，候选池即完整职业列表）；
- 不改变 `spellSelections` 结构、不新增 schema 字段；
- 不改变 known/pact 模式的导出与展示（规则上无全列表参考需求）；
- 不实现“长休”计时或自动重置逻辑（准备切换为即时交互，持久化即最终状态）；
- 不改变 PDF 法术表的环位分区渲染与容量截断机制（仅调整排序，保证已准备法术优先可见）。

# 角色卡导出重构需求

> 状态：需求草案（2026-08-20）  
> 适用项目：`dnd-character-builder/app`  
> 适用规则集：D&D 5e 2014，1—20 级单职业  
> 重构范围：PDF / XLSX 导出；JSON 导入导出保持现状

## 1. 背景

当前项目已经能够下载 PDF 与 XLSX 文件，但“文件生成成功”不等于“角色数据导出完整”。基于样例角色与参考模板的核验，现状存在以下问题：

- PDF 只填写第一页，第二页人物资料与第三页法术卡未接线；第一页部分坐标错位、文字颜色错误、长文本覆盖模板区域。
- XLSX 模板有 274 个唯一字段映射键，当前数据组装仅输出 53 个键；196 个法术键与 12 个攻击键没有数据来源接线。
- 钱币在草稿中有数据、模板中有显示区域，但 XLSX 字段映射缺少对应键。
- “特性、专长与资源”当前只输出职业名与子职名，没有输出实际职业特性、子职特性和专长。
- XLSX 依赖查看器打开后重算公式，但没有明确的强制重算配置或缓存结果策略，不同查看器可能显示空白或错误预览。
- PDF 与 XLSX 分别组装业务数据，逻辑重复且已经出现字段含义不一致。
- 填充服务遇到缺少映射、缺少工作表或目标不可写时静默跳过，无法发现数据丢失。
- 现有测试主要验证文件可生成、公式仍存在，没有验证字段完整性、版面位置和最终可见结果。

本次重构应解决导出链路的结构性问题，不以继续追加零散坐标和字段特判作为主要方案。

## 2. 重构目标

### 2.1 核心目标

1. 建立唯一、与输出格式无关的角色导出数据模型，作为 PDF 与 XLSX 的共同事实源。
2. 角色草稿和规则层中已经存在的数据，应在模板存在承载位置时完整导出。
3. PDF 三页均按模板用途填充，文本位置、颜色、换行和截断可验证。
4. XLSX 字段映射有明确契约，能够检测未覆盖、重复、无效和不可写字段。
5. XLSX 在 Excel、WPS、LibreOffice 中打开后能够得到一致的核心派生数值。
6. 导出错误必须可诊断，不得继续静默丢弃本应导出的数据。
7. 使用真实样例角色建立端到端回归基线，验证产物内容而不只验证文件格式。

### 2.2 成功标准

- 同一个角色的 PDF、XLSX 与角色卡页面在属性、调整值、熟练加值、HP、AC、先攻、速度、豁免、技能、攻击、施法数值和法术选择上保持一致。
- 样例角色中的 5 个戏法、24 个法术书法术、9 个已准备法术、已装备长棍、10 GP、警觉专长和冲锋者专长均能在适合的导出区域中找到。
- PDF 第二、三页不再与空模板相同。
- XLSX 模板中所有“应由程序填写”的字段都被导出模型覆盖，所有“允许留空”的字段都有明确原因。
- 自动化测试和人工兼容性验收同时通过。

## 3. 范围

### 3.1 本次包含

- 统一导出数据模型与组装逻辑。
- PDF 三页坐标映射、文本布局和填充。
- XLSX 字段映射契约、字段填充和公式重算策略。
- 身份、核心数值、豁免、技能、攻击、装备、钱币、特性、专长、法术与已有备注的导出。
- 导出诊断、错误提示、字段覆盖率检查。
- 单元测试、契约测试、端到端产物测试和视觉核验。
- 必要的模板字段映射补充与模板版本标记。

### 3.2 本次不包含

- 修改 JSON schema 或 JSON 导入导出格式。
- 为导出专门新增年龄、性别、身高、体重、外貌、个性特征、理想、羁绊、缺点、同盟等角色编辑功能。
- 多职业或 D&D 5e 2024 导出。
- 后端生成、云端保存或服务器转换。
- 在导出层重新实现 D&D 规则计算。
- 导出未通过当前角色完整性校验的草稿。

## 4. 数据完整性规则

### 4.1 数据来源优先级

导出数据必须按以下优先级取得：

1. `CharacterDraft`：用户原始选择和文本输入。
2. `DerivedCharacter` 与现有 rules 纯函数：属性、调整值、HP、AC、先攻、速度、熟练加值、豁免、技能、攻击和施法数值。
3. `rulesRepository`：职业、子职、种族、背景、装备、法术、专长和特性的中文展示信息。

模板、页面组件和导出 service 不得自行计算规则结果。

### 4.2 必须导出的数据

#### 身份与核心数值

- 角色名、职业、等级、子职、种族/子种族、背景/背景变体、阵营。
- 六项属性值、六项调整值。
- 熟练加值、被动感知。
- HP 上限、当前 HP 初始值、临时 HP 初始值。
- AC、先攻、速度、生命骰。
- 六项豁免的数值和熟练状态。
- 18 项技能的数值、熟练和专精状态。

当前草稿没有运行中状态时：

- 当前 HP 默认等于 HP 上限。
- 临时 HP 默认 `0`。
- 激励、死亡豁免成功与失败保持空白，不伪造运行中状态。
- 经验值继续按已确认决策填 `0`。

#### 攻击

- 从已装备且可用于攻击的装备生成攻击条目。
- 每条至少包括名称、命中加值、伤害骰、伤害调整值和伤害类型。
- 使用力量、敏捷、灵巧、远程、熟练和特殊装备规则时，必须复用 rules 层结果或新增可测试的 rules 纯函数，不得在导出适配器中猜测。
- 模板容量不足时优先输出已装备攻击；仍超出容量时返回明确的截断诊断。

#### 装备与钱币

- 背包按聚合后的物品名称与数量导出，重复物品应合并或清楚区分来源，不出现无意义的重复文本。
- 输出 CP、SP、EP、GP、PP。
- 已装备状态应在攻击区或装备文本中得到体现。
- 长文本必须按目标区域容量布局；超出时不得覆盖标题、边框或钱币区域。

#### 特性、专长与资源

- 输出当前等级实际获得的职业特性名称。
- 输出当前等级实际获得的子职特性名称。
- 输出已选择专长及属性提升结果。
- 输出种族/子种族特性和背景特性中已有可靠数据的条目。
- 默认输出名称与简要摘要；不得复制项目版权边界外的完整商业规则正文。
- 模板空间不足时按“专长与关键资源优先、自动获得特性其次”的顺序截断，并产生诊断。

#### 法术

- 输出施法职业、施法关键属性、法术豁免 DC、法术攻击加值。
- 输出当前等级的法术位总数；已消耗法术位保持空白或 `0`，不得伪造跑团状态。
- 法术按环级分组。
- 戏法必须输出。
- `known` / `pact` 模式输出已知法术。
- `prepared` 模式输出已准备法术。
- `spellbook` 模式输出法术书全部法术，并用明确标记区分已准备法术。
- 法术名称必须来自仓库中文名，查不到时回退稳定 ID 并产生诊断。

### 4.3 允许留空的数据

下列字段在当前草稿没有数据源时允许留空，不视为导出缺陷：

- 玩家名。
- 年龄、性别、身高、体重。
- 外貌描述。
- 个性特征、理想、羁绊、缺点。
- 同盟与组织。
- 独立的财宝备注。
- 激励与死亡豁免运行状态。

`draft.notes` 继续写入“背景故事”或“备注”区域，不得错误填入其他无数据字段。

## 5. 统一导出模型要求

### R1 唯一导出模型

在 `src/features/character-export/` 内建立格式无关的导出模型，例如 `CharacterExportModel`。模型至少包含：

- `identity`
- `abilities`
- `combat`
- `savingThrows`
- `skills`
- `proficiencies`
- `attacks`
- `inventory`
- `currency`
- `features`
- `spellcasting`
- `profile`
- `diagnostics`

模型应使用明确类型，不使用无约束的 `Record<string, string | number>` 作为业务事实源。

### R2 单一组装入口

- 只允许一个公共组装入口接收 `CharacterDraft` 与 `DerivedCharacter`。
- PDF 和 XLSX 适配器只能消费统一模型，不得再次读取 store、页面状态或自行拼装规则数据。
- `useCharacterBuilderPage` 只负责触发导出和展示错误，不再包含 PDF 字段组装函数。

### R3 诊断结果

组装和适配过程必须能够返回诊断，至少区分：

- `missing-rule-data`：草稿引用的规则 ID 无法解析。
- `missing-template-field`：模型有数据但模板没有承载字段。
- `unsupported-template-field`：模板要求字段但当前产品无数据源。
- `invalid-template-target`：工作表、单元格或 PDF 页面/区域不存在。
- `content-truncated`：内容超过模板容量。
- `formula-not-recalculated`：公式结果无法保证更新。

阻断核心字段导出的错误应终止导出并显示中文原因；允许留空或非关键截断可完成导出，但应在开发环境和测试中可见。

## 6. XLSX 重构要求

### R4 模板字段契约

- “字段映射”表继续作为模板目标位置的事实源。
- 每个字段 Key 必须唯一，每个“工作表 + 单元格”目标必须唯一。
- 模板增加版本标记，运行时只接受兼容版本。
- 字段契约应区分：必填、条件必填、允许留空、公式输出、运行状态字段。
- 补充 CP、SP、EP、GP、PP 和各环法术位总数字段映射。
- 保留现有 196 个法术名称/准备标记映射，并由统一模型填充。

### R5 映射覆盖检查

导出前必须完成：

1. 重复 Key 检查。
2. 重复目标检查。
3. 工作表存在性检查。
4. 单元格地址合法性检查。
5. 必填字段覆盖检查。
6. 模型非空数据无目标检查。
7. 目标公式保护检查。

不得以无提示 `continue` 作为缺少映射的默认行为。

### R6 公式策略

实施时必须选择并记录一种明确策略：

- 优先方案：输入字段写入模板，保留公式，同时设置自动计算、完整重算和打开时重算属性。
- 如目标查看器仍不能稳定显示：为关键公式写入与 rules 结果一致的缓存值，或将关键展示字段改为程序直接写入。

无论采用哪种策略，都必须保证：

- 不覆盖模板要求保留的公式。
- Excel、WPS、LibreOffice 打开后核心数值一致。
- 公式错误扫描不存在 `#REF!`、`#VALUE!`、`#NAME?`、`#DIV/0!`。

### R7 工作簿结构保留

填充后必须保留：

- 6 个现有工作表。
- 合并单元格。
- 下拉验证。
- 公式。
- 行列尺寸、打印区域和样式。
- 中文文本与字体显示。

## 7. PDF 重构要求

### R8 三页完整填充

- 第 1 页：核心数据、战斗、技能、攻击、特性、装备和钱币。
- 第 2 页：身份摘要、已有备注/背景故事；无数据源区域保持空白。
- 第 3 页：施法信息、戏法、1—9 环法术、法术位总数和准备标记。

### R9 坐标映射

- 建立独立、版本化的 PDF 字段/区域映射，不把大量坐标散落在 service 中。
- 每个映射项包含页面、边界矩形、对齐方式、字号范围、颜色、最大行数和溢出策略。
- 坐标必须基于最终运行时模板重新测量；历史逆向值不得未经视觉核对直接复用。
- 属性框的文字颜色必须与实际背景对比可读。

### R10 文本布局

- 支持中文、英文、数字和常见符号混排。
- 单行字段优先缩小字号到允许下限，再截断并标记诊断。
- 多行区域按真实边界换行，不只按固定 12 行截断。
- 文本不得覆盖标题、边框、其他字段或页脚。
- 装备、特性和法术应按语义条目换行，不得按单个字符形成不可读断行。

### R11 PDF 验证

- 输出仍为 3 页，页面尺寸与模板一致。
- 重新打开 PDF 后无损坏。
- 三页均需渲染为图片进行视觉核验。
- 核心字段应通过文本提取或绘制指令检查确认存在。
- 页面 2、3 不得与空模板渲染结果完全一致。

## 8. 架构与模块边界

推荐依赖方向：

```text
views/character-builder/hooks
  -> features/character-export（统一模型、格式适配、诊断）
       -> rules（派生、装备攻击、法术位等纯函数）
       -> types
  -> services/export-pdf（模板加载、PDF 写入、下载）
  -> services/export-xlsx（模板加载、XLSX 写入、下载）
```

约束：

- `services` 只处理文件、模板和浏览器下载边界，不查询职业、法术或装备规则。
- `features/character-export` 可以消费 rules 与 types，但不得依赖 views。
- 新增攻击派生或法术导出规则时，应放入 rules 并有纯函数测试。
- 共享导出类型放在 feature 内；只有出现其他业务调用方时才考虑上提到 `src/types`。
- 所有 `src` 内部导入继续使用 `@` 别名。

实施后必须同步复核并更新 `docs/frontend-architecture.md` 的当前实际拓扑。

## 9. 错误处理与用户反馈

- 模板加载失败、模板版本不兼容、关键字段映射缺失、PDF 页面缺失时禁止下载不完整文件。
- 导出入口应显示进行中状态，避免重复点击。
- 失败提示使用中文，说明用户可以采取的动作，例如“角色卡模板版本不兼容，请刷新页面后重试”。
- 非关键内容被截断时可以下载，但开发环境必须记录字段、原始长度和模板容量；是否向普通用户提示由实施阶段根据频率决定。
- 不在错误信息中泄露本地路径或内部堆栈。

## 10. 测试要求

### 10.1 统一模型单元测试

至少覆盖：

- 非施法职业与施法职业。
- 已知法术、准备法术、法术书和契约法术四种模式。
- 有/无子职、有/无专长。
- 装备攻击、无攻击装备、超过模板攻击容量。
- 钱币全零与混合钱币。
- 熟练、专精、豁免熟练。
- 规则 ID 无法解析。

### 10.2 XLSX 契约测试

- 模板字段 Key 和目标无重复。
- 所有必填及条件必填键均有模型适配。
- 196 个法术映射键可按环级填充。
- 攻击与钱币映射可填充。
- 公式、验证、合并和样式往返后保留。
- 打开时重算配置符合选定策略。
- 公式错误扫描通过。

### 10.3 PDF 测试

- 三页字段映射均被执行。
- 核心文本实际存在于输出内容中。
- 字段矩形不越出页面。
- 长文本产生可预期的换行或截断诊断。
- 三页渲染截图通过视觉检查；对固定黄金样例可使用稳定区域截图回归。

## 11. 兼容性与人工验收

### 11.1 XLSX

在以下软件中实际打开同一黄金样例：

- Microsoft Excel。
- WPS 表格。
- LibreOffice Calc。

逐项核对核心数值、中文、公式结果、法术列表、下拉验证和打印范围。若某查看器存在无法规避的差异，必须记录版本、表现和降级方案，不能仅写“理论兼容”。

### 11.2 PDF

- 在浏览器 PDF 查看器和至少一个桌面 PDF 查看器中打开。
- 按 100% 比例检查三页。
- 执行一次打印预览，确认内容不越出可打印区域。
- 检查小字号中文仍可辨认，属性值不再使用低对比颜色。

## 12. 实施阶段建议

### 阶段一：统一模型与契约

- 建立 `CharacterExportModel`。
- 将 PDF 数据组装从页面 hook 移出。
- 为当前模板生成字段分类和覆盖报告。
- 先补齐黄金样例的纯数据测试，不改模板绘制。

### 阶段二：XLSX

- 补充钱币与法术位映射。
- 接通攻击、特性、钱币和 196 个法术字段。
- 实现模板校验和重算策略。
- 完成三种表格软件兼容性验证。

### 阶段三：PDF

- 重新测量第一页坐标和颜色。
- 建立第二、三页映射。
- 接通攻击、钱币、特性和法术。
- 完成三页视觉回归和打印验收。

### 阶段四：清理与交付

- 删除重复数据组装和失效坐标。
- 收紧导出入口错误状态。

# 种族熟练项接入需求

## 1. 背景与目标

用户反馈：角色熟练项加值目前只计算了**背景与职业**两个来源，**种族提供的熟练项完全遗漏**。要求排查链条、查阅官方文档，并覆盖**项目中已登记的全部种族**（含扩展书），不限于 PHB 核心种族。

排查结论：

- **链条现状**：`app/src/rules/derive.ts`（130 行）`proficientSkillIds = new Set([...draft.backgroundSkillIds, ...selectedClassSkillIds])`——技能熟练只有背景、职业两个来源；来源标注仅"来自背景/来自职业"。
- **数据层**：`RaceRule`（`types/rules.ts` 176—198 行）无任何熟练字段，种族熟练在数据层无法表达。
- **职业数量**：逐职业对照 PHB 2014——吟游诗人 3、游荡者 4、游侠 3、其余 2，**全部正确**；游荡者"专家"专精已实现。
- **背景**：2 项技能 ✓；工具/语言有字段（工具无派生模型）。
- **豁免**：职业 `savingThrowAbilities` ✓；2014 种族不提供豁免熟练。
- **已核验的种族熟练项**：见 2.2 全量清单（以项目已核验的种族 `description` 为线索逐条提取，共 30+ 条）。

目标：为项目中全部提供熟练项的种族接入数据登记、技能熟练派生与自选交互，来源标注"来自种族"；武器/护甲/工具熟练按派生边界登记为展示数据。

### 2.3 官方规则要点（2014）

- 2014 规则**没有"重复熟练替换"机制**：种族与背景/职业技能重叠时无额外收益，也不强制替换（与 2024 不同）——校验只需保证来源合法、数量正确，允许重复但不叠加。
- 工具熟练不参与技能派生（系统无工具检定模型）；武器/护甲熟练影响攻击/护甲派生，但当前攻击模型硬编码"熟练武器"（`derive.ts` 220—222 行），武器熟练来源暂不区分（见非目标）。

## 3. 需求项

### R1 数据层：`RaceRule` 熟练字段与全量登记（必须）

1. `RaceRule` 新增字段：
   - `skillProficiencies?: readonly string[]`（固定技能熟练，如精灵察觉）；
   - `skillProficiencyChoices?: { count: number; optionIds?: readonly string[] }`（自选技能：数量 + 限定列表，`optionIds` 缺省为全部 18 项）；
   - `toolProficiencyChoices?: { count: number }`（工具自选，展示级）；
   - `weaponArmorProficiencies?: readonly string[]`（武器/护甲熟练，展示级）。
2. 按 2.2 清单为 30+ 条种族/子种族登记（A/B/C/D 类）；子种族继承父种族（如精灵子种族继承察觉；`parentRaceId` 关联）。
3. **数据描述补全**：矮人 base `description` 补"矮人战斗训练：熟练战斧、手斧、轻型锤与战锤；工具熟练：自选一种工匠工具"（与地底矮人条目一致）。

### R2 派生层：种族技能熟练并入技能加值（必须）

1. `derive.ts` 熟练集改为三来源：`[...backgroundSkillIds, ...selectedClassSkillIds, ...raceSkillIds]`（种族固定 + 种族自选结果）。
2. 来源标注：种族来源的熟练显示"来自种族"（`detail`），与"来自背景/来自职业"并列。
3. 熟练来源可解释性：角色卡技能来源行可区分三个来源。

### R3 交互层：自选技能/工具选择（必须，全部一次性实现）

1. 草稿新增 `raceSkillChoices?: readonly string[]`（自选技能结果）与 `raceToolChoice?: string`（自选工具结果；兼容旧草稿缺省为空）。
2. 起源步骤（`OriginStep`）在种族含 `skillProficiencyChoices` 时展示选择 UI（复用背景技能选择模式）：限定列表 + 数量上限；**13 处技能自选一次性全部实现**：半精灵（2 项全技能）、变体人类（1 项全技能）、兽人（7 选 2）、肯库（4 选 2）、蜥蜴人（5 选 2）、变形怪（4 选 2）、战俑（1 项全技能）、维达肯（1 项全技能）、吉斯洋基（技能或工具二选一，见下）、米诺陶（威吓/游说 2 选 1）、半人马（驯兽/医药/自然/求生 4 选 1）。
3. **工具自选 UI 本批实现**：战俑、维达肯各 1 项工具熟练、矮人 1 项工匠工具（随描述补全登记）；工具选择结果保存至 `raceToolChoice`，作为展示数据（工具不参与派生，见 R5 TODO）。
4. **吉斯洋基完整二选一**：技能或工具二选一交互（选技能则 `raceSkillChoices` 1 项、选工具则 `raceToolChoice` 1 项），两路互斥。

### R4 校验层（必须）

1. 自选数量校验：`count` 不足/超选报中文错误（与背景技能校验同构）。
2. 选项合法性：所选技能必须在限定列表内（或全列表）。
3. **不实现重复替换机制**（2014 无此规则）：种族与背景/职业重叠时允许，不叠加、不报错（可在来源标注中如实展示）。

### R5 派生边界：武器/工具熟练（数据与选择本批实现，派生标注 TODO）

1. `weaponArmorProficiencies`/`toolProficiencyChoices` 作为种族卡片展开区展示数据（`description` 已含要点，字段用于结构化展示）；工具选择结果 `raceToolChoice` 同样展示。
2. 攻击派生维持"熟练武器"假设（现状），武器熟练来源区分属后续批次（见非目标）。
3. **TODO（后续批次）**：工具熟练参与检定派生——需先建立工具检定模型（当前无）；矮人石工/岩石侏儒工匠知识等特殊 expertise 类检定同理。工具选择本批仅保存与展示，不产生任何数值影响。

### R6 测试（必须）

1. 数据测试：A/B/C 类全部登记项存在且 ID 合法；精灵子种族继承察觉；无重复登记。
2. 派生测试：精灵（+子种族）察觉 +2 熟练加值；半兽人威吓；歌利亚运动；来源标注含"来自种族"；背景+种族重叠不叠加；工具选择不影响任何数值。
3. 自选测试：半精灵选 2 生效、选 3 报错、越权选项报错；兽人限定列表外选项报错。
4. 组件测试：起源步骤自选 UI 展示与 emit（技能自选、工具自选、吉斯洋基技能/工具二选一互斥）；角色卡技能来源显示"来自种族"。
5. 兼容测试：旧草稿无 `raceSkillChoices` 时行为不变（缺省空）。

### R7 文档同步（必须）

1. `docs/rules.md`：种族熟练约定（三来源合并、2014 无重复替换、武器/工具为展示数据）。
2. `docs/dnd-species.md`/种族资料：登记熟练项字段说明。
3. 本文件 6a 登记实施状态；`docs/frontend-architecture.md` 如新增模块登记拓扑。

## 4. 非目标与边界

- **不实现武器熟练来源区分**：攻击派生保持"熟练武器"假设；种族武器训练（精灵/矮人/大地精等）仅展示，后续批次评估。
- **不实现工具熟练派生**：系统无工具检定模型；工具熟练本批仅数据与展示（选择 UI 已实现），参与派生标注 TODO（后续批次需先建工具检定模型）。
- **不实现 2014 重复熟练替换**（2024 才有替换规则）。
- **不处理专长/子职熟练**：`feat-skilled`（熟练专长）、子职效果保持"仅展示不参与计算"既定边界。
- **不实现特殊 expertise 类检定**（矮人石工、岩石侏儒工匠知识、肯库伪造）——无对应检定模型，维持 description 展示。
- 费兹本龙裔、莲沼半身人、苍白精灵等无熟练项的种族不新增任何字段值。

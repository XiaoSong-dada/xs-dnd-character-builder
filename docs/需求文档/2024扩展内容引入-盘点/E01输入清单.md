## 2. 类型改动点（E01-01）

| 文件 | 改动 |

| `app/src/types/character.ts` | `RuleSource` 增加可选字段 `readonly contentKind?: 'official' \| 'playtest'`；缺省视为 `official`，2014 来源与现有 2024 核心来源不填 |

## 3. 来源解析改动点（E01-03）

`app/src/rules/source-books.ts`：

```ts
// 现有
export function isSourceEnabled(sourceIds, enabledSourceIds?, repository?): boolean
export function getSelectableSources()
export function getDefaultEnabledSourceIds()
export function normalizeEnabledSourceIds(ids)
```

目标：

| 函数 | 目标行为 |
| --- | --- |
| `isSourceEnabled` | 保持不变；已支持传入 `repository` 判定核心来源 |
| `getSelectableSources(ruleset?)` | 按规则集返回 `selectable` 来源；缺省 `5e-2014`，保持既有调用行为 |
| `getDefaultEnabledSourceIds(ruleset?)` | `5e-2014` 返回全部可选来源（现状不变）；`5e-2024` 返回 `[]`（D-02 默认全关） |
| `normalizeEnabledSourceIds(ids, ruleset?)` | 按规则集的可选来源白名单过滤；缺省 `5e-2014` |

实现建议：直接导入 `sources2014`／`sources2024` 构造 `ruleset → selectable ID Set` 映射，避免为来源解析引入 `repositories` 依赖。

调用点修正：

| 文件 | 现状 | 目标 |
| --- | --- | --- |
| `app/src/views/character-builder/hooks/useCharacterBuilderPage.ts` `updateSources` | `normalizeEnabledSourceIds(sourceIds)` | 传入 `draft.ruleset` |
| 同文件 `sourceChangeAffectedContent` | `isSourceEnabled(rule.sourceIds, enabledSourceIds)` 未传 repository | 传入 `repositoryFor(draft)`，避免 2024 核心来源被误判为已关闭 |
| `app/src/services/draft-storage.ts` `normalizeDraftSourceIds` | 2024 只去重 | 2024 也按 `normalizeEnabledSourceIds(ids, draft.ruleset)` 规范化；旧 2024 草稿的未知 ID 被过滤、已知 UA 来源保留 |
| `app/src/stores/character-drafts.ts` 两处默认值 | `ruleset === '5e-2014' ? getDefaultEnabledSourceIds() : []` | `getDefaultEnabledSourceIds(ruleset)`（2024 仍为 `[]`，行为不变但逻辑统一） |

## 4. 来源页面改动点（E01-05）

`app/src/views/character-builder/components/SourcesStep.vue`：

1. `selectableSources` 改为按 `props.ruleset` 取 `getSelectableSources(props.ruleset)`，不再对 2024 返回空数组。
2. 保留「核心规则始终启用」提示，核心书名按 repository 解析（2014 为 Basic Rules／PHB 等，2024 为 PHB 2024／DMG 2024）。
3. 2024 追加游玩测试提示：「破解奥秘为官方游玩测试内容，不是正式规则；启用后需 DM 同意。」
4. 可选来源列表按内容性质分组：正式扩展（暂无）与「游玩测试（UA）」；UA 来源渲染统一标记。
5. 保留「全部启用」「只用核心规则」操作与「已启用 n / m」统计；2024 默认未启用任何来源。
6. 关闭来源的非破坏语义与确认弹窗沿用 `useCharacterBuilderPage` 现有流程，不新增交互。

## 5. 游玩测试标记（E01-06）

新增可复用的标记出口，供本批 SourcesStep 与后续内容页面／导出复用：

- 建议在 `app/src/components/ui/` 新增轻量展示组件（如 `UiPlaytestMark.vue`），接受 `contentKind` 或布尔值，输出「游玩测试」文字标记；
- 或先在 `app/src/constants/` 统一文案常量、由 SourcesStep 内联渲染。二选一，实施时以「后续至少还有 3 处复用」为准；默认选组件方案。
- 标记不得只依赖颜色；必须带文字，且与 2014／核心内容视觉可区分。

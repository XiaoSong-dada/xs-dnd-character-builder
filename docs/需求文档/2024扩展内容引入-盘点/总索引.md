研究编号只定义一次，其他文档可引用；已发布编号不因排序变化重排。运行时 ID 用版本化前缀（见 5.3），研究编号与运行时 ID 的映射由各批次实施文档维护。

### 5.2 研究状态

- `待核验`：只有 CHM 目录／标题定位，字段未核对。
- `已核对`：机制字段、等级节点、依赖关系已按 CHM 正文核对。
- `已闭合`：全部字段、依赖、勘误处理完毕，可进入实施。

本盘点除明确标注外均为 `待核验`；E02 起的批次任务负责把关。

### 5.3 运行时 ID 与来源规范

- 来源 ID：`source-2024-ua-<topic>`（正式书到达后为 `source-2024-<book>`）。
- 职业：`class-2024-ua-<slug>`；正式书版本同概念保持同一运行时 ID，不重命名。
- 子职：`subclass-2024-ua-<class>-<slug>`。
- 专长：`feat-2024-ua-<slug>`；法术：`spell-2024-ua-<slug>`；物品：沿用 2024 装备 ID 规范。
- 规范正文写入 `docs/rules.md`「2024 扩展登记约定」，本文件只做登记。

### 5.4 游玩测试标记与完成度口径（E00-05）

- 所有 UA 条目必须携带「游玩测试内容，需 DM 同意」标记，来源关闭或未启用时不可选。
- 完成度沿用 `implemented`／`selectable`／`index-only`；UA 内容最高到 `selectable`（D-07），除非后续决策允许提升。
- 情境效果以原创摘要提示，不进入自动计算；未核验的具体效果不得伪造数值。

## 6. 维护规则

1. 每批实施文档必须引用本盘点的研究编号，并在实施完成后把对应行状态从「待核验／已核对」更新为「已接入」。
2. CHM 升级或正式书上书时，先更新 [来源与修订映射](来源与修订映射.md) 的版本记录，再启动受影响批次的重新核验。
3. 本目录不复制规则书或 CHM 正文，只记录必需的研究字段与原创摘要。
4. 新增、删除或重排研究编号时，同步更新 [子职矩阵](子职矩阵.md) 与 [职业与配套选项](职业与配套选项.md) 的引用。

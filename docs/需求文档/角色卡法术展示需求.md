# 角色卡法术展示需求

## 1. 背景与目标

用户反馈：法系职业创建角色后，角色卡"法术"页签**只显示 0 环（戏法），已选的 1 环以上法术完全不显示**。

上一轮分析已确认根因：**不是数据没保存，而是角色卡组件读取字段与写入侧不一致**。法师（`spellbook` 法术书模式）的准备法术写入 `preparedSpellIds`，规则层读取函数 `getSelectedSpellIds` 也按 `preparedSpellIds` 读取，但角色卡组件只区分 `prepared` 与非 `prepared`，把 `spellbook` 模式误当成 `known` 模式去读空的 `knownSpellIds`，导致法师的高环法术全部丢失展示。

目标产物：

- 修复角色卡法术读取字段 bug：所有施法职业（spellbook / prepared / known / pact 四种模式）的已选法术完整展示在角色卡"法术"页签。
- 展示完善：按环级分组、区分"戏法 / 已准备 / 已掌握 / 在法术书中"状态、法师法术书内容可见。
- 展示逻辑与规则层共用同一事实源（`getSelectedSpellIds`），避免再次出现读取分叉。

## 2. 现状调查（已核验）

### 2.1 数据与规则层（已就绪，无缺口）

| 模块 | 现状 |
|---|---|
| `app/src/rules/data/spells-2014.ts` | 全量法术表；各职业 `classSpellIds` 由该表按职业过滤派生 |
| `app/src/types/character.ts` `SpellSelections` | 4 个字段齐备：`cantripIds`、`knownSpellIds`、`preparedSpellIds`、`spellbookSpellIds` |
| `app/src/rules/spellcasting.ts` `getSelectedSpellIds` | 模式映射正确：`known`→`knownSpellIds`、`prepared`→`preparedSpellIds`、`spellbook`→`preparedSpellIds`、`pact`→`knownSpellIds` |
| `app/src/rules/validate.ts` | `spell-count`、`duplicate-spell`、`unavailable-spell`、`cantrip-count`、`spellbook-count` 校验完备，错误含中文原因与修正指引 |
| `app/src/rules/derive.ts` | 法术攻击 / 法术豁免 DC 派生已接入并展示；**无法术位派生**（法术位登记与展示属后续批次） |
| `app/src/rules/repository.ts` | `getSpell(id)` / `getClass(id)` 可查法术与职业施法配置 |

### 2.2 界面层（缺口定位）

| 界面 | 现状 | 缺口 |
|---|---|---|
| `SpellcastingStep.vue`（施法选择步骤） | 写入侧正确：`prepared`/`spellbook` 模式写 `preparedSpellIds`，其余写 `knownSpellIds`；`toggleSpellbook` 写 `spellbookSpellIds`；计数、分组、失效提示完整 | 无（本需求不改动） |
| `CharacterSheetStep.vue`（角色卡）`selectedSpells`（41–47 行） | 只区分 `mode === 'prepared'` 与非 prepared，非 prepared 一律读 `knownSpellIds` | **`spellbook` 模式误读 `knownSpellIds`（空）→ 法师高环法术不显示，只剩戏法** |
| 角色卡"法术"页签模板（140–155 行） | 平铺 `<li>` 列表，无分组、无状态标注 | 无环级分组；无法术书区块；无"已准备/已掌握/在书中"状态区分 |
| `features/quick-build/components/CharacterDrawer.vue` | 快速车卡摘要抽屉，不涉及法术展示 | 无（本需求不涉及） |

### 2.3 各职业影响矩阵（已核验）

| 职业 | 施法模式 | 写入字段 | 角色卡现读取字段 | 现状 |
|---|---|---|---|---|
| 法师 | spellbook | `preparedSpellIds` + `spellbookSpellIds` | `knownSpellIds`（空） | ✗ **只显示戏法** |
| 牧师 / 德鲁伊 / 圣武士 | prepared | `preparedSpellIds` | `preparedSpellIds` | ✓ 正常 |
| 术士 / 吟游诗人 / 游侠 | known | `knownSpellIds` | `knownSpellIds` | ✓ 正常 |
| 邪术师 | pact | `knownSpellIds` | `knownSpellIds` | ✓ 正常 |

### 2.4 结论

- **bug 单点定位**：`CharacterSheetStep.vue` 41–47 行读取字段与 `SpellcastingStep.vue` 写入侧、`getSelectedSpellIds` 规则函数不一致；仅法师受影响。
- **展示完善缺口**：角色卡法术页签无环级分组、无法术书内容、无状态标注。
- 数据流转本身无问题：`SpellcastingStep` 的 `change` 事件经 `useCharacterBuilderPage.ts`（`store.updateDraft({ spellSelections })`）直接写入，中间无丢失。

## 3. 需求项

### R1 修复角色卡法术读取（必须）

`CharacterSheetStep.vue` 的 `selectedSpells` 改为与规则层共用同一事实源：

1. 戏法：`draft.spellSelections.cantripIds`；
2. 已准备 / 已掌握法术：调用 `getSelectedSpellIds(draft, config)`（内部已按四种模式正确映射，禁止在组件内复制模式判断）；
3. `spellbook` 模式额外纳入 `draft.spellSelections.spellbookSpellIds`（法术书内容，见 R2）。

预期结果：法师角色卡法术页签显示全部戏法与已准备法术；其余职业行为不变。

### R2 角色卡法术展示完善

1. **环级分组**：按 `spell.level` 分组展示（0 环戏法、1 环、2 环……最高环），分组标题显示计数 `已选 / 需要`，计数复用 `getRequiredSpellCount` / `getRequiredCantripCount` / `getRequiredSpellbookCount`，组件不硬编码规则。
2. **法师法术书区块**：`spellbook` 模式展示法术书内容（`spellbookSpellIds`），与"已准备"法术并列，同一法术可同时出现在"在书中"与"已准备"两个状态维度。
3. **状态标注**：prepared 模式标注"已准备"；known / pact 模式标注"已掌握"；法术书中的法术标注"在书中"。
4. **空状态**：无任何已选法术时保留"当前没有需要展示的法术"提示。
5. **失效保留**：沿用现有行为——失效但保留的旧选择（如换职业/降级后）仍展示，不静默删除，与 `docs/rules.md`"旧选择保留并标记失效"原则一致。

### R3（后续，非本批必须）法术位与资源展示

- 当前 `derive.ts` 无法术位派生数据；`docs/rules.md` 约定跑团查看模式优先展示"可用资源（法术位）"。
- 法术位按职业等级表登记与展示（含邪术师契约法术位短休恢复、秘法奥秘等）建议作为后续批次，本需求不阻塞 R1—R2。

## 4. 非目标与边界

- 不修改 `SpellcastingStep.vue` 的写入、计数与校验逻辑（现有实现正确）。
- 不修改 `rules/spellcasting.ts` 规则函数（`getSelectedSpellIds` 映射已正确）。
- 不新增 `CharacterDraft` 字段（现有 4 个 `SpellSelections` 字段已覆盖全部施法模式，保持导入导出兼容）。
- 不实现法术效果正文展示（版权约定：法术只保存选择所需元数据，效果以规则来源为准）。
- 圣武士"誓言法术"、邪术师"秘法奥秘"等"始终准备"类法术登记属后续批次，不在本批。
- 不实现 R3 法术位与资源展示。

## 5. 涉及模块与依赖方向

```text
views/character-builder/components/CharacterSheetStep.vue
  -> rules/spellcasting（getSelectedSpellIds / getRequiredSpellCount / getRequiredCantripCount / getRequiredSpellbookCount）
  -> rules/repository（getSpell / getClass）
  -> components/ui（StatTile / UiBadge；分组样式沿用现有 scoped SCSS）
```

依赖方向不变：`views → rules → types`，rules 保持框架无关；不新增模块，无需调整 `docs/frontend-architecture.md` 拓扑（如新增页面私有组件除外）。

## 6. 验收标准

1. `pnpm test` 全量通过；新增或更新组件测试覆盖四种施法模式（spellbook / prepared / known / pact）角色卡法术展示的数据绑定，其中 spellbook 模式必须断言"戏法 + 已准备法术 + 法术书内容"同时可见。
2. `pnpm build`（含 `vue-tsc -b`）通过。
3. 手机宽度流程验证：
   - 法师 3 级：戏法 3 + 法术书 4 + 准备 2 → 角色卡法术页签按环级分组展示全部已选法术，"在书中"与"已准备"标注正确；
   - 牧师 3 级：戏法 + 准备法术全部可见；
   - 术士 3 级：戏法 + 已知法术全部可见。
4. 变更职业或等级后，失效法术仍保留展示（不静默删除）。
5. 文档同步：如角色卡法术展示行为写入规则约定，同步更新 `docs/rules.md`；更新 `docs/quick-build-implementation.md` 实施状态；交付说明写明"已复核前端依赖拓扑"。

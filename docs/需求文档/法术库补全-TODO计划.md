> 本计划只确定批次、任务、依赖与验收，不修改业务代码，不承诺发布日期与函数签名。

## 1. 使用方式与计划边界

- 工作对象为 `app` 产品项目；不修改原型图项目与 CHM 源文件。
- 每个 `Sxx-nn` 是一个可独立展开的更新任务；实施时必须引用对应编号，并写明范围、不包含项、验证与文档同步。
- 一批只做一类内容：官方来源与 20 条 → EGtW → 第三方（分 3 小批）→ 2024 层 → 收尾；禁止「一次性把 286 条全部录入」的巨型任务。
- 决策未确认时，依赖该决策的 TODO 保持未勾选，并在任务中标注「决策门」。
- 所有批次共享同一规则边界：只登记需求文档 R7 规定的字段（中英文名／环级／职业／来源／原创中文摘要；`ritual` 为必填），不复制 CHM 正文，不把未核验效果接入自动计算。
- 所有批次的共同完成标准：`vue-tsc -b` 通过、相关测试通过、生产构建通过、依赖拓扑复核，并按批同步对应文档。
- 未获得用户明确要求，不执行 `git commit`、`git push` 或分支合并；发布登记只在 S05 由用户确认后执行。

### 1.1 编号与勾选约定

- `Sxx` 为批次，`Sxx-nn` 为可追踪 TODO；细拆沿用父编号加后缀（如 `S03-02a`）。
- `[ ]` 未完成；只有交付物存在且完成标准通过才改为 `[x]`。
- 「已创建更新任务」不等于「TODO 已完成」。
- 决策未确认时，依赖该决策的 TODO 保持未勾选，并标注「决策门」。

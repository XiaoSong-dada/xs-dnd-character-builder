## 4. 每批实施步骤（统一模板）

1. **读原文**：`.chm_output/DND.26.09.13/markdown/<书名>_<章节>_<标题>.md` 逐条读取；**专长名（中／英）、类别、先决、增益与代价条目必须取自原文**，禁止回译或编造（G 批次曾因虚构特性名返工 15 处）。
2. **落类型**：新类别先改 `app/src/types/rules.ts` 的 `FeatCategory`，再改展示层标签映射（`feat-2024.ts` 的类别标签表）。
3. **落数据**：按 `FeatRule` 登记（`id` 命名 `feat-2024-<source>-<slug>` / `feat-2014-...`），第三方专长带 `sourceIds` 指向对应第三方来源；黑暗赠礼类必须在 `detail` 写明**代价**。
4. **接背景**：单一专长填 `originFeatId`；二选一填 `originFeatOptions`（Q1-A）；2014 侧按 Q2-B 只建条目、不自动授予。
5. **跑测试**：断言一律用**覆盖度／下界**写法，复用既有「`originFeatId` 必须可解析」校验，并为 `originFeatOptions` 补同等校验。
6. **更新文档**：本文件第 3 节标记状态，背景主文件补「起源专长」小节。

## 6. 风险与注意

1. **二选一授予（Q1-A）需要改类型+校验+界面**：`originFeatOptions` 会牵动 `validate.ts`、`OriginStep.vue` 的专长展示与既有测试，属本批唯一的**结构性改动**，建议单独一批（G3-A）做完并单独验证。
2. **黑暗赠礼是负面专长**：同时给增益与代价，展示层若按普通专长呈现会误导，`detail` 必须显式写出代价，且不要进入「推荐专长」类派生。
3. **改名牵连面**：龙纹专长改名会影响到高等龙纹／强效龙纹的文本、测试断言与文档；改名前先 `grep` 全仓库「之纹」，一次性替换后跑全量测试。
4. **Q3-B 范围很大**：第三方非背景内容涉及子职（约 40+）与种族（约 30+），远超背景批次。**先普查再补录**，普查报告出来后再确认批次节奏。
5. **不要用「背景」字面搜索判定无背景节**：G2 已证明会漏（`工具熟练项` 写法、2024 写法、书名重复渲染段），TP-1 必须双路复核。
6. **CHM 重复渲染段**：凡疑似新书段落，回到「含 Credits 的书锚点页」核对书名与创作人员，不按相邻 ID 推断。
7. **第三方专长与来源的对应**：新增专长的 `sourceIds` 必须与背景一致（例如斯坦哈德 4 条背景现已双来源登记，其专长归属需与之一致）。

## 3. 每批实施步骤（统一模板）

1. **读原文**：`.chm_output/DND.26.09.13/markdown/<书名>_<章节>_<标题>.md` 逐条读取；**专长名（中／英）、类别、先决、增益条目必须取自原文**，禁止回译或编造（G 批次曾因虚构特性名返工 15 处）。
2. **落类型**：新类别先改 `app/src/types/rules.ts` 的 `FeatCategory`，再改展示层标签映射。
3. **落数据**：按 `FeatRule` 登记（`id` 命名 `feat-2024-<source>-<slug>` / `feat-2014-...`），第三方专长带 `sourceIds` 指向对应第三方来源。
4. **接背景**：把背景的 `originFeatId` 指向新专长；二选一或替代型（鸦阁黑暗赠礼、避世潜藏薄血）需按 §6 Q1 的口径处理（单值字段无法表达二选一，可能需扩展字段或改为「主要项 + 描述说明」）。
5. **跑测试**：断言一律用**覆盖度／下界**写法，并复用既有 `originFeatId 必须可解析` 校验。
6. **更新文档**：本文件第 2 节标记状态，背景主文件补「起源专长」小节。

## 5. 风险与注意

1. **二选一授予**：鸦阁 4 条背景与避世潜藏「薄血」都是「A 或 B 二选一」，而 `BackgroundRule.originFeatId` 是单值。需先定口径（§6 Q1），否则会出现「登记了但语义不对」。
2. **黑暗赠礼是负面专长**：该类专长同时给增益与代价，展示层若按普通专长呈现可能误导，需要在 `detail` 中明确写出代价。
3. **2014 背景授予专长**：2014 侧没有 `originFeatId` 字段，「巨人养子 → 巨人打击」「符文雕刻者 → 符文塑形者」这类是**背景特性说明专长**，需确认是否要为其建专长条目并接入（§6 Q2）。
4. **第三方专长来源**：斯坦哈德与避世潜藏的专长需先确保来源已注册（避世潜藏 / 斯坦哈德已注册，Beyond Drops 已注册）。
5. **不要用「背景」字面搜索判定无背景节**：G2 已证明该做法会漏（`工具熟练项` 写法、2024 写法、书名重复渲染段），TP-1 必须双路复核。
6. **CHM 重复渲染段**：凡疑似新书段落，回到「含 Credits 的书锚点页」核对书名与创作人员，不按相邻 ID 推断。

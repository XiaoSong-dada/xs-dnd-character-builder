## 1. 目标与范围

目标：把 2014 邪术师的魔能祈唤从 **3 条索引**补全为 **54 条全量数据**，按 PHB 职业表建立 7 个分级检查点，等级／魔契／法术先决可校验，译名与新版 CHM 的 **2014 章节**一致；魔契恩泽补齐 4 项。

范围内：

| 域 | 数量 | 内容 |
| --- | ---: | --- |
| 魔能祈唤 | 54 | 32 PHB + 14 XGtE + 8 TCoE：稳定 ID／中英文名／来源／先决／原创摘要 |
| 魔契恩泽 | 4 | 3 条改名（ID 不变）+ 新增「符之魔契」 |
| 检查点 | 7 | 2 级（2 项）、5／7／9／12／15／18 级（各 +1），累计 8 项 |
| 先决字段 | 1 | 新增 `RuleOption.requiredSpellIds`（法术先决，5 条） |
| 授予法术 | 3 | 深海馈赠、诡术师的逃脱术、永恒奴役 |
| 测试与文档 | — | 新增祈唤测试、更新既有测试、`docs/*` 与版本公告同步 |

范围外：2024 侧数据改动（已复核为零差异，仅登记）、祈唤替换交互、TCoE「替换魔能」、UA／第三方来源、祈唤对战斗回合的模拟。

## 3. 设计

### 3.1 数据文件 `invocations-2014.ts`

新增 `app/src/rules/data/invocations-2014.ts`，结构仿 `invocations-2024.ts`：

| 导出 | 内容 |
| --- | --- |
| `invocations2014` | `readonly RuleOption[]`，54 条 |
| `INVOCATION_2014_OPTION_IDS` | 54 个 ID（供测试与检查点复用） |
| `INVOCATION_2014_CHECKPOINTS` | 等级与选择数量表：`[2,5,7,9,12,15,18]` → `[2,1,1,1,1,1,1]` |
| `invocationIdsAt(level)` | 按 `minimumLevel` 筛选候选（仿 `warlock-2024.ts` 的同名函数与 `artificer-2014.ts` 的 `infusionIdsAt`） |

- **ID 口径**：新增条目统一 `invocation-2014-<英文名 slug>`；**保留**旧 ID `invocation-agonizing-blast`／`invocation-devils-sight`／`invocation-mask-of-many-faces` 不改（旧草稿兼容硬约束）。
- **状态**：`status: 'index-only'`，与既有 3 条一致（界面显示「仅索引」徽标，效果不进入自动计算）。
- **来源**：PHB → `['phb-2014-index']`；XGtE → `['xgte-2017-index']`；TCoE → `['tcoe-2020-index']`。三者均已在 `sources-2014.ts` 登记，**不改来源表**。
- **英文名**：54 条全部登记 `englishName`；既有 3 条同步补齐该字段。
- **名称**：2014 侧一律取 CHM 2014 章节译名（`苦痛魔爆`／`千面之脸`／`迷雾幻影`／`坟墓低语`）。

### 3.2 先决字段

| 类型 | 字段 | 条数 | 说明 |
| --- | --- | ---: | --- |
| A 等级 | `minimumLevel` | 20 | 已存在字段 |
| B 魔契 | `requiredOptionIds` | 7 | 已存在字段，值取 `pact-chain`／`pact-blade`／`pact-tome`／`pact-talisman` |
| C 法术 | **`requiredSpellIds`** | 5 | **新增字段**，值为 `['spell-2014-eldritch-blast']` |
| D 组合 | `minimumLevel` + `requiredOptionIds` | 8 | 已存在字段并用 |
| E 诅咒 | `minimumLevel`（5／7）+ 条件写入描述 | 2 | 等级部分**照常硬校验**；后半句「法术**或**特性」降级为 `description` 文本 |

- 在 `app/src/types/rules.ts` 的 `RuleOption` 增加：`readonly requiredSpellIds?: readonly string[]`（附中文注释：引用法术 ID，如 2014 魔能爆系祈唤）。
- **不新增**「择一先决」表达（E 类后半句已确认降级为描述提示）。
- 字段汇总：`minimumLevel` **30 条**（A 20 + D 8 + E 2）、`requiredOptionIds` **15 条**（B 7 + D 8）、`requiredSpellIds` **5 条**、三者全无 **12 条**。

### 3.3 检查点

替换 `arcane-casters-2014.ts` 中的单一检查点 `warlock-2014-invocations-2`：

```ts
// 伪代码（实现时落在 arcane-casters-2014.ts）
const invocationCheckpoint = (level: number, count: number) => ({
  id: level === 2 ? 'warlock-2014-invocations-2' : `warlock-2014-invocations-${level}`,
  level, step: 'timeline', kind: 'class-choice',
  title: level === 2 ? '选择2项魔能祈唤' : '新增魔能祈唤',
  description: '选择尚未掌握且符合等级与先决条件的祈唤；先决不满足时会给出来自校验的说明。',
  required: true, minSelections: count, maxSelections: count,
  optionIds: invocationIdsAt(level),
  uniqueGroup: 'warlock-2014-invocations-known',
})
```

- **保留** `warlock-2014-invocations-2` 的 ID 与 `min/maxSelections: 2`（旧草稿引用）。
- **新增** `warlock-2014-invocations-{5,7,9,12,15,18}`，各 1 项。
- `uniqueGroup: 'warlock-2014-invocations-known'` 实现跨等级不可重复（`validate.ts` 的 `duplicate-option-group` 校验）；先例为 `artificer-2014.ts` 的 `artificer-infusions-known`。
- 候选按来源过滤由 `timeline.ts` 既有逻辑处理（静态 `optionIds` 会经 `isSourceEnabled` 过滤），本批无需额外代码。

### 3.4 校验

| 先决 | 校验点 | 既有实现 |
| --- | --- | --- |
| 等级（A／D） | 已存在 | `validate.ts`：issue id `option-level-<checkpointId>-<optionId>` |
| 魔契（B／D） | 已存在 | `validate.ts`：issue id `option-prerequisite-<checkpointId>-<optionId>`，resolution 为「先选择前置祈唤，或移除该选择。」 |
| 法术（C） | **新增分支** | 在 `requiredOptionIds` 校验之后追加：读取 `draft.spellSelections.cantripIds`，未含目标法术时产出 `option-spell-prerequisite-<checkpointId>-<optionId>`，message「「X」需要先习得戏法：魔能爆。」，resolution「先在法术步骤习得该戏法，或移除该选择。」 |
| 跨等级重复 | 已存在 | `uniqueGroup` → `duplicate-option-group-warlock-2014-invocations-known` |
| E 类 | 等级校验、条件不校验 | `minimumLevel`（5／7）走既有等级分支；「法术**或**特性」仅写入描述 |

- `requiredSpellIds` 的解析走 `rulesRepository.getSpell(id)` 取中文名；ID 缺失时按原 ID 回退显示，避免硬报错。
- 2014 与 2024 校验逻辑共用同一段代码，新增分支对 2024 无影响（2024 无 `requiredSpellIds` 数据）。

### 3.5 授予法术（`grantedSpells`）

仅登记「无需法术位施展一次、每次长休恢复」的 3 条（目标法术均已在 `spells-2014.ts` 中存在）：

| 祈唤 | 法术 | `spellId` |
| --- | --- | --- |
| 深海馈赠 | 水下呼吸 | `spell-2014-water-breathing` |
| 诡术师的逃脱术 | 行动自如 | `spell-2014-freedom-of-movement` |
| 永恒奴役 | 活化死尸 | `spell-2014-animate-dead` |

统一写法：`grantedSpells: [{ spellId, freeCastings: 1, recovery: 'long-rest' }]`。

**不登记**（只写描述，沿用 2024 口径——2024 仅「深海馈赠」登记了 `grantedSpells`）：

- 「随意施展」类 12 条（幽影护甲、野兽之语、星移步法、魔能视界、邪魔活力、千面之脸、万形之主、迷雾幻影、超凡跳跃、穹宇尽视、坟墓低语、卡瑟利之链）——at will 无既有表达；
- 「消耗法术位施展、每次长休后可再施展」类 7 条（惑人低语、恐惧箴言、混沌手下、心灵泥沼、重塑血肉、凶兆符记、五运窃贼）——**不是免费施法**，不属 `grantedSpells` 语义。

### 3.6 摘要口径

- 54 条各写 1—2 句原创中文摘要，含先决与效果要点；不复制 CHM 正文。
- 不得出现「元数据条目」「以规则来源为准」等占位文本。
- E 类在描述中保留「法术**或**特性」的原文条件。
- 魔契恩泽 4 项同步更新 `description`（现状为「获得强化魔宠路线。」等占位式描述）。

### 3.7 魔契恩泽

- 改名：`pact-chain` 链之魔契、`pact-blade` 刃之魔契、`pact-tome` 书之魔契（ID 不变）。
- 新增：`pact-talisman`「符之魔契」，来源 `['tcoe-2020-index']`，`status: 'index-only'`。
- 3 级检查点 `warlock-2014-pact-3`：`optionIds` 增补 `pact-talisman`，`title`／`description` 同步为 4 选项口径。

### 3.8 明确不做

## 9. 第二批（W02）：邪术师祈唤与恩泽的展示优化

- 提出时间：2026-09-19（用户在 v1.5.1 试用中反馈）。状态：**待实施**。
- 决策：**C1——本次只针对邪术师**（不切全职业静态选项分支，不动 2024 与其它职业）。

### 9.1 问题

魔能祈唤与魔契恩泽在时间线上走的是**静态选项分支**，该分支使用 `OptionCard`（纯 `<button>`，无展开区），因此：

- 54 条祈唤 + 4 项恩泽的 `description` 全部平铺，列表又长又难扫；
- 无法在“只看名字”与“读完整效果”之间切换。

同一个 `TimelineStep.vue` 的**其它分支早已使用可展开组件**（职业特性、子职特性、法术候选、武器精通），角色卡能力页签也用同一组件展示特性详情。仅静态选项分支缺这个能力。

### 9.2 目标

时间线上的邪术师**魔能祈唤、魔契恩泽与宗主选择**改为项目封装的 `ExpandableOptionCard`：**折叠态**只显示名称 + 一行省略摘要，**展开态**显示完整详情。

### 9.3 设计

#### 9.3.1 启用方式：检查点展示开关（推荐）

在 `app/src/types/rules.ts` 的 `ChoiceCheckpoint` 新增可选字段：

```ts
/** 候选卡片的展示形式：`card` 为紧凑卡（默认），`expandable` 可展开读取详情。 */
readonly optionPresentation?: 'card' | 'expandable'
```

在 `arcane-casters-2014.ts` 的 `invocationCheckpoint()`、`warlock-2014-pact-3` 与 `warlock-2014-subclass-1`（宗主选择）检查点上置为 `'expandable'`。

> 宗主检查点（`kind: 'subclass'`）的 `optionIds` 由 `timeline.ts` 的 `buildSubclassCheckpoint()` 动态注入，但检查点对象本身来自职业规则，因此新增字段会正常透传，无需改 `timeline.ts`。

- 优点：零外溢（默认值不变，其它职业与 2024 完全不受影响）；将来若要扩到全职业，只需改默认值或批量标记；不在视图里硬写职业 ID 判断。
- 备选（未采纳）：在 `TimelineStep.vue` 里按 `checkpoint.id` 前缀判断，会把职业知识泄露到视图层。

#### 9.3.2 折叠／展开的内容口径

| 位置 | 内容 |
| --- | --- |
| 折叠态标题 | 选项中文名（`RuleOption.name`） |
| 折叠态摘要 | 现有 `description` 的单行省略（含【任意施法】/【被动】/【契约】等标签） |
| 折叠态徒标 | 「仅索引」徒标（`#suffix`，保持现状） |
| **展开态** | 1. **效果详情**：完整 `description`（原创中文转述）<br>2. **先决条件**：由 `minimumLevel`／`requiredOptionIds`／`requiredSpellIds` 生成中文行（如「先决：12 级，刃之魔契」）；无先决时不显示<br>3. **来源行**：英文名 + 出处简写（PHB／XGtE／TCoE），由 `englishName` 与 `sourceIds` 生成 |
| `expandedLabel` | 「祈唤详情」／「魔契详情」／「宗主详情」 |

宗主选择（3 项）的展开内容同样适用，但需先补描述（现状为占位文本「2014邪术师异界宗主索引。」）：一句主题概括 + 1／6／10／14 级特性要点，依据 CHM `3931`（旧日支配者）／`3932`（至高妖精）／`3933`（邪魔），并与已登记的 15 条宗主子职特性保持一致。

效果详情文本**以《5e 不全书》为准确性基准**，章节对应：

| 来源 | CHM 章节 | 条数 |
| --- | --- | ---: |
| PHB 2014 | `3934` | 32 |
| XGtE | `4430` | 14 |
| TCoE | `1307` | 8 |
| 魔契恩泽 | `3931`／`3935`／`1308` | 4 |

**版权边界**（项目硬约束）：详情为**原创中文转述**，不复制规则书正文；CHM 只用作核对事实与数值的依据，不直接粘贴文本。现有 54 条摘要已按此口径撰写，本批只做**逐条回校**（数值、条件、时效、限次是否与 CHM 一致），必要时补全遗漏细节，不扩写为长篇。

#### 9.3.3 附带修复：角色卡「已选选项详情」漏掉已选祈唤与恩泽

现状：`CharacterSheetStep.vue` 的 `selectedOptionEntries` 只收集 `classInfo.features.flatMap(feature => feature.checkpointIds ?? [])`，而 2014 的两个特性**没有 `checkpointIds`**（2024 侧有），导致玩家选完 8 条祈唤 + 1 个魔契后，**角色卡上看不到自己选了什么**。这是第一批的遗漏（当时只对齐了描述文本）。

修复：

- 在 `invocations-2014.ts` 导出 `invocationCheckpointId(level)` 与 `INVOCATION_2014_CHECKPOINT_IDS`（与检查点构建共用同一来源，避免 ID 逻辑分叉）；
- `arcane-casters-2014.ts` 改用该函数生成 ID；
- `class-features-2014.ts` 给 `warlock-2014-class-eldritch-invocations` 挂 `checkpointIds: INVOCATION_2014_CHECKPOINT_IDS`，给 `warlock-2014-class-pact-boon` 挂 `['warlock-2014-pact-3']`。

影响：角色卡「已选选项详情」将与 2024 行为对齐（可展开读详情）；导出（PDF/XLSX）**已在既有「展示类选择」通用管道内**（`class-choice` 属 `DISPLAY_SELECTION_KINDS`），无需修改。

#### 9.3.4 取消索引态（已分析：建议执行）

**用户提议**：这些条目的 `status` 不再用 `index-only`。

**分析结论：提议合理，应改为 `implemented`。** 依据：

1. **项目对 `index-only` 的定义不支持此场景**——`docs/rules.md` 177—181：
   - `implemented`：数据足以参与计算与合法性校验。
   - `selectable`：结构化选择已完整，可保存与导出；情境效果以摘要提示并由桌面裁定。
   - `index-only`：**仅可浏览，缺少必选数据时不可选择**。
   而这些条目已具备全部必选数据（稳定 ID、中英文名、来源、先决条件、经核验的原创摘要），套用「缺少必选数据」在定义上就不成立。
2. **项目内同类条目全部是 `implemented`**（同类先例，非孤例）：
   - 2024 魔契师 28 条祈唤 = `implemented`（效果同样是描述级、不进自动计算）；
   - 2014 超魔 10 项 = `implemented`（超魔效果已明确「不做自动计算」）；
   - 2014 战技与子职选项 73 项 = `implemented`。
   若 2014 祈唤坚持 `index-only`，会成为全项目唯一例外，且与 2024 同概念条目自相矛盾。
3. **顺带解决两个可见问题**：去掉「仅索引」徒标与 `incompatible` 黄色警示态（9.7 登记的「满屏黄色」风险因此消失）；去掉每条已选祈唤产生的 `index-only` warning。
4. **不违反「未经核验的效果不得进入自动计算」**：本批不把任何祈唤效果接入自动计算（仅 3 条已核验的 `grantedSpells` 是结构化的）。

**语义边界（必须写入文档，防止后续误读）**：`implemented` 在本项目里表示「**条目数据完整、可参与选择合法性与结构校验**」，不表示「效果已自动计算」。与超魔、2024 祈唤的口径一致。

**未采纳 `selectable` 的理由**：语义上也说得通（「情境效果以摘要提示并由桌面裁定」），但它仍会保留徒标 + 每条已选选项的 warning，达不到「取消」的目标，且与 2024 祈唤不一致。

**改动范围（限邪术师）**：

| 对象 | 现状 | 改为 | 数量 |
| --- | --- | --- | ---: |
| 魔能祈唤选项 | `index-only` | `implemented` | 54 |
| 魔契恩泽选项 | `index-only` | `implemented` | 4 |
| 宗主选项（`subclass-2014-warlock-*`） | `index-only` | `implemented` | 3 |
| 宗主 `SubclassRule` | `index-only` | `implemented` | 3 |
| 宗主子职特性 | `index-only` | `implemented` | 15 |

> 宗主 `SubclassRule` 与 15 条特性一并处理的理由：否则玩家选完宗主后，角色卡子职特性区块仍显示「仅索引 · 未核验」+ `subclass-index-only` warning，与刚改干净的选项自相矛盾（这 15 条特性已登记真实摘要，情况与祈唤相同）。
>
> **不改**：同文件内法师的 8 个奥术传承仍为 `index-only`（不在本批范围；其特性完整度为另一议题，建议另开批次核查）。

- 不改 2024 侧与其它职业的静态选项渲染（C2 未采纳）；

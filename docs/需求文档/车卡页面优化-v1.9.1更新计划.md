> 制定日期：2026-09-21。依据需求：[《车卡页面优化需求（v1.9.1）》](车卡页面优化-v1.9.1需求.md)（R1—R3、D1—D6 已确认）。

## 1. 目标与范围

**目标**：按需求 R1—R3 完成三处页面优化——① 种族／背景完整目录与搜索结果的推荐优先排序；② 法术步骤筛选行在车卡容器（32rem）内自适应，消除 iPad／Windows 横向溢出；③ 吸底区结构修复（当前角色框不再被未完成提示遮挡）并统一两步的「去完成」行为。

**范围内**：

| 域 | 内容 |
| --- | --- |
| 规则层 | `app/src/rules/recommend.ts` 新增推荐优先的稳定分区纯函数（R1-5） |
| 页面 | `OriginStep.vue`（候选排序 + 聚焦出口）、`SpellcastingStep.vue`（筛选行样式 + 聚焦出口）、`index.vue`（吸底栏动作接线） |
| 外壳 | `features/quick-build` 的 `QuickBuildShell.vue`（吸底结构）、`StickyActionBar.vue`（动作按钮化） |
| 页面私有类型/hook | `views/character-builder/selection-task.ts`（聚焦句柄接口）、`hooks/useSelectionTaskFlow.ts`（切换 + 聚焦） |
| 测试 | 规则单测、OriginStep/法术步骤组件测试、新增外壳与吸底栏契约测试 |
| 文档 | `docs/rules.md`、`docs/dnd-species.md`、`docs/dnd-backgrounds.md`、`docs/quick-build-implementation.md`、需求文档实施状态 |
| 版本 | `CHANGELOG.md`、`app/src/constants/update-notices.ts`、`app/package.json` → `1.9.1` |

**范围外**：规则数据、派生计算与校验口径；第 8 步任务派生与筛选维度；职业列表／法术候选／角色卡／跑团助手的既有排序；其它 10 个步骤的版心与视觉；原型图项目；人工点击与浏览器视觉验收（按 AGENTS §修改流程 10 不作为完成条件）。

**实施前基线（2026-09-21 实测）**：

- 版本 `1.9.0`（`app/package.json`）。
- `cd app && npm run test:run`：**160 个测试文件 / 1398 项全部通过**（78.6s）。
- 现状事实：`app/test/rules/recommend.test.ts` **已存在**（4 项，覆盖成长速览与推荐理由）；无 `QuickBuildShell`/`StickyActionBar` 测试；`builder-step-tasks` 锚点仅被 `index.vue` L251 引用。

**决策门**：无。需求 §5 的 D1—D6 已全部确认，可自 P1 起直接开工；实施中若发现与需求冲突的事实，先回报再改需求文档，不自行扩大范围。

## 3. 逐批任务

### P1 种族／背景推荐优先排序（R1）

**目标**：完整目录（查看全部）与搜索／来源筛选结果统一「推荐分组在前，其余沿用规则库登记顺序」，组内不乱序。

- [x] **P1-01 规则层纯函数**（`app/src/rules/recommend.ts`）
  - 语义：稳定分区——`recommendedClassIds.includes(classId)` 的条目在前，其余在后；两组内部均保持入参顺序；`classId` 为空时返回入参顺序；不修改入参。
  - 约束：泛型只约束 `{ id: string; recommendedClassIds: readonly string[] }`；不得使用 `localeCompare` 或按名称排序；保持框架无关（不依赖 Vue／Pinia／DOM）。
  - 交付物：函数 + 注释（注明沿用「推荐只用于排序、不限制选择」基线）。
  - 完成标准：`npx vue-tsc -b` 通过；P1-03 单测全绿。
- [x] **P1-02 OriginStep 接入**（`OriginStep.vue`）
  - `filteredRaces`／`filteredBackgrounds` 保持过滤职责；新增「排序后的候选池」，`visibleRaces`／`visibleBackgrounds` 的 `full` 分支（查看全部／搜索／来源筛选）改用排序后的池。
  - 保持不变的语义：`recommendedRaces`／`recommendedBackgrounds` 仍取推荐前 6 项；无推荐时取前 6 项；`item.id !== raceId/backgroundId` 隐藏当前已选项；「查看全部 N 项」计数与已选摘要卡。
  - 完成标准：既有 `OriginStep.test.ts` 的 11 项用例全部通过（回归默认 6 项视图、搜索与动态任务行为）。
- [x] **P1-03 测试**
  - 扩展 `app/test/rules/recommend.test.ts`：① 2014 种族（战士视角）推荐项全部在前、其余顺序与入参一致；② 2024 物种同构；③ 2014 与 2024 背景各一组同构；④ `classId` 为空时顺序不变；⑤ 空数组与「无推荐命中」时顺序不变；⑥ 入参未被修改（与 `slice()` 快照比对）。
  - 扩展 `app/test/components/OriginStep.test.ts`：传 `classId` 后点「查看全部」，前 K 张卡片全部带「推荐」徽标、第 K+1 张起相对顺序与规则库一致；**K 由测试内独立按规则数据计算，不复用被测排序函数**（避免同义断言）。
  - 完成标准：撤销 P1-02 的排序接入后新增断言失败（可验证断言有效性）。
- 风险：某职业命中较多推荐项时完整目录会出现较长的推荐块——属 D1 预期，不设上限。

### P2 法术筛选行容器自适应（R2）

**目标**：法术步骤内容（含筛选行）在 32rem 车卡容器内自适应，不再以视口宽度决定列数。

- [x] **P2-01 筛选行改写**（`SpellcastingStep.vue` 的 `&__filters`）
  - 列定义改为容器内自适应：`repeat(auto-fit, minmax(min(100%, 9rem), 1fr))`（与 `AboutLinksSection`／`TipQrSection` 既有的 `minmax(min(100%, …), 1fr)` 写法一致）；搜索框 `grid-column: 1 / -1` 独占整行。
  - 删除 `@media (max-width: 760px)` 与 `@media (max-width: 430px)` 两个视口断点。
  - 保留控件 `min-height: 2.75rem` 与 `select` 的 `min-width: 0`；SCSS 保持嵌套，不新增顶层平铺选择器。
  - 完成标准：源码中筛选行不再含视口断点与固定 rem 最小列宽；筛选控件数量随元数据条件增减时布局稳定。
- [x] **P2-02 源码契约测试**（新增 `app/test/components/SpellcastingStepFilters.test.ts`）
  - 读取 `SpellcastingStep.vue` 源码，按花括号配对提取 `&__filters` 规则块（参照 `app/test/components/ui/ExpandableOptionCard.test.ts` L101—113 的源码契约写法）。
  - 断言：块内无 `@media (max-width`；`grid-template-columns` 不含未包在 `min(` 内的 `minmax(<数字>rem`；块内含 `min-height: 2.75rem`；`select` 规则含 `min-width: 0`。
  - 断言 `QuickBuildShell.vue` 仍为 `width: min(100%, 32rem)`（锁定容器口径，防顺手加宽）。
  - 完成标准：把视口断点或固定最小列宽写回去会让测试失败。
- [x] **P2-03 排版口径入文档（D6）**（`docs/rules.md`）
  - 在 UI／界面约定处补一条：固定宽度单列容器内的多控件筛选行必须按容器宽度自适应，禁止以视口 `max-width` 断点切列或使用固定 rem 最小列宽。
  - 完成标准：条文与实现一致，对应需求 R2-8。
- 风险：`auto-fit` 使列数随容器变化，筛选行行数可能变化——属预期；320px 极窄容器由 `min(100%, 9rem)` 兜底不溢出。

### P3 吸底结构与「去完成」统一（R3）

**目标**：当前角色框在任何提示行数下都不被吸底栏覆盖；起源与法术两步的「去完成」统一为「切换到首个未完成任务 + 聚焦任务标题」。

#### P3-A 吸底结构（D3）

- [x] **P3-A1 外壳结构**（`QuickBuildShell.vue`）
  - 新增 `.quick-build-shell__bottom` 容器包裹 `__drawer` 与 `__actions`（保留各自插槽与类名）；`position: sticky; z-index: 5; bottom: 0` 移到该容器。
  - 删除 `&--drawer#{&}--actions &__drawer { bottom: 4.75rem; }` 常量让位。
  - **保持 `position: sticky`（在流内）**，不得改为 `fixed`／`absolute`（改为脱离文档流就必须再加永久占位与留白补偿，正是本次要消除的不一致来源）。
  - 三档 `padding-bottom`（6.5／6／10.5rem）重新校准为「与吸底区无关的呼吸留白」：可统一为固定值或保留现状，但必须保证滚到底部时最后一条内容完整可见。
  - 覆盖四种插槽组合：仅 drawer、仅 actions、两者都有、两者都无（`step === 'sheet'`）。
  - 完成标准：DOM 中 drawer 与 actions 为同一容器内相邻兄弟；源码无 `bottom: 4.75rem` 让位常量。

#### P3-B 「去完成」统一（D4）

- [x] **P3-B1 吸底栏动作按钮化**（`StickyActionBar.vue`）
  - `helperHref` 改为 `helperAction?: boolean`；渲染 `<button type="button" class="sticky-action-bar__action">去完成</button>` 并 `emit('helperAction')`。
  - 提示行改为 flex 行（`align-items: center` + `gap: 0.35rem`），避免 2.75rem 触控区在段落行内造成错位；动作样式与 `OriginStep.__jump` 对齐（主色、下划线、键盘焦点态），触控目标 ≥2.75rem；`helperText` 与按钮布局不变。
- [x] **P3-B2 页面私有聚焦句柄**（`views/character-builder/selection-task.ts`）
  - 新增页面私有接口 `SelectionTaskFocusHandle { focusFirstIncomplete(): void }`，供步骤组件 `defineExpose` 与页面 ref 共用（避免在 `index.vue` 内联类型）。
- [x] **P3-B3 步骤组件暴露出口**（`OriginStep.vue`、`SpellcastingStep.vue`）
  - `defineExpose<SelectionTaskFocusHandle>({ focusFirstIncomplete: flow.focusFirstIncomplete })`；起源步骤页面内既有的 UiNotice「去完成」按钮保持不变（两条入口同源）。
- [x] **P3-B4 hook 支持重复点击**（`hooks/useSelectionTaskFlow.ts`）
  - `focusFirstIncomplete` 改为「切换 + 显式聚焦」：`selectTask(next.id)` 后始终 `void nextTick(() => heading.value?.focus())`（任务 ID 未变化时也要有反馈，R3-7）。
  - 与既有 `watch(activeTaskId)` 的聚焦二选一（保留其一或确认无重复聚焦抖动），实施时在代码注释中登记选择。
  - **实施发现（缺陷修复，超出原计划但属 R3-6 前置）**：v1.9.0 的 `ref="flow.heading"` 是嵌套字符串 ref，只会写入 `$refs['flow.heading']`，不会回填 hook 内的 `heading` ref，因此**任务标题聚焦从未生效**（切换与滚动正常，聚焦静默失效）。修正方式：`useSelectionTaskFlow` / `useSpellcastingStepFlow` 接受调用方传入的 `headingRef`，两个步骤组件改用本地 `ref="headingEl"` 并传入；`watch(activeTaskId)` 的自动聚焦与「去完成」聚焦因此同时恢复。
- [x] **P3-B5 页面接线**（`views/character-builder/index.vue`）
  - `const activeStepRef = ref<SelectionTaskFocusHandle | null>(null)`；`function focusIncompleteTask(): void { activeStepRef.value?.focusFirstIncomplete() }`。
  - `OriginStep`／`SpellcastingStep` 挂 `ref="activeStepRef"`（`v-else-if` 保证同时只挂载一个）；吸底栏改为 `:helper-action="!canContinue && (step === 'origin' || step === 'spells')"` 与 `@helper-action="focusIncompleteTask"`。
  - `index.vue` 不新增业务状态、生命周期或副作用（仅组装与 UI 动作转发）。
- [x] **P3-B6 不变量登记（R3-9）**
  - 法术步 `tasks` 为空 ⇔ `canContinue` 为 `true` ⇒ 不显示提示行；起源步 `tasks` 恒非空 ⇒ 动作目标恒存在。以注释登记该不变量，并由 P3-C 的用例固定。
  - `SelectionTaskNavigator.vue` 的 `id="builder-step-tasks"`：**保留**（已确认无其它引用，但保留可作稳定锚点与测试选择器；吸底栏不再使用它）。
- 完成标准：两步点击吸底栏「去完成」后活动任务切到首个未完成项且标题获得焦点；重复点击仍有反馈；源码不再出现 `helperHref` 与 `#builder-step-tasks` 锚点。

# 车卡法术与专长编辑协调更新计划

- 对应需求：[《车卡法术与专长编辑协调需求》](车卡法术与专长编辑协调需求.md)
- 制定日期：2026-09-29
- 状态：实施中（F01—F02 已完成，F03 待实施）
- 目标版本：建议 `v1.11.0`，最终以实施时版本线为准

## 1. 计划结论

本轮按 6 个批次实施：

1. 固定授予的“魔法学徒”生成完整的法术表、戏法、1 环法术和关键属性选择任务；2014 版魔法学徒在同轮独立补齐。
2. 更换职业或降低等级时主动协调既有法术；失效项进入可追溯的停用记录，不再阻塞创建，也不直接丢失。
3. 首次创建 18／20 级法师时，精通／招牌法术允许先选，并与后续法术书联动且计入正常学习额度。
4. 角色卡编辑状态的能力页可手动添加专长；结构化效果自动生效，未结构化效果只展示并警告。

实施顺序：

`F01 数据契约 → F02 法术协调 → F03 魔法学徒 → F04 高等级法师 → F05 手动专长 → F06 联验发布`

F03—F05 在 F01 后可以并行开发，但合并验收仍按上述顺序，避免多套选择实例和迁移逻辑并行演化。三项产品决策均已确认，当前没有待确认问题。

## 2. 已确认产品决策

| 编号 | 决策 | 实施约束 |
| --- | --- | --- |
| D-01 | 失效法术进入“停用记录” | 不参与规则、校验、角色卡和常规导出；JSON／ZIP 保留；恢复必须由用户显式操作。 |
| D-02 | 手动专长“结构化效果自动计算，未结构化只展示” | 可复用现有结构的效果自动生效；只有说明文本的效果不猜测数值。 |
| D-03 | 2014 版魔法学徒同轮补齐 | 与 2024 共用授予实例框架，但按 2014 规则单独建模、单独测试。 |

## 3. 范围与非目标

### 3.1 本轮范围

- 产品目录固定为 `app/`，不修改“跑团车卡辅助”原型项目。
- 角色创建、重新编辑、角色卡能力页、规则派生、草稿存储、JSON／ZIP 往返及相关导出。
- 2014／2024 两个规则版本中受影响的背景、专长和法师节点。
- 旧草稿无损迁移、单元测试、组件测试、关键路径验收、构建和文档同步。

### 3.2 本轮不做

- 不为全部自然语言专长补写通用规则引擎。
- 不支持任意名称和任意规则文本的自定义专长，只从当前规则版本的专长仓库添加。
- 不让停用法术参与已知、准备、法术书、免费施法或资源结算。
- 不自动恢复历史法术；规则重新满足时只提供恢复入口。
- 不改变职业法术数量、法术位或专长规则本身。

## 4. 数据与架构基线

### 4.1 草稿 schema v9

新增数据需要持久化，建议将 `CharacterDraft.schemaVersion` 从 `8` 升为 `9`：

- 本地存储键升级到 `dnd-character-builder:drafts:v9`，读取 v8 后规范化写入 v9。
- JSON 支持 v2—v9；既有规则版本隔离约束保持不变。
- v8→v9 为无损补字段迁移，停用记录、手动专长和法术书预留默认空。
- v2—v7 继续走现有迁移入口再落到 v9，不绕开旧 2024 草稿限制。
- ZIP 内角色 JSON 与独立 JSON 使用同一契约。

建议结构如下，命名可在 F01 中按现有类型风格微调：

```ts
interface InactiveSpellSelection {
  id: string
  spellId: string
  originalBucket:
    | 'cantripIds'
    | 'knownSpellIds'
    | 'preparedSpellIds'
    | 'spellbookSpellIds'
    | 'transcribedSpellIds'
    | 'spellbookExtraSpellIds'
    | 'manualAddedSpells'
  reason: 'class-changed' | 'level-reduced' | 'source-removed' | 'user-archived'
  sourceKey?: string
  invalidatedAt: string
}

interface ManualFeatGrant {
  instanceId: string
  featId: string
  addedAt: string
  note?: string
}

interface SpellSelections {
  spellbookReservedSpellIds?: string[]
}

interface CharacterManualEdits {
  addedFeats?: ManualFeatGrant[]
}

interface CharacterDraft {
  inactiveSpellSelections?: InactiveSpellSelection[]
}
```

### 4.2 统一“专长授予实例”

背景固定授予、用户选择授予和手动添加都生成专长授予实例。实例至少包含稳定的 `instanceId`、`featId`、来源类型和来源标签。子选项以 `instanceId + choiceId` 保存和校验，不能只以 `featId` 为键，否则重复获得可重复专长时会互相覆盖。

系统实例 ID 由规则版本、来源类型、背景／等级节点及专长 ID 确定性生成；手动实例使用新建 ID。只读规则入口可以继续按 `featId` 聚合，但选择和编辑操作必须使用实例 ID。

### 4.3 停用历史与有效规则分层

规则层只消费有效选择。停用记录不进入创建校验、能力／法术派生、法术位、免费施法、跑团资源、角色卡法术列表和 PDF／XLSX；JSON／ZIP 保留。重新编辑页提供查看、删除和满足当前规则时的显式恢复操作。

## 5. F01：数据契约、迁移与授予实例

### 5.1 任务

1. 扩展 `CharacterDraft`、`CharacterManualEdits`、`SpellSelections` 及默认值和规范化函数。
2. 新增授予实例类型，扩展现有 `FeatGrant` 来源，至少区分背景、职业／等级和手动添加。
3. 固定背景专长映射为稳定实例；子选项未完成不影响实例本身存在。
4. 实现 schema v9 本地存储和 JSON 迁移，处理缺省、去重和无效记录。
5. 将角色重置、replace、导入和默认草稿纳入新字段处理。
6. 更新 JSON／ZIP 序列化与兼容错误文案。

### 5.2 预计文件

| 领域 | 预计文件／目录 | 变更重点 |
| --- | --- | --- |
| 草稿类型 | `app/src/types/character.ts` 及关联类型 | schema v9、新字段、授予实例 |

文件名以实施时仓库为准。若新增独立规则模块，必须同步 `docs/frontend-architecture.md` 的依赖拓扑。

### 5.3 验证与门槛

- v8 草稿迁移后业务字段不变，新字段为空。
- v9 JSON／ZIP 再导入后完整保留新增数据。
- v2—v7 原有兼容测试继续通过。
- reset 清除新增手工数据，replace 不遗漏新增字段。
- schema、存储、JSON、ZIP 测试全绿，后续批次不再追加临时顶层字段。

## 6. F02：职业／等级变化后的法术协调

### 6.1 协调器

建议新增纯规则模块 `app/src/rules/spell-selection-reconciliation.ts`，输入旧草稿、新构筑上下文和法术仓库，输出：

- 仍有效的 `SpellSelections`；
- 转入停用记录的项目与原因；
- 当前合法但超出数量的待处理项目；
- 当前可恢复的历史项目；
- 面向 UI 的变更摘要。

协调器由角色状态变更入口调用，不反向依赖页面组件。`spellcasting` 等基础规则不依赖协调器，以避免循环依赖。

### 6.2 规则

更换职业时：

- 原职业来源的戏法、已知、准备、法术书和抄录法术转为 `class-changed`。
- 背景、种族、专长和明确手动添加的独立来源法术按其来源重新校验，不随职业法术一并清除。
- 新职业为非施法职业时，旧职业法术立即退出有效 JSON 和最终校验。
- 切回原职业只展示可恢复项，不自动恢复。

降低等级时：

- 当前等级无法施放／学习的高环法术转为 `level-reduced`。
- 仍合法但数量超过新上限时，不由系统猜测删除对象；低等级页面展示清单，由用户选择归档。
- 准备法术超过上限走同一交互；不得要求用户先升回高等级。
- 与高等级能力绑定且来源消失的法术按 `source-removed` 处理。

恢复与删除时：

- 候选、等级、数量和重复校验均通过后才可恢复。
- 恢复回原 bucket；原 bucket 已不适用时引导走当前正常添加入口。
- 删除停用记录只删除历史，不影响有效选择。

### 6.3 UI 与测试

- 变更后显示非阻塞摘要，如“3 个原法师法术已移入停用记录”。
- 法术步骤新增停用记录折叠区，展示原因、恢复和删除状态。
- “合法但超额”提供当前页可操作清单。
- 最终校验不再引用已停用法术。

| 场景 | 预期 |
| --- | --- |
| 法师→战士 | 职业法术停用，战士可继续创建 |
| 法师→牧师 | 原法师法术停用，独立来源法术保留 |
| 10级→3级 | 高环法术停用，不阻塞低等级流程 |
| 降级后仍合法但超额 | 在当前页选择归档 |
| 再升回原等级 | 可恢复但不自动恢复 |
| JSON／ZIP | 有效选择和停用历史稳定 |
| PDF／XLSX | 只输出有效法术 |

覆盖 2014／2024、已知施法、准备施法、法术书施法和非施法职业。完成后不得再存在“先升回高等级才能删除”或“转为非施法职业仍被旧法术阻塞”的路径。

## 7. F03：固定背景魔法学徒与 2014 数据

### 7.1 通用实现

1. 背景数据允许固定 `originFeatId` 携带预设选择（如法术表）和仍需用户完成的子选项。
2. `buildBackgroundFeatCheckpoints` 为固定专长生成实例和子任务，不再只处理可选专长。
3. `buildFeatChoiceCheckpoints` 接收授予实例，并按 `instanceId + choiceId` 保存。
4. 固定预设项只读展示；戏法、1 环法术和施法属性按规则开放。
5. 未完成子任务进入检查清单且可跳转；完成后在回顾页和角色卡回显。
6. 已知／始终准备／免费施法等效果仍由统一规则层派生。

### 7.2 2024 魔法学徒

- 为固定背景写入正确的奥术／神术／原初法术表预设。
- 开放规则要求的戏法、1 环法术和施法属性选择。
- 验证免费施法、常规法术位再次施放和来源标签。
- 切换背景时清理失去来源的实例选择，不能污染新背景。

### 7.3 2014 魔法学徒

- 建立结构化的法术列表、戏法和 1 环法术选择定义。
- 按 2014 规则处理法术表、施法属性、免费施法和法术位再次施放，不照搬 2024 行为。
- 固定授予与主动选择共用实例框架，但分别测试。
- 实现口径同步到 `docs/dnd-feats.md`。

### 7.4 完成门槛

- 所有固定授予魔法学徒的背景都有完整选择入口。
- 预设法术表不可改成其他表，必选子项可由最终检查定位。
- 同一角色的多个可重复实例互不覆盖。
- 2014／2024 候选、资源和说明互不串版。

## 8. F04：18／20 级法师首次创建联动

### 8.1 候选口径

- 已有法术书的升级／重新编辑：候选仍严格来自有效法术书。
- 首次创建 18 级以上且法术书尚未建立：精通候选临时来自符合环阶和职业限制的法师法术表。
- 首次创建 20 级：招牌法术使用同样的启动逻辑，并遵守自身环阶与数量。
- 不能只靠“法术书为空”判断首次创建，应结合草稿状态和既有选择，避免清空法术书后绕过限制。

### 8.2 联动规则

1. 精通／招牌选择写入 `spellbookReservedSpellIds`。
2. 法术书页把预留项标为“由法术精通／招牌法术预留”，默认已选，不能被普通批量清除。
3. 预留项计入正常学习总数，不额外赠送名额。
4. 更换能力选择时释放旧预留；若旧法术有其他合法来源则不误删。
5. 降级、转职或失去能力时，交给 F02 协调器处理。
6. 最终校验保证精通／招牌法术确实位于有效法术书。

UI 提示该选择会加入法术书并占用正常名额；法术书步骤展示预留来源和剩余数量。

### 8.3 测试与门槛

- 2014／2024 首次 18 级法师可先选精通再完成法术书。
- 2014／2024 首次 20 级法师的精通和招牌均联动。
- 预留只计数一次，重复和多来源不造成重复。
- 更换选择后旧预留正确释放。
- 既有角色重新编辑时不把候选扩大到整个职业表。
- 首次高等级法师可按现有页面顺序完成，且不能额外获得法术。

## 9. F05：能力页手动添加专长

### 9.1 入口与编辑

- 仅在角色卡编辑状态的能力页显示“添加专长”。
- 弹窗支持名称搜索、来源／类别筛选、规则版本标识和详情预览。
- 候选限定为当前规则版本仓库中的专长；未开放或跨版本条目不进入候选。
- 作为 DM／手工修正，先决条件只警告、不硬阻塞。
- 添加后创建独立 `ManualFeatGrant`，来源显示“手动添加”。
- 有子选择的专长立即进入配置；未完成前作为编辑待办。
- 可重复专长允许多实例且配置隔离；不可重复专长阻止重复获得。
- 移除只影响该手动实例，确认前展示将失去的结构化效果摘要。

### 9.2 自动生效边界

已有结构化数据时自动参与计算：

- 属性、技能、工具、语言等派生；
- 法术、戏法、始终准备与免费施法；
- 已结构化的资源、次数、动作和修正；
- 现有选择检查点能表达的子选项。

以下只展示，不推断数值：

- 仅有说明文本的效果；
- 规则引擎尚未支持的条件、触发器或替换计算；
- 明确标记为索引／展示用途的数据。

UI 显示“部分效果仅供查阅，未自动计入角色数据”，并区分已生效和仅展示部分。

### 9.3 规则、导出与测试

- `listFeatGrants`／`listActiveFeats` 纳入手动实例并保留来源。
- 派生、法术授予、免费施法和跑团资源消费统一授予列表，不在页面重复计算。
- JSON／ZIP 保留实例与配置；PDF／XLSX 输出有效专长和“手动添加”来源，不输出内部 ID。
- 测试无子选项结构化专长、有子选项专长、魔法学徒、未结构化专长、先决条件警告、重复限制和往返保存。

完成后用户可在能力页添加、配置和移除专长；结构化效果与系统专长走同一规则层，未结构化效果不产生虚构数值。

## 10. F06：整体验收、文档与发布

### 10.1 关键路径

1. 2024 固定魔法学徒背景 → 完成选择 → 创建 → 免费施法 → JSON 往返。
2. 2014 魔法学徒 → 完成子选择 → 角色卡与导出核对。
3. 首次高等级法师 → 精通／招牌 → 法术书联动 → 创建成功。
4. 高等级法师降级 → 高环法术停用 → 低等级直接完成编辑。
5. 施法职业转非施法职业 → 职业法术停用 → 背景／专长法术保留。
6. 能力页手动添加结构化专长 → 派生生效 → 移除回退。
7. 添加未结构化专长 → 只展示警告 → 导出来源正确。
8. v8 草稿打开、保存为 v9、再次打开和导出，无业务数据丢失。

### 10.2 自动化验证

在 `app/` 下执行当前已存在的脚本：

```powershell
npm run test:run
npm run build
```

其中 `npm run build` 已包含 `vue-tsc -b` 类型检查；还需运行受影响模块的定向测试。新增中文文本后执行字体字符检查，发现缺字再更新字体子集。

- 不存在只能靠升回高等级等绕路解除的已知阻塞。

## 11. 风险控制

| 风险 | 控制措施 |
| --- | --- |
| `featId` 作为唯一键导致重复授予串写 | F01 先落实例 ID，所有新选择按实例定位 |
| 法术来源不足导致误停用 | 协调器按 bucket 与来源联合判断；旧数据采用保守迁移并补专项测试 |
| 自动恢复造成构筑变化或超限 | 只提示可恢复，显式操作后重新校验 |
| 法师联动额外赠送法术 | 预留强制占用正常学习额度，最终校验双向一致 |
| 自然语言专长被误算 | 只计算结构化字段，文本效果只展示并警告 |
| 2014／2024 串版 | 数据、规则判断和测试夹具都显式携带 ruleset |
| schema 升级遗漏 | 存储、JSON、ZIP、replace、reset 使用同一迁移／规范化测试集 |
| 新模块循环依赖 | 协调器保持纯函数，由编排层调用，并同步架构拓扑 |

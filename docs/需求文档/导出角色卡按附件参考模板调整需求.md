# 导出角色卡按附件参考模板调整需求

> 来源：GitHub Issue #18《更改导出角色卡》（2026-11-04）附件  
> 状态：**PDF 部分已实施；XLSX 自动卡部分暂停，等待确认填充契约**  
> 适用规则集：D&D 5e 2014 / 2024

## 1. 原始诉求

用户提供了三份参考文件：

1. `2_DnD_5E.pdf`：三页 Letter、334 个 AcroForm 字段的 2014 中文角色卡；
2. `DND 5E人物卡（法术查询列表整合版v4.4.5）.xlsx`：2014 自动计算卡；
3. `dnd5e2024人物卡模板v1.3.xlsm`：2024 自动计算卡。

补充说明：**导出的 PDF 按附件 PDF 模板；导出的自动卡按对应版本的自动卡模板。**

## 2. PDF 部分（已实施）

- 运行时模板 `app/public/templates/character-sheet-zh-plus.pdf` 替换为 `2_DnD_5E.pdf`；
- 原始文件归档到 `docs/export-templates/2_DnD_5E.pdf`；
- 字段集合与页面结构不变（334 字段 / 3 页），继续复用现有 AcroForm 填充、字体与扁平化链路；
- 映射版本 `CHARACTER_SHEET_PDF_MAPPING_VERSION` 从 7 升到 8；
- 参考模板修正了 18 项技能的中文标签顺序；导出映射从“按旧模板错位行映射”改为“按同名字段直连”，解决旧模板中体操/运动等技能数值显示到相邻行的问题；
- 仍沿用现有页面顺序：属性页、法术页、人物资料页。

## 3. XLSX 自动卡部分（暂停）

### 3.1 现状

项目现有 `export-xlsx.ts` 依赖运行时模板自带的「字段映射」工作表（v4 契约）：
模板给出 `字段 Key → 工作表!单元格`，服务只写入输入格并保留公式。

用户新提供的两份自动卡**不含「字段映射」工作表**，且：

- 2014 卡为 19 个工作表、含大量公式、合并单元格、隐藏表和查询页；
- 2024 卡为 `.xlsm`（12 个工作表，含 VBA、ActiveX、动态数组公式），ExcelJS 4.4 在 Node 中读取该文件会长时间占用 CPU/内存，无法在浏览器导出链路中稳定使用；
- 两张卡的表单输入区布局不同，派生值由模板公式自行计算（AC、HP、技能、法术位等），无法直接套用现有 56 个稳定字段键。

### 3.2 待确认

导出自动卡应选择哪种契约：

1. **保留公式、只写输入格**：与现有导出一致，用户在 Excel 中改角色仍会自动重算；需要逆向两张卡的全部输入格，并接受模板公式口径与页面派生值可能存在的手动改值差异；
2. **最终值覆盖为静态快照**：把页面派生值写入卡片显示格并关闭自动重算；实现简单、与页面数值完全一致，但失去“自动计算卡”的继续重算能力；
3. 由用户补充带「字段映射」表的自动卡版本，沿用现有契约，改动最小。

在确认前不把新自动卡作为运行时资产替换，避免导出一张字段错位或无法重算的卡。

## 4. 验收

- PDF：`test/services/export-pdf.test.ts` 全部通过；同一角色导出后技能数值与页面一致；提供修改前后对照图。
- XLSX：待契约确认后补充输入格映射、公式校验与打开兼容性验证。

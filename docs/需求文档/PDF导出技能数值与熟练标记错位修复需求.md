# PDF导出技能数值与熟练标记错位修复需求

## 1. 文档状态与目标

- 整理日期：2026-09-05。
- 状态：已完成问题排查，本轮整理需求，尚未制定更新计划或修改业务代码。
- 对象：产品项目 `app` 的角色卡 PDF 导出，当前使用国内5E术语版三页模板。
- 目标：导出的六项豁免、十八项技能及其熟练标记，与角色卡有效派生结果一致，并显示在正确的中文名称旁。
- 本轮仅新增需求文档，不修改原型、模板、规则计算、版本号或更新公告，不提交或推送。

## 2. 用户反馈与样本

用户提供同一角色的 JSON 和 PDF，反馈“PDF 中的豁免鉴定与技能部分为0”，要求先排查，再整理需求，后续另行制定更新计划。

排查样本为“月光.埃尔德里奇”：10级高等精灵法师、贵族背景，JSON schemaVersion为7，规则集为5e-2014。

- JSON：`月光.埃尔德里奇-740af769-f3b1-4230-ac90-79edceacd30c.json`。
- PDF：`月光.埃尔德里奇-dnd5e.pdf`。
- 两个原文件由用户提供，位于本机Downloads目录；本需求不复制完整角色数据或原文件进仓库。

## 3. 已核验的问题与原因

### 3.1 技能栏存在数值和熟练标记错位

通过现有 `deriveCharacter` 和 `buildCharacterExportModel` 读取样本，技能数值计算正常。对照用户PDF第一页的实际渲染，发现结果被写入了其他技能所在的行。

| 技能 | 正确值 | 用户PDF对应中文行显示 |
| --- | --- | --- |
| 调查 | +8 | +0 |
| 奥秘 | +8 | +3 |
| 隐匿 | +3 | +8 |
| 察觉（模板标为“观察”） | +7 | +0 |
| 游说 | +4 | +3 |

原因：中文模板的技能名称按属性重新排列，但内部AcroForm字段仍沿用英文版名称及原位置。现有导出映射按内部英文名称的语义写入，没有对应模板上实际可见的中文名称。

例如，内部名为 `Arcana` 的字段实际位于“隐匿”旁。奥秘的数值和熟练标记被一起写到隐匿行。该问题具有模板适配层面的共性，不是样本JSON损坏，也不是数值统一丢失或归零。

### 3.2 本样本豁免栏未发现数值错误

样本PDF的力量、敏捷、体质、智力、感知、魅力豁免依次为 `+0、+3、+2、+8、+7、+0`，与JSON经当前规则计算的结果一致。力量和魅力为0是有效结果，不应为了消除零而修改计算。

豁免或技能左侧的空心圆表示未熟练，不是数值0；熟练标记和数值必须分别检查。本需求保留六项豁免回归范围，但不将豁免全部归零写成已证实缺陷。

### 3.3 现有验证存在覆盖缺口

现有PDF测试覆盖字段结构、成功生成、页数、字体、扁平化和部分内容容量，但没有验证全部技能的“可见中文标签—数值—熟练标记”对应关系。因此，字段存在且成功写入不能证明其显示位置正确。

## 4. 功能需求与边界

1. 全部18项技能的加值必须出现在对应中文技能名称旁，不能只修复样本中显示为0的几项。
2. 熟练或专精标记必须与同一行技能对应；不能只修数值而保留错误标记。沿用现有PDF标记表达，不新增专精图标样式。
3. 六项豁免的加值与熟练标记保持正确，合法的0正常显示。
4. 以角色卡有效派生结果和统一导出模型为数值来源，保留已有熟练、专精、人工调整结果，不在PDF适配中另算一套规则。
5. 模板术语别名要对应正确技能：“观察”对应察觉，“求生”对应生存；本批不要求修改模板中文名称或重做版式。
6. 修复对使用该模板的所有角色生效，不按角色名称、职业或样本数值进行特判。
7. 保持现有三页顺序、字体、扁平化及其他区域的导出行为；XLSX、JSON导出与草稿结构不因本问题调整。
8. 修复生效于重新导出的PDF；已下载的静态PDF不会自动更新，原角色无需重新创建。

## 6. 验收要求

- 样本重新导出后，全部技能及豁免与上述基准逐项一致，数值、熟练标记和中文标签属于同一行。
- 覆盖正数、0和负数，以及未熟练、熟练、专精及人工调整的角色数据，不因多个技能值相同而漏掉错位。
- 验证必须包含模板实际位置与中文标签的对应关系，不能仅检查“给预期英文字段写入了预期值”。
- 豁免栏及其他导出区域无回归，继续满足现有模板、页序、字体和扁平化约定。
- 后续代码实现按项目约定执行类型检查、相关回归及完整自动化测试、生产构建。具体映射策略和验证方式由下一步更新计划确定；默认不要求人工浏览器点击验收。

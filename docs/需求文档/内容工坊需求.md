## 1. 背景与用户设计

### 1.1 用户反馈原文（2026-10-19）

> 「我认为通过一直更新项目文件的方式来更新整个系统中的扩展、种族、职业、专长、法术等是个不优雅的方式，所以我希望可以让当前项目引入自定义功能，我希望这个自定义做在跑团助手中，也就是扩展一下助手，将现在仅仅的局内模式做成一个子 router 放在跑团助手功能下的一部分，将自定义扩展、种族、职业、专长、法术等放在第二个功能中，不过我还没想好这个功能的名字，最终的效果是，点击车卡助手，点击这个功能，选择要自定义的内容（种族、职业、专长、法术），填写或输入对应信息，保存，保存后可再辅助车卡对应步骤中可看到自定义内容。」

**用户补充回答（2026-10-19，首轮问答）：**

1. 功能名：**内容工坊**。
2. 关于「点击车卡助手」：**这是打错了**。「内容是放在跑团助手中的；在跑团助手中新增完对应自定义内容后，可在车卡助手中选择；并且车卡第二步也可以当成这个工坊的便捷入口。」

**由补充回答形成的确认结论：**

- 内容工坊的**主入口与归属都在跑团助手**（`/assistant/workshop`）。
- 车卡助手是**消费方**：新增的内容在第 3／4／6／8 步与角色卡中被选择与展示。
- 车卡第 2 步「选择扩展书」**额外提供便捷入口**，可跳到内容工坊新建扩展/条目（§8 第 11 项）。

### 1.2 设计拆解（本需求的目标形态）

| 线 | 现状 | 目标 |
| --- | --- | --- |
| 内容扩展方式 | 新增扩展/种族/职业/专长/法术 = 改 `rules/data/*.ts` + 在 `rules/repository.ts` / `rules/repositories.ts` 手工注册 + 补 `docs/<类别>/` 资料 + 补测试，随版本发布 | 玩家在应用内自行录入，保存在本机，立即生效，不随版本更新 |
| 跑团助手 | 单页（`/assistant`）：角色列表 ⇄ 局内面板 | 改为**父级 + 两个子路由**：局内模式（原内容）/ 内容工坊（新增） |
| 内容工坊（功能名，§3 已确认） | 不存在（只有「自定义属性值」「自定义物品」「人工添加法术/专长」等单点兜底） | 五类条目的**完整录入、编辑、启停、删除、导入导出** |
| 生效路径 | 无 | 保存后自动成为车卡第 2 步「扩展书」中的一个来源；勾选后在第 3/4/6/8 步与角色卡可见 |
| 命名 | — | 待定，见 §3 命名提案 |

### 1.3 本次整理必须回答的三个问题

1. **前置条件**：现有规则数据是编译期静态注册表，运行期不可改。要让自定义内容"真的能用"，必须动哪些位置、哪些位置绝对不能动（§5、§8）。
2. **子页面该怎么设计**：五个类型 × 移动端，怎么分层、怎么防丢失、怎么让玩家知道"我填的这行字会不会影响自动计算"（§6、§7）。
3. **边界**：哪些东西本需求**不做**，避免变成不可维护的规则引擎（§9）。

## 2. 目标信息架构

### 2.1 路由树（目标形态）

```text
/
├─ MainLayout（底部导航不变化）
│  ├─ /character-builder                       辅助车卡（不动）
│  ├─ /assistant              → redirect /assistant/session
│  │   ├─ /assistant/session   name: session-assistant        跑团助手 · 局内模式（现有实现整体迁入）
│  │   ├─ /assistant/workshop   name: workshop                跑团助手 · 内容工坊（列表）
│  │   └─ /assistant/workshop/:kind/:entryId
│  │                           name: workshop-editor          新建（entryId = new）/ 编辑条目
│  ├─ /dice                                    赛博骰娘（不动）
│  └─ /about                                   关于本站（不动）
└─ /:pathMatch(.*)*                            404（不动）
```

- **刻意不重命名既有路由名 `session-assistant`**（`router.ts:26`）：它在 `useBottomNavigation.ts:3,18` 是导航项关联键，改名会连带牵动导航类型与既有测试；只把它的 `path` 从 `assistant` 改为 `session`。
- **刻意不改 pinia store id 与 localStorage 键**（`stores/session-assistant.ts:6,30` 的 `session-assistant` / `dnd-session-assistant:view:v1`）：它们被 8 个测试文件与玩家已保存的页签状态引用，改名会造成无意义的状态丢失。
- 列表页与编辑器页是同级的两个子路由（不是父子）：编辑器的「← 返回」用 `router.push` 显式回列表，**不依赖浏览器历史**是否可回退（沿用 404 页既有约定）。
- `:kind` 取值仅五种：`expansion` / `race` / `class` / `feat` / `spell`；非法值或条目不存在时回到列表并给出中文提示，**不跳全局 404**（避免玩家从深层链接直接迷失）。
- 编辑器是**独立路由页**而不是弹窗：手机表单长、软键盘遮挡、需要「返回」语义，且刷新后要能恢复上下文。
- 规则集归属（2014/2024）通过**列表页的规则集切换**决定，编辑器继承；不放进 URL 路径（避免四段路径）。

## 3. 命名（已确认：内容工坊）

**用户回答（2026-10-19）：** 选择「**内容工坊**」。

**确认结论：**

| 层级 | 用词 |
| --- | --- |
| 一级分段控件 / 页面标题 | 「**内容工坊**」 |
| 与「局内模式」并列时的文案 | 「局内模式」「内容工坊」 |
| 数据与条目术语 | 「自定义扩展 / 自定义种族 / 自定义职业 / 自定义专长 / 自定义法术」，集合统称"自定义内容" |
| 代码内命名 | `custom-content`（类型、模块、存储键、`custom-` ID 前缀），与 UI 名解耦 |
| 路由 | `/assistant/workshop`，路由名 `workshop` / `workshop-editor`；页面目录 `views/workshop/` |

**曾比较并放弃的候选**（保留以便日后回溯）：

| 候选 | 放弃原因 |
| --- | --- |
| 自定义内容 | 零歧义但略平，无记忆点（保留为数据术语） |
| 自制扩展 | 容易被误认为只有"扩展书"，不含种族/职业/专长/法术 |
| 我的资料库 | 与既有「物品库」混淆 |
| 房规工坊 | 与本项目"暂不实现 DM 房规编辑器"的既有边界冲突，容易被理解为规则改写 |

> 注：「内容工坊」与「跑团助手」语义距离略远，因此**进入该子页面后的首屏必须有一句话说明**（"在这里录入自己的扩展、种族、职业、专长与法术，保存后会出现在车卡对应步骤"），避免玩家猜不到。

## 4. 术语

| 术语 | 含义 |
| --- | --- |
| 自定义扩展 | 玩家自制的一本"扩展书"，是本需求唯一的容器与来源门禁；同时是一个 `RuleSource` |
| 自定义条目 | 挂在某个自定义扩展下的种族 / 职业 / 专长 / 法术；ID 以 `custom-` 前缀，永不与内置 ID 冲突 |
| 内容库 | 本机（localStorage）保存的自定义扩展与条目的总和，按规则集分两套 |
| 覆盖层 / 叠加层 | 运行期把内容库并入静态规则仓库的只读层；不改动任何内置数据 |
| 自动结算 | 该字段会进入派生计算（属性、AC、HP、速度、法术位、候选池等） |
| 仅展示 | 该字段只在界面/导出中显示为文字，不参与任何计算 |
| 归档 | 停用但不删除；引用它的角色继续可用，条目不再出现在新建可选池 |

## 5. 前置条件：现状取证

### 5.1 当前"更新项目文件"到底要改哪些地方（印证用户判断）

以"新增一个 2024 种族"为例，当前最小改动链：

| 步骤 | 位置 | 说明 |
| --- | --- | --- |
| 1 | `app/src/rules/data/origins-2024.ts` / `species-*.ts` | 手写 `RaceRule` 与可选 `RaceFeature` |
| 2 | `app/src/rules/repositories.ts:83` | 手工并入 `races` 数组（2014 见 `repository.ts:52`） |
| 3 | `app/src/rules/data/sources-2024.ts` | 登记来源书名与开关策略 |
| 4 | `docs/species/<规则集>/<ID>/` | 逐条资料文件 + 索引链接（`AGENTS.md` 强制） |
| 5 | `app/test/rules/*.test.ts` | 规则回归测试 |
| 6 | 版本与公告 | `package.json` / `CHANGELOG.md` / `update-notices.ts` |

也就是说：**每一次内容扩充都是一次发版**。本需求要把 1—3 步的"代码"变成"数据录入"，第 4—6 步只在发布功能本身时发生。

### 5.2 规则仓库是编译期静态常量（核心约束）

| 事实 | 取证 |
| --- | --- |
| 仓库按规则集各一份单例，模块加载时构造完成 | `rules/repositories.ts:114-134`（`repositories` 常量 + `getRulesRepository`），`rules/repository.ts:42-133`（2014 直接内联装配） |
| 仓储查询是 `Array.find`，无索引、无写入口 | `rules/repository-builder.ts:23-79` |
| 规则函数普遍接受 `repository` 参数，但**默认值取单例** | `rules/origins.ts:20`、`rules/feats.ts:281`、`rules/spellcasting.ts:551,573`、`rules/starting-equipment.ts:35` 等 |
| 直接调用单例的调用点约 **95 处 / 30+ 文件**，其中 `.vue` 组件 14 个 | `views/**`、`features/**`、`rules/**`、`stores/character-drafts.ts:108` |

**结论**：不可能逐个调用点改造（成本与回归面不可控）。可行方案只有一个——**让 `getRulesRepository()` 本身返回"内置 + 自定义"合并后的结果，并在内容变化时重建**（§6.1）。所有 95 处调用点因此零改动地看到自定义内容。

### 5.3 来源开关是唯一的内容门禁（可复用的既有机制）

| 行为 | 取证 |
| --- | --- |
| 条目是否可见/可算，由 `isSourceEnabled(条目.sourceIds, draft.enabledSourceIds, repository)` 判定 | `rules/source-books.ts:24-43`，被 `origins.ts:27`、`feats.ts:292`、`spellcasting.ts:594` 等广泛使用 |
| 可切换来源由**静态白名单**过滤 | `rules/source-books.ts:14-18,46-48` |
| 新草稿默认启用的来源：2014 = 全部可切换来源，2024 = **空数组** | `rules/source-books.ts:54-57` |
| 草稿读取/切换来源时会按白名单**归一化，未知 ID 直接丢弃** | `services/draft-storage.ts:161`、`views/character-builder/hooks/useCharacterBuilderPage.ts:736-748` |

**这是本需求最大的隐性陷阱**：如果只把自定义来源塞进仓库而不改白名单与默认值，会出现两个现象——①自定义扩展在第 2 步根本不显示；②即使显示，勾选保存后再读草稿会被"归一化"静默丢掉。必须一并改造（§8 第 2、3 项）。

### 5.4 可直接复用的能力

| 能力 | 位置 | 复用方式 |
| --- | --- | --- |
| 条目选择/展开卡片 | `components/ui/OptionCard.vue`、`ExpandableOptionCard.vue`、`ListShell.vue`、`UiChip.vue`、`UiBadge.vue`、`UiNotice.vue` | 列表页与选择器直接使用，不新造列表 |
| 弹窗与层级 | `components/ui/UiModal.vue`、`UiScrollModal.vue`、`modal-layer.ts` | 新建类型选择、删除确认、未保存离开确认 |
| 二级页签 | `components/ui/UiTabs.vue`（支持 wrap） | 列表页类型筛选；外壳一级切换改用分段控件以免与面板页签混淆 |
| 吸底操作条 | `features/quick-build/components/StickyActionBar.vue` | 编辑器保存栏；若被 2+ 处使用需上提（§8 第 12 项） |
| 本机存储范式 | `services/draft-storage.ts`（localStorage + 版本化归一化）、`services/session-state-storage.ts` | 自定义内容存储照抄同一模式 |
| 文本录入范式 | `AddManualSpellModal.vue`（搜索+选择）、`ManualFeatConfigModal.vue`（人工配置） | 自定义条目的"从模板新建"与"人工添加"入口参考 |

### 5.5 一个已存在的先例（说明"仅展示的自定义内容"在本项目是可接受的）

- `AddItemModal.vue` 的「自定义物品」：`itemId` 直接用玩家输入的名字，展示层回退显示，**不参与装备数值派生**，并在界面注明"自定义物品"。
- `AddManualSpellModal.vue:43`：人工添加法术直接列全量 `repository.spells`，含来源未启用的条目。

本需求的"仅展示"级别沿用同一诚实口径：**能做计算的就自动算，做不到的明说不算**。

## 6. 数据模型与运行时叠加层

### 6.1 合并策略（架构核心）

```text
localStorage（内容库，按规则集分两套）
   ↓ services/custom-content-storage.ts（读写、版本、归一化）
stores/custom-content.ts（响应式状态 + CRUD + 变更后 bump revision）
   ↓ rules/custom-content.ts（纯函数：校验、ID 生成规则、合并、摘要）
rules/repositories.ts#registerCustomContent(ruleset, bundle)  ← 唯一的写入口（另有 resetCustomContent）
   ↓ 重建缓存
getRulesRepository(ruleset) 返回“内置 + 自定义”只读仓库
   ↑ 所有 95 处调用点（零改动）
```

**四条硬约束**：

1. `src/rules` 仍必须框架无关：不读 localStorage、不依赖 Vue/Pinia。存储读取在 `services`，注册在 `rules` 的显式函数（如 `registerCustomContent` / `resetCustomContent`）。
2. **只增不改**：合并只追加派生条目，不允许覆盖内置 ID；自定义 ID 强制 `custom-` / `source-custom-` 前缀；若因导入的 JSON 造成冲突，整包拒绝并给出中文原因。
3. 合并结果必须**缓存 + 可失效**：以 `(ruleset, revision)` 为键；`revision` 由 store 在每次增删改后自增。
4. 提供 `resetCustomContent()` 供测试使用；单元测试默认运行在"零自定义内容"状态，不得被其他用例污染。

### 6.2 类型草案（`types/custom-content.ts`）

```ts
export type CustomContentKind = 'expansion' | 'race' | 'class' | 'feat' | 'spell'

interface CustomEntryBase {
  /** 稳定 ID：custom-<kind>-<uuid>；导入/导出与草稿引用都靠它。 */
  readonly id: string
  readonly kind: CustomContentKind
  /** 内容不跨规则集：2014 与 2024 各自独立，不共享、不隐式转换。 */
  readonly ruleset: RulesetId
  /** 必填：所属自定义扩展（= 来源门禁）。 */
  readonly expansionId: string
  readonly name: string
  readonly englishName: string
  /** 卡片摘要行（一句话）。 */
  readonly summary: string
  /** 原创中文详细说明（展开区/角色卡展示）。 */
  readonly description: string
  /** 归档后不再进入新建候选池，但被引用的角色仍可解析。 */
  readonly archived?: boolean
  readonly createdAt: string
  readonly updatedAt: string
}

export interface CustomExpansion {
  /** 映射为 RuleSource.id：source-custom-<uuid> */
  readonly id: string
  readonly ruleset: RulesetId
  readonly title: string
  readonly shortTitle: string
  readonly note?: string
  /** 新车卡是否默认勾选该扩展（默认 true，见 §6.4）。 */
  readonly defaultEnabled: boolean
}

export interface CustomContentBundle {
  readonly version: 1
  readonly expansions: readonly CustomExpansion[]
  readonly races: readonly CustomRaceEntry[]
  readonly classes: readonly CustomClassEntry[]
  readonly feats: readonly CustomFeatEntry[]
  readonly spells: readonly CustomSpellEntry[]
}

/** 每个规则集一套，互不混合。 */
export interface CustomContentState {
  readonly '5e-2014': CustomContentBundle
  readonly '5e-2024': CustomContentBundle
}
```

- 自定义条目的类型是内置类型的**子集投影**（例如 `CustomRaceEntry` 只保留 §7.2 表格中列出的字段），由纯函数转换为 `RaceRule` / `FeatRule` / `SpellRule` / `ClassRule` / `RaceFeature[]` / `ClassFeature[]`。
- 所有生成条目统一：`status: 'selectable'`、`sourceIds: [expansionId]`。**不新增 `CompatibilityStatus` 取值**（避免波及 `validate.ts`、`timeline.ts` 现有的 `status === 'unavailable'` 判定）；"这是自定义内容"一律通过 `sourceIds[0].startsWith('source-custom-')` 识别，界面据此加「自定义」徽标。

### 6.3 存储

- 键：`dnd-custom-content:v1`（与 `dnd-session-assistant:view:v1` 风格一致）。
- 结构：`{ version: 1, state: CustomContentState }`；读取时逐字段归一化，未知字段忽略、非法条目丢弃并记入"已跳过 N 条"提示（**静默丢弃不可接受**）。
- 体积：localStorage 单域约 5 MB。内容库接近 1 MB 时在列表页提示"建议导出备份"；超过 4 MB 时拒绝保存新条目并提示导出后清理。
- 不提供云同步、不联网上传（Q13）。

### 6.4 与来源开关的联动规则

| 规则 | 说明 |
| --- | --- |
| 自定义扩展默认启用 | `defaultEnabled: true` → 新车卡即勾选。**这是"保存后车卡里立刻能看见"的前提**（2024 默认来源为空，若不这样处理，玩家保存后在车卡里找不到任何东西） |
| 白名单同步 | `getSelectableSources` / `normalizeEnabledSourceIds` / `getDefaultEnabledSourceIds` 必须认识自定义来源 ID（§8 第 2、3 项） |
| 关闭来源 = 暂时失效 | 与既有扩展书完全一致：选择保留、派生暂停、重新开启后恢复 |
| 删除扩展 | 只允许在"扩展下无条目"时直接删除；否则要求先归档或迁移条目 |

### 6.5 ID 与重名

- ID 与展示名解耦：允许两个自定义条目重名（来自不同扩展），但同一扩展内同名时给出**警告不阻断**（提示"同名可能导致角色卡难以区分"）——与既有"展示名不作为关联键"的约定一致。
- 修改名称不改变 ID；角色卡引用保持有效。

## 7. 五类内容的需求明细

通用要求（对五类都成立）：

1. 必填项未填时，保存按钮禁用 + 字段下方中文说明"如何修正"。
2. 每个"会影响自动计算"的字段旁边有小字说明其后果（如"速度会写入角色卡与跑团面板"）。
3. 每类提供**「从模板新建」**：可从内置同类条目复制一份作为起点（可大幅降低录入成本），复制后 ID 重新生成、名称自动加「（自制）」后缀。
4. 每类提供**「复制此条目」**。
5. 保存后立即生效：无需重启、无需刷新页面；正在车卡中的草稿同步可见（若当前草稿规则集匹配且已勾选该扩展）。
6. 编辑器底部固定「保存 / 取消」；有未保存修改时离开（返回按钮、浏览器后退、切换一级分段）需二次确认。

#### 7.3.1 施法：引用已有职业的法术表（Q4 已确认）

**用户回答（2026-10-19）：** 按建议来——引用已有职业的法术表，不做完整施法配置。

**确认结论与字段设计：**

| 字段 | 说明 |
| --- | --- |
| 是否施法者 | 开关，默认关；关闭时不写 `spellcasting`，第 8 步不出现 |
| 法术表来源职业 | **必填**，从当前规则集已启用的内置职业中单选（如法师/牧师/吟游诗人…），只引用其法术表与数量/法术位表 |
| 施法属性 | 六选一，默认跟随所引用职业的施法属性（允许改，用于 DC 与"准备数量＝属性调整值"类公式） |

**行为约定：**

- 直接复用所引用内置职业的 `SpellcastingConfig`（模式、戏法/已知/准备/法术书数量表、法术位表、最大环级表全部继承），只替换 `ability`；**不提供逐项覆写**，避免出现"数量表与模式不匹配"的非法组合。
- 由于继承 `classSpellIds`，该自定义职业能选到被引用职业的全部法术（含注入到该职业的自定义法术）。
- **实现顺序要求**：合并时先完成"自定义法术注入内置职业 `classSpellIds`"，再派生自定义职业的施法配置；否则自定义职业会拿到注入前的旧表。
- 引用关系存为 `spellcastingSourceClassId`，不复制快照；被引用职业的内置数据不可被玩家改写，故不会漂移。
- 限制（v1）：只能引用一个职业的法术表；不能同时拥有两套施法（如"法师+牧师"）；自定义职业不生成契约法术位等特殊分支——按所引用职业原样继承。

### 7.4 自定义专长

**基础（必填）**：名称、英文名、所属扩展、类别、一句话概括、详细效果。

- 类别：2014 固定 `general`；2024 可选 `origin` / `general` / `fighting-style` / `epic-boon`。
- 选 `origin` 的自定义专长会进入 2024"任选起源专长"类背景的候选池（`getFeatPool`），这正是玩家最常想要的能力。

**机制（会影响计算，全部可选）**：每级最大生命加成、固定最大生命加成、速度加值、护甲训练、固定授予法术、可重复选择、前置（等级下限、属性最低、需要施法能力）。

**明确不支持（v1）**：子选择（`choices`，如"任选一项属性 +1"）、扩表（`expandedSpellPool`）、全部技能熟练、依赖其他专长的链式前置。

### 7.5 自定义法术

**基础（必填）**：名称、英文名、所属扩展、环级（0—9）、学派、职业归属（12 职业多选，可空）、效果说明。

**机制（会影响计算）**：环级与职业归属决定它进入哪个职业的第 8 步候选池与戏法/已知/准备数量校验；施法时间/射程/成分/持续时间/专注/仪式为展示字段（与内置 `SpellRule` 一致）。

**明确不支持（v1）**：戏法成长（`cantripScaling`）、按等级变化的授予、自定义法术学派枚举之外的字段。

**必须补的注入逻辑**：内置职业的 `classSpellIds` 是**数据定义期**由 `spell.classIds` 预计算出来的（`rules/data/full-casters-2014.ts:20,67`；2024 见 `rules/repositories.ts:65-78`）。因此合并时必须把自定义法术 ID **追加进所属职业的 `spellcasting.classSpellIds`**，否则第 8 步候选池里不会出现（`rules/spellcasting.ts:573-596` 只认 `classSpellIds` 与扩表）。

## 9. 页面与交互需求（R）

### R1 外壳：一级分段切换（必须）

- 跑团助手两个子页面顶部都有「局内模式 / 内容工坊」分段控件，**由路由驱动**（点击 = `router.push`，当前项 `aria-current`），不使用组件内部状态。
- `/assistant` 重定向到 `/assistant/session`；浏览器前进/后退在两个子页面间正常工作；直接刷新 `:kind` / `:entryId` 路由时编辑器能恢复上下文（找不到条目则回列表并提示）。
- 底部导航仍高亮「跑团助手」；重复点击当前一级导航不触发行为。激活与"当前项"判定统一按路径前缀 `/assistant`（不再用 `router-link-exact-active`）。
- 分段控件与局内面板已有的 5 个 `UiTabs` 存在**层级差异**：一级用分段控件（pill + 填充背景），二级用页签（下划线）；两者不得视觉混淆。

### R2 列表页（必须）

- 顶部规则集分段（2014 / 2024），默认取"上次使用的规则集"，缺省取全局 `ruleset-preference`。
- 摘要行展示五类计数；计数为 0 的类型筛选 chip 置灰不可点。
- 搜索：名称、英文名、ID、所属扩展名，忽略大小写。
- 条目卡信息：名称、所属扩展、`自定义` 徽标、参与计算级别（「会参与计算」/「仅展示」）、被 N 个角色使用。
- 条目操作：编辑 / 复制 / 归档或恢复 / 删除（`⋯` 菜单）。
- 空状态：说明"内容只保存在本机浏览器；添加后可在车卡第 2 步的扩展书里勾选"，并给出主按钮。
- 页尾：导入 / 导出（见 R9）。

### R3 新建流程（必须）

1. 点「＋ 新建」→ 底部弹层选择类型（扩展 / 种族 / 职业 / 专长 / 法术），并说明各类型能做什么。
2. 进入编辑器；若是第一条内容，先要求创建扩展（编辑器内联创建，不要求先跳出去建扩展）。
3. 「从模板新建」：在编辑器顶部提供入口，从内置同类条目复制（选择器带搜索），复制后名称加后缀、ID 重新生成。

### R4 编辑器（必须）

- 分区顺序与折叠状态：基础信息（展开）→ 机制（展开）→ 特性/效果清单（展开）→ 进阶（折叠）→ 规则摘要预览（可折叠，实时更新）。
- 校验：失焦行内校验 + 保存时汇总；错误文案说明如何修正（沿用项目既有口径）。
- 数字字段使用 `inputmode="numeric"`，范围外（如速度 0—120）给出中文提示。
- 「保存」在无修改时不产生写入；保存成功后回列表并高亮该条目；若来源为车卡跳转，额外显示「返回车卡」主按钮。
- 未保存离开的确认弹窗（含浏览器返回键，需 `onBeforeRouteLeave`）。

### R5 生效与提示（必须）

- 保存后在列表页顶部显示一次性提示："已保存。若已在该规则集的草稿中勾选本扩展，对应步骤会立即出现该内容。"
- 若该条目正被角色使用且改动影响计算，提示："N 个角色正在使用，其派生数值已按新规则更新。"

### R6 删除与归档（必须）

- 归档：条目退出新建可选池；被引用角色继续解析（显示"已归档的自定义内容"）。
- 删除：先检测引用，若被引用则默认只允许归档；「强制删除」需列出受影响角色并二次确认，删除后角色草稿保留原 ID（解析为"未知内容"，由第 10 步校验给出提示，**不崩溃、不静默清空**）。

### R7 车卡侧联动（必须）

- 第 2 步来源列表出现「自定义内容」分组与「自定义」徽标 + DM 同意提示。
- 第 3 步职业、第 4 步种族、第 6 步专长、第 8 步法术的候选列表中，自定义条目与内置条目同列，但**统一带「自定义」徽标**（复用既有 `UiBadge` tone）。
- 角色卡与跑团助手中，自定义条目名称/描述正常显示，展开区显示原创说明，并注明"自定义内容，未经规则核验"。
- 第 2 步提供「＋ 新建自定义扩展」快捷入口（§8 第 11 项）。

### R8 数据完整性（必须）

- 读取内容库失败（JSON 损坏）：不阻塞应用，内容库降级为空，并在列表页提示"内容库读取失败，已忽略"。
- 保存失败（超配额）：明确提示"存储空间不足，请导出备份后删除部分内容"，且不破坏已有数据。
- 导入非法包：整包拒绝并说明原因（哪一条、哪个字段）。

### R9 导入 / 导出（必须，成本低价值高）

- 导出：单文件 JSON `{ version, exportedAt, ruleset, expansions, races, classes, feats, spells }`；默认导出当前规则集，可勾选"导出全部规则集"。
- 导入：预览页显示"将新增 X 项 / 覆盖 Y 项 / 跳过 Z 项"，ID 冲突时逐条选择"保留本机 / 使用导入"。
- 角色包（zip）内是否附带自定义内容快照：**v1 不做**（Q11）。但导入角色包时若引用了本机不存在的自定义 ID，必须在导入结果中列出"缺少 N 项自定义内容"，并提供跳转到内容工坊的入口。

### R10 文案与可访问性（必须）

- 全程中文；术语一致：扩展 / 种族 / 职业 / 专长 / 法术。
- 语义化 HTML：`<form>` + `<label for>`、必填项 `required`/`aria-required`、错误用 `aria-describedby` 关联、保存结果用 `role="status"` 播报。
- 触控目标 ≥ 2.5 rem；不使用仅靠悬停的交互；颜色对比满足项目既有规范。

## 10. 明确不做（本需求范围外）

1. 不做 DM 房规编辑器：不覆盖/改写内置规则数值，只做"新增自制内容"。（本条对应 `docs/rules.md:59` 既有边界「暂不包含 DM 房规编辑器」；本需求**扩展**该边界为"允许玩家自行录入内容"，但不允许改写内置规则。）
2. 不做自定义**背景、子职、装备、魔法物品**（后续批次，接口预留：`kind` 枚举可扩展）。
3. 不做自然语言/OCR 自动解析成条目（"粘贴一段规则书文字自动生成专长"），避免把未核验内容伪装成自动结算。
4. 不做云同步、账号、跨设备自动同步、社区分享市场。
5. 不做自定义条目的效果自动化引擎（条件触发、状态机、脚本）。
6. 不改动内置规则数据与 `docs/<类别>/` 资料索引（自定义内容不进入静态资料体系）。
7. 不因本需求新增第三方依赖。

## 12. 用户友好性设计原则（评审时逐条对照）

1. **看得懂影响**：任何影响数值的字段旁有小字说明；纯展示字段标注「仅展示」。玩家永远知道"我填的这行会不会改变我的 AC"。
2. **少填就能用**：必填项只有 5—6 个（名称、扩展、概括、详细说明 + 少量核心机制）；其余全部折叠。
3. **从已有出发**：支持从内置条目/已有自定义条目复制，避免从空白表单开始。
4. **不会填错丢数据**：行内校验、未保存离开确认、保存失败不清空、导入预览、导出备份入口常驻。
5. **随时能找回**：归档优先于删除；被引用的内容删除前必须列清影响。
6. **立刻看见结果**：保存后默认启用，车卡对应步骤即时出现；提供"回到车卡"入口。
7. **口径诚实**：不做自动结算的效果一律写明"仅展示 / 请与 DM 确认"，与既有第三方内容标注风格一致。
8. **移动优先**：单列布局、吸底操作条、44px 级触控目标、输入框与软键盘不互相遮挡（长表单滚动而不是弹窗内滚动）。

1. `/assistant` 重定向到 `/assistant/session`；`/assistant/session`、`/assistant/workshop`、`/assistant/workshop/:kind/:entryId` 可直接访问、刷新、前进后退；底部导航在全部子路由上仍高亮「跑团助手」。

3. 自定义扩展创建后，第 2 步「自定义内容」分组出现，默认勾选；取消勾选后第 3/4/6/8 步候选消失，重新勾选后恢复。
4. 五类条目分别创建后：种族进入第 4 步候选并正确展示属性加值/速度/技能/特性；职业进入第 3 步并在时间线显示职业特性、不生成子职检查点；专长进入第 6 步专长检查点候选（2024 `origin` 类别进入背景起源专长池）；法术出现在所属职业第 8 步候选池，并计入戏法/已知/准备数量校验。
5. 角色卡与跑团助手中自定义条目正常显示名称、描述与「自定义」徽标；导出 JSON / ZIP / PDF / XLSX 不报错且名称正确。
6. 2014 与 2024 内容互不串台：2014 草稿看不到 2024 自定义内容，反之亦然。
7. 归档后的内容不出现在新建候选池，但已引用它的角色仍可正常打开、校验只给提示不崩溃。
8. 删除被引用内容需二次确认并列出受影响角色；强制删除后角色打开不崩溃，第 10 步校验给出"自定义内容缺失"的中文提示。
9. 导入/导出往返一致；导入冲突走预览并逐条决策；损坏文件被整包拒绝且原数据不变。
10. `pnpm typecheck`、`pnpm test:run`、`pnpm build` 全部通过；新增单测覆盖 §8 第 18 项的六类场景。
11. 无浏览器控制台错误；预渲染产物中不出现自定义内容残留（预渲染环境无 localStorage 时内容库为空）。
12. `docs/rules.md`、`docs/frontend-architecture.md`、`docs/router-layout-requirements.md`、`docs/seo-requirements.md` 已同步；交付说明包含"已复核前端依赖拓扑，已更新"。

# 物品删除与数量调整需求

## 1. 背景与目标

用户反馈：角色卡"物品"页签目前**只能新增物品**（添加物品弹窗：内置物品库 / 自定义物品），**没有对应的删除能力**。添加后物品无法移除、数量无法减少，玩家若误加、多加了数量或想丢弃冒险中不需要的物品，没有任何手段处理，物品栏只能持续膨胀。

上一轮《角色卡物品与金币需求》已实现新增物品（`AddItemModal` + `addAdventureItem` 合并规则）与金币调整；其 R7 明确将"物品移除 / 丢弃 / 数量减少（本批只加不减）"列为后续批次——本需求承接该缺口。

目标产物（已确认）：

- 角色卡"物品"页签的每个**冒险获得（`sourceKind === 'adventure'`）物品条目**提供**数量调整入口**（条目卡片操作位内）：
  - **减少数量**：输入指定数量从该条目数量中扣除，装备数量同步受约束（`equippedQuantity ≤ quantity` 恒成立）；扣除至 0 时移除整条；
  - **增加数量**：输入指定数量向该条目追加（复用合并规则，与添加弹窗行为一致）；
  - **删除整条**：直接移除整个物品条目（含装备数量）。
- 删除/扣减至移除前需**二次确认**（防误触，符合触控交互约定），确认文案说明删除影响。
- **删除不返还金币**（已确认：出售/折价属后续批次）。
- 删除变更随草稿持久化，导出 JSON 自动包含，重新编辑流程中不丢失。
- 遵守既有边界：**只允许调整"冒险获得"（`sourceKind === 'adventure'`）的物品**；职业/背景起始装备条目（`class`/`background`/`legacy`）由重新编辑流程管理，不在物品页签直接调整（避免破坏起始装备一致性）。

## 2. 现状调查（已核验）

### 2.1 数据与规则层

| 模块 | 现状 |
|---|---|
| `app/src/types/character.ts` `InventoryEntry`（66–73 行） | `{ id, itemId, quantity, sourceKind: 'class'\|'background'\|'legacy'\|'adventure', sourceId, equippedQuantity }`；`sourceKind` 已含 `'adventure'` |
| `app/src/rules/starting-equipment.ts` `addAdventureItem`（158–185 行） | 新增/合并冒险物品的纯函数：同 `itemId` + `sourceKind === 'adventure'` 合并数量，`equippedQuantity ≤ quantity` 恒成立；**无删除/减量函数** |
| `app/src/rules/starting-equipment.ts` `updateEquippedQuantity` | 装备/卸下切换已有现成实现（编辑流程使用），物品页签未接 |
| `app/src/services/character-json.ts` | 草稿全量 JSON 序列化，`inventory` 随导出自动包含；无需改导出格式与版本号 |

### 2.2 界面层

| 界面 | 现状 | 缺口 |
|---|---|---|
| `CharacterSheetStep.vue` 物品页签（约 500–535 行） | "已装备"区与"物品栏"区均为 `ExpandableOptionCard` 条目化展示，`suffix` 位仅显示数量徽标（`×{{ entry.quantity }}`）；物品条目**无任何操作位** | 无删除/减量入口 |
| `AddItemModal.vue` | 新增物品弹窗完整（搜索/分类/自定义/数量/加入物品栏或装备栏） | 无（本需求不涉及新增） |
| 事件通道 | `changeInventory` 事件 → `index.vue` → store 已存在（新增物品复用） | 删除/减量复用同一通道，无需新增事件 |

### 2.3 结论

- 数据层缺**删除/减量纯函数**（`removeAdventureItem` / `decreaseAdventureItem`，参照 `addAdventureItem` 模式）。
- 界面层物品条目 `suffix` 位是现成操作位（已有按钮样式的先例：法术条目的"取消准备/准备"按钮、装备详情的数量徽标），删除/减量按钮放此处即可。
- 二次确认复用现成 `UiModal` 或轻量确认交互；删除范围限定 `sourceKind === 'adventure'`，起始装备不受影响。

## 3. 需求项

### R1 规则层：删除、减量、增量纯函数（必须）

`app/src/rules/starting-equipment.ts` 新增三个纯函数（规则层保持框架无关，参照 `addAdventureItem` 模式）：

1. **删除整条**：
   ```ts
   /** 移除指定的冒险获得物品条目（按 entry.id 精确匹配）；非 adventure 条目不可删除，原样返回。 */
   export function removeAdventureItem(
     inventory: readonly InventoryEntry[],
     entryId: string,
   ): readonly InventoryEntry[]
   ```
   - 仅当目标条目 `sourceKind === 'adventure'` 时移除；否则返回原数组（防御性兜底）。
2. **减少指定数量**：
   ```ts
   /** 将冒险获得物品数量减少 count（调用方传入，≥ 1）；装备数量同步收缩，恒满足 equippedQuantity ≤ quantity；数量减至 0 或以下时移除整条。 */
   export function decreaseAdventureItem(
     inventory: readonly InventoryEntry[],
     entryId: string,
     count: number,
   ): readonly InventoryEntry[]
   ```
   - `quantity - count ≤ 0` 时整条移除；
   - `equippedQuantity` 收缩为 `min(equippedQuantity, 新 quantity)`；
   - 非 adventure 条目不处理。
3. **增加指定数量**（对已有条目，按数量新增）：
   ```ts
   /** 向冒险获得物品条目追加 count（≥ 1），等价于添加弹窗的同条目合并逻辑；数量与装备数量同步增加，恒满足 equippedQuantity ≤ quantity。 */
   export function increaseAdventureItem(
     inventory: readonly InventoryEntry[],
     entryId: string,
     count: number,
   ): readonly InventoryEntry[]
   ```
   - 仅处理 `sourceKind === 'adventure'` 条目；
   - 装备数量策略：与 `addAdventureItem(equip: false)` 一致——追加到**物品栏数量**，不改变装备数量（玩家如要装备可另行装备/卸下）；若需追加到装备数量属后续扩展，不在本批。

### R2 界面：物品条目数量调整入口（必须）

`CharacterSheetStep.vue` 物品页签（已装备区与物品栏区）：

1. **仅对 `sourceKind === 'adventure'` 的条目**显示操作区（职业/背景起始装备条目不显示，保持现状展示）：
   - **数量调整入口**（如"调整"按钮）：点击打开数量调整弹层/行内输入（复用 `UiModal` 或行内扩展区），提供：
     - **数量输入框**（数字，≥ 1，默认 1）与操作选择：
       - **「减少」**：按输入数量扣减（装备数量同步收缩；扣至 0 移除整条）；
       - **「增加」**：按输入数量追加（仅增加物品栏数量，装备数量不变）；
       - **「删除全部」**：整条移除（无需输入数量）。
   - 或采用条目内两枚快捷按钮 + 数量弹层组合：`「−」`（减 1）、`「＋」`（加 1）直接操作，长按/展开进入指定数量输入——实现时二选一，推荐**入口按钮 + 数量弹层**（一次可指定任意数量，符合"输入指定数量"要求）。
2. 按钮放 `ExpandableOptionCard` 的 `suffix` 操作位（现有样式先例：`character-sheet__spell-action` 按钮；按钮高度 ≥ 44px 或由组件 `:deep(button)` 兜底 2.25rem 保持一致）。
3. 非 adventure 条目显示来源徽标（如"起始装备"），不显示操作按钮；冒险条目可显示"冒险获得"徽标（如已有 `sourceLabel` 逻辑则复用）。
4. 数量调整事件均通过现有 `changeInventory` 通道：`emit('changeInventory', removeAdventureItem(...))` 等，`index.vue`/store 无需改动。

### R3 二次确认（必须）

1. **删除整条**必须二次确认：复用 `UiModal` 或轻量确认弹层（标题如"删除物品"，正文说明"将移除 {{ 物品名 }} × {{ 数量 }}（含已装备 {{ 装备数 }} 件），此操作不可撤销，且不返还金币。"），确认按钮「删除」/取消按钮「取消」。
2. **指定数量扣减至 0 或以下**（即输入数量 ≥ 当前数量）等价于删除整条，同样触发确认流程（确认文案按"将移除该物品"提示）；其余扣减（结果数量 > 0）与增加不弹确认。
3. 确认弹层保持键盘可达（焦点管理、Esc 关闭），与 `UiModal` 既有行为一致。

### R4 数据与持久化（必须）

1. 删除/减量后经 `changeInventory` → store 保存，导出 JSON 自动包含；不新增草稿字段、不提升 `schemaVersion`。
2. 重新编辑流程（`EquipmentStep.vue`）中已删除的冒险物品自然消失（重新编辑重建物品栏时保留的是现存条目）；职业/背景起始装备不被影响。
3. 数量约束：任何操作后 `equippedQuantity ≤ quantity` 恒成立（R1 函数内保证）。

### R5 单元测试（必须）

`app/test/rules/starting-equipment-2014.test.ts`（或现有对应测试文件）扩展：

| 用例 | 断言 |
|---|---|
| 删除冒险条目 | `removeAdventureItem` 按 `entry.id` 移除该条；其余条目原样保留 |
| 删除非 adventure 条目 | 原数组返回（不被误删） |
| 减少指定数量 | `decreaseAdventureItem(inventory, id, 3)`：`quantity` 减 3；`equippedQuantity` 同步收缩（如 5 件中装备 3 件，减 3 后为 2/1） |
| 减量至 0 或以下 | 输入数量 ≥ 当前数量时整条移除 |
| 增加指定数量 | `increaseAdventureItem(inventory, id, 3)`：`quantity` 加 3，`equippedQuantity` 不变 |
| 增加/减少非 adventure 条目 | 原数组返回 |
| 不变量 | 所有操作后全数组 `equippedQuantity ≤ quantity` |

组件测试（`CharacterSheetStep.test.ts` 扩展）：
- adventure 条目显示数量调整入口；非 adventure 条目不显示；
- 打开弹层输入数量点「减少」emit `changeInventory` 且数量正确扣减；
- 点「增加」emit 且数量正确追加、装备数量不变；
- 点「删除全部」先弹确认，确认后 emit 且条目移除，取消则不移除；
- 扣减至 0 的输入触发确认流程。

## 4. 非目标与边界

- **不调整起始装备**：`sourceKind === 'class'/'background'/'legacy'` 条目不在物品页签提供数量调整（其管理归属重新编辑流程）。
- **不做批量操作**：不支持多选删除、一键清空（后续如需另行立项）。
- **不返还金币**：删除/丢弃物品不返还金币（出售/折价属后续批次，已确认）。
- **不做负重计算**：删除不影响负重数值（负重未实现）。
- **增加数量只入物品栏**：`increaseAdventureItem` 不改变装备数量（装备/卸下仍走既有能力）；如需"增加并装备"属后续扩展。
- 不新增 `CharacterDraft` 字段；不提升 `schemaVersion`；导入导出兼容。
- 不改变新增物品（添加弹窗）、金币调整、装备/卸下等既有行为。

## 6. 验收标准

1. `pnpm test` 全量通过；R5 用例覆盖删除/减量纯函数边界与组件交互。
2. `pnpm build`（含 `vue-tsc -b`）通过。
3. 手机宽度流程验证：
   - 添加一件冒险物品（如长剑 ×3、装备 2 件）→ 物品栏条目显示数量调整入口与数量/装备数量；
   - 打开数量调整弹层输入 2 点「减少」：数量 3→1，装备 2→1（按收缩规则），不弹确认；
   - 再输入 1 点「减少」（数量将为 0）→ 弹确认"将移除该物品"→ 确认后条目消失；
   - 重新添加 → 打开弹层点「删除全部」→ 弹确认 → 取消不生效 → 再删除确认后条目消失；
   - 打开弹层输入 2 点「增加」：数量 +2（如 1→3），装备数量不变；
   - 起始装备（职业/背景条目）不显示数量调整入口；
   - 导出 JSON 不包含已删除条目；重新编辑后冒险物品保持删除结果、起始装备不受影响；
   - 所有按钮触控面积 ≥ 44px（或与既有操作位一致）。
4. 无浏览器控制台错误；删除确认弹层键盘可达、Esc 可关闭。

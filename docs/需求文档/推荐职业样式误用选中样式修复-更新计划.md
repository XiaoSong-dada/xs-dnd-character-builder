# 推荐职业样式误用选中样式修复 · 更新计划

> 依据排查结论制定（2026-08-17 排查：职业页面推荐职业与选中职业视觉一致，不符合"推荐只多 tag 标签"的预期）。

## 目标与范围

- **现象**：车卡第 3 步职业页面（`ClassStep`），前 3 名推荐职业与当前选中职业的**视觉样式完全相同**（主色边框 + 暖色背景 + 左侧主色内阴影条），无法区分；预期推荐职业只比普通卡片多出"① 推荐 · 匹配X项偏好"tag 标签。
- **根因**（已核验）：`ExpandableOptionCard.vue`（251—252、263、265 行）与 `OptionCard.vue`（87—88、100 行）的 SCSS 把 `--recommended` 与 `--selected` **合并声明**为同一组强调样式：
  ```scss
  &--selected,
  &--recommended {
    border-color: var(--color-primary);
    background: #fff9f6;
    box-shadow: inset 0.2rem 0 var(--color-primary);
  }
  ```
  另含 radio 标记：两者都显示实心圆点（选中语义）。
- **逻辑层无问题**：`ClassStep.vue` 33 行 `selected ? 'selected' : 推荐前3 ? 'recommended' : 'default'` 意图正确；`aria-pressed` 仅对 `selected` 生效；推荐 badge 已正确渲染。
- **测试盲区**：`ClassStep.test.ts` 43—48 行只断言推荐卡片"不含 `--selected` class"（类名本就不同），jsdom 无法断言计算样式 → 测试通过但视觉错误。
- **方案（已确认方向）**：移除两个组件的 `--recommended` 专属强调样式，使其外观等同 `default`（推荐信息完全由 badge 承载）；保留 `state` 类型与 `--recommended` class（语义标记，未来如需轻区分可再加）。`OptionCard` 虽暂无 `recommended` 调用方，一并修正避免潜在同错。

## 关键实施细节（已核验）

1. `ExpandableOptionCard.vue` 需删除 3 处合并声明中的 `--recommended`：
   - `&--selected, &--recommended { border/background/box-shadow }` → 只留 `&--selected`；
   - `&--selected &__mark, &--recommended &__mark { border-color }` → 只留 `&--selected`；
   - `&--selected &__mark::after, &--recommended &__mark::after { background }` → 只留 `&--selected`。
2. `OptionCard.vue` 同 3 处（87—88、100 行及 `__mark::after` 对应行）。
3. `state` 类型（`'default' | 'selected' | 'recommended' | ...`）与 `ClassStep` 传值**不变**——`recommended` 保留为语义状态，只是无专属样式（等同 default）。
4. 无规则数据、无交互逻辑变化；不影响其他使用 `ExpandableOptionCard`/`OptionCard` 的页面（`selected`/`complete`/`locked` 等状态样式不动）。

## 已确认决策（2026-08-17 排查确认）

1. **推荐外观**：`--recommended` 无专属强调样式，等同 `default`；推荐信息只由 badge 承载（符合"推荐职业只会多出推荐的 tag 标签"）。
2. **状态语义保留**：`recommended` 状态类型与 class 名保留（不改为直接传 `default`），未来如需轻量区分（如仅主色边框）可在同一状态下追加样式。
3. **一并修正 `OptionCard`**：虽当前无调用方，避免潜在同错。

## 待执行时确认点

1. 契约断言的匹配写法：以"`&--selected,` 与 `&--recommended` 相邻出现在同一选择器列表"为锁定目标（`not.toMatch(/&--selected,\s*&--recommended/)`）；若实施时采用多行声明，可改用更宽松的正则或改为断言两行之间不存在连续关系，以最小实现为准。
2. 是否需要在 `ClassStep` 中补充"推荐职业视觉与 default 一致"的注释说明（无功能影响，可选）。

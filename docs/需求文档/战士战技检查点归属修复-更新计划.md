# 战士战技检查点归属修复 · 更新计划

> 依据《docs/需求文档/战士战技检查点归属修复需求.md》制定。本文件为实施计划存档，执行时按阶段推进。

## 目标与范围

- **根因**：4 个战技检查点（`fighter-2014-maneuvers-3/7/10/15`）定义在 `fighter.ts` **职业级** checkpoints 中，`buildTimeline` 无条件装配 → 勇士/奥法骑士也被强制选战技，校验拦截、角色卡"待补全"。
- **已确认方案**：方案 A——战技检查点**子职特性化**：从职业级检查点移除，改由 `subclass-features-2014.ts` 登记多选规格，`timeline.ts` 按战斗大师子职生成 `subclass-feature-*` 检查点。
- **战技数量不修改**（已对照 PHB 2014 核验：3 级 3 项、7/10/15 级各 +2，合计 9，与现状一致）；仅修正"战斗超驰"摘要文案"四项战技"→"三项战技"。

## 关键实施细节（已核验）

1. `SubclassFeature` 类型（`src/types/rules.ts` 138—154 行）**无多选规格字段**，需新增可选 `minSelections?` / `maxSelections?`（缺省 1/1，兼容现有 19 个 `requiresChoice` 特性）。
2. `subclass-features-2014.ts` 战斗大师相关特性现状：
   - 战斗超驰（3 级）：已有 `requiresChoice: true` + 11 项 `optionIds` → 补 `minSelections: 3`；摘要"四项战技"→"三项战技"。
   - 额外战技（7 级 `extra-maneuvers-7` / 15 级 `extra-maneuvers-15`）：`kind: 'choice'` 但**无 `requiresChoice` / `optionIds`** → 补全 + `minSelections: 2`。
   - **10 级缺口**：当前仅 passive 的"优势骰强化"（`superiority-die-10`），无 10 级战技选择特性 → 新增 `fighter-battle-master-extra-maneuvers-10`（choice，`requiresChoice: true`，11 项战技，`minSelections: 2`）。
3. 两处 `kind === 'maneuvers'` 的查重/统计需适配新检查点（`kind` 变为 `subclass-feature`），统一改为**按选项 ID 前缀判定**（战技选项统一 `maneuver-` 前缀）：
   - `validate.ts` 253—254 行：战技跨检查点唯一性校验；
   - `dependency.ts` `buildLevelReductionReviews`（38—40 行 `countCheckpointKind(draft, level, 'maneuvers')`）：降级战技数量复查。非战斗大师无战技检查点 → 复查提示自然不出现（符合预期）。
   - `TimelineStep.vue` `isUniqueOptionUsedElsewhere`（76—82 行）：界面锁定"已在较低等级掌握"。
4. `dependency.ts` 换子职作废（`subclass-feature-` 前缀，76—88 行）与升降级 `added`/`invalidated`（按 `buildTimeline`）对新检查点**自动生效，无需改动**——这正是方案 A 相比方案 B 的收益。
5. `TimelineStep.vue` 选项渲染走通用分支（`checkpoint.optionIds.length` → `ListShell + OptionCard`，`toggle` 已支持多选、badge 显示 `x/y`），子职特性检查点多选交互**无需新增界面**。

## 已确认决策（2026-08 用户确认）

1. **方案 A 完整修复**：战技检查点子职特性化，不做方案 B 止血过渡。
2. **战技数量不修复**：已对照 PHB 2014 核验官方标准为 3 级 3 项、7/10/15 级各 +2（合计 9），与现状一致；仅修正"战斗超驰"摘要"四项战技"→"三项战技"。

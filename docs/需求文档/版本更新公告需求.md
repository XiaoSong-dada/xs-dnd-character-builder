# 版本更新公告需求

> 2026-08-31 制定。当前应用版本基线为 `v1.1.2`。
>
> 实施更新（2026-08-31）：已完成 package.json 版本注入、结构化公告、独立已读存储、全站单实例弹窗与“关于本站”回看入口，并补充自动化测试与架构记录。

## 1. 背景与目标

项目持续发布新功能与缺陷修复，但更新内容目前只记录在仓库根目录 `CHANGELOG.md`，普通用户进入网站后无法获知版本已经变化，也没有站内入口回看本次更新。

本需求目标是建立全站统一的更新公告机制：浏览器进入网站时比较“当前应用版本”与“本地已读版本”，在首次访问或版本变化时展示当前版本的更新内容；用户读完并关闭后记录最新版本，同一版本不再自动打扰。

## 2. 产品原则

1. 更新公告是非阻断提示，不影响角色草稿恢复、页面导航和离线使用。
2. 已读版本是站点级浏览器偏好，与角色草稿 schema、跑团状态及账号数据相互独立。
3. 自动弹窗只展示当前版本内容，不把用户错过的多个历史版本堆叠到一个弹窗中；完整历史继续由 `CHANGELOG.md` 维护。
4. 更新内容必须由运行时结构化数据提供，不在浏览器中读取或解析仓库 Markdown。
5. 版本发布时，运行时版本、公告内容、`CHANGELOG.md`、`app/package.json` 与 README 最新版本摘要必须同步。

## 3. 用户流程

### 3.1 自动检查

1. 应用在浏览器端完成初始化后读取当前应用版本和本地已读版本。
2. 本地没有已读版本，或已读版本与当前版本不一致时，自动展示更新公告。
3. 两者一致时不自动展示。
4. 检查在全站根级执行，用户从首页、车卡、跑团助手、骰娘或关于页进入时行为一致；一次页面会话只展示一次。

### 3.2 阅读与确认

1. 弹窗标题显示“已更新至 v{当前版本}”。
2. 正文展示该版本面向用户的更新条目，内容简短、可滚动，不能复制完整规则书正文。
3. 提供明确的“我知道了”按钮和关闭按钮；点击遮罩、关闭按钮或“我知道了”均视为本次已读。
4. 只有用户执行关闭动作后，才把当前版本写入本地存储；弹窗刚出现时不得提前写入。
5. 页面在用户确认前刷新或关闭，下次进入仍应再次展示。

### 3.3 手动回看

“关于本站”页面提供“查看本次更新”入口。手动打开不受已读版本限制，也不会改变角色数据；关闭后可保持已读版本为当前版本。

## 4. 功能需求

### R1 当前版本与公告数据

1. 当前应用版本在生产构建中必须始终为非空字符串，统一由 `src/config` 暴露，业务组件不得直接读取 `import.meta.env`。
2. 公告数据使用稳定的结构化类型，至少包含 `version`、`title` 和按顺序排列的 `items`。
3. 当前版本必须能找到同版本公告；缺失时不弹空白弹窗，并在开发/测试阶段产生可定位的校验失败。
4. 版本比较采用规范化后的精确字符串比较：允许输入带或不带 `v`，内部统一去掉前导 `v`；不根据 SemVer 大小推断是否升级。部署回滚后版本不一致同样展示对应版本公告。

### R2 本地已读状态

1. 通过独立 service 封装 localStorage，建议键名为 `dnd-character-builder:update-notice:v1`。
2. 存储值至少包含规范化后的 `lastSeenVersion`；不得复用或修改草稿存储键。
3. 读取到空值、非法 JSON 或非法字段时按“未读”处理，不抛出阻断应用的异常。
4. localStorage 被禁用、超额或写入失败时，网站继续可用；当前会话可以关闭公告，但后续访问可能再次展示。
5. 服务端预渲染阶段不得访问 `window` 或 `localStorage`，避免破坏 vite-ssg 构建与水合。

### R3 全局弹窗

1. 公告挂载在全站根级，只创建一个实例，不分别写入各路由页面。
2. 复用现有弹窗基础能力，标题栏固定、正文区域滚动，并满足手机端触控、键盘焦点、Escape 关闭与可访问名称要求。
3. 公告不得遮蔽后自动执行草稿修改、导航跳转或其他业务副作用。
4. 同一会话内路由切换不得重复弹出；手动回看除外。

### R4 发布维护

1. 每次发布新版本必须新增对应结构化公告，并同步 `CHANGELOG.md`、`app/package.json` 与 README 最新版本条目。
2. README 继续只保留最新版本摘要；历史版本只保留在 `CHANGELOG.md`。
3. 公告只写用户可感知变化，内部重构、测试调整和无体验变化的维护项不进入弹窗。

## 5. 异常与边界

| 场景 | 预期行为 |
| --- | --- |
| 首次访问，没有已读版本 | 展示当前版本公告，确认后写入当前版本 |
| 已读版本等于当前版本 | 不自动展示 |
| 已读版本早于、晚于或不同于当前版本 | 展示当前版本公告，确认后覆盖为当前版本 |
| 公告显示前刷新或关闭页面 | 不写入，下次继续展示 |
| 已读数据损坏 | 当作未读，不影响网站其他数据 |
| localStorage 读取或写入失败 | 网站正常运行；不把错误扩散到角色流程 |
| 当前版本缺少公告数据 | 不展示空弹窗；测试或开发校验失败 |
| vite-ssg 预渲染 | 不访问浏览器存储，不产生水合差异 |

## 6. 验收标准

1. 清空公告存储后进入任意路由，页面只弹出一次 `v1.1.2` 更新公告。
2. 不关闭弹窗直接刷新，公告再次出现；点击关闭或“我知道了”后刷新，不再出现。
3. 将本地已读版本改为其他合法版本后刷新，重新出现当前版本公告，并在确认后写回当前版本。
4. 在“关于本站”可随时手动打开当前版本公告。
5. 非法存储值、禁用 localStorage 和缺失公告数据均不会阻断应用启动。
6. 手机与桌面尺寸下标题和操作可见、长内容仅正文滚动；键盘可以完成阅读与关闭。
7. 类型检查、相关组件与 service 测试、完整自动化测试及生产构建通过，浏览器控制台无新增错误。

## 7. 影响范围与非目标

预计涉及全站根组件、站点配置、独立本地存储 service、更新公告数据与弹窗组件，以及“关于本站”的手动入口。依赖方向保持为 `App/layout -> component -> config/service`，不得由 service 反向依赖 Vue、视图或路由。

本需求不包含 Service Worker 强制刷新、远程公告接口、账号级已读同步、按用户灰度发布、强制升级、数据库迁移或自动解析 `CHANGELOG.md`。

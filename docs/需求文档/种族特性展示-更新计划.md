# 种族特性展示 · 更新计划

> 依据《docs/需求文档/种族特性展示需求.md》制定，用户 2026-09-02 已确认全部决策：**背景特性纳入、分组展示、属性提升条目纳入、PDF/XLSX 导出暂不纳入、跑团助手同步展示、等级特性仅按等级过滤不建检查点**。本文件为实施计划存档，执行时按阶段推进。

## 目标与范围

- **根因**：`races2014` / `backgrounds2014`（`origins-2014.ts`）没有结构化特性注册表，种族/背景特性只存在于 `description` 文本，导致角色卡与跑团助手「能力」页签无法逐条展示（职业/子职特性已有结构化注册表）。
- **已确认方案**：
  1. 新建 `race-features-2014.ts`（~240 条，来源 `docs/species/5e-2014/`，含 `ability-score-increase` 条目）与 `background-features-2014.ts`（40 条，来源 `docs/backgrounds/5e-2014/`）。
  2. 角色卡与跑团助手「能力」页签**分组展示**：种族特性 · 基础种族 / 种族特性 · 子种族 / 背景特性 · 背景，按 `level <= targetLevel` 过滤，复用 `ExpandableOptionCard`。
  3. 3/5 级种族特性按等级过滤展示，**不新增时间线检查点**。
  4. **PDF/XLSX 导出本次不纳入**（`ExportFeature` 的 `'race'` / `'background'` 类目保持预留）。
- **不改动范围**：`description` 文本与规则数值、`origins-2014.ts` 的既有字段与 ID、2024 物种（`5e-2024`）资料、时间线检查点结构、草稿 schema。

## 关键实施细节（已核验）

1. **兼容性**：新增注册表与 `RaceRule.features` 挂载均为增量；草稿存档（`raceId` / `subraceId` / `backgroundId`）不变，导入导出完全兼容。
2. **特性 ID**：种族特性沿用 docs 已定义的 `race-2014-<种族>-<特性>` / `race-2014-<种族>-<子种族>-<特性>`；背景特性建议 `background-2014-<背景>-feature`（实施阶段 0 与 docs 核对）。
3. **继承与分组**：子种族特性只含自身条目（docs 子种族文件只记录相对父项新增/替换内容）；展示时基础种族与子种族分两组，父项特性不重复出现。
4. **属性提升条目**：`race-2014-*-ability-score-increase` 纳入（属性值实际派生仍由 `origins-2014.ts` 的 `fixedAbilityBonuses` 等字段计算，特性条目仅作展示）。
5. **状态与来源**：与 docs 核验状态一致（`implemented` / `index-only`）；`sourceIds` 沿用 `origins-2014.ts` 的登记（basic-rules-2014、vgm-2016-index、erftlw-2019-index、mtof-2018-index、ggr-2018-index、eepc-2015-index、ftd-2021-index、phb-2014-index 等）。
6. **展示复用**：`CharacterSheetStep.vue` 与 `SessionPanel.vue` 的职业/子职特性区块结构一致（`ListShell` + `ExpandableOptionCard` + `仅索引 · 未核验` 标记 + 空态提示），种族/背景区块照此模式新增。
7. **背景变体**：变体背景（间谍/角斗士等，`parentBackgroundId`）沿用父背景特性条目；展示时按草稿实际选择的背景 ID 取特性（背景变体与父项 `featureName` 相同，实施时确认是否复用同一特性 ID 或按变体登记）。

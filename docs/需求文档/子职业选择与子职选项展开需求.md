# 子职业选择与子职选项展开需求

> 提出日期：2026-09-20；决策确认日期：2026-09-20。
> 来源：用户口头需求——「完善第 6 步中的子职业选择，以及子职业项选择，希望这些选择都为已经封装好的列表，默认为未展开、展开后可看到详情，可参考邪术师的魔能祈唤列表；需要分析有哪些职业不是用的这种方式、哪些职业选择不是用的这种方式」。
> **本次交付仅为需求理解、现状盘查与前置条件整理，未修改任何产品代码。**
> 状态：**批次 A（展示与交互）已完成**；批次 B（资料补齐：D1／D2／D4 与术语统一）待实施。需求决策 Q1—Q11 全部落定（见 6.1）。最终范围 **183 个检查点**（27 子职选择 + 58 子职特性选项 + 98 职业级静态选项，其中含 28 个技能选择检查点）。
> 批次 A 的实施记录见[批次 A 更新计划](子职业可展开列表-批次A更新计划.md)第 7 节。
> 数据与术语基准：**《5e 不全书》CHM v2026.09.13**（用户提供，已解包并核验，见 4.4）；**术语冲突一律以该 CHM 为准**（Q10）。
> 数据来源：本地《5e 不全书》CHM（见 4.4）。
> 基线参考：邪术师魔能祈唤展示优化（W02）——[《邪术师魔能祈唤补全与译名核验需求》](邪术师魔能祈唤补全与译名核验需求.md)、[更新计划第 9 节](邪术师魔能祈唤补全-更新计划.md)。本次是该展示口径从「仅邪术师」扩展到「全部子职与职业级静态选项」的后续批次。

## 1. 背景与目标

### 1.1 现状一句话

车卡第 6 步（时间线）里，**只有 2014 邪术师的宗主选择**用了可展开卡片（`ExpandableOptionCard`），其余 **26 个子职选择检查点**与**所有 58 个有静态候选的子职特性选项检查点**都用的是不可展开的紧凑卡片（`OptionCard`）。

### 1.2 本批目标

| 编号 | 目标 | 现状 |
| --- | --- | --- |
| G1 | 第 6 步子职选择（`kind: 'subclass'`）统一为可展开列表：默认折叠只看名称与一行摘要，展开后读完整详情 | 仅 2014 邪术师符合 |
| G2 | 第 6 步子职特性选项选择（`kind: 'subclass-feature'` 中的静态选项）统一为可展开列表 | 0 个符合 |
| G3 | 第 6 步**职业级静态选项**（技能、职业选择、专精、战斗风格、灌注）统一为可展开列表（**Q3-B 追加**） | 0 个符合；能力提升／专长已由 `FeatChoicePanel` 用可展开卡 |
| G4 | 建立可复用的候选卡渲染口径，后续新增职业／子职自动继承，不在视图层按职业 ID 分支 | 靠检查点 `optionPresentation` 逐条标记 |
| G5 | 2014 子职与子职选项的资料完整度核查与状态升级（**Q6-B 追加**） | 111 项 `selectable`／2 项 `dm-only`，无 `implemented` 以外的真实摘要 |

### 1.3 交付物

- 本文档：现状基线、差异清单、前置条件、改造要求、验收口径、决策记录。
- 不改产品代码、不改规则数据；实施另开批次（建议编号 **W03**）。

## 2. 现状盘查（实测）

盘查方式：以 Vite SSR 加载规则层，遍历两版规则集 × 27 个职业 × 208 个子职，在 20 级下构建时间线并逐检查点归类（共 346 个去重检查点）。口径为「按草稿规则集解析 + 全部来源开启 + 已选子职」。

### 2.4 同一检查点内的重复展示（现状事实）

`subclass` 检查点展开后，除候选卡外还会渲染只读的「子职特性 · {子职名}」区块（`TimelineStep.vue` 第 353—368 行），其条目已经是可展开卡。因此玩家在同一屏会看到两种卡片：**可选**的紧凑候选卡（要改的对象）与**只读**的可展开特性卡（保持现状）。改造后两者视觉统一。

## 3. 问题与差异清单

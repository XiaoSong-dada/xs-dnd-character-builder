# 角色卡物品与金币需求

## 1. 背景与目标

用户反馈：角色卡"物品"页签目前**只读展示**已装备物品、物品栏条目与一行"起始金币"文本，角色在冒险中获得的物品与金币**无法记录**，角色卡不具备冒险成长能力。

上一轮分析已确认现状：`CharacterSheetStep.vue` 的 `items` 页签从 `draft.inventory` 派生展示，数据层（`InventoryEntry` / `CurrencyWallet`）已具备扩展条件，但界面没有任何写入交互；金币仅展示 `draft.currency.gp` 一个只读文本。

目标产物：

- 角色卡"物品"页签支持**添加物品**：点击"添加物品"弹出弹窗，从**内置物品库**选择（支持搜索与分类筛选），或**自定义物品名**，指定数量后加入**物品栏或装备栏**。
- 角色卡"物品"页签支持**金币调整**：以 GP 为单位，支持"输入增量添加"与"直接设置数值"两种方式（负值即扣减）。
- 新增物品与金币变更随草稿持久化，导出 JSON 自动包含，重新编辑流程中不丢失。
- 前置条件：官方全量物品规则文档（`docs/dnd-equipment.md` 及 `docs/equipment/5e-2014/` 分文档）作为内置物品库的数据依据；`app/src/rules/data/equipment-2014.ts` 的数据补全列为后续批次（见 R8）。

## 2. 现状调查（已核验）

### 2.1 数据层（已具备扩展条件）

| 模块 | 现状 |
|---|---|
| `app/src/types/character.ts` `InventoryEntry` | `{ id, itemId, quantity, sourceKind: 'class'\|'background'\|'legacy', sourceId, equippedQuantity }`；**缺冒险获得来源**（`sourceKind` 需新增 `'adventure'`） |
| `app/src/types/character.ts` `CurrencyWallet` | 五种币种齐备（`cp/sp/ep/gp/pp`），但界面只使用 `gp` |
| `app/src/rules/data/equipment-2014.ts` | 内置物品库当前仅 SRD 普通物品（护甲 12 + 盾 1、武器 37、冒险装备、工具、法器、套组）；**官方全量物品（含魔法物品）整理见 `docs/dnd-equipment.md`** |
| `app/src/rules/repository.ts` | `getEquipment(id)` 可查物品；`EquipmentRule` 含 `category`（armor/shield/weapon/tool/gear）与 `equippable`，可支撑弹窗分类筛选与装备约束 |
| `app/src/services/character-json.ts` | 草稿全量 JSON 序列化，`inventory`/`currency` 随导出自动包含；`schemaVersion 3` 导入时保留两字段，**无需改导出格式与版本号** |
| `app/src/rules/starting-equipment.ts` `updateEquippedQuantity` | 装备/卸下切换已有现成实现（编辑流程使用） |

### 2.2 界面层（缺口定位）

| 界面 | 现状 | 缺口 |
|---|---|---|
| `CharacterSheetStep.vue` `items` 页签（335–364 行） | 只读展示"已装备"与"物品栏"，底部一行"起始金币"文本 | 无添加物品入口、无弹窗、无金币调整交互 |
| `UiModal.vue` | 现成弹窗组件（open/title + close + 默认插槽 + footer 插槽） | 可直接复用 |
| `ExpandableOptionCard.vue` | 现成卡片组件（title/description/expanded 插槽） | 可直接复用 |
| 数据流 | `CharacterSheetStep` emit → `index.vue` → `useCharacterBuilderPage.ts`（`store.updateDraft`） | 需新增 `changeInventory` / `changeAdventureGold` 事件通道（参照现有 `changeSpellSelections` 模式） |

### 2.3 结论

- 数据层无需改结构即可支持"冒险获得"物品（仅需为 `sourceKind` 增加 `'adventure'` 字面量）。
- 界面层缺口集中：物品页签需新增「添加物品」按钮、选择弹窗与金币调整面板。
- 物品库的完整性依赖前置条件：官方全量物品规则文档（本批交付），数据文件补全为后续批次。

## 3. 需求项

### R1 添加物品入口（必须）

物品页签新增「添加物品」按钮（满足 44px 点击目标约定），点击打开弹窗。弹窗复用 `UiModal`。

### R2 弹窗：内置物品库选择（必须）

弹窗主体为内置物品库选择区：

1. **搜索框**：按物品中文名（及英文名）模糊过滤。
2. **分类筛选**：全部 / 护甲 / 盾牌 / 武器 / 工具 / 杂物（对应 `EquipmentRule.category`），单选切换。
3. **物品列表**：每项展示物品名与简介（复用 `ExpandableOptionCard` 或轻量列表），点击选中（单选高亮）。
4. 弹窗内同时提供**数量选择**（默认 1，可增减，最少 1）与两个加入按钮：「加入物品栏」「加入装备栏」。
5. 「加入装备栏」仅当所选物品 `equippable` 时可用，否则置灰并给出原因提示（选中非可装备物品时提示"该物品无法装备"）。

### R3 弹窗：自定义物品（必须）

弹窗内提供"自定义物品"入口（与内置库并列的独立输入区，或"未找到？自定义添加"链接）：

1. 输入物品名（必填，去首尾空白后非空）。
2. 自定义物品作为普通物品加入物品栏，**不可装备**（「加入装备栏」置灰）。
3. `itemId` 直接使用物品名；展示层 `getEquipment(itemId)?.name ?? itemId` 已天然回退显示自定义名。
4. 自定义物品的展开详情显示"自定义物品"占位说明。

### R4 数据写入规则（必须）

对 `draft.inventory` 执行：

1. `InventorySourceKind` 类型增加 `'adventure'`（`app/src/types/character.ts`）。
2. 新增条目：`{ id: 唯一（如 \`adventure:<draftId>:<itemId>:<时间戳>\`）, itemId, quantity: 所选数量, sourceKind: 'adventure', sourceId: 'adventure', equippedQuantity: 加入装备栏 ? 所选数量 : 0 }`。
3. **合并规则**：仅当物品栏中已存在 `sourceKind === 'adventure'` 的同 `itemId` 条目时合并数量（`quantity` 累加；若加入装备栏，`equippedQuantity` 同步累加）；否则新建独立 adventure 条目，不合并进职业/背景起始装备条目，避免污染其数量（实现为 `addAdventureItem` 纯函数）。
4. 数量与装备数量关系约束：`equippedQuantity ≤ quantity` 恒成立。

### R5 金币调整（必须）

物品页签新增金币面板。数据模型将"起始金币"与"冒险净增金币"分离：`currency.gp` 为起始金币（由职业/背景确定，换职业/背景时重算），`adventureGold` 为冒险净增金币（GP，可为负）；持有总额 = `currency.gp + adventureGold`。

1. 展示当前持有总额：`{{ draft.currency.gp + draft.adventureGold }} GP`（保留"起始金币 {{ draft.currency.gp }} GP"来源说明文案）。
2. 输入框（数字，允许负数输入）+ 两个操作按钮：
   - **「添加」**：增量，`adventureGold += 输入值`（输入负数即扣减）。
   - **「设置」**：设置持有总额，`adventureGold = 输入值 - currency.gp`。
3. 校验：输入为空或非整数时不生效；持有总额必须为非负整数（`currency.gp + adventureGold ≥ 0`），否则提示中文原因（如"金币不能为负"）且不写入。
4. 仅操作 GP；`cp/sp/ep/pp` 不暴露（保持现状；后续批次见 R7）。

### R6 持久化与回读（必须）

1. 变更经 `changeInventory` / `changeAdventureGold` 事件 → `index.vue` → `useCharacterBuilderPage.ts` → `store.updateDraft` 保存，与现有 `changeSpellSelections` 通道一致。
2. 导出 JSON 自动包含新增物品与金币变更（全量序列化，无需改导出逻辑）。
3. 重新编辑流程（`EquipmentStep.vue`）中，`'adventure'` 条目正常展示，`sourceLabel` 增加 `'adventure'` →「冒险获得」分支（避免落入 `legacy` 的"旧草稿"文案）。
4. **重新编辑换职业/背景不丢失**：`buildStartingEquipmentState` 重建物品栏时会保留 `sourceKind === 'adventure'` 的条目（与 `legacy` 同级追加，不静默删除），冒险物品与金币在重新编辑后继续保留。

### R7（后续，非本批必须）金币与物品能力扩展

- 五种币种完整支持（cp/sp/ep/gp/pp 独立调整与换算展示）。
- 物品移除 / 丢弃 / 数量减少（本批只加不减；如需撤销可后续补充）。
- 购买 / 出售：按 `docs/dnd-equipment.md` 收录的官方价格扣减 / 增加金币。
- 负重（按官方重量计算）。

### R8（后续，非本批必须）内置物品库数据补全

- 将 `docs/equipment/5e-2014/` 整理的官方全量物品（含魔法物品）逐批登记进 `app/src/rules/data/equipment-2014.ts`（原创摘要转述，遵守 `docs/rules.md` 版权边界）。
- 魔法物品按稀有度 / 来源标记 `status`（`implemented` / `index-only`），未核验效果的条目只入目录不参与派生计算。
- 数据补全后，"添加物品"弹窗的内置库将覆盖官方全部物品，自定义入口保留作为库外物品兜底。

## 4. 非目标与边界

- 新增 `adventureGold` 字段以分离起始金币与冒险净增金币；不提升 `schemaVersion`（旧草稿经 `adventureGold ?? 0` 兜底兼容）。
- 不实现物品删除、数量减少、出售（R7 后续）。
- 不实现 cp/sp/ep/pp 界面与换算（R7 后续）。
- 本批不补全 `equipment-2014.ts` 数据（R8 后续；前置文档本批交付）。
- 自定义物品不参与装备数值派生（不可装备）。
- 魔法物品等库外物品在本批通过自定义入口添加；内置库补全后自动进入选择列表。
- 旧 v3 草稿导入时 `currency.gp` 被重新解释为起始金币：持有总额不变，仅"起始金币"标签语义漂移（旧语义下 `currency.gp` 可能是用户已调整的总额）。

## 5. 涉及模块与依赖方向

```text
views/character-builder/components/CharacterSheetStep.vue
  -> components/ui（UiModal / ExpandableOptionCard / StatTile 等）
  -> rules/repository（getEquipment）
  -> types/character（InventoryEntry / CurrencyWallet / InventorySourceKind）
views/character-builder/components/AddItemModal.vue（新建，页面私有组件）
views/character-builder/index.vue / hooks/useCharacterBuilderPage.ts（新增事件通道）
views/character-builder/components/EquipmentStep.vue（sourceLabel 增加 'adventure' 分支）
rules/data/equipment-2014.ts（R8 数据补全，后续批次）
```

依赖方向不变：`views → rules → types`；`AddItemModal.vue` 为页面私有组件，无需调整 `docs/frontend-architecture.md` 拓扑。

## 6. 验收标准

1. `pnpm test` 全量通过；为 `InventorySourceKind` 扩展与物品合并逻辑补充单元测试（若现有测试框架覆盖规则层）。
2. `pnpm build`（含 `vue-tsc -b`）通过。
3. 手动验证：
   - 点击「添加物品」弹出弹窗；搜索与分类筛选生效。
   - 内置物品加入物品栏：数量正确；重复添加同一物品合并数量。
   - 可装备物品（如长剑）加入装备栏：物品栏与"已装备"区同步展示，装备数量正确。
   - 非可装备物品（如口粮）「加入装备栏」置灰且提示原因。
   - 自定义物品名添加成功，展示名正确，不可装备。
   - 金币「添加」：`+10`、`-5`（扣减）结果正确；「设置」直接覆盖；负数结果被拒绝并提示。
   - 导出 JSON 包含新增物品与金币；导入回读一致。
   - 重新编辑流程中冒险物品显示"冒险获得"来源标识，金币保留。
